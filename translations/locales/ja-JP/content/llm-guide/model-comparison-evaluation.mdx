## 評価の範囲と方法

- **評価の目的**：HagiCode プロジェクトでの実際の導入経験に基づいて、モデル選定の参考情報を示します。
- **テストしたタスクの種類**：フロントエンドコンポーネントの実装、バックエンド API のリファクタリング、テストケースの補完、ドキュメント生成。
- **評価の観点**：効率と完成度（タスクを安定して完了できるか）、およびコストパフォーマンス（コスト + 中国国内での利用しやすさ）。

## テスト時期と場面の説明

- **直近のテスト日**：2026-03-08
- **テスト期間**：2026-03-01 から 2026-03-08
- **サンプルについて**：HagiCode チームの実際の開発タスクに基づく感覚的な評価であり、ベンダー公式のベンチマークを表すものではありません。
- **適用範囲**：結論は主に本プロジェクトの現在のワークフローとエンジニアリング上の制約に当てはまるもので、一般的な結論と同じではありません。

## 本ページは実測したモデルのみを対象とします

以下のモデルは、いずれもプロジェクトで実際に導入し、使用したことのあるモデルです。

- GLM 4.7
- GLM 5
- Qwen 3.5
- Qwen Code Next
- GPT 5.3 Codex
- GPT 5.4
- Minimax M2.5

## モデル比較の概要（実測）

| モデル名 | テスト日 | 効率と完成度 | コストパフォーマンス | 主な使用感 |
|---------|---------|-----------|--------|---------|
| GPT 5.4 | 2026-03-08 | 非常に高い | 中〜高 | 要求を安定して上回り、エンジニアリングの実践も実装の品質も非常に優れている |
| GPT 5.3 Codex | 2026-03-08 | 非常に高い | 中〜高 | 要求の範囲内での完成度が高く、エンジニアリングとしての出力品質が優れている |
| GLM 5 | 2026-03-08 | 高い | 高い | タスクを比較的スムーズに完了でき、総合的に安定している |
| GLM 4.7 | 2026-03-08 | 高い | 非常に高い | 要求を比較的スムーズに満たせ、コストを抑えやすい |
| Minimax M2.5 | 2026-03-08 | 中〜高 | 最高 | 多くの目標は達成できるが、コードの閉じ忘れによるエラーが出やすい |
| Qwen 3.5 / Code Next | 2026-03-08 | 中 | 中〜高 | 私たちの場面では、完成度が相対的に低め |

## 効率と完成度の評価（筆者のおすすめ順）

「タスク完了の品質 + エンジニアリング実践の効果」で並べています。

1. GPT 5.4
2. GPT 5.3 Codex
3. GLM 5
4. GLM 4.7
5. Minimax M2.5
6. Qwen（3.5 / Code Next）

### 主な結論

- Qwen を除くほかのモデルは、私たちのプロジェクトのタスクで、ある程度は目標を達成できました。
- GLM 4.7 以上（GLM 4.7、GLM 5）は、全体として私たちの要求を比較的スムーズに満たせます。
- GPT 5.3 Codex と GPT 5.4 は、要求を満たすだけでなく、より優れたエンジニアリングの実践と実装結果を示すことも多くあります。
- Minimax M2.5 の主な問題は、コードの閉じ忘れによるエラー（たとえば括弧やブロックの閉じ方が不完全なこと）が出やすく、追加の確認が必要になる点です。

## コストパフォーマンスの評価（経済的コスト + 中国国内での利用しやすさ）

「コストに対する効果 + 中国国内でスムーズに使えるか」を優先して並べています。

1. Minimax M2.5
2. GLM 4.7
3. GLM 5
4. Qwen 3.5 / Code Next
5. GPT 5.3 Codex
6. GPT 5.4

> 補足：この順位は効率と完成度の順位とは異なり、主に経済的コストと入手しやすさという現実的な制約を反映しています。

## モデル選定の提案

- **品質優先**：GPT 5.4 / GPT 5.3 Codex を優先します。
- **バランス優先**：GLM 5 / GLM 4.7 を優先します。
- **コスト優先**：Minimax M2.5 を優先します（ただし、コードの閉じ忘れのチェックを強化してください）。
- **運用方針**：「高品質なモデルで重要なタスクを処理し、コストパフォーマンスの高いモデルで通常のタスクを処理する」という階層的なルーティングの採用をおすすめします。

## 未テストのモデルについて

本ページに記載のないその他のモデルについては、現時点で**テストを行っておらず**、**実際の使用経験もない**ため、評価はしていません。

スポンサーの方が該当するモデルのリソースを提供してくださる場合は、実際のワークフローに沿って引き続き感覚的な評価を行い、本ページを更新します。

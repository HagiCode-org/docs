Quelle que soit la méthode d'installation ([Microsoft Store](/fr-FR/installation/windows-store), [Desktop](/fr-FR/installation/desktop) ou [Docker Compose](/fr-FR/installation/docker-compose)), l'**assistant d'initialisation** s'affiche à la première ouverture de l'interface Web de HagiCode. Une fois terminé, vous disposez d'un Hagicoder par défaut opérationnel et d'au moins un projet, et vous pouvez démarrer directement votre première session.

:::note[Différence avec le guide de premier lancement de Desktop]
Le guide « Configuration initiale » de Desktop (choisir la langue, confirmer les documents juridiques, télécharger Hagicode Server) se déroule avant l'apparition de l'interface Web, voir [Installation de bureau](/fr-FR/installation/desktop#guide-du-premier-lancement). Cette page décrit l'assistant d'initialisation qui apparaît ensuite dans l'interface Web.
:::

## Avant de commencer

Vérifiez d'abord les points suivants :

- **Au moins un Agent CLI installé et connecté.** L'assistant ne liste que les CLI détectés sur la machine qui exécute Hagicode Server ; tant qu'aucun n'est détecté, vous ne pouvez pas continuer pour créer un Hagicoder. Les CLI pris en charge et leur mode d'installation figurent dans [Installation de la CLI de l'agent IA](/fr-FR/related-software-installation/ai-agent-cli/).
- **Utilisateurs Desktop / Store** : Node.js 24+ et Git sont déjà installés, conformément au [Guide d'installation](/fr-FR/installation/#préparation-avant-linstallation).
- **Utilisateurs Docker** : le fournisseur d'API et le jeton sont déjà configurés dans Docker Compose Builder.
- Préparez un dépôt local ou un répertoire de travail à connecter : l'étape 3 vous demandera de l'enregistrer.

## Aperçu de l'assistant

L'assistant comporte 4 étapes ; la navigation de gauche affiche la progression :

| Étape | Objectif | Critère d'achèvement |
| --- | --- | --- |
| 1. Configuration de base | Choisir la langue de l'interface et le thème | Cliquer sur « Suivant : configurer Hagicoder » |
| 2. Configurer Hagicoder | Choisir un CLI et un modèle, puis créer le Hagicoder par défaut | Cliquer sur « Confirmer et créer Hagicoder », ou disposer déjà d'un Agent utilisable |
| 3. Créer un projet | Créer au moins un projet | L'étape du projet affiche « Étape du projet terminée » |
| 4. Guide communauté | Découvrir les points d'entrée de la communauté | Cliquer sur « Commencez à utiliser HagiCode » |

## Étape 1 : Configuration de base

**Objectif** : définir la langue de l'interface et le thème.

1. Dans « Choisir la langue de l'interface », sélectionnez une langue. Cela ne change que les textes de l'interface, pas le style de langage du Hagicoder.
2. Dans « Choisir un thème », sélectionnez un thème. Les thèmes actuellement proposés sont « Printemps clair » et « Printemps sombre ».
3. Cliquez sur « Suivant : configurer Hagicoder ».

## Étape 2 : Configurer Hagicoder

**Objectif** : créer l'Agent par défaut, dont le nom est toujours **Hagicoder**.

Si le système contient déjà un Agent, cette étape affiche « Agents existants détectés » ; vous pouvez alors simplement conserver la composition existante. Sinon :

1. **Choisissez votre AgentCLI principal** : la liste déroulante n'affiche que les CLI détectés sur la machine. Si l'assistant indique qu'aucun CLI utilisable n'a été détecté, installez-en un et connectez-vous en suivant [Installation de la CLI de l'agent IA](/fr-FR/related-software-installation/ai-agent-cli/), puis revenez actualiser.
2. **Choisissez votre Modèle principal** :
   - **Sélectionner un modèle existant** : réutilisez un modèle déjà disponible pour ce CLI ; vous pouvez le rechercher par nom ou par ID de modèle.
   - **Saisir un modèle personnalisé** : saisissez manuellement un nom de modèle, par exemple `gpt-5.5`, `glm-5.1` ou `claude-opus-4-7` ; le modèle correspondant est réutilisé ou créé automatiquement lors de la création.
3. **(Facultatif) Cliquez sur « Tester la disponibilité »** : cela envoie un ping-pong au CLI et au modèle choisis pour vérifier que le modèle répond `pong`. Le résultat n'est valable que pour la combinaison CLI + modèle actuelle ; après toute modification, relancez le test. La création du Hagicoder n'exige pas que le test réussisse.
4. **(Facultatif) Cliquez sur « Mélanger »** pour changer le portrait par défaut ; l'avatar est tiré au hasard dans la galerie.
5. Cliquez sur « Confirmer et créer Hagicoder ». Une fois créé, il est ajouté à l'équipe d'urgence, et le CLI et le modèle choisis sont inscrits dans sa configuration par défaut.

:::tip[Quels CLI sont pris en charge]
Les CLI proposés dans l'assistant dépendent des Agent CLI installés et détectés sur la machine ; ils ne se limitent pas à un seul. La liste complète des CLI pris en charge et leurs modes d'installation font foi dans [Installation de la CLI de l'agent IA](/fr-FR/related-software-installation/ai-agent-cli/) ; Hermes, Gemini et DeepAgents nécessitent d'abord une installation ou une authentification manuelle.
:::

**Problèmes fréquents**

- **Mon CLI n'apparaît pas dans la liste** : vérifiez qu'il est installé et utilisable dans l'environnement qui exécute Hagicode Server ; les utilisateurs de Desktop doivent redémarrer Desktop pour actualiser le `PATH`.
- **Le test de disponibilité échoue** : les causes courantes sont un CLI non connecté, un jeton invalide ou un nom de modèle non pris en charge par ce CLI. Lancez d'abord une conversation minimale avec ce CLI dans un terminal pour vérifier qu'il fonctionne par lui-même.
- **L'ajout à l'équipe d'urgence échoue** : la page propose « Réessayer d'ajouter à l'équipe d'urgence » ; il suffit de réessayer.

## Étape 3 : Créer un projet

**Objectif** : enregistrer au moins un projet, pour que les sessions suivantes disposent d'un répertoire de travail lisible. L'assistant vérifie d'abord si un projet local existe déjà : s'il y en a un, il affiche le résumé du projet actuel ; sinon, vous devez d'abord en enregistrer un.

1. Dans « Enregistrez un projet local », renseignez le nom du projet, le chemin du dossier et, facultativement, une description du projet. Les champs et la validation du chemin sont exactement les mêmes que dans la boîte de dialogue « Nouveau projet » de l'interface principale.
2. Cliquez sur « Créer et continuer » pour passer à l'étape suivante ; si vous voulez rester sur cette étape pour en ajouter d'autres, cliquez sur « Créer un projet ».
3. Si un projet existe déjà, vous pouvez cliquer directement sur « Continuer vers la communauté », « Créer un autre projet », ou revenir à la configuration (« Retour à la configuration »).

:::tip[Envie d'essayer d'abord avec un projet d'exemple ?]
L'assistant ne propose que l'enregistrement d'un projet local. Le « Projet de démonstration » se trouve dans l'onglet « Projet de démonstration » de la boîte de dialogue « Nouveau projet » de l'interface principale : il clone et enregistre automatiquement le dépôt officiel MonoSpecs Demo, dans le chemin par défaut `data/repos/monospecs-demo` ; le répertoire réel suit la configuration du répertoire de données d'exécution (DataDir). Cette méthode nécessite Git et un accès à GitHub.
:::

**Problèmes fréquents**

- **La validation du chemin échoue** : vérifiez que le chemin du dossier est correct et existe réellement ; avec un déploiement Docker, vous devez saisir un répertoire monté accessible dans le conteneur, et non un chemin de la machine hôte.

## Étape 4 : Guide communauté

**Objectif** : garder les points d'entrée de la communauté à portée de main.

La page « À propos » du site officiel regroupe tous les points d'entrée de la communauté. Les liens s'ouvrent dans un nouvel onglet ; une fois que vous avez terminé, revenez à l'assistant et cliquez sur « Commencez à utiliser HagiCode » pour accéder à l'espace de travail. Vous pourrez toujours rouvrir l'assistant après cette étape.

HagiCode Desktop utilise les **commandes externes `node` et `npm` installées sur votre système**. Installez Node.js avant le premier lancement de Desktop et assurez-vous que les deux commandes sont accessibles via le `PATH` du système.

Cette FAQ explique comment Desktop trouve votre environnement Node externe, où sont installés les Agent CLI et comment résoudre les problèmes lorsque Node ou npm est introuvable.

## Version requise

**Node.js 24 ou supérieur** est requis (le minimum est lui aussi 24). `npm` est installé avec Node.js. Pour l'installation, voir [Installer Node.js](/fr-FR/related-software-installation/nodejs/installation).

Git doit lui aussi être installé par vos soins, voir le [Guide d'installation](/fr-FR/installation/#installer-git).

## Comment Desktop trouve node et npm

Desktop lit le `PATH` du système au démarrage et y recherche `node`, `npm` et `git`. Cela signifie que :

- La version affichée par `node --version` dans votre terminal est généralement celle que Desktop utilise.
- Desktop ne fait qu'**utiliser** votre environnement Node, sans le remplacer ni le modifier.
- Si vous installez ou mettez à jour Node.js alors que Desktop est déjà ouvert, quittez complètement Desktop puis relancez-le afin qu'il lise le nouveau `PATH`.

:::caution[Gestionnaires de versions et PATH]
Sous macOS et Linux, les gestionnaires de versions comme nvm ou fnm ne définissent généralement le `PATH` que dans les fichiers de configuration du shell. Desktop lancé depuis le Dock, le menu des applications ou une icône du bureau ne lit pas ces fichiers et risque de ne pas trouver `node`. Lancez Desktop depuis un terminal où `node` fonctionne déjà, ou utilisez plutôt une installation au niveau du système.
:::

## Où sont installés les paquets gérés comme les Agent CLI

La page de gestion des dépendances de Desktop détecte `node` et `npm` dans le `PATH`, affiche le préfixe global de npm résolu et installe les paquets CLI listés dans le catalogue dans ce répertoire global **externe**.

Pour chaque CLI géré, Desktop recherche l'exécutable dans l'ordre suivant :

1. Le chemin géré existant
2. Le répertoire `bin` global de npm (sous Windows, y compris les scripts de lancement `.cmd` et `.ps1`)
3. Le `PATH`

Les paramètres de miroir npm s'appliquent aux opérations d'installation et de synchronisation. La désinstallation cible elle aussi le répertoire global externe et doit être confirmée dans l'interface. Vous pouvez afficher le répertoire global actuel avec la commande suivante :

```bash
npm prefix -g
```

Si le répertoire global se trouve dans un emplacement qui exige des droits d'administrateur, l'installation peut produire une erreur de permissions ; reportez-vous à [Configurer le répertoire global de npm](/fr-FR/related-software-installation/nodejs/installation#configurer-le-répertoire-global-de-npm).

## Que faire si Node ou npm est introuvable

1. Exécutez `node --version` dans un terminal et vérifiez que Node.js est en version 24 ou supérieure. Exécutez ensuite `npm --version` pour vérifier que npm est disponible.
2. Si Node.js n'est pas installé ou si la version est trop ancienne, installez-le d'abord en dehors de Desktop.
3. Quittez complètement Desktop puis relancez-le, retournez sur la page des dépendances et cliquez sur actualiser.

Lorsque Desktop indique qu'un paquet CLI doit être installé manuellement, exécutez la commande fournie dans un terminal en dehors de Desktop, puis revenez dans Desktop et actualisez une fois pour qu'il refasse la détection.

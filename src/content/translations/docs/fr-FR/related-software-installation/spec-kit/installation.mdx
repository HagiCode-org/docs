Spec Kit est la boîte à outils open source de GitHub pour le développement piloté par les spécifications (Spec-Driven Development) : on écrit d'abord la spécification, puis un plan et des tâches, et enfin on laisse son assistant de codage IA implémenter les tâches. Sa ligne de commande s'appelle `specify` et provient du paquet `specify-cli`.

De nombreux tutoriels en ligne utilisent encore l'ancienne commande d'installation, l'option `--ai` et des noms de commandes comme `/speckit.specify`, et les copier échoue souvent. Cette page suit la documentation officielle pour présenter la méthode actuelle et liste ce qui a changé.

:::note[Date de vérification]
Rédigé d'après la [documentation officielle de Spec Kit](https://github.github.com/spec-kit/), vérifiée le 2026-10-26. Le projet évolue vite : en cas de divergence, fiez-vous à `specify --help` sur votre machine et à la documentation officielle plutôt qu'à cette page.
:::

## À qui s'adresse cette page

- Aux personnes qui veulent essayer un flux piloté par les spécifications dans un assistant de codage IA tel que Claude Code, GitHub Copilot, Gemini CLI, CodeBuddy CLI, Pi ou Oh My Pi.
- Aux personnes qui ont installé Spec Kit avec un ancien tutoriel et obtiennent maintenant des erreurs ou des commandes introuvables.

## Prérequis

| Élément | Exigence |
| --- | --- |
| Système | Linux, macOS ou Windows (les scripts PowerShell fonctionnent sans WSL) |
| Python | 3.11 ou supérieur |
| Gestionnaire de paquets | uv (recommandé) ou pipx |
| Assistant de codage IA | Tout assistant pris en charge ; la documentation officielle liste des dizaines d'intégrations |
| Git | Facultatif, nécessaire uniquement lorsque l'extension git est activée |

Spec Kit lui-même n'a pas besoin de Node.js. Si votre assistant s'installe via npm, consultez d'abord [Installation des AI Agent CLI](/fr-FR/related-software-installation/ai-agent-cli/).

## Installer specify-cli

### Option 1 : depuis PyPI (la plus courte)

```bash
# Recommandé : uv
uv tool install specify-cli

# Ou pipx
pipx install specify-cli

# Ou pip
pip install specify-cli
```

Pour fixer une version : `uv tool install specify-cli==0.12.11` (utilisez la version indiquée sur la page des versions).

### Option 2 : depuis un tag de version GitHub

La documentation officielle la présente comme la voie reproductible recommandée. Elle nécessite uv :

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@vX.Y.Z
```

Remplacez `vX.Y.Z` par un tag de [Releases](https://github.com/github/spec-kit/releases). **Conservez le `v` initial**, par exemple `v0.12.11`.

### Vérifier l'installation

```bash
specify version
specify self check
```

`specify version` confirme que la commande fonctionne et affiche sa version. `specify self check` est en lecture seule et indique s'il existe une version plus récente.

## Initialiser un projet

```bash
specify init my-project --integration claude
cd my-project
```

`--integration` choisit votre assistant IA. Les valeurs courantes sont `claude`, `copilot`, `gemini`, `codebuddy`, `pi` et `omp`. Options utiles :

- `--script sh|ps|py` : choisit le type de script. Par défaut, `ps` sous Windows et `sh` ailleurs.
- `--here --force` : initialise dans un répertoire existant non vide. `--force` reconnaît l'avertissement de fusion, donc validez ou sauvegardez d'abord vos modifications locales.
- `--non-interactive` : pour la CI. **Sans `--integration`, GitHub Copilot est choisi par défaut**, ne vous laissez pas surprendre par cette valeur par défaut.

## Noms des commandes : `/speckit-*`

Après l'initialisation, exécutez-les dans le chat de votre assistant IA, pas dans le terminal :

| Étape | Commande | Ce qu'elle fait |
| --- | --- | --- |
| 1 | `/speckit-constitution` | Rédige les principes du projet auxquels les étapes suivantes sont comparées ; une fois par projet |
| 2 | `/speckit-specify` | Transforme une description de la fonctionnalité en langage courant en `spec.md` |
| 3 | `/speckit-clarify` | Pose des questions sur les lacunes de la spécification et y intègre les réponses |
| 4 | `/speckit-plan` | Génère `plan.md` et d'autres artefacts de conception pour votre pile technique |
| 5 | `/speckit-checklist` | Génère une liste de contrôle de la qualité des exigences |
| 6 | `/speckit-tasks` | Génère un `tasks.md` ordonné par dépendances |
| 7 | `/speckit-analyze` | Contrôle en lecture seule des conflits et lacunes entre `spec.md`, `plan.md` et `tasks.md` |
| 8 | `/speckit-implement` | Exécute `tasks.md` dans l'ordre |
| 9 | `/speckit-converge` | Compare le code à la spécification et ajoute des tâches pour les écarts ; répétez implement et converge jusqu'à l'indication `Converged` |

Le chemin le plus court est specify → plan → tasks → implement → converge. Seul le chemin complet ajoute constitution, clarify, checklist et analyze.

:::caution[Votre assistant peut les écrire autrement]
Le guide de démarrage officiel utilise les noms avec trait d'union `/speckit-*` (mode compétences par défaut de GitHub Copilot). Les anciens tutoriels et les notes de mise à jour montrent encore la forme avec point, comme `/speckit.specify`. Le format d'appel diffère selon les assistants et les modes : fiez-vous aux noms qui apparaissent réellement dans la liste de commandes de votre assistant après l'initialisation.
:::

## Ce qui a changé par rapport aux anciens tutoriels

| Courant dans les anciens tutoriels | Maintenant |
| --- | --- |
| Uniquement `uv tool install ... --from git+https://...` | `specify-cli` est aussi sur PyPI, installable avec uv, pipx ou pip ; l'installation depuis un tag GitHub reste prise en charge |
| `specify init --ai claude` | La documentation officielle utilise partout `--integration claude` |
| `/speckit.specify`, `/speckit.plan` | Le guide de démarrage utilise `/speckit-specify` et `/speckit-plan`, et ajoute `/speckit-converge` |
| `/constitution` propage les changements dans les modèles et les fichiers de commandes | Elle met désormais à jour uniquement `.specify/memory/constitution.md` ; pour retrouver l'ancienne propagation, exécutez `specify preset add constitution-sync` |
| Fonctions git toujours actives | Désormais une extension facultative : `specify extension add git` |
| La fonctionnalité active est déduite de la branche Git | `.specify/feature.json` enregistre le répertoire de la fonctionnalité active |

## Mise à jour

Mettre à jour la ligne de commande elle-même :

```bash
specify self check                 # lecture seule : y a-t-il une version plus récente ?
specify self upgrade --dry-run     # aperçu sans mise à jour
specify self upgrade               # mise à jour vers la dernière version stable
specify self upgrade --tag vX.Y.Z  # fixer un tag de version
```

Mettre à jour les fichiers d'un projet existant, depuis le répertoire du projet :

```bash
specify integration status         # liste les intégrations installées et les fichiers modifiés
specify integration upgrade <key>  # à exécuter une fois par intégration installée
specify extension update           # met à jour toutes les extensions
```

N'ajoutez `--force` à `specify integration upgrade` que lorsqu'il signale des fichiers gérés modifiés localement et que vous avez examiné la différence.

## Problèmes courants

- **`command not found: uv`** : installez d'abord uv, puis relancez la commande d'installation.
- **`No such option: --integration`** : un ancien `specify` (par exemple 0.1.6) se trouve plus tôt dans votre `PATH`. Réinstallez avec l'outil utilisé à l'origine, par exemple `uv tool install --force specify-cli`, puis confirmez avec `specify version`.
- **Deux copies installées** : installer avec uv, pipx et pip laisse chacun une copie distincte. Mettez à jour avec le même outil et ne les mélangez pas.
- **Une installation PyPI ne se met pas à jour toute seule** : la version reste celle installée, utilisez donc les commandes de mise à jour ci-dessus.
- **L'initialisation refuse un répertoire existant** : une fois vos modifications validées ou sauvegardées, ajoutez `--here --force`.

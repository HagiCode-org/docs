The official Desktop app is now the recommended path: download the Windows, macOS, or Linux installer from [OmniRoute GitHub Releases](https://github.com/diegosouzapw/OmniRoute/releases). The npm procedure below remains available for headless environments.

Cette page présente le chemin local recommandé pour OmniRoute : `npm install -g omniroute`, puis `omniroute start`, avec le tableau de bord sur `http://localhost:20128` et l'URL de base compatible OpenAI sur `http://localhost:20128/v1`.

:::tip[Chemin recommandé]
Le tableau de bord est disponible sur `http://localhost:20128` et l'URL de base compatible OpenAI sur `http://localhost:20128/v1`. Docker et les modes avancés sont facultatifs.
:::

## Conditions préalables

- Node.js doit être `>=22.0.0 <23` ou `>=24.0.0 <27`. Node.js 21 et 23 ne sont pas pris en charge. Terminé [Installation de Node.js](/fr-FR/related-software-installation/nodejs/installation) d'abord si nécessaire.
- Les ports locaux `20128` et `20129` sont disponibles et non occupés.
- Vous disposez d'au moins un compte de fournisseur de modèles en amont que vous prévoyez d'acheminer via OmniRoute.
- Avant d'intégrer HagiCode, une CLI ou un SDK, séparez ces deux adresses :
  - Tableau de bord : `http://localhost:20128`
  - URL de base compatible OpenAI : `http://localhost:  20128/v1`

## Installer et exécuter localement

Commencez par le chemin npm global recommandé :

```bash
npm install -g omniroute
omniroute start
```

Une fois le service démarré, validez-le dans cet ordre :

1. Ouvert `http://localhost:20128` dans un navigateur et confirmez que le tableau de bord se charge.
2. Allez au `Endpoints` dans le tableau de bord et créez ou copiez une clé API.
3. Notez l'URL de base que vous transmettrez aux outils plus tard : `http://localhost:20128/v1`.

:::note[Pourquoi commencer par le tableau de bord]
Pour la première configuration, le tableau de bord constitue le moyen le plus rapide de confirmer qu'OmniRoute est en cours d'exécution, que vos fournisseurs sont connectés et qu'une clé API existe. Si un appel client ultérieur échoue, il est généralement plus rapide de vérifier d'abord le tableau de bord que de déboguer immédiatement le code du SDK.
:::

## Valider le service en cours d'exécution

### Validation 1 : confirmer que le catalogue de modèles est lisible

Mettez la clé du `Endpoints` page dans une variable d'environnement :

```bash
export OMNIROUTE_API_KEY="replace-with-the-key-you-copied-from-the-Endpoints-page"
```

Alors demandez `/v1/models`:

```bash
curl http://localhost:20128/v1/models \
  -H "Authorization: Bearer ${OMNIROUTE_API_KEY}"
```

Si vous obtenez une liste de modèles, le point de terminaison et le flux d'authentification compatibles OpenAI fonctionnent.

### Validation 2 : envoyer une demande de chat minimale

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer ${OMNIROUTE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "replace-with-a-model-id-from-v1-models",
    "messages": [
      { "role": "user", "content": "Reply with ok." }
    ]
  }'
```

Le but ici n’est pas une qualité rapide. Il s'agit de prouver que le modèle que vous avez choisi peut déjà être acheminé avec succès via OmniRoute.

HagiCode 讓 AI 修改程式碼時不遺失脈絡：**先讀懂儲存庫，再界定範圍，最後可追蹤地執行。** 它是面向專案開發的 AI 工作台，串接你既有的 Agent CLI 與模型，不需要更換編輯器。豐富、便利的介面互動讓規劃、Agent 執行與專案工作更容易上手和跟進，帶來更投入的開發體驗。

你不必每次都走提案流程：只想了解程式碼或處理簡單問題，可以從一般會話開始。HagiCode 的重點是讓任務需要更多脈絡時，仍有一條可追蹤的推進路徑。

## 功能詳解

### 先理解，再動手

HagiCode 把「讀程式碼」與「改程式碼」分開，讓你依任務大小選擇，而不是任由 AI 直接修改一切。

- **一般會話：** 預設唯讀。用來探索儲存庫、調查問題，或詢問某段邏輯在哪裡。只有需要修改檔案時，才切換至編輯模式。
- **提案會話：** 用於複雜變更。選擇專案與儲存庫範圍，整理目標、任務與驗證方式，對規劃滿意後再推進執行。
- **會話看板：** 「Proposal & Review」、「Execution」、「Archived」三條泳道，讓你一眼看出每個會話進行到哪裡。可在 Classic、Execution Flow Kanban、Dashboard Kanban 三種版面之間切換。

了解更多：[建立一般會話](/zh-Hant/quick-start/conversation-session) · [建立提案會話](/zh-Hant/quick-start/proposal-session) · [會話看板](/zh-Hant/user-guide/sessions)

### 跨儲存庫的統一範圍

當一項需求同時涉及前端、後端與文件時，MonoSpecs 能讓 HagiCode 把它們理解為同一個專案。

- 在 `.hagicode/monospecs.yaml` 中登錄子儲存庫的位置、Git URL 與顯示名稱。
- 變更規格（OpenSpec）集中放在主儲存庫，子儲存庫的程式碼目錄保持乾淨。
- 建立提案時，選擇它涉及哪些子儲存庫。專案頁面會顯示各儲存庫的分支與未提交的變更。

![MonoSpec 專案頁面，顯示 11 個儲存庫的分支與變更狀態，以及 VS Code、Git 與 AI Compose Commit 操作](../img/screenshots/monospecs/hover-project-show-repository-status/original.png)

了解更多：[MonoSpecs 指南](/zh-Hant/guides/monospecs)

### 沿用你的 Agent CLI

HagiCode 不會取代你的工具鏈，而是把它們帶進同一個工作台。

- **Agent 由 CLI、模型與選填的個性文字組成。** 你可以建立多個 Agent，指派給不同的執行情境，並設定備援群組。
- 支援 11 個 Agent CLI，包括 Claude Code、Codex 與 GitHub Copilot。工作台會顯示各 CLI 的版本、回應時間與健康狀態。
- 搭配 [OmniRoute](/zh-Hant/related-software-installation/omniroute/)，可以把多個 OpenAI 相容工具與模型接到同一個本機閘道，而 CLI 與模型連線仍分開管理。

![AI 監控彈出面板，列出 Claude Code、Codex、GitHub Copilot 等 Agent CLI 的版本、回應時間與健康狀態](../img/screenshots/shared/status-of-agent-clis/original.png)

了解更多：[Agents 工作台](/zh-Hant/user-guide/agents) · [AI Agent CLI 安裝與支援範圍](/zh-Hant/related-software-installation/ai-agent-cli/)

### Skills

Skills 面板把你機器上已有的技能，以及可從 Gallery 安裝的技能，放在同一個入口之後。

- **Local Skills：** 查看這台機器上已安裝的內容，並批次檢查更新。
- **Gallery：** 依關鍵字與來源搜尋，並看出某項技能是否已安裝。
- **Trusted Providers：** 安裝前確認來源、信任狀態與實際會執行的指令，並自行決定哪些來源算是可信任。

![Skills Gallery，包含搜尋欄位、來源篩選，以及列出技能、來源與安裝次數的表格](../img/screenshots/shared/skills-gallary/original.png)

了解更多：[Skills 使用指南](/zh-Hant/guides/skills)

### Vault 與 Code Server

- **Vault** 是專案儲存庫之外、允許 HagiCode 瀏覽的資料夾，適合存放參考文件、筆記與研究成果。支援三種類型：Folder、CodeRef 與 Obsidian。
- 建立會話時，選擇要把哪些 Vault 納入其範圍。將其中一個標示為可編輯，AI 才能寫入；否則它只是唯讀參考。
- **Code Server** 提供瀏覽器中的編輯入口，可直接從 Vault 或專案開啟。

### AI Compose Commit

在 Git 分頁中點擊「AI Compose Commit」，HagiCode 會讀取目前的變更，並以 Conventional Commits 格式撰寫提交訊息。

- 相關的變更會被分成多個提交，而不是擠進一個大雜燴提交。
- 在 MonoSpecs 專案中，變更會提交到正確的子儲存庫。
- 會自動加上 Co-Authored-By 標記，其名稱與電子郵件可依專案或全域設定。

## 適合誰

- **適合**：同時維護多個儲存庫、希望複雜改動先規劃再執行的開發者與團隊；已經在使用 Claude Code、Codex 等 Agent CLI，想把它們放進同一個工作台的人。
- **不是必需品**：如果你只需要在編輯器裡補全幾行程式碼，現有工具已經足夠。

## 取得方式與定價

基本功能免費。Desktop 與 Microsoft Store 是兩種不同的取得方式，不是兩檔付費版本。Microsoft Store 通路另有一次性購買的 Turbo Engine 增強包，用於解鎖更高的提案並行上限，以及文件主題、自訂署名、品牌與自訂頭像上傳等功能。具體解鎖項目以 [Turbo Engine 增強包](/zh-Hant/dlc/turbo-engine-dlc/)為準。

| 你的環境 | 建議入口 |
| --- | --- |
| Windows，且可以使用 Microsoft Store | [Microsoft Store 安裝](/zh-Hant/installation/windows-store) |
| Windows 手動安裝，或 macOS、Linux 本機使用 | [Desktop 安裝](/zh-Hant/installation/desktop) |

Steam 主應用程式已退役，不是目前的安裝管道；詳情見 [Steam 發行狀態](/zh-Hant/faq/steam-distribution-status/)。

## 為什麼還要做成工作台

我是 HagiCode 的製作人俞坤。單次問答能解決眼前的問題，但實際開發還需要理解專案、界定邊界、推進變更、回顧結果。我希望把這些原本分散的環節串在一起；遊戲化回饋則讓長期工作中的進度更容易被看見。你可以只使用其中一部分功能，不需要為了開始寫程式而先學會所有模組。

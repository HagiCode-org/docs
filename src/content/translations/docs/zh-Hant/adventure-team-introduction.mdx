**Agent** 是 HagiCode 的核心：工作階段由 Agent 執行，開始工作之前至少需要一個。本頁是一份概覽，幫你看懂 Agent 由什麼組成、不同類型的工作由誰來做，以及與 Agent 相關的設定分散在哪些地方。逐項操作請看 [Agents 工作區指南](/zh-Hant/user-guide/agents)。

## 功能概覽

- 一個 **Agent = Agent CLI + 模型 + 可選的個性文字**。Agent CLI 是實際執行的命令列工具（例如 Claude Code、Codex），模型是它使用的模型，個性文字（Trait 和 Soul）用來塑造工作方式和說話風格。
- 你可以建立多個 Agent，例如一個用 Opus 做審查，一個用 Haiku 做快速修改，一個用 Codex 做重構。
- 每類工作用哪個 Agent，由**執行場景**決定；沒有合適成員時，由 **Fallback Crew** 接手。
- Agent 的檢查和調校分布在 **Agents 工作區**和**設定**裡：前者管理 Agent、場景、CLI 和模型，後者管理重試、記憶體和 CPU 上限等執行階段行為。

## Agent 清單

![Agents 分頁：五個 Agent 依 Claude Code 和 Codex 分組，每個都附頭像和模型](../img/screenshots/guides/agent-roster/original.png)

點擊頂端列的 **Agents** 開啟 **Agents Workspace**。**Agents** 分頁裡的 **My Agents** 依 Agent CLI 分組列出你的 Agent，每張卡片顯示頭像、名稱和模型。在這裡你可以：

1. 用 **New Agent** 建立一個 Agent：選擇 AgentCLI 和相容的模型，可選擇性地寫入 Trait（知識與行為）和 Soul（語言風格）。
2. 用 **Batch create Agents** 一次建立多個，或用搜尋框依名稱、CLI 或簡介篩選。
3. 透過 **Battle ready** 開關啟用或停用某個 Agent。

建立過程的完整說明請見 [Agents](/zh-Hant/user-guide/agents#建立-agent)。

## 分工：執行場景與 Fallback Crew

![Execution Scenarios 分頁：Proposal 和 HagiTask 場景各自的 Agent 編組，右側是已編組和可加入的 Agent](../img/screenshots/guides/agent-scenarios/original.png)

**Execution Scenarios** 分頁決定每類工作由哪些 Agent 來做。場景依用途分組：

| 分組 | 場景 |
| --- | --- |
| **Proposal** | 最佳化、產生、執行和封存提案 |
| **HagiTask** | Super Commit、建立一般工作階段、建立程式碼調查任務 |
| **Chat** | 工作階段標題最佳化 |

點擊一個場景，右側的 **Assigned Agents** 顯示它的編組，**Available Agents** 顯示可以加入的 Agent，點 **Add** 或 **Remove** 即可調整。**Fallback Crew** 是安全網：當某個場景自己的編組裡沒有合適的 Agent 時，HagiCode 會從 Fallback Crew 裡挑選符合條件的成員。**在 Fallback Crew 至少有一個已啟用的 Agent 之前，其他場景都保持鎖定。** 初始化精靈會自動把你的第一個 Agent 加進去。

一個常見的搭配：

1. 把擅長長上下文和審查的 Agent 放進 **Generate Proposal**。
2. 把執行力強、成本合適的 Agent 放進 **Execute Proposal**。
3. 把便宜、快速的 Agent 放進 **Super Commit** 和 **Conversation Title Optimization**。
4. 讓 Fallback Crew 保留一個穩定的通用 Agent。

## 相關設定在哪裡

| 想做的事 | 去哪裡 |
| --- | --- |
| 建立、編輯、啟用或停用 Agent | **Agents** → **Agents** 分頁 |
| 為每類工作分配 Agent、維護 Fallback Crew | **Agents** → **Execution Scenarios** |
| 查看 Agent CLI 是否已安裝、是否健康、是否啟用 | **Agents** → **AgentCLI**，狀態列的 AI Monitoring 彈層 |
| 瀏覽或新增某個 CLI 可用的模型 | **Agents** → **Model** |
| 更換頭像、更換文案主題 | **Agents** → **Avatar Gallery** / **Document Theme** |
| 失敗執行的自動重試 | **設定** → **Error Retry** |
| 產生的 prompt 中是否聲明「本次執行為非互動式」 | **設定** → **AgentCLI Interactive Control** |
| 限制每個 Agent 能使用的記憶體和 CPU | **設定** → **Agent resource limits** |
| 把多個 OpenAI 相容模型接到同一個本機 gateway | **設定** → **OmniRoute** |

各設定項目的作用請見[設定](/zh-Hant/user-guide/settings)。

## 適用場景與邊界

- 當你想讓不同階段使用不同的模型或 CLI（例如審查和執行分開），就依場景分工。
- 只有一個 Agent 也完全可以使用：把它放進 Fallback Crew，所有場景都會使用它。
- Agent 只決定**由誰執行**。要執行什麼，仍然來自你建立的工作階段、提案或計畫。

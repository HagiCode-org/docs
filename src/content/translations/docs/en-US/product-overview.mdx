HagiCode is an AI workspace for project development. Start with a session to understand a repository, define the request and its scope, let AI make changes, and review progress, prepare commits, and reuse project knowledge in one place. It connects the Agent CLI and models you use rather than requiring a particular code editor.

**New here?** [Choose an installation method](/en-US/installation/), complete the [setup wizard](/en-US/quick-start/wizard-setup), create a project, and start with a [conversation session](/en-US/quick-start/conversation-session). If the task calls for planning before implementation, use a [proposal session](/en-US/quick-start/proposal-session).

## How a development task works

For example, suppose you need to change a feature spanning several repositories:

1. **Understand first:** Analyze the existing code in a [conversation session](/en-US/quick-start/conversation-session). Conversation sessions are read-only by default; switch to edit mode when you need to change files.
2. **Define the scope:** For a complex change, select the project and repositories in a [proposal session](/en-US/quick-start/proposal-session). Outline the goals, tasks, and verification steps before proceeding with execution.
3. **Track the outcome:** Review sessions and execution status in the workspace. When you need to prepare a commit, use [AI Compose Commit](/en-US/guides/ai-compose-commit).
4. **Keep the context:** Revisit proposals and commit history. For cross-repository work, use [MonoSpecs](/en-US/guides/monospecs) to manage repository relationships and change scope.

You do not need a proposal for every task. Start with a conversation session when you only want to explore the code or handle a simple issue. HagiCode provides a traceable path when a task needs more context.

Vault brings together reference repositories, folders, and notes for later work; Code Server offers an editing entry point in the browser. Neither is required to get started with HagiCode. For the design background, see [Working with the Vault knowledge base](/en-US/blog/2026-04-10-vault-system-ai-knowledge-base/) and [Browser editing integration](/en-US/blog/2026-04-13-vscode-web-integration-browser-editing/).

HagiCode also offers feedback through heroes, achievements, daily reports, and Token metrics to make status and progress more visible over time. These are part of the workspace experience, not a requirement for using it as a regular development tool. See the [article on gamification design](/en-US/blog/2026-03-16-gamifying-ai-coding/).

## Editions & Pricing

**Desktop, Container, and Microsoft Store are different ways to obtain or deploy HagiCode, not three paid tiers.** Core features are free to use. Turbo Engine in the Microsoft Store channel is a separate, one-time license that unlocks a higher proposal concurrency limit and enhancements such as documentation themes, custom attribution, branding, and avatars. See the [Turbo Engine add-on](/en-US/dlc/turbo-engine-dlc/) for the specific features it unlocks.

| Your environment | Recommended option |
| --- | --- |
| Windows with access to Microsoft Store | [Install from Microsoft Store](/en-US/installation/windows-store) |
| Manual Windows installation, or local use on macOS or Linux | [Install Desktop](/en-US/installation/desktop) |
| Server, NAS, or team deployment | [Install with Docker Compose](/en-US/installation/docker-compose) |

The Steam main application has been retired and is no longer an installation channel. See [Steam distribution status](/en-US/faq/steam-distribution-status/).

## Why make it a workspace?

I'm Kun Yu, the creator of HagiCode. A single question and answer can solve an immediate problem, but real development also means understanding the project, setting boundaries, carrying changes through, and reviewing the result. I wanted to bring these scattered steps together; gamified feedback makes progress in long-running work easier to see. You can use just some of these features. You do not have to learn every module before you start coding.

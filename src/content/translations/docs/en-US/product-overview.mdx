HagiCode keeps AI from losing context when it changes your code: **understand the repository first, set the scope, then execute with a traceable trail.** It is an AI workspace for project development that connects the Agent CLI and models you already use, so you do not need to switch editors. Rich, convenient UI interactions make planning, agent execution, and project work approachable and easy to navigate, creating an engaging development experience.

## Features in detail

### Understand first, then act

HagiCode separates "reading the code" from "changing the code" so you can choose by the size of the task instead of letting AI edit everything directly.

- **Conversation session:** Read-only by default. Use it to explore a repository, investigate an issue, or ask where some logic lives. Switch to edit mode only when you need to change files.
- **Proposal session:** For complex changes. Choose the project and repository scope, outline the goals, tasks, and verification steps, then move on to execution once you are happy with the plan.
- **Session board:** Proposal & Review, Execution, and Archived lanes show where every session stands at a glance. You can switch between the Classic, Execution Flow Kanban, and Dashboard Kanban layouts.

Learn more: [Create a conversation session](/en-US/quick-start/conversation-session) · [Create a proposal session](/en-US/quick-start/proposal-session) · [The session board](/en-US/user-guide/sessions)

### One scope across repositories

When a request touches the frontend, the backend, and the docs at once, MonoSpecs lets HagiCode understand them as a single project.

- Register sub-repository locations, Git URLs, and display names in `.hagicode/monospecs.yaml`.
- Change specs (OpenSpec) live in the main repository, so the code directories of the sub-repositories stay clean.
- When you create a proposal, choose which sub-repositories it involves. The project page shows the branch and uncommitted changes of each repository.

![MonoSpec project page showing branch and change status for 11 repositories, with VS Code, Git, and AI Compose Commit actions](../img/screenshots/monospecs/hover-project-show-repository-status/original.png)

Learn more: [MonoSpecs guide](/en-US/guides/monospecs)

### Keep your Agent CLI

HagiCode does not replace your toolchain. It brings it into one workspace.

- **An Agent is a CLI, a model, and optional personality text.** Create several Agents, assign them to execution scenarios, and set up backup groups.
- Supports 11 Agent CLIs, including Claude Code, Codex, and GitHub Copilot. The workspace shows each CLI's version, response time, and health.
- With [OmniRoute](/en-US/related-software-installation/omniroute/), you can connect several OpenAI-compatible tools and models to one local gateway, while CLI and model connections stay managed separately.

![AI Monitoring popover listing Claude Code, Codex, GitHub Copilot, and other Agent CLIs with version, response time, and health](../img/screenshots/shared/status-of-agent-clis/original.png)

Learn more: [Agents workspace](/en-US/user-guide/agents) · [AI Agent CLI installation and support](/en-US/related-software-installation/ai-agent-cli/)

### Skills

The Skills panel puts the skills already on your machine and the skills you can install from the gallery behind one entry.

- **Local Skills:** See what is installed on this machine and check for updates in batch.
- **Gallery:** Search by keyword and source, and see whether a skill is already installed.
- **Trusted Providers:** Before installing, confirm the source, trust status, and the command that will actually run, and decide which sources count as trusted.

![Skills gallery with a search field, source filters, and a table of skills, sources, and install counts](../img/screenshots/shared/skills-gallary/original.png)

Learn more: [Skills guide](/en-US/guides/skills)

### Vault and Code Server

- A **Vault** is a folder outside your project repositories that HagiCode may browse. Use it for reference documents, notes, and research output. Three types are supported: Folder, CodeRef, and Obsidian.
- When you create a session, choose which Vaults to include in its scope. Mark one as editable for AI to write to it; otherwise it is read-only reference.
- **Code Server** provides an editing entry point in the browser that you can open straight from a Vault or project.

![Vault workspace with registered Vault cards, system Vaults, and Open Code Server buttons](../img/screenshots/shared/vault-view/original.png)

Learn more: [Vault guide](/en-US/user-guide/vault) · [Working with the Vault knowledge base](/en-US/blog/2026-04-10-vault-system-ai-knowledge-base/) · [Browser editing integration](/en-US/blog/2026-04-13-vscode-web-integration-browser-editing/)

### AI Compose Commit

Click "AI Compose Commit" in the Git tab and HagiCode reads your current changes and writes commit messages in Conventional Commits format.

- Related changes are grouped into several commits instead of one catch-all.
- In MonoSpecs projects, changes are committed to the right sub-repository.
- A Co-Authored-By tag is added automatically, and its name and email can be set per project or globally.

![The AI Compose Commit button in the Git tab](../img/screenshots/ai-compose-commit/trigger-ai-compose-commit-button/original.png)

Learn more: [AI Compose Commit guide](/en-US/guides/ai-compose-commit)

### Visible progress

Rich, convenient UI interactions make planning, agent execution, and project work approachable and easy to navigate, creating an engaging development experience. Heroes, achievements, daily reports, and Token metrics add supporting feedback for long-running work. In the [Adventure Team introduction](/en-US/adventure-team-introduction), you can see how Hero Dungeon works; the [gamification article](/en-US/blog/2026-03-16-gamifying-ai-coding/) explains its design. These game elements support the workspace experience, and HagiCode remains usable as a regular development tool without them.

![Achievement hall with daily and global progress, cycle status, and proposal lifecycle metrics](../img/screenshots/shared/achivement-view/original.png)

Learn more: [Status bar and progress](/en-US/user-guide/status-bar-and-progress)

## Who it is for

- **A good fit:** Developers and teams who maintain several repositories and want complex changes planned before they are executed, and people who already use Agent CLIs such as Claude Code or Codex and want them in one workspace.
- **Not essential:** If you only need a few lines completed in your editor, your current tools are enough.

## Editions & Pricing

Core features are free. Desktop and Microsoft Store are two different ways to obtain HagiCode, not two paid tiers. The Microsoft Store channel also offers Turbo Engine, a separate one-time purchase that unlocks a higher proposal concurrency limit and enhancements such as documentation themes, custom attribution, branding, and avatars. See the [Turbo Engine add-on](/en-US/dlc/turbo-engine-dlc/) for the specific features it unlocks.

| Your environment | Recommended option |
| --- | --- |
| Windows with access to Microsoft Store | [Install from Microsoft Store](/en-US/installation/windows-store) |
| Manual Windows installation, or local use on macOS or Linux | [Install Desktop](/en-US/installation/desktop) |

The Steam main application has been retired and is no longer an installation channel. See [Steam distribution status](/en-US/faq/steam-distribution-status/).

## Why make it a workspace?

I'm Kun Yu, the creator of HagiCode. A single question and answer can solve an immediate problem, but real development also means understanding the project, setting boundaries, carrying changes through, and reviewing the result. I wanted to bring these scattered steps together; gamified feedback makes progress in long-running work easier to see. You can use just some of these features. You do not have to learn every module before you start coding.

An **Agent** is the core of HagiCode: sessions are run by Agents, and you need at least one before you can start working. This page is an overview that helps you understand what an Agent is made of, who handles each kind of work, and where the Agent-related configuration lives. For step-by-step instructions, see the [Agents workspace guide](/en-US/user-guide/agents).

## Overview

- One **Agent = Agent CLI + model + optional personality text**. The Agent CLI is the command-line tool that actually does the work (for example Claude Code or Codex), the model is what it uses, and the personality text (Trait and Soul) shapes how it works and how it speaks.
- You can create multiple Agents, for example one using Opus for review, one using Haiku for quick edits, and one using Codex for refactoring.
- Which Agent handles each kind of work is decided by the **execution scenario**; when no suitable member exists, the **Fallback Crew** takes over.
- Checking and tuning Agents is spread across the **Agents workspace** and **Settings**: the former manages Agents, scenarios, CLIs, and models, while the latter manages runtime behavior such as retries and memory and CPU limits.

## Agent list

![Agents tab: five Agents grouped by Claude Code and Codex, each with an avatar and a model](../img/screenshots/guides/agent-roster/original.png)

Click **Agents** in the top bar to open the **Agents Workspace**. **My Agents** on the **Agents** tab lists your Agents grouped by Agent CLI, and each card shows the avatar, name, and model. Here you can:

1. Create an Agent with **New Agent**: choose an AgentCLI and a compatible model, and optionally write a Trait (knowledge and behavior) and a Soul (language style).
2. Create several at once with **Batch create Agents**, or filter by name, CLI, or description using the search box.
3. Enable or disable an Agent with the **Battle ready** switch.

For the full creation walkthrough, see [Agents](/en-US/user-guide/agents#create-an-agent).

## Dividing work: execution scenarios and Fallback Crew

![Execution Scenarios tab: the Agent lineups for the Proposal and HagiTask scenarios, with assigned and available Agents on the right](../img/screenshots/guides/agent-scenarios/original.png)

The **Execution Scenarios** tab decides which Agents handle each kind of work. Scenarios are grouped by purpose:

| Group | Scenarios |
| --- | --- |
| **Proposal** | Optimize, generate, execute, and archive proposals |
| **HagiTask** | Super Commit, create a regular session, create a code research task |
| **Chat** | Conversation title optimization |

Click a scenario and **Assigned Agents** on the right shows its lineup, while **Available Agents** shows the Agents you can add. Click **Add** or **Remove** to adjust it. The **Fallback Crew** is the safety net: when a scenario's own lineup has no suitable Agent, HagiCode picks an eligible member from the Fallback Crew. **All other scenarios stay locked until the Fallback Crew has at least one enabled Agent.** The setup wizard automatically adds your first Agent to it.

A common setup:

1. Put an Agent that is good at long context and review into **Generate Proposal**.
2. Put an Agent with strong execution and a reasonable cost into **Execute Proposal**.
3. Put a cheap, fast Agent into **Super Commit** and **Conversation Title Optimization**.
4. Keep one reliable general-purpose Agent in the Fallback Crew.

## Where related settings live

| What you want to do | Where to go |
| --- | --- |
| Create, edit, enable, or disable an Agent | **Agents** → **Agents** tab |
| Assign Agents to each kind of work and maintain the Fallback Crew | **Agents** → **Execution Scenarios** |
| Check whether an Agent CLI is installed, healthy, and enabled | **Agents** → **AgentCLI**, and the AI Monitoring popover in the status bar |
| Browse or add the models available to a CLI | **Agents** → **Model** |
| Change the avatar or the copy theme | **Agents** → **Avatar Gallery** / **Document Theme** |
| Automatic retry for failed runs | **Settings** → **Error Retry** |
| Whether the generated prompt declares "this run is non-interactive" | **Settings** → **AgentCLI Interactive Control** |
| Limit the memory and CPU each Agent can use | **Settings** → **Agent resource limits** |
| Connect several OpenAI-compatible models to one local gateway | **Settings** → **OmniRoute** |

For what each setting does, see [Settings](/en-US/user-guide/settings).

## When to use it and its limits

- When you want different stages to use different models or CLIs (for example, separating review from execution), divide the work by scenario.
- Using just one Agent works fine too: put it in the Fallback Crew and every scenario will use it.
- An Agent only decides **who executes**. What gets executed still comes from the sessions, proposals, or plans you create.

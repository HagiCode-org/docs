A **plan** (also called a scheduled plan or scheduled task) makes HagiCode start a session automatically at a time you set, without you being there to click Submit. Typical uses: run a code review at 2:00 every weekday, check for dependency updates every morning, or draft release notes tomorrow at 10:00.

A plan stores two things: **everything needed to create the session** (exactly what you would normally fill in on a creation dialog) and a **schedule**. When the time comes, HagiCode creates the session through the same flow a manual submit uses, so a session started by a plan is no different from one you created yourself.

## Concepts

| Concept | Meaning |
| --- | --- |
| **Type** | There are two kinds of plan: **Proposal** (creates a proposal session when it runs) and **HagiTask** (creates a session from a HagiTask when it runs). The type is decided by which creation dialog you save the plan from. |
| **Run once / Recurring** | A one-time plan runs at a single moment. A recurring plan repeats daily or weekly between a start date and an end date. |
| **Next run** | The next time the plan will start on its own, shown in the time zone you chose. |
| **Scheduled / Completed** | The state of the plan. A one-time plan becomes Completed after it runs; a recurring plan becomes Completed once its end date has passed. |
| **Enabled / Disabled** | Every plan has an enable switch. A disabled plan stays in the list but never runs automatically. |

## Open the plan manager

The **Plans** button in the header opens the plan manager. In a narrow window the button shows only the calendar icon; hover over it to see the **Scheduled plans** tooltip.

![HagiCode header with a new Plans button between Vault and Get Support](../../img/user-guide/workbench/03-header-navigation.png)

The list is empty the first time you open it. The manager is for **viewing and managing** existing plans only; you cannot create one here. Plans are always saved from the dialog that creates a proposal or a HagiTask.

![Plan manager drawer showing the empty state, "No scheduled plans yet", with a hint on how to create one](../../img/user-guide/plans/01-empty-manager.png)

## Create a plan

Both the proposal and HagiTask creation dialogs can switch from "start now" to "start on a schedule". **Create Normal Session** has no plan switch.

1. Open a creation dialog as usual, for example **New Idea**, and fill in the idea name, project, and request. For the fields, see [Sessions](/en-US/user-guide/sessions#create-an-idea-proposal).
2. Look at the bottom right of the dialog. Next to the submit button there is a **Plan** switch, off by default.

   ![Footer of the Create Proposal drawer with Cancel on the left and the Plan switch and Submit idea button on the right](../../img/user-guide/plans/02-plan-switch.png)

3. Turn the **Plan** switch on. The dialog switches to plan mode:
   - The label at the top left changes from **Create Proposal** to **Proposal plan**.
   - A required **Plan name** field appears at the top, for example "Nightly code review", up to 200 characters.
   - A **Schedule** section appears at the bottom.
   - The submit button becomes **Save plan**.

   ![Create Proposal drawer in plan mode: Plan name at the top, the original form below, and the Schedule section and Save plan button at the bottom](../../img/user-guide/plans/03-plan-mode-once.png)

4. Set when the plan runs in **Schedule**; see [Set the schedule](#set-the-schedule). A HagiTask plan also needs an Agent; see [Choose an Agent for a HagiTask plan](#choose-an-agent-for-a-hagitask-plan).
5. Click **Save plan**. HagiCode shows a **Plan saved** notice; click **View plans** to open the plan manager right away.

   ![Notice at the bottom left of the screen: Plan saved, with a View plans button](../../img/user-guide/plans/07-plan-saved-toast.png)

:::note
Plans cannot include images. If images are already attached to the form, the **Plan** switch is disabled and tells you to remove them before saving the task as a plan.
:::

## Set the schedule

The two buttons at the top of **Schedule** choose how the plan runs: **Run once** or **Recurring**. In both modes, **Next run** at the bottom of the section updates live to the next run time the current settings produce. If it shows **Not scheduled**, no run time is possible with the current settings, so adjust the dates or the time.

### Run once

Runs a single time.

| Field | Description |
| --- | --- |
| **Date** and **Time** | The day and time of the run. Defaults to tomorrow at 09:00. It must be later than now. |
| **Run in** | Quick buttons: `+5 min`, `+10 min`, `+30 min`, `+1 hour`, counted from now. |
| **Next at** | Quick buttons: `02:00`, `09:00`, `12:00`, `18:00`, `22:00`. They pick the next occurrence of that time, today if it is still ahead, otherwise tomorrow. |
| **Time zone** | The time zone the date and time are read in. Defaults to the browser's current time zone. |

### Recurring

Repeats daily or weekly between a start date and an end date.

![Recurring mode of the Schedule section: start and end dates, time, Every week, Monday to Friday, time zone Asia/Shanghai, and the next run time](../../img/user-guide/plans/04-recurring-schedule.png)

| Field | Description |
| --- | --- |
| **From** and **To** | The first and last date of the period, both inclusive. Defaults to starting today and lasting one month. Under **Start**, `Today`, `Tomorrow`, `In 1 week`, `In 1 month`, and `In 3 months` set the start date quickly; under **Length**, `+1 week`, `+1 month`, and `+3 months` set the duration. |
| **Time** | The time of day of each run, in `HH:mm`. **Quick time** offers `02:00`, `09:00`, `12:00`, `18:00`, and `22:00`. |
| **Repeat** | **Every day** or **Every week**. |
| **On** | Appears when you choose **Every week**. Pick the weekdays, `Mon` to `Sun`, on which the plan runs; choose at least one. |
| **Time zone** | The time zone the time is read in. Every run follows local time in this zone, so a plan at 02:00 every day stays at 02:00 across daylight saving changes. |

:::tip
To make a plan "long-lived", set **To** far out, for example by clicking **+3 months**. After the end date the plan becomes **Completed** and stops running.
:::

## Choose an Agent for a HagiTask plan

A proposal plan needs no Agent. **A HagiTask plan must have one Agent selected**, because nobody is there to pick one when it starts on its own:

- In plan mode the dialog shows an **Available Agents** section explaining that this is the Agent the plan runs with, and that the plan keeps this choice when it starts. Click an Agent to select it.
- The bottom bar shows `Agent: name`. Until you choose, it shows `No agent selected yet.` and the plan cannot be saved.
- Currently a plan can have only one Agent. To create Agents, see [Agents](/en-US/user-guide/agents).

## Manage existing plans

Open **Plans** to see all plans. Each row is one plan.

![Plan manager listing five plans: a weekday proposal plan, a daily HagiTask plan, a one-time proposal plan, a disabled weekly plan, and a completed plan](../../img/user-guide/plans/05-plan-manager.png)

Each row contains:

- The **name**, a **Proposal** or **HagiTask** type badge, and a **Scheduled** or **Completed** state badge.
- A **schedule summary**, for example `Weekly on Mon, Tue, Wed, Thu, Fri 02:00 AM, Oct 18, 2026 - Jan 18, 2027 (Asia/Shanghai)`.
- **Next run**. A completed plan shows `–`.

The right side of each row has four controls:

| Control | What it does |
| --- | --- |
| **Enabled / Disabled** switch | Enables or disables the plan. A disabled plan does not run automatically but stays in the list. When you enable it again, HagiCode recalculates the next run from the current time; times missed while it was disabled are not made up. |
| **Run now** | Creates a session right now from the saved inputs; on success the row shows **Session started.** It does not change the plan's schedule or **Next run**, and a disabled or completed plan can be run manually too. |
| **Edit** | Opens the same dialog used to create the plan, in plan mode. Change the name, content, Agent, or schedule and click **Save plan**. A saved plan always stays a plan: the **Plan** switch is locked and cannot turn it back into a normal task. |
| **Delete** | Asks for confirmation first. Deleting only stops the plan from running; **sessions it already started are kept**. |

![Delete confirmation dialog: Delete this scheduled plan? It says "Weekly docs cleanup" will stop running and that sessions it already started are kept](../../img/user-guide/plans/06-delete-confirm.png)

## When plans run

- **Plans run only while HagiCode is running.** HagiCode checks for due plans every 30 seconds, so a run can start up to about 30 seconds after its scheduled time.
- **Missed times are made up once.** If HagiCode was not running when a plan came due (for example, the computer was off), the plan runs once as soon as HagiCode starts, and then the next run is scheduled normally. However many times were missed, it runs only once, not in a batch.
- **Failed runs are not retried.** If a run cannot create its session (for example, the project was removed or the chosen Agent is unavailable), that run is skipped and the plan waits for its next scheduled time. To recover, fix the problem and click **Run now**. If a manual run fails, the row shows **Run now failed:** and the reason.
- **A one-time plan becomes Completed after it runs.** To use it again, click **Edit** and set a new time in the future. Turning on the switch of an expired one-time plan is rejected because its run time is already in the past.
- **Every run creates a new session.** A proposal plan creates a proposal session and a HagiTask plan creates a HagiTask session. They appear on the session board like sessions you create by hand.

## FAQ

**Saving a plan says the run time must be later than the current time, or to choose at least one weekday.**
This is form validation, and the reason appears under the field. A one-time plan must be later than now. For a recurring plan, the end date cannot be before the start date, a weekly plan needs at least one weekday, and the range must contain at least one possible run.

**The Plan switch is greyed out.**
Images are attached to the form, and plans do not support images. Remove them and the switch works again.

**A plan did not run when it was due.**
Check in order: the plan is **Enabled**; **Next run** is the time you expect (especially the time zone); HagiCode was running at that moment; the project and Agent used by the plan still exist.

**Where are plans stored?**
All plans are stored in `scheduled-plans.json` in HagiCode's system-managed configuration directory. They do not depend on the browser, so opening the same HagiCode from another browser shows the same plans.

A **plan** (also called a scheduled plan or scheduled task) makes HagiCode start a session automatically at a time you set, without you being there to click Submit. Typical uses: run a code review at 2:00 every weekday, check for dependency updates every morning, or draft release notes tomorrow at 10:00.

A plan stores two things: **everything needed to create the session** (exactly what you would normally fill in on a creation dialog) and a **schedule**. When the time comes, HagiCode creates the session through the same flow a manual submit uses, so a session started by a plan is no different from one you created yourself.

## Concepts

| Concept | Meaning |
| --- | --- |
| **Type** | There are two kinds of plan: **Proposal** (creates a proposal session when it runs) and **HagiTask** (creates a session from a HagiTask when it runs). The type is decided by which creation dialog you save the plan from. |
| **Scope** | When you save a plan you choose **Team** (goes into version control) or **Personal** (the file name carries `.user.yaml` and can be ignored by version control). The scope cannot be changed after saving. |
| **Run once / Recurring** | A one-time plan runs at a single moment. A recurring plan repeats daily or weekly between a start date and an end date. |
| **Occurrence** | One specific time of a plan on the calendar. A one-time plan has one; a recurring plan has one for every time it comes due, and each can be changed or deleted on its own without touching the others. |
| **Next run** | The next time the plan will start on its own, shown in the plan's own time zone. |
| **Scheduled / Completed** | The state of the plan. A one-time plan becomes Completed after it runs; a recurring plan becomes Completed once its end date has passed. |
| **Enabled / Disabled** | Every plan has an enable switch. A disabled plan stays in the list and on the calendar but never runs automatically. |

## Find your plans

There are two ways in: the plan agenda in the header, which is good for a quick look at what is coming up in the next few days, and the **Plans** tab in the project details, where you view and manage all of one project's plans.

### The plan agenda in the header

When at least one **enabled** plan has a run time from today through the next three days (four local days in all), a calendar icon button appears in the header. The number at its top right is how many runs fall in that window (shown as `99+` above 99). When no plan falls in the window, the button does not appear and takes no space.

![Header plan agenda popover: Plans, today to 3 days ahead, listing each plan's run times grouped by date](../../img/user-guide/plans/01-header-plans-button.png)

Hover over the button, focus it with the keyboard, or click it to open the **Plans, today to 3 days ahead** agenda:

- It is grouped by date in ascending order and lists only dates that have run times. Each date heading carries a **Today** or **Upcoming** (after today) label; days before today are not listed.
- Each row shows the time, the plan's icon and name, the project name, the type (**Proposal** or **HagiTask**), and how it repeats (**Once**, **Daily**, **Weekly**). A time that was moved on its own carries **Modified**, a completed one-time plan carries **Completed**, and rows already past today are dimmer.
- It covers every project you can read, but it **counts enabled plans only**: a disabled plan does not appear in the agenda and is not counted in the badge.
- The agenda lists only **planned times**, which is what **Scheduled times, not run records.** at the bottom means.

Click a row in the agenda to open the project details drawer of the plan's project, on the **Plans** tab, with this plan's editor already open. For a recurring plan the editor opens on **Current event** (it changes only the one time shown on that row), and you can switch to **Overall plan** at any time; see [Edit a plan](#edit-a-plan).

### The Plans tab in the project details

In the project panel, click **View Project Details**. The tabs along the top are **Details**, **MonoSpecs**, **Standard Words**, **Prompts**, **Plans**, and **Git**. **Plans** manages only the plans of the current project, and has two views at the top:

- **Calendar**: shows by month, week, or agenda when plans will run.
- **All plans**: lists every plan of this project, where you can enable, disable, run now, edit, and delete it.

The **Plans** tab is only for **viewing and managing** existing plans; you cannot create one here. Plans are always saved from the dialog that creates a proposal or a HagiTask. With no plans yet, **All plans** tells you to use the **Plan** switch in the creation dialog; on a phone-width screen it tells you to create one on a wider screen. When you switch to another tab and come back, the view and date range stay as they were; switching to another project starts from scratch.

## See your plans on the calendar

**Calendar** opens on the current month. Every time a plan will run is one entry on the calendar, preceded by the plan's own icon and color (see [Icons and colors](#icons-and-colors)).

![Month view of the calendar: October 2026, with recurring plans marked by a repeat icon and today highlighted](../../img/user-guide/plans/02-calendar-month.png)

The controls at the top:

| Control | What it does |
| --- | --- |
| **Today** | Jumps back to the month, week, or agenda that contains today. |
| **‹ / ›** | Moves to the previous or next period: by month in Month view, by week in Week and Agenda views. |
| **Month / Week / Agenda** | Switches the view. The layout adapts to the width of the tab itself: when it is too narrow for the grid, Month and Week views scroll horizontally inside the calendar, and the page itself does not scroll. |
| **Display time zone** | The time zone the calendar uses to arrange and show times. It defaults to the browser's current time zone. It changes only how times are displayed, never the plan's own time zone or when it actually runs. |

The three views show the same data (only the current project's plans):

- **Month**: each day cell shows up to 3 entries; beyond that **+N more** appears, and clicking it opens a dialog with every run time of that day.
- **Week**: seven columns side by side, with room for the full plan name on each entry.
- **Agenda**: a list grouped by date, listing only days that have run times, with the state written out at the right of each entry.

![Week view of the calendar: October 25 to October 31, with one Tuesday entry carrying the pencil icon for a changed time](../../img/user-guide/plans/03-calendar-week.png)

![Agenda view of the calendar: every run time listed by date, with Repeats, Completed, and Disabled shown at the right](../../img/user-guide/plans/04-calendar-agenda.png)

Each entry shows the **time** and the **plan name**. Month and Week views mark the state with icons (hover for the text); Agenda writes it out:

| Marker | Meaning |
| --- | --- |
| Repeat icon / **Repeats** | This is one time of a recurring plan. |
| Check icon / **Completed** | The plan is completed (for example, a one-time plan that has already run). |
| Pause icon / **Disabled** | The plan is disabled, so this time will not run automatically. |
| Pencil icon / **Changed** | This single time was changed and differs from the recurring plan in time or content. |

:::note
The calendar shows **times worked out from the plan's current settings, not a run history**. That is what **Scheduled times from current plan settings. They are not run history.** on the page means: after a plan is edited, disabled, or completed, the calendar still lays it out from its current settings and does not record what ran before. To see sessions that already started, use the session board.
:::

### See the details of one time

Click any entry to slide in a details drawer for that time. You do not need to open the editor to look.

![Details drawer for one time: This time, Original time, Schedule, Next run, and Project / repositories, with Delete, Edit single, and Edit all buttons at the bottom](../../img/user-guide/plans/05-event-details.png)

| Field | Description |
| --- | --- |
| Title and badges | The plan name, its type (**Proposal** or **HagiTask**), its state (**Scheduled** or **Completed**), and **Enabled** or **Disabled**. |
| **This time** | The run time of this entry, arranged in the display time zone. |
| **Original time** | Appears only when this time was moved, and shows the time the recurring plan originally scheduled. |
| **Schedule** | The plan's full schedule. |
| **Schedule time zone** | The time zone the plan itself uses. |
| **Next run** | The real next run of the whole plan; a completed plan shows `–`. Note that it is not necessarily the same as "this time". |
| **Project / repositories** | The target project and repositories saved with the plan. |
| **Agent** | Appears only when the plan has an Agent, and shows **Random agent from the plan pool**. |

The buttons at the bottom of the drawer depend on the plan type:

- **Recurring plan**: **Edit single** changes only this time, **Edit all** changes the whole plan, and **Delete** deletes this time or the whole series. The drawer explains: **Edit single changes only this time. Edit all changes every time of the plan.**
- **One-time plan**: just **Edit** and **Delete**; **Edit** opens the editor for the whole plan directly.

For details, see [Edit a plan](#edit-a-plan) and [Delete a plan](#delete-a-plan).

## Create a plan

Both the proposal and HagiTask creation dialogs can switch from "start now" to "start on a schedule". **Create Normal Session** has no plan switch.

1. Open a creation dialog as usual, for example **New Idea**, and fill in the idea name, project, and request. For the fields, see [Sessions](/en-US/user-guide/sessions#create-an-idea-proposal).
2. Look at the bottom right of the dialog. Next to the submit button there is a **Plan** switch, off by default.

   ![Footer of the Create Proposal drawer with Cancel on the left and the Plan switch and Submit idea button on the right](../../img/user-guide/plans/10-plan-switch.png)

3. Turn the **Plan** switch on. The dialog switches to plan mode:
   - The label at the top left changes from **Create Proposal** to **Proposal plan**.
   - A required **Plan name** field appears at the top of **Basic Setup**, for example "Weekly release check", up to 200 characters.
   - A **Schedule** section appears.
   - The submit button becomes **Save plan**.

   ![Create Proposal drawer in plan mode: Plan name and the original form on the left, the Required content checklist and Schedule section on the right, and Save plan at the bottom](../../img/user-guide/plans/11-plan-mode-once.png)

4. Set when the plan runs in **Schedule**; see [Set the schedule](#set-the-schedule). A HagiTask plan also needs an Agent; see [Choose an Agent for a HagiTask plan](#choose-an-agent-for-a-hagitask-plan).
5. Click **Save plan**. HagiCode shows a **Plan saved** notice; click **View plans** to open this project's **Plans** tab right away.

   ![Notice on the screen: Plan saved, with a View plans button on the right](../../img/user-guide/plans/13-plan-saved-toast.png)

At the very top of the **Schedule** section there are also **Team / Personal** buttons, which choose whether the plan is saved as a team plan or a personal plan; the default is **Team**. A **Personal** plan is saved as `.hagicode/plans/*.user.yaml`, and you can exclude such files from version control with `.gitignore`. After saving, the scope is read-only and cannot be changed.

The **Required content** checklist tells you live what is still missing. A proposal plan checks **Project**, **Requirement description**, **Plan name**, and **Schedule**; a HagiTask plan checks **Project**, the HagiTask's own required inputs, **Plan name**, **Schedule**, and **Agent**. When everything is done it shows **All required content is ready**.

:::note[Window width and layout]
When the window is wide enough (about 1464 pixels or more), **Required content** and **Schedule** appear as two cards to the right of the drawer. In a narrower window, **Schedule** moves to the bottom of the drawer above the submit button, and **Required content** collapses into a bar you can expand. The content and rules are identical in both layouts.
:::

:::note
Plans cannot include images. If images are already attached to the form, the **Plan** switch is disabled and tells you to remove them before saving the task as a plan.
:::

## Set the schedule

The two buttons at the top of **Schedule** choose how the plan runs: **Run once** or **Recurring**. In both modes, **Next run** at the bottom of the section updates live to the next run time the current settings produce. If it shows **Not scheduled**, no run time is possible with the current settings, so adjust the dates or the time.

### Run once

Runs a single time.

| Field | Description |
| --- | --- |
| **Date** and **Time** | The day and time of the run. Defaults to tomorrow at 09:00. It must be later than now. |
| **Run in** | Quick buttons: `+5 min`, `+10 min`, `+30 min`, `+1 hour`, counted from now. |
| **Next at** | Quick buttons: `02:00`, `09:00`, `12:00`, `18:00`, `22:00`. They pick the next occurrence of that time, today if it is still ahead, otherwise tomorrow. |
| **Time zone** | The time zone the date and time are read in. Defaults to the browser's current time zone. |

### Recurring

Repeats daily or weekly between a start date and an end date.

![Recurring mode of the Schedule section: start and end dates, time, Every week, Friday, and the next run time](../../img/user-guide/plans/12-recurring-schedule.png)

| Field | Description |
| --- | --- |
| **From** and **To** | The first and last date of the period, both inclusive. Defaults to starting today and lasting one month. Under **Start**, `Today`, `Tomorrow`, `In 1 week`, `In 1 month`, and `In 3 months` set the start date quickly; under **Length**, `+1 week`, `+1 month`, and `+3 months` set the duration. |
| **Time** | The time of day of each run, in `HH:mm`. **Quick time** offers `02:00`, `09:00`, `12:00`, `18:00`, and `22:00`. |
| **Repeat** | **Every day** or **Every week**. |
| **On** | Appears when you choose **Every week**. Pick the weekdays, `Mon` to `Sun`, on which the plan runs; choose at least one. |
| **Time zone** | The time zone the time is read in. Every run follows local time in this zone, so a plan at 02:00 every day stays at 02:00 across daylight saving changes. |

:::tip
To make a plan "long-lived", set **To** far out, for example by clicking **+3 months**. After the end date the plan becomes **Completed** and stops running.
:::

## Choose an Agent for a HagiTask plan

A proposal plan needs no Agent. **A HagiTask plan must have one Agent selected**, because nobody is there to pick one when it starts on its own:

- In plan mode the dialog shows an Agent selection section explaining that this is the Agent the plan runs with, and that the plan keeps this choice when it starts. Click an Agent to select it.
- The bottom bar shows `Agent: name`. Until you choose, it shows `No agent selected yet.` and the plan cannot be saved.
- Currently a plan can have only one Agent. To create Agents, see [Agents](/en-US/user-guide/agents).

## Icons and colors

Every plan can have its own **icon** and **color**, so you can tell plans apart at a glance in the calendar, the list, and the header agenda. Next to **Plan name** there is an appearance field:

![The appearance field next to Plan name in the plan editor: the icon button, Reset to default icon, and the Automatic color](../../img/user-guide/plans/16-plan-appearance.png)

- Click the icon button to open the Lucide icon picker, choose an icon, and confirm; click **Reset to default icon** to return to the default calendar icon.
- For the color you can choose **Automatic** (a color picked stably from the plan's number, the same in every view) or pick a fixed color from the palette.
- The appearance belongs to the **whole plan**. When you change only one time (**Current event**), this field is not shown and is not changed.

## Edit a plan

There are three ways in: click a row in the header agenda; click **Edit single** / **Edit all** in the details drawer of a time on the **Calendar** (a one-time plan has just **Edit**); or click **Edit** on the plan's row in **All plans**. Whichever you use, HagiCode first reads the plan's latest saved content, then opens the same dialog used to create it, in plan mode. A saved plan always stays a plan: the **Plan** switch is locked and cannot turn it back into a normal task.

### A one-time plan

The editor opens directly. Change the name, content, Agent, or time and click **Save plan**. A one-time plan has only one scope, so the editor has no **Edit scope** switch.

### A recurring plan: Current event and Overall plan

When you edit an existing recurring plan, an **Edit scope** switch sits next to the **Plan** switch in the bottom bar. Exactly one of its two options is selected at a time, and the selected one carries a check mark:

![The editor's bottom bar: the Current event and Overall plan options of Edit scope with Overall plan selected, and the Plan switch and Save plan on the right](../../img/user-guide/plans/06-edit-scope-control.png)

| Option | What it changes |
| --- | --- |
| **Current event** | Only the time you are editing. The plan's other times stay as they are. It states which time that is. |
| **Overall plan** | Every time of the recurring plan. Times that were changed individually and no longer match the new schedule are reset. |

Each way in starts on a different scope:

| Way in | Default scope |
| --- | --- |
| A row in the header agenda | **Current event**, the time shown on that row |
| **Edit single** in the calendar details | **Current event** |
| **Edit all** in the calendar details | **Overall plan** |
| **Edit** in **All plans** | **Overall plan** |

Whichever way you came in, you can switch in the editor at any time:

- **Switching does not close the editor and does not lose what you typed.** Fields you changed keep your values across the two scopes; fields you have not changed show the new scope's own values.
- When you come in from **All plans** and choose **Current event**, it means the plan's next run. If the plan has no future run time left, **Current event** is greyed out with the reason, and only **Overall plan** can be edited.
- **Saving writes only the scope selected at the moment you save.**

With **Overall plan** selected, the top of the drawer says **This is a recurring plan. Saving changes the entire series, not a single time.**, to remind you that saving affects every time.

With **Current event** selected, the top of the drawer says "Saving changes only this time, …", and the schedule area shrinks to this time's **date, time, and time zone**; it can no longer be changed to recurring. You can change this time's run time, name, request, and Agent; any field you leave alone keeps following the whole plan.

![Editing one time: the top of the drawer says only this time changes, and the Schedule on the right has just a date, a time, and a time zone](../../img/user-guide/plans/14-edit-occurrence.png)

After saving you are back on the calendar. The changed time now carries the pencil icon (**Changed**), and the top of the calendar shows **Saved.**

![Calendar after saving: Saved. at the top, and the October 27 entry now at 03:00 with the pencil icon](../../img/user-guide/plans/15-calendar-saved.png)

:::note
If the saved plan has no run time in the month, week, or agenda currently shown, the calendar says `"…" has no scheduled time in this period` and offers an **All plans** button, where the plan's details stay available.
:::

## Delete a plan

There are two ways to delete as well, and both ask for confirmation first.

- **From the calendar**: click **Delete** in the details drawer of a time. A recurring plan first opens the **Delete this time or the series** scope dialog:

  ![Delete this time or the series dialog: the This occurrence and Entire series options, with Cancel and Continue buttons](../../img/user-guide/plans/07-delete-scope.png)

  Choose **This occurrence** and click **Continue** to reach the **Delete this time?** confirmation; choose **Entire series** to confirm deleting the whole plan. A one-time plan has only one scope, so it goes straight to the delete confirmation.

  ![Delete this time? confirmation: only the chosen time is deleted, and the plan's other times stay scheduled](../../img/user-guide/plans/07-delete-time-confirm.png)

- **From All plans**: click **Delete** on the plan's row and confirm to delete the whole plan.

  ![Delete confirmation dialog: Delete this scheduled plan? It says "Weekly docs cleanup" will stop running and that sessions it already started are kept](../../img/user-guide/plans/09-delete-plan-confirm.png)

Deleting one time only stops that single time from running; deleting the whole plan stops the plan. **Either way, sessions that already started are kept.**

## Manage plans in All plans

Switch to **All plans** to see every plan. Each row is one plan.

![All plans list: All / Team / Personal filter at the top, and each row with the plan icon, name, type, scope and state badges, schedule, next run, and definition file path, with the enable switch and action buttons at the right](../../img/user-guide/plans/08-all-plans.png)

The **All / Team / Personal** buttons above the list filter by scope, with the count of each in parentheses. Each row contains:

- The **name**, a **Proposal** or **HagiTask** type badge, a **Team** or **Personal** scope badge, and a **Scheduled** or **Completed** state badge.
- A **schedule summary**, for example `Weekly on Mon, Tue, Wed, Thu, Fri 02:00 AM, Oct 19, 2026 - Jan 18, 2027 (America/New_York)`.
- **Next run**. A completed plan shows `–`.
- **Definition file**: the full path of the plan's definition file, under the project's `.hagicode/plans/`: `<name>.yaml` for a team plan and `<name>.user.yaml` for a personal plan. The button at the right copies this path, and a successful copy shows **File path copied**.

The controls at the right of each row:

| Control | What it does |
| --- | --- |
| **Enabled / Disabled** switch | Enables or disables the plan. A disabled plan does not run automatically but stays in the list and on the calendar. When you enable it again, HagiCode recalculates the next run from the current time; times missed while it was disabled are not made up. |
| **Run now** | Creates a session right now from the saved inputs; on success the row shows **Session started.** It does not change the plan's schedule or **Next run**, and a disabled or completed plan can be run manually too. |
| **Edit** | Edits the entire plan; see [Edit a plan](#edit-a-plan). |
| **Delete** | Deletes the entire plan; see [Delete a plan](#delete-a-plan). |

## Plan files

Besides the **definition file** above (where the plan itself is stored), when you save a plan HagiCode also syncs its contents to Markdown files in the **Scheduled Plans** vault, which HagiCode manages for you; you do not need to create it. Each plan gets a folder named by its id:

- `series.md`: the whole plan's configuration and request text.
- `occurrence-<time>.md`: one for each changed time that carries its own content.

These files are **copies** generated from the plan, handy for reading, searching, or referring to elsewhere. HagiCode rewrites them from the plan's latest content and cleans them up when the plan is deleted. To change a plan, edit it in the **Plans** tab: changing a copy does not change the plan, and the change is overwritten. For vaults in general, see [Vault](/en-US/user-guide/vault).

## When plans run

- **Plans run only while HagiCode is running.** HagiCode checks for due plans every 30 seconds, so a run can start up to about 30 seconds after its scheduled time.
- **Missed times are made up once.** If HagiCode was not running when a plan came due (for example, the computer was off), the plan runs once as soon as HagiCode starts, and then the next run is scheduled normally. However many times were missed, it runs only once, not in a batch.
- **Failed runs are not retried.** If a run cannot create its session (for example, the project was removed or the chosen Agent is unavailable), that run is skipped and the plan waits for its next scheduled time. To recover, fix the problem and click **Run now**. If a manual run fails, the row shows **Run now failed:** and the reason.
- **A one-time plan becomes Completed after it runs.** To use it again, click **Edit** and set a new time in the future. Turning on the switch of an expired one-time plan is rejected because its run time is already in the past.
- **Every run creates a new session.** A proposal plan creates a proposal session and a HagiTask plan creates a HagiTask session. They appear on the session board like sessions you create by hand.

## FAQ

**Saving a plan says the run time must be later than the current time, or to choose at least one weekday.**
This is form validation, and the reason appears under the field. A one-time plan must be later than now. For a recurring plan, the end date cannot be before the start date, a weekly plan needs at least one weekday, and the range must contain at least one possible run.

**The Plan switch is greyed out.**
Images are attached to the form, and plans do not support images. Remove them and the switch works again.

**The plan I just saved is not on the calendar.**
The calendar shows only the times inside the month, week, or agenda range on screen. Switch to a month that contains those dates, or look at the plan in **All plans**.

**The times on the calendar differ from what I set.**
The calendar arranges times in the **Display time zone**, which defaults to the browser's time zone. The plan's own time zone is shown as **Schedule time zone** in the details, and a plan always runs by its own time zone.

**A plan did not run when it was due.**
Check in order: the plan is **Enabled**; **Next run** is the time you expect (especially the time zone); HagiCode was running at that moment; the project and Agent used by the plan still exist; that single time was not deleted. The calendar shows plan settings, not a run record, so it cannot confirm whether something ran.

**Where are plans stored?**
Each plan is stored as a file in its project's `.hagicode/plans/` folder: `<name>.yaml` for a team plan and `<name>.user.yaml` for a personal plan. See the `.hagicode` data files section of the project guide for the file format and how to write one by hand. Run state, such as the next run time, is kept on this machine and is not written to the plan file. The old global `scheduled-plans.json` is no longer read, and its plans are not imported.

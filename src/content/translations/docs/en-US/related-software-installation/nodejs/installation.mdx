This guide covers installing Node.js on Windows, macOS, and Linux. Desktop and the Microsoft Store edition no longer bundle Node.js; they use the `node` and `npm` on your system directly, and OpenSpec and most Agent CLIs depend on it as well.

:::tip[Version Requirements]
**Node.js 24 or higher** is required, and 24 is also the minimum. In most cases, just install the latest LTS version. `npm` is installed together with Node.js, so you do not need to install it separately.
:::

:::note[Which Installation Methods Need It]
- **Microsoft Store / Desktop**: Required, and `node` and `npm` must be found on the system `PATH`.
:::

## Installing Node.js

<Tabs>
  <TabItem value="windows" label="Windows" default>

### Method One: Official Installer (Recommended)

1. Visit the [Node.js Official Website](https://nodejs.org/)
2. Download the **LTS (Long Term Support)** version Windows installer (`.msi` file), and confirm the version is not lower than 24
3. Double-click to run the installer
4. Follow the installation wizard prompts to complete installation:
   - Accept the license agreement
   - Choose installation path (default is fine)
   - Keep "Add to PATH" checked
   - Click "Install" to start installation
5. After installation completes, click "Finish"

### Method Two: Using winget

Open PowerShell or Command Prompt and run:

```powershell
winget install OpenJS.NodeJS.LTS
```

After installation, reopen the terminal for changes to take effect.

  </TabItem>
  <TabItem value="macos" label="macOS">

### Method One: Official Installer (Recommended)

1. Visit the [Node.js Official Website](https://nodejs.org/)
2. Download the **LTS (Long Term Support)** version macOS installer (`.pkg` file), and confirm the version is not lower than 24
3. Double-click to run the installer
4. Follow the installation wizard prompts to complete installation:
   - Click "Continue"
   - Accept the license agreement
   - Choose installation disk
   - Click "Install" and enter administrator password
5. After installation completes, click "Close"

### Method Two: Using Homebrew

If you have [Homebrew](https://brew.sh/) installed, you can install Node.js via terminal:

```bash
brew install node
```

:::tip
Homebrew will automatically add Node.js to your PATH. If the command is not available, restart the terminal or run:
```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```
:::

  </TabItem>
  <TabItem value="ubuntu" label="Ubuntu/Debian">

### Using NodeSource Repository (Recommended)

The Node.js in the distribution's own repositories is usually lower than 24, so use the 24.x repository provided by NodeSource:

```bash
# Use curl to download the installation script
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs
```

:::caution
Do not install the distribution's bundled version directly with `sudo apt-get install nodejs npm`; it most likely does not meet the minimum requirement of 24.
:::

If you do not want to add a third-party package source, you can also use [nvm or fnm](#using-version-management-tools) described below.

  </TabItem>
  <TabItem value="centos" label="CentOS/RHEL">

### Using NodeSource Repository (Recommended)

```bash
# Use curl to download the installation script
curl -fsSL https://rpm.nodesource.com/setup_24.x | sudo bash -
sudo yum install -y nodejs
```

The Node.js in the distribution's own repositories is usually lower than 24, so installing it directly is not recommended. You can also use [nvm or fnm](#using-version-management-tools) described below instead.

  </TabItem>
  <TabItem value="fedora" label="Fedora">

### Using dnf Package Manager

```bash
sudo dnf install -y nodejs npm
```

After installation, run `node --version` to confirm the version is not lower than 24. If the version in the repository is lower, use the NodeSource 24.x repository instead, or use [nvm or fnm](#using-version-management-tools) described below.

  </TabItem>
</Tabs>

## Using Version Management Tools

If you need to switch between multiple Node.js versions, you can use version management tools.

:::caution[Note for Desktop Users]
On macOS and Linux, tools such as nvm and fnm usually set `PATH` only in shell configuration files (such as `.bashrc` and `.zshrc`). Desktop launched from the Dock, the application menu, or a desktop icon does not read those files and may not find `node`. If you use a version management tool, launch Desktop from a terminal where `node` already works, or use the system-wide installation methods above instead.
:::

### nvm (Node Version Manager)

<Tabs>
  <TabItem value="nvm-install" label="Installing nvm" default>

#### Linux/macOS

Copy the latest installation command directly from the [nvm official repository README](https://github.com/nvm-sh/nvm#installing-and-updating); do not use old installation script URLs.

After installation, reload your shell configuration:

```bash
source ~/.bashrc
# Or for Zsh users
source ~/.zshrc
```

#### Windows

On Windows, we recommend using [nvm-windows](https://github.com/coreybutler/nvm-windows):

1. Download the latest `nvm-setup.exe` from [nvm-windows releases](https://github.com/coreybutler/nvm-windows/releases)
2. Run the installer
3. Reopen Command Prompt or PowerShell

  </TabItem>
  <TabItem value="nvm-use" label="Using nvm">

After installing nvm, you can use it to install and manage Node.js versions:

```bash
# Install Node.js 24
nvm install 24

# Switch to Node.js 24
nvm use 24

# Set default version
nvm alias default 24

# List installed versions
nvm list
```

The `alias` command is not available in nvm-windows; just use `nvm install 24` and `nvm use 24`.

  </TabItem>
</Tabs>

### fnm (Fast Node Manager)

fnm is a faster and simpler Node.js version management tool built with Rust.

<Tabs>
  <TabItem value="fnm-install" label="Installing fnm" default>

#### Linux/macOS

```bash
# Install using curl
curl -fsSL https://fnm.vercel.app/install | bash

# After installation, reload shell configuration
source ~/.bashrc
# Or for Zsh users
source ~/.zshrc
```

#### Windows

Use [scoop](https://scoop.sh/) or [winget](https://learn.microsoft.com/en-us/windows/package-manager/winget/):

```powershell
# Use scoop
scoop install fnm

# Or use winget
winget install Schniz.fnm
```

  </TabItem>
  <TabItem value="fnm-use" label="Using fnm">

```bash
# Install Node.js 24
fnm install 24

# Switch to Node.js 24
fnm use 24

# Set default version
fnm default 24

# List installed versions
fnm list
```

  </TabItem>
</Tabs>

## Acceleration for Mainland China Users

If you are in Mainland China, downloading Node.js and npm packages may be slow. You can use domestic mirrors.

### npm Mirror

```bash
# Temporarily use the mirror to install
npm install --registry=https://registry.npmmirror.com

# Permanently set the mirror
npm config set registry https://registry.npmmirror.com

# Verify the mirror is set successfully
npm config get registry
```

### Node.js Installer Mirror

Node.js installers also have a mirror download address: [https://npmmirror.com/mirrors/node/](https://npmmirror.com/mirrors/node/). After visiting it, choose a version not lower than 24 to download.

### Homebrew Mirror

If you use Homebrew in Mainland China, you can configure the USTC mirror for bottles:

```bash
export HOMEBREW_BOTTLE_DOMAIN=https://mirrors.ustc.edu.cn/homebrew-bottles
```

## Verifying Installation

After installation, verify that Node.js and npm are available in a **newly opened terminal**:

```bash
# Check the Node.js version, v24.0.0 or higher is required
node --version

# Check the npm version
npm --version
```

Successful output should look like:

```
$ node --version
v24.3.0

$ npm --version
11.4.2
```

:::note
If `node --version` shows a version lower than 24, reinstall using the methods above, or use a version management tool to switch to 24 or higher.
:::

## Configuring the npm Global Directory

Desktop installs managed packages such as Agent CLIs into your local npm global directory. If the global directory is in a location that requires administrator privileges, you may see an `EACCES` permission error during installation. It is recommended to move the global directory into your user directory instead of changing the permissions of system directories:

```bash
mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
```

Then add `~/.npm-global/bin` (on Windows, the npm global directory itself) to the system `PATH`, and restart your terminal and Desktop. When you use nvm or fnm, the global directory is already under your user directory, so this step is not needed.

## Troubleshooting

### Windows Issues

<Tabs>
  <TabItem value="win-path" label="Command Not Available">

If the `node` or `npm` command is not available after installation:

1. Restart Command Prompt or PowerShell
2. If still not available, manually add Node.js to PATH:
   - Search for "Environment Variables" and open "Edit system environment variables"
   - Click "Environment Variables"
   - Find "Path" in "System variables" and click "Edit"
   - Add Node.js installation path (default: `C:\Program Files\nodejs\`)
   - Click "OK" to save changes
3. Fully quit and restart Desktop

  </TabItem>
  <TabItem value="win-policy" label="PowerShell Execution Policy">

If you encounter execution policy errors when using nvm or npm scripts:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

  </TabItem>
</Tabs>

### macOS Issues

<Tabs>
  <TabItem value="mac-perm" label="Permission Errors">

If you encounter permission errors when installing global npm packages, see [Configuring the npm Global Directory](#configuring-the-npm-global-directory) above, or use nvm / fnm instead.

  </TabItem>
  <TabItem value="mac-path" label="Command Not Available">

If the command is not available after installation, restart the terminal and confirm that the directory containing Node.js (usually `/usr/local/bin` or `/opt/homebrew/bin`) is in `PATH`.

  </TabItem>
</Tabs>

### Linux Issues

<Tabs>
  <TabItem value="linux-perm" label="Permission Errors">

If you encounter permission errors when installing global npm packages, see [Configuring the npm Global Directory](#configuring-the-npm-global-directory) above, or use nvm / fnm instead of installing global packages with `sudo`.

  </TabItem>
  <TabItem value="linux-old" label="Version Too Old">

If the Node.js version installed via the system package manager is lower than 24:

1. Use the NodeSource 24.x repository (see above)
2. Or use a version management tool (nvm / fnm)

  </TabItem>
</Tabs>

### Checking Environment

If verification fails, check the following:

<Tabs>
  <TabItem value="win-check" label="Windows">

```powershell
# Check if Node.js is in PATH
where node

# Check installation path
Get-Command node
```

  </TabItem>
  <TabItem value="mac-check" label="macOS">

```bash
# Check if Node.js is in PATH
which node

# Check installation path
ls -l $(which node)
```

  </TabItem>
  <TabItem value="linux-check" label="Linux">

```bash
# Check if Node.js is in PATH
which node

# Check installation path
ls -l $(which node)
```

  </TabItem>
</Tabs>

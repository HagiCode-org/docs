HagiCode Desktop verwendet das **auf Ihrem System installierte externe `node` und `npm`**. Installieren Sie Node.js vor dem ersten Start von Desktop und stellen Sie sicher, dass beide Befehle über den System-`PATH` verfügbar sind.

Diese FAQ erklärt, wie Desktop Ihre externe Node-Umgebung findet, wo Agent CLIs installiert werden und wie Sie Probleme mit nicht gefundenem Node oder npm beheben.

## Versionsanforderungen

Erforderlich ist **Node.js 24 oder höher** (auch die Mindestanforderung ist 24). `npm` wird zusammen mit Node.js installiert. Hinweise zur Installation finden Sie unter [Node.js installieren](/de-DE/related-software-installation/nodejs/installation).

Auch Git müssen Sie selbst installieren, siehe [Installationsanleitung](/de-DE/installation/#git-installieren).

## Wie Desktop node und npm findet

Desktop liest beim Start den System-`PATH` und sucht darin nach `node`, `npm` und `git`. Das bedeutet:

- Die Version, die Sie im Terminal mit `node --version` sehen, ist in der Regel auch die von Desktop verwendete.
- Desktop **verwendet** Ihre Node-Umgebung nur; es ersetzt oder verändert sie nicht.
- Wenn Sie Node.js erst installieren oder aktualisieren, nachdem Desktop bereits geöffnet war, beenden Sie Desktop vollständig und starten Sie es neu, damit es den neuen `PATH` einliest.

:::caution[Versionsverwaltungstools und PATH]
Unter macOS und Linux setzen Versionsverwaltungstools wie nvm und fnm den `PATH` in der Regel nur in Shell-Konfigurationsdateien. Ein Desktop, das über das Dock, das Anwendungsmenü oder ein Desktop-Symbol gestartet wird, liest diese Konfiguration nicht und findet `node` möglicherweise nicht. Starten Sie Desktop aus einem Terminal, in dem `node` bereits funktioniert, oder verwenden Sie stattdessen eine systemweite Installation.
:::

## Wo Agent CLIs und andere verwaltete Pakete installiert werden

Die Abhängigkeitsverwaltung von Desktop erkennt `node` und `npm` im `PATH`, zeigt das ermittelte globale npm-Präfix an und installiert die im Katalog aufgeführten CLI-Pakete in dieses **externe** globale Verzeichnis.

Für jede verwaltete CLI sucht Desktop die ausführbare Datei in dieser Reihenfolge:

1. Ein bereits vorhandener verwalteter Pfad
2. Das globale npm-`bin`-Verzeichnis (unter Windows einschließlich der Startskripte `.cmd` und `.ps1`)
3. `PATH`

Die npm-Mirror-Einstellungen gelten für Installations- und Synchronisierungsvorgänge. Auch die Deinstallation bezieht sich auf das externe globale Verzeichnis und muss in der Oberfläche bestätigt werden. Das aktuelle globale Verzeichnis können Sie mit folgendem Befehl anzeigen:

```bash
npm prefix -g
```

Liegt das globale Verzeichnis an einem Ort, der Administratorrechte erfordert, kann bei der Installation ein Berechtigungsfehler auftreten. Lesen Sie dazu [Globales npm-Verzeichnis konfigurieren](/de-DE/related-software-installation/nodejs/installation#globales-npm-verzeichnis-konfigurieren).

## Was tun, wenn Node oder npm nicht gefunden wird

1. Führen Sie im Terminal `node --version` aus und prüfen Sie, ob Node.js mindestens Version 24 hat. Führen Sie anschließend `npm --version` aus, um zu prüfen, ob npm verfügbar ist.
2. Wenn Node.js nicht installiert oder die Version zu niedrig ist, installieren Sie Node.js zuerst außerhalb von Desktop.
3. Beenden Sie Desktop vollständig, starten Sie es neu und klicken Sie dann auf der Abhängigkeitsseite auf „Aktualisieren“.

Wenn Desktop meldet, dass ein CLI-Paket manuell installiert werden muss, führen Sie den angezeigten Befehl in einem Terminal außerhalb von Desktop aus, kehren Sie danach zu Desktop zurück und aktualisieren Sie einmal, damit es die Pakete neu erkennt.

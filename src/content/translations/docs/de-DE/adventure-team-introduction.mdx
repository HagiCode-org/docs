Der **Agent** ist der Kern von HagiCode: Sitzungen werden von einem Agent ausgeführt, und bevor Sie arbeiten können, wird mindestens einer benötigt. Diese Seite ist eine Übersicht, die Ihnen zeigt, woraus ein Agent besteht, wer welche Art von Arbeit übernimmt und an welchen Stellen sich die Agent-bezogene Konfiguration verteilt. Schritt-für-Schritt-Anleitungen finden Sie im [Leitfaden zum Agents-Arbeitsbereich](/de-DE/user-guide/agents).

## Funktionsübersicht

- Ein **Agent = Agent CLI + Modell + optionaler Persönlichkeitstext**. Die Agent CLI ist das Kommandozeilenwerkzeug, das die Arbeit tatsächlich ausführt (z. B. Claude Code, Codex), das Modell ist das von ihr verwendete Modell, und der Persönlichkeitstext (Trait und Soul) prägt Arbeitsweise und Sprachstil.
- Sie können mehrere Agents anlegen, zum Beispiel einen mit Opus für Reviews, einen mit Haiku für schnelle Änderungen und einen mit Codex für Refactorings.
- Welcher Agent welche Art von Arbeit übernimmt, bestimmt das **Ausführungsszenario**; gibt es keinen geeigneten Agent, springt die **Fallback Crew** ein.
- Prüfung und Feinabstimmung von Agents verteilen sich auf den **Agents-Arbeitsbereich** und die **Einstellungen**: Ersterer verwaltet Agents, Szenarien, CLI und Modelle, Letztere steuern das Laufzeitverhalten wie Wiederholungen sowie Speicher- und CPU-Limits.

## Agent-Liste

![Reiter Agents: fünf Agents, nach Claude Code und Codex gruppiert, jeweils mit Avatar und Modell](../img/screenshots/guides/agent-roster/original.png)

Klicken Sie in der oberen Leiste auf **Agents**, um den **Agents Workspace** zu öffnen. Unter **My Agents** im Reiter **Agents** sind Ihre Agents nach Agent CLI gruppiert aufgelistet; jede Karte zeigt Avatar, Namen und Modell. Hier können Sie:

1. mit **New Agent** einen Agent erstellen: AgentCLI und ein kompatibles Modell auswählen und optional Trait (Wissen und Verhalten) sowie Soul (Sprachstil) hinterlegen.
2. mit **Batch create Agents** mehrere auf einmal erstellen oder über das Suchfeld nach Namen, CLI oder Beschreibung filtern.
3. über den Schalter **Battle ready** einen Agent aktivieren oder deaktivieren.

Eine vollständige Beschreibung des Erstellungsvorgangs finden Sie unter [Agents](/de-DE/user-guide/agents#agent-erstellen).

## Aufgabenverteilung: Ausführungsszenarien und Fallback Crew

![Reiter Execution Scenarios: Agent-Zuweisungen für die Szenarien Proposal und HagiTask, rechts die zugewiesenen und die hinzufügbaren Agents](../img/screenshots/guides/agent-scenarios/original.png)

Der Reiter **Execution Scenarios** legt fest, welche Agents welche Art von Arbeit übernehmen. Die Szenarien sind nach Verwendungszweck gruppiert:

| Gruppe | Szenarien |
| --- | --- |
| **Proposal** | Proposals optimieren, generieren, ausführen und archivieren |
| **HagiTask** | Super Commit, normale Sitzung erstellen, Code-Recherche-Aufgabe erstellen |
| **Chat** | Sitzungstitel optimieren |

Wenn Sie ein Szenario anklicken, zeigt **Assigned Agents** rechts dessen Zuweisung und **Available Agents** die Agents, die hinzugefügt werden können; mit **Add** oder **Remove** passen Sie sie an. Die **Fallback Crew** ist das Sicherheitsnetz: Hat ein Szenario in seiner eigenen Zuweisung keinen geeigneten Agent, wählt HagiCode einen passenden Agent aus der Fallback Crew. **Solange die Fallback Crew keinen aktivierten Agent enthält, bleiben alle anderen Szenarien gesperrt.** Der Initialisierungs-Assistent fügt Ihren ersten Agent automatisch dort hinzu.

Eine typische Aufteilung:

1. Den Agent, der bei langem Kontext und Reviews stark ist, in **Generate Proposal** legen.
2. Den ausführungsstarken Agent mit passenden Kosten in **Execute Proposal** legen.
3. Den günstigen, schnellen Agent in **Super Commit** und **Conversation Title Optimization** legen.
4. In der Fallback Crew einen stabilen Allzweck-Agent behalten.

## Wo die zugehörige Konfiguration liegt

| Was Sie tun möchten | Wohin |
| --- | --- |
| Agents erstellen, bearbeiten, aktivieren oder deaktivieren | **Agents** → Reiter **Agents** |
| Jeder Art von Arbeit Agents zuweisen, Fallback Crew pflegen | **Agents** → **Execution Scenarios** |
| Prüfen, ob eine Agent CLI installiert, gesund und aktiviert ist | **Agents** → **AgentCLI**, Overlay AI Monitoring in der Statusleiste |
| Modelle einer CLI durchsuchen oder hinzufügen | **Agents** → **Model** |
| Avatar oder Textthema wechseln | **Agents** → **Avatar Gallery** / **Document Theme** |
| Automatische Wiederholung fehlgeschlagener Läufe | **Einstellungen** → **Error Retry** |
| Ob der generierte Prompt „dieser Lauf ist nicht interaktiv" deklariert | **Einstellungen** → **AgentCLI Interactive Control** |
| Speicher und CPU begrenzen, die jeder Agent nutzen darf | **Einstellungen** → **Agent resource limits** |
| Mehrere OpenAI-kompatible Modelle an dasselbe lokale Gateway anbinden | **Einstellungen** → **OmniRoute** |

Die Wirkung der einzelnen Einstellungen beschreiben die [Einstellungen](/de-DE/user-guide/settings).

## Einsatzszenarien und Grenzen

- Wenn Sie in verschiedenen Phasen unterschiedliche Modelle oder CLIs verwenden möchten (z. B. Review und Ausführung getrennt), verteilen Sie die Arbeit nach Szenarien.
- Auch mit nur einem Agent können Sie HagiCode vollständig nutzen: Legen Sie ihn in die Fallback Crew, dann verwenden alle Szenarien ihn.
- Ein Agent bestimmt nur, **wer ausführt**. Was ausgeführt wird, ergibt sich weiterhin aus den von Ihnen erstellten Sitzungen, Proposals oder Plänen.

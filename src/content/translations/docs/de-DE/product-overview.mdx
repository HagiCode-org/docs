HagiCode sorgt dafür, dass die KI beim Ändern Ihres Codes den Kontext nicht verliert: **zuerst das Repository verstehen, den Umfang festlegen, dann nachvollziehbar ausführen.** Es ist ein KI-Arbeitsbereich für die Projektentwicklung, der die Agent CLI und Modelle verbindet, die Sie bereits nutzen, sodass Sie den Editor nicht wechseln müssen. Reichhaltige, komfortable UI-Interaktionen machen Planung, Agent-Ausführung und Projektarbeit zugänglich und leicht nachvollziehbar – für ein ansprechendes Entwicklungserlebnis.

Nicht jede Aufgabe braucht einen Vorschlag. Beginnen Sie mit einer Konversationssitzung, wenn Sie nur den Code erkunden oder ein einfaches Problem lösen möchten. Für Aufgaben, die mehr Kontext erfordern, bietet HagiCode einen nachvollziehbaren Ablauf.

## Funktionen im Detail

### Erst verstehen, dann handeln

HagiCode trennt „Code lesen“ von „Code ändern“, sodass Sie nach Umfang der Aufgabe entscheiden können, statt die KI alles direkt bearbeiten zu lassen.

- **Konversationssitzung:** Standardmäßig schreibgeschützt. Nutzen Sie sie, um ein Repository zu erkunden, ein Problem zu untersuchen oder zu fragen, wo bestimmte Logik liegt. Wechseln Sie nur dann zum Bearbeitungsmodus, wenn Sie Dateien ändern müssen.
- **Vorschlagssitzung:** Für komplexe Änderungen. Wählen Sie Projekt und Repository-Umfang, halten Sie Ziele, Aufgaben und Prüfschritte fest und gehen Sie zur Ausführung über, sobald Sie mit dem Plan zufrieden sind.
- **Sitzungsboard:** Die Spalten „Proposal & Review“, „Execution“ und „Archived“ zeigen auf einen Blick, wo jede Sitzung steht. Sie können zwischen den Layouts „Classic“, „Execution Flow Kanban“ und „Dashboard Kanban“ wechseln.

### Ein gemeinsamer Umfang aller Repositories

Wenn eine Anforderung Frontend, Backend und Dokumentation gleichzeitig betrifft, kann HagiCode sie mit MonoSpecs als ein einziges Projekt verstehen.

- Tragen Sie Speicherorte, Git-URLs und Anzeigenamen der Unter-Repositories in `.hagicode/monospecs.yaml` ein.
- Die Änderungsspezifikationen (OpenSpec) liegen im Haupt-Repository, sodass die Code-Verzeichnisse der Unter-Repositories sauber bleiben.
- Wenn Sie einen Vorschlag erstellen, wählen Sie aus, welche Unter-Repositories betroffen sind. Die Projektseite zeigt Branch und nicht committete Änderungen jedes Repositorys.

### Ihre Agent CLI behalten

HagiCode ersetzt Ihre Werkzeugkette nicht. Es führt sie in einem Arbeitsbereich zusammen.

- **Ein Agent besteht aus einer CLI, einem Modell und optionalem Persönlichkeitstext.** Legen Sie mehrere Agents an, weisen Sie sie Ausführungsszenarien zu und richten Sie Ersatzgruppen ein.
- Es werden 11 Agent CLIs unterstützt, darunter Claude Code, Codex und GitHub Copilot. Der Arbeitsbereich zeigt Version, Antwortzeit und Zustand jeder CLI an.
- Mit [OmniRoute](/de-DE/related-software-installation/omniroute/) können Sie mehrere OpenAI-kompatible Werkzeuge und Modelle an ein lokales Gateway anbinden, während CLI- und Modellanbindungen getrennt verwaltet bleiben.

### Skills

Das Skills-Panel bündelt die Skills, die bereits auf Ihrem Rechner liegen, und die Skills, die Sie aus der Galerie installieren können, an einer Stelle.

- **Local Skills:** Sehen Sie, was auf diesem Rechner installiert ist, und prüfen Sie gesammelt auf Updates.
- **Gallery:** Suchen Sie nach Stichwort und Quelle und sehen Sie, ob ein Skill bereits installiert ist.
- **Trusted Providers:** Bestätigen Sie vor der Installation Quelle, Vertrauensstatus und den Befehl, der tatsächlich ausgeführt wird, und entscheiden Sie, welche Quellen als vertrauenswürdig gelten.

### Vault und Code Server

- Ein **Vault** ist ein Ordner außerhalb Ihrer Projekt-Repositories, den HagiCode durchsuchen darf. Nutzen Sie ihn für Referenzdokumente, Notizen und Rechercheergebnisse. Unterstützt werden drei Typen: Folder, CodeRef und Obsidian.
- Wenn Sie eine Sitzung erstellen, wählen Sie, welche Vaults in ihren Umfang gehören. Markieren Sie einen als bearbeitbar, damit die KI darin schreiben darf; andernfalls dient er nur als schreibgeschützte Referenz.
- **Code Server** bietet einen Bearbeitungszugang im Browser, den Sie direkt aus einem Vault oder Projekt öffnen können.

![Vault-Arbeitsbereich mit registrierten Vault-Karten, System-Vaults und Schaltflächen „Open Code Server“](../img/screenshots/shared/vault-view/original.png)

Mehr dazu: [Vault-Anleitung](/de-DE/user-guide/vault)

### AI Compose Commit

Klicken Sie im Git-Tab auf „AI Compose Commit“, und HagiCode liest Ihre aktuellen Änderungen und schreibt Commit-Nachrichten im Format Conventional Commits.

- Zusammengehörige Änderungen werden in mehrere Commits gruppiert, statt in einen einzigen Sammel-Commit zu fließen.
- In MonoSpecs-Projekten werden die Änderungen im jeweils richtigen Unter-Repository committed.
- Ein Co-Authored-By-Eintrag wird automatisch ergänzt; Name und E-Mail-Adresse lassen sich pro Projekt oder global festlegen.

## Für wen es gedacht ist

- **Gut geeignet:** Entwicklerinnen, Entwickler und Teams, die mehrere Repositories pflegen und komplexe Änderungen vor der Ausführung planen möchten, sowie Personen, die bereits Agent CLIs wie Claude Code oder Codex nutzen und diese in einem Arbeitsbereich vereinen wollen.
- **Nicht zwingend nötig:** Wenn Sie in Ihrem Editor nur ein paar Zeilen ergänzen lassen möchten, genügen Ihre bisherigen Werkzeuge.

## Editionen und Preise

Die Grundfunktionen sind kostenlos. Desktop und Microsoft Store sind zwei verschiedene Bezugswege, keine zwei kostenpflichtigen Stufen. Der Microsoft-Store-Kanal bietet zusätzlich Turbo Engine, einen separaten Einmalkauf, der eine höhere Obergrenze für gleichzeitig laufende Vorschläge und Erweiterungen wie Dokumentationsthemen, individuelle Namensnennung, Branding und benutzerdefinierte Avatar-Uploads freischaltet. Welche Funktionen genau freigeschaltet werden, steht beim [Turbo-Engine-Zusatzpaket](/de-DE/dlc/turbo-engine-dlc/).

| Ihre Umgebung | Empfohlene Option |
| --- | --- |
| Windows mit Zugang zum Microsoft Store | [Über den Microsoft Store installieren](/de-DE/installation/windows-store) |
| Manuelle Windows-Installation oder lokale Nutzung unter macOS oder Linux | [Desktop installieren](/de-DE/installation/desktop) |

Die Steam-Hauptanwendung wurde eingestellt und ist kein Installationsweg mehr. Siehe [Status der Steam-Verteilung](/de-DE/faq/steam-distribution-status/).

## Warum ein Arbeitsbereich?

Ich bin Kun Yu, der Entwickler von HagiCode. Eine einzelne Frage mit Antwort kann ein akutes Problem lösen. Zur tatsächlichen Entwicklung gehören aber auch das Verständnis des Projekts, die Abgrenzung der Aufgabe, die Umsetzung von Änderungen und die Prüfung der Ergebnisse. Ich wollte diese verstreuten Schritte zusammenführen; spielerische Rückmeldungen machen Fortschritte bei längerfristiger Arbeit leichter sichtbar. Sie können auch nur einige dieser Funktionen nutzen. Sie müssen nicht jedes Modul kennen, bevor Sie mit dem Programmieren beginnen.

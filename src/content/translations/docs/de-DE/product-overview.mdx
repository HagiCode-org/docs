HagiCode sorgt dafür, dass die KI beim Ändern Ihres Codes den Kontext nicht verliert: **zuerst das Repository verstehen, den Umfang festlegen, dann nachvollziehbar ausführen.** Es ist ein KI-Arbeitsbereich für die Projektentwicklung, der die Agent CLI und Modelle verbindet, die Sie bereits nutzen, sodass Sie den Editor nicht wechseln müssen.

**[HagiCode installieren](/de-DE/installation/)** · [Demovideo ansehen](#product-video-showcase-en)

Unterstützt 11 Agent CLIs (Claude Code, Codex, GitHub Copilot und weitere) · Läuft unter Windows, macOS und Linux · Grundfunktionen kostenlos

## Ablauf einer Entwicklungsaufgabe

Nehmen wir als Beispiel die Änderung einer Funktion, die mehrere Repositories betrifft:

1. **Zuerst verstehen:** Analysieren Sie den vorhandenen Code in einer [Konversationssitzung](/de-DE/quick-start/conversation-session). Konversationssitzungen sind standardmäßig schreibgeschützt; wechseln Sie erst zum Bearbeitungsmodus, wenn Sie Dateien ändern müssen.
2. **Umfang festlegen:** Wählen Sie bei komplexen Änderungen in einer [Vorschlagssitzung](/de-DE/quick-start/proposal-session) Projekt und Repositories aus. Halten Sie Ziele, Aufgaben und Prüfschritte fest, bevor Sie mit der Ausführung fortfahren.

   ![Schublade „Neuer Vorschlag“ mit Repository-Auswahl und Vorschlagsvorschau](../img/screenshots/shared/create-proposal-drawser/original.png)

3. **Ergebnis verfolgen:** Prüfen Sie Sitzungen und Ausführungsstatus im Arbeitsbereich. Wenn Sie einen Commit vorbereiten möchten, nutzen Sie [AI Compose Commit](/de-DE/guides/ai-compose-commit).

   ![Sitzungsdetails, nachdem ein Vorschlags-Workflow vollständig ausgeführt wurde](../img/screenshots/shared/classic-proposal-view/original.png)

4. **Kontext bewahren:** Vorschläge und Commit-Verlauf lassen sich später erneut einsehen. Nutzen Sie bei repositoryübergreifender Arbeit [MonoSpecs](/de-DE/guides/monospecs), um Beziehungen zwischen Repositories und den Änderungsumfang zu verwalten.

Nicht jede Aufgabe braucht einen Vorschlag. Beginnen Sie mit einer Konversationssitzung, wenn Sie nur den Code erkunden oder ein einfaches Problem lösen möchten. Für Aufgaben, die mehr Kontext erfordern, bietet HagiCode einen nachvollziehbaren Ablauf.

## Für wen es gedacht ist

- **Gut geeignet:** Entwicklerinnen, Entwickler und Teams, die mehrere Repositories pflegen und komplexe Änderungen vor der Ausführung planen möchten, sowie Personen, die bereits Agent CLIs wie Claude Code oder Codex nutzen und diese in einem Arbeitsbereich vereinen wollen.
- **Nicht zwingend nötig:** Wenn Sie in Ihrem Editor nur ein paar Zeilen ergänzen lassen möchten, genügen Ihre bisherigen Werkzeuge.

## Funktionen nach Bedarf entdecken

| Wenn Sie … | Was es ist | Beginnen Sie hier |
| --- | --- | --- |
| Code verstehen möchten, bevor Sie über Änderungen entscheiden | Konversationssitzung: standardmäßig schreibgeschützt, bei Bedarf Wechsel zum Bearbeiten | [Konversationssitzung erstellen](/de-DE/quick-start/conversation-session) |

| Erweiterungen suchen, installieren und verwalten möchten | Skills: Erweiterungen, die Sie suchen und installieren können | [Skills-Anleitung](/de-DE/guides/skills) |
| eine vertraute Agent CLI verwenden möchten | Agent CLI: KI-Werkzeuge für die Kommandozeile wie Claude Code und Codex | [Installation und Unterstützung von AI Agent CLI](/de-DE/related-software-installation/ai-agent-cli/) |

Vault sammelt Referenz-Repositories, Ordner und Notizen zur späteren Wiederverwendung; Code Server bietet einen Bearbeitungszugang im Browser. Beides ist für den Einstieg in HagiCode nicht erforderlich. Hintergründe finden Sie in den Artikeln zur [Arbeit mit der Vault-Wissensdatenbank](/de-DE/blog/2026-04-10-vault-system-ai-knowledge-base/) und zur [Browser-Editor-Integration](/de-DE/blog/2026-04-13-vscode-web-integration-browser-editing/).

## Langfristigen Fortschritt sichtbar machen

HagiCode wandelt Helden, Erfolge, Tagesberichte und Token-Metriken in Rückmeldungen um, damit Status und Fortschritt über längere Zeit leichter sichtbar werden. Das unterscheidet es von gewöhnlichen KI-Coding-Werkzeugen. In der [Einführung in das Abenteuerteam](/de-DE/adventure-team-introduction) sehen Sie, wie Helden gruppiert werden und wie Dungeons voranschreiten; die Überlegungen zum Design finden Sie im [Artikel über das Gamification-Design](/de-DE/blog/2026-03-16-gamifying-ai-coding/). Das gehört zum Erlebnis im Arbeitsbereich, und Sie können HagiCode auch ohne es als gewöhnliches Entwicklungswerkzeug verwenden.

## Editionen und Preise

Die Grundfunktionen sind kostenlos. Desktop und Microsoft Store sind zwei verschiedene Bezugswege, keine zwei kostenpflichtigen Stufen. Der Microsoft-Store-Kanal bietet zusätzlich Turbo Engine, einen separaten Einmalkauf, der eine höhere Obergrenze für gleichzeitig laufende Vorschläge und Erweiterungen wie Dokumentationsthemen, individuelle Namensnennung, Branding und Avatare freischaltet. Welche Funktionen genau freigeschaltet werden, steht beim [Turbo-Engine-Zusatzpaket](/de-DE/dlc/turbo-engine-dlc/).

| Ihre Umgebung | Empfohlene Option |
| --- | --- |
| Windows mit Zugang zum Microsoft Store | [Über den Microsoft Store installieren](/de-DE/installation/windows-store) |
| Manuelle Windows-Installation oder lokale Nutzung unter macOS oder Linux | [Desktop installieren](/de-DE/installation/desktop) |

Die Steam-Hauptanwendung wurde eingestellt und ist kein Installationsweg mehr. Siehe [Status der Steam-Verteilung](/de-DE/faq/steam-distribution-status/).

## Warum ein Arbeitsbereich?

Ich bin Kun Yu, der Entwickler von HagiCode. Eine einzelne Frage mit Antwort kann ein akutes Problem lösen. Zur tatsächlichen Entwicklung gehören aber auch das Verständnis des Projekts, die Abgrenzung der Aufgabe, die Umsetzung von Änderungen und die Prüfung der Ergebnisse. Ich wollte diese verstreuten Schritte zusammenführen; spielerische Rückmeldungen machen Fortschritte bei längerfristiger Arbeit leichter sichtbar. Sie können auch nur einige dieser Funktionen nutzen. Sie müssen nicht jedes Modul kennen, bevor Sie mit dem Programmieren beginnen.

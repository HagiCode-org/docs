Auf dieser Seite erfahren Sie, wie Sie Hagicode mit Docker Compose bereitstellen. Das eignet sich für Server, NAS, die gemeinsame Nutzung im Team oder Szenarien, in denen Umgebungsisolierung gefragt ist. Für die persönliche lokale Nutzung sollten Sie zuerst den [Microsoft Store](/de-DE/installation/windows-store) oder [Desktop](/de-DE/installation/desktop) in Betracht ziehen.

:::tip[Warum Docker Compose]
- Umgebungsisolierung, weniger Abhängigkeitskonflikte
- Der aktuell unterstützte Hagicode-Dienststack lässt sich auf einmal starten
- Einheitlicher Weg für Konfiguration, Upgrades und Wartung
- Auf dem Host wird nur Docker benötigt, **Node.js oder Git müssen nicht zusätzlich installiert werden**
:::

:::note[Zur standardmäßigen Datenspeicherung]
Die derzeit unterstützten Docker Compose-Vorlagen organisieren persistente Daten über den standardmäßigen lokalen SQLite-Datenpfad. In den meisten Fällen müssen Sie auf dem Host keinen separaten Datenbankdienst bereitstellen.
:::

## Voraussetzungen

Stellen Sie vor dem Start sicher, dass auf Ihrem System Docker und Docker Compose installiert sind.

### Docker installieren

#### Windows

Laden Sie [Docker Desktop für Windows](https://www.docker.com/products/docker-desktop/) herunter und installieren Sie es. Stellen Sie nach der Installation sicher, dass Docker Desktop ausgeführt wird.

#### macOS

Laden Sie [Docker Desktop für Mac](https://www.docker.com/products/docker-desktop/) herunter und installieren Sie es. Stellen Sie nach der Installation sicher, dass Docker Desktop ausgeführt wird.

#### Linux

Installieren Sie Docker Engine und das Docker Compose-Plugin für Ihre Distribution gemäß der offiziellen Docker-Dokumentation: [Install Docker Engine](https://docs.docker.com/engine/install/). Paketquellen und Paketnamen unterscheiden sich je nach Distribution; übernehmen Sie daher keine Befehle einer anderen Distribution unverändert.

Starten Sie nach der Installation den Docker-Dienst und richten Sie ein, dass er beim Systemstart gestartet wird:

```bash
sudo systemctl start docker
sudo systemctl enable docker
```

### Installation überprüfen

Führen Sie nach der Installation die folgenden Befehle aus, um zu überprüfen, ob Docker und Docker Compose korrekt installiert sind:

```bash
docker --version
docker compose version
```

## Schnellstart

### 1. Docker Compose-Konfigurationsdatei generieren

Verwenden Sie den [Docker Compose Builder](https://builder.hagicode.com/), um die Datei `docker-compose.yml` zu generieren. Er ist eine eigenständige Website; maßgeblich für Generierungsregeln und Updates ist diese Site.

Der Generator unterstützt:
- Auswahl des API-Anbieters (Zhipu AI, Anthropic offiziell, benutzerdefinierte API) sowie Konfiguration von API-URL und Token
- Anpassung von Port, Containername, Persistenzverzeichnis und Arbeitsverzeichnis
- Wahl zwischen integrierter und externer Datenbank
- Automatische Behandlung von Plattformunterschieden zwischen Windows und Linux sowie typischer Dateiberechtigungsprobleme
- Verwendung unterstützter Docker-Hub-Images

Vorgehensweise:

1. Öffnen Sie den [Docker Compose Builder](https://builder.hagicode.com/).
2. Füllen Sie die Konfiguration nach Ihren Anforderungen aus: Wählen Sie einen API-Anbieter und konfigurieren Sie Optionen wie Port, Datenbank und Arbeitsverzeichnis.
3. Klicken Sie auf die Schaltfläche „Generieren“, um die Konfiguration für `docker-compose.yml` zu erhalten.
4. Speichern Sie die generierte Konfiguration als Datei `docker-compose.yml`.
5. Erstellen Sie bei Bedarf eine `.env`-Datei für vertrauliche Angaben, damit Sie das Token nicht direkt in die Compose-Datei schreiben.

#### Image-Quelle

Der Generator verwendet Docker Hub als unterstützte Image-Quelle:

- **Image-Adresse**: `newbe36524/hagicode:{tag}`
- **Anwendbare Szenarien**: Geeignet für Benutzer, die die Image-Beschleunigung von Docker Hub nutzen
- **Hinweis**: In manchen Regionen muss möglicherweise ein Registry-Mirror zur Beschleunigung konfiguriert werden

:::note[API-Token abrufen]
Die Docker-Bereitstellung greift über den im Generator konfigurierten API-Anbieter auf Modelle zu. Sie müssen daher zuerst ein gültiges API-Token bereitstellen:

**Zhipu AI**: [API-Token abrufen →](https://www.bigmodel.cn/glm-coding?ic=14BY54APZA)
- Stabiler Zugriff in China, schnellere Antworten
- Gutes Preis-Leistungs-Verhältnis, geeignet für den Alltag

**Anthropic offiziell**: [API-Token abrufen →](https://console.anthropic.com/)
- Direkte Nutzung der Dienste von Anthropic

Im Generator können Sie auch eine benutzerdefinierte API wählen.
:::

### 2. Dienste starten

Führen Sie im Verzeichnis, in dem sich Ihre Datei `docker-compose.yml` befindet, den folgenden Befehl aus:

```bash
docker compose up -d
```

Dieser Befehl:
- lädt die in der generierten Konfiguration definierten Hagicode-Container herunter und startet sie
- erstellt und konfiguriert das Netzwerk
- initialisiert das Standarddatenverzeichnis und die Laufzeitabhängigkeiten

### 3. Dienststatus überprüfen

Prüfen Sie, ob die Container laufen:

```bash
docker compose ps
```

Die in der generierten Konfiguration definierten Dienste sollten den Status „running“ haben.

Dienstprotokolle anzeigen:

```bash
# Protokolle aller Dienste anzeigen
docker compose logs

# Protokolle des Hagicode-Dienstes anzeigen
docker compose logs hagicode

# Protokolle in Echtzeit verfolgen
docker compose logs -f hagicode
```

## Anwendung aufrufen

Rufen Sie nach erfolgreichem Start des Dienstes die Anwendung im Browser auf:

```
http://localhost:45000
```

Wenn Sie im Generator den Port geändert haben, verwenden Sie den von Ihnen festgelegten Host-Port. Beim ersten Öffnen erscheint der Initialisierungsassistent; lesen Sie dazu weiter unter [Assistent zum Einrichten](/de-DE/quick-start/wizard-setup).

## Konfigurationsanweisungen

Wenn Sie die Konfiguration ändern möchten (zum Beispiel den Port ändern oder den API-Anbieter wechseln), haben Sie folgende Möglichkeiten:

1. Erzeugen Sie mit dem [Docker Compose Builder](https://builder.hagicode.com/) eine neue Konfiguration
2. Bearbeiten Sie die Dateien `docker-compose.yml` und `.env` manuell
3. Erstellen Sie die Container neu, damit die Konfiguration wirksam wird:

```bash
docker compose up -d
```

:::note
`docker compose restart` startet nur die vorhandenen Container neu und übernimmt keine Änderungen an `docker-compose.yml` oder `.env`. Verwenden Sie nach Konfigurationsänderungen `docker compose up -d`.
:::

## Datenpersistenz

Der aktuell unterstützte Docker Compose-Pfad verwendet standardmäßig SQLite-Datendateien und persistente Volumes. Wenn Sie die Einbindungspunkte der Daten oder eine Backup-Strategie prüfen möchten, sehen Sie sich direkt die Volume- und Datenverzeichnis-Zuordnungen in der generierten Datei `docker-compose.yml` an.

## Laufende Wartung

### Stoppen und starten

```bash
# Dienste stoppen (Container und Daten bleiben erhalten)
docker compose stop

# Erneut starten
docker compose start

# Stoppen und Container entfernen (Datenvolumes bleiben erhalten)
docker compose down
```

:::caution
Hängen Sie nicht leichtfertig `-v` an `docker compose down` an. Die Option löscht zugleich die in der Compose-Datei deklarierten Datenvolumes.
:::

### Version aktualisieren

1. Sichern Sie vor dem Upgrade das Datenverzeichnis (siehe unten).
2. Ändern Sie in `docker-compose.yml` das Image-Tag `newbe36524/hagicode:{tag}` auf die gewünschte Version oder erzeugen Sie die Konfiguration mit dem Generator neu.
3. Laden Sie das neue Image herunter und erstellen Sie die Container neu:

```bash
docker compose pull
docker compose up -d
```

### Daten sichern

Führen Sie zuerst `docker compose stop` aus, damit der Dienst keine Daten mehr schreibt. Sichern Sie dann die Verzeichnisse oder Datenvolumes, auf die die Volume- und Datenverzeichnis-Zuordnungen in `docker-compose.yml` verweisen, und stellen Sie den Dienst anschließend mit `docker compose start` wieder her.

Auf dieser Seite erfahren Sie, wie Sie Node.js unter Windows, macOS und Linux installieren. Desktop und die Microsoft Store-Version enthalten kein Node.js mehr; sie verwenden direkt `node` und `npm` aus Ihrem System. Auch OpenSpec und die meisten Agent CLIs sind darauf angewiesen.

:::tip[Versionsanforderung]
Erforderlich ist **Node.js 24 oder höher**; auch die Mindestanforderung ist 24. In der Regel genügt es, einfach die neueste LTS-Version zu installieren. `npm` wird zusammen mit Node.js installiert und muss nicht separat installiert werden.
:::

:::note[Welche Installationsmethoden es benötigen]
- **Microsoft Store / Desktop**: Erforderlich, und `node` sowie `npm` müssen im System-`PATH` auffindbar sein.
:::

## Node.js installieren

<Tabs>
  <TabItem value="windows" label="Windows" default>

### Methode eins: Offizieller Installer (empfohlen)

1. Besuchen Sie die [offizielle Website von Node.js](https://nodejs.org/)
2. Laden Sie das Windows-Installationsprogramm der Version **LTS (Long Term Support)** herunter (`.msi`-Datei) und stellen Sie sicher, dass die Versionsnummer mindestens 24 ist
3. Doppelklicken Sie, um das Installationsprogramm auszuführen
4. Befolgen Sie die Anweisungen des Installationsassistenten, um die Installation abzuschließen:
   - Akzeptieren Sie die Lizenzvereinbarung
   - Wählen Sie den Installationspfad (die Standardeinstellung genügt)
   - Lassen Sie die Option „Add to PATH“ aktiviert
   - Klicken Sie auf „Install“, um die Installation zu starten
5. Klicken Sie nach Abschluss der Installation auf „Finish“

### Methode zwei: winget verwenden

Öffnen Sie PowerShell oder die Eingabeaufforderung und führen Sie den folgenden Befehl aus:

```powershell
winget install OpenJS.NodeJS.LTS
```

Öffnen Sie nach der Installation das Terminal erneut, damit die Änderungen wirksam werden.

  </TabItem>
  <TabItem value="macos" label="macOS">

### Methode eins: Offizieller Installer (empfohlen)

1. Besuchen Sie die [offizielle Website von Node.js](https://nodejs.org/)
2. Laden Sie das macOS-Installationsprogramm der Version **LTS (Long Term Support)** herunter (`.pkg`-Datei) und stellen Sie sicher, dass die Versionsnummer mindestens 24 ist
3. Doppelklicken Sie, um das Installationsprogramm auszuführen
4. Befolgen Sie die Anweisungen des Installationsassistenten, um die Installation abzuschließen:
   - Klicken Sie auf „Fortfahren“
   - Akzeptieren Sie die Lizenzvereinbarung
   - Wählen Sie das Installationsvolume
   - Klicken Sie auf „Installieren“ und geben Sie das Administratorkennwort ein
5. Klicken Sie nach Abschluss der Installation auf „Schließen“

### Methode zwei: Homebrew verwenden

Wenn Sie [Homebrew](https://brew.sh/) bereits installiert haben, können Sie Node.js über das Terminal installieren:

```bash
brew install node
```

:::tip
Homebrew fügt Node.js automatisch zu Ihrem PATH hinzu. Wenn der Befehl nicht verfügbar ist, starten Sie das Terminal neu oder führen Sie Folgendes aus:
```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```
:::

  </TabItem>
  <TabItem value="ubuntu" label="Ubuntu/Debian">

### NodeSource-Repository verwenden (empfohlen)

Das Node.js in den Standard-Repositories der Distribution ist meist älter als 24. Verwenden Sie daher das 24.x-Repository von NodeSource:

```bash
# Installationsskript mit curl herunterladen
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs
```

:::caution
Installieren Sie nicht mit `sudo apt-get install nodejs npm` die mit der Distribution gelieferte Version. Sie erfüllt die Mindestanforderung 24 mit hoher Wahrscheinlichkeit nicht.
:::

Wenn Sie keine Paketquelle eines Drittanbieters hinzufügen möchten, können Sie auch [nvm oder fnm](#versionsverwaltungstools-verwenden) verwenden (siehe unten).

  </TabItem>
  <TabItem value="centos" label="CentOS/RHEL">

### NodeSource-Repository verwenden (empfohlen)

```bash
# Installationsskript mit curl herunterladen
curl -fsSL https://rpm.nodesource.com/setup_24.x | sudo bash -
sudo yum install -y nodejs
```

Das Node.js in den Standard-Repositories der Distribution ist meist älter als 24 und wird daher nicht zur direkten Verwendung empfohlen. Sie können stattdessen auch [nvm oder fnm](#versionsverwaltungstools-verwenden) verwenden (siehe unten).

  </TabItem>
  <TabItem value="fedora" label="Fedora">

### dnf-Paketmanager verwenden

```bash
sudo dnf install -y nodejs npm
```

Führen Sie nach der Installation `node --version` aus und bestätigen Sie, dass die Version mindestens 24 ist. Ist die Version im Repository älter, verwenden Sie stattdessen das 24.x-Repository von NodeSource oder [nvm oder fnm](#versionsverwaltungstools-verwenden) (siehe unten).

  </TabItem>
</Tabs>

## Versionsverwaltungstools verwenden

Wenn Sie zwischen mehreren Node.js-Versionen wechseln müssen, können Sie Versionsverwaltungstools verwenden.

:::caution[Hinweis für Desktop-Nutzer]
Unter macOS und Linux setzen Tools wie nvm und fnm den `PATH` in der Regel nur in Shell-Konfigurationsdateien (etwa `.bashrc`, `.zshrc`). Ein Desktop, das über das Dock, das Anwendungsmenü oder ein Desktop-Symbol gestartet wird, liest diese Konfiguration nicht und findet `node` möglicherweise nicht. Wenn Sie ein Versionsverwaltungstool verwenden, starten Sie Desktop aus einem Terminal, in dem `node` bereits funktioniert, oder verwenden Sie stattdessen die oben beschriebene systemweite Installation.
:::

### nvm (Node Version Manager)

<Tabs>
  <TabItem value="nvm-install" label="nvm installieren" default>

#### Linux/macOS

Kopieren Sie bitte direkt den aktuellen Installationsbefehl aus der [README des offiziellen nvm-Repositorys](https://github.com/nvm-sh/nvm#installing-and-updating) und verwenden Sie keine veralteten Adressen von Installationsskripten.

Laden Sie nach der Installation Ihre Shell-Konfiguration neu:

```bash
source ~/.bashrc
# Oder für Zsh-Nutzer
source ~/.zshrc
```

#### Windows

Unter Windows empfehlen wir [nvm-windows](https://github.com/coreybutler/nvm-windows):

1. Laden Sie die neueste `nvm-setup.exe` von den [nvm-windows-Releases](https://github.com/coreybutler/nvm-windows/releases) herunter
2. Führen Sie das Installationsprogramm aus
3. Öffnen Sie die Eingabeaufforderung oder PowerShell erneut

  </TabItem>
  <TabItem value="nvm-use" label="nvm verwenden">

Nach der Installation von nvm können Sie damit Node.js-Versionen installieren und verwalten:

```bash
# Node.js 24 installieren
nvm install 24

# Zu Node.js 24 wechseln
nvm use 24

# Standardversion festlegen
nvm alias default 24

# Installierte Versionen auflisten
nvm list
```

Der Befehl `alias` von nvm-windows ist nicht verfügbar; verwenden Sie `nvm install 24` und `nvm use 24`.

  </TabItem>
</Tabs>

### fnm (Fast Node Manager)

fnm ist ein schnelleres und einfacheres Node.js-Versionsverwaltungstool, das mit Rust erstellt wurde.

<Tabs>
  <TabItem value="fnm-install" label="fnm installieren" default>

#### Linux/macOS

```bash
# Mit curl installieren
curl -fsSL https://fnm.vercel.app/install | bash

# Nach der Installation die Shell-Konfiguration neu laden
source ~/.bashrc
# Oder für Zsh-Nutzer
source ~/.zshrc
```

#### Windows

Verwenden Sie [scoop](https://scoop.sh/) oder [winget](https://learn.microsoft.com/en-us/windows/package-manager/winget/):

```powershell
# Mit scoop
scoop install fnm

# Oder mit winget
winget install Schniz.fnm
```

  </TabItem>
  <TabItem value="fnm-use" label="fnm verwenden">

```bash
# Node.js 24 installieren
fnm install 24

# Zu Node.js 24 wechseln
fnm use 24

# Standardversion festlegen
fnm default 24

# Installierte Versionen auflisten
fnm list
```

  </TabItem>
</Tabs>

## Beschleunigung für Benutzer auf dem chinesischen Festland

Wenn Sie sich auf dem chinesischen Festland befinden, kann das Herunterladen von Node.js- und npm-Paketen langsam sein. Sie können dann inländische Mirrors verwenden.

### npm-Mirror

```bash
# Mirror vorübergehend für die Installation verwenden
npm install --registry=https://registry.npmmirror.com

# Mirror dauerhaft festlegen
npm config set registry https://registry.npmmirror.com

# Prüfen, ob der Mirror erfolgreich festgelegt wurde
npm config get registry
```

### Mirror für Node.js-Installationspakete

Auch für Node.js-Installationspakete gibt es eine Mirror-Download-Adresse: [https://npmmirror.com/mirrors/node/](https://npmmirror.com/mirrors/node/). Wählen Sie dort zum Herunterladen eine Version ab 24.

### Homebrew-Mirror

Wenn Sie Homebrew auf dem chinesischen Festland verwenden, können Sie für Bottles den Mirror der USTC konfigurieren:

```bash
export HOMEBREW_BOTTLE_DOMAIN=https://mirrors.ustc.edu.cn/homebrew-bottles
```

## Installation überprüfen

Prüfen Sie nach der Installation in einem **neu geöffneten Terminal**, ob Node.js und npm verfügbar sind:

```bash
# Node.js-Version prüfen, erforderlich ist v24.0.0 oder höher
node --version

# npm-Version prüfen
npm --version
```

Die Ausgabe einer erfolgreichen Überprüfung sollte etwa so aussehen:

```
$ node --version
v24.3.0

$ npm --version
11.4.2
```

:::note
Wenn `node --version` eine Version unter 24 anzeigt, installieren Sie Node.js gemäß den obigen Methoden neu oder wechseln Sie mit einem Versionsverwaltungstool auf Version 24 oder höher.
:::

## Globales npm-Verzeichnis konfigurieren

Desktop installiert verwaltete Pakete wie Agent CLIs in das globale npm-Verzeichnis Ihres Rechners. Liegt das globale Verzeichnis an einem Ort, der Administratorrechte erfordert, kann bei der Installation der Berechtigungsfehler `EACCES` auftreten. Statt die Berechtigungen von Systemverzeichnissen zu ändern, empfiehlt es sich, das globale Verzeichnis in das Benutzerverzeichnis zu verlegen:

```bash
mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
```

Fügen Sie anschließend `~/.npm-global/bin` (unter Windows das globale npm-Verzeichnis selbst) zum System-`PATH` hinzu und starten Sie Terminal und Desktop neu. Bei Verwendung von nvm oder fnm liegt das globale Verzeichnis bereits im Benutzerverzeichnis; dieser Schritt ist dann nicht nötig.

## Fehlerbehebung

### Windows-Probleme

<Tabs>
  <TabItem value="win-path" label="Befehl nicht verfügbar">

Wenn die Befehle `node` oder `npm` nach der Installation nicht verfügbar sind:

1. Starten Sie die Eingabeaufforderung oder PowerShell neu
2. Wenn sie weiterhin nicht verfügbar sind, fügen Sie Node.js manuell zum PATH hinzu:
   - Suchen Sie nach „Umgebungsvariablen“ und öffnen Sie „Systemumgebungsvariablen bearbeiten“
   - Klicken Sie auf „Umgebungsvariablen“
   - Suchen Sie unter „Systemvariablen“ nach „Path“ und klicken Sie auf „Bearbeiten“
   - Fügen Sie den Installationspfad von Node.js hinzu (Standard: `C:\Program Files\nodejs\`)
   - Klicken Sie auf „OK“, um die Änderungen zu speichern
3. Beenden Sie Desktop vollständig und starten Sie es neu

  </TabItem>
  <TabItem value="win-policy" label="PowerShell-Ausführungsrichtlinie">

Wenn bei der Verwendung von nvm- oder npm-Skripten Fehler wegen der Ausführungsrichtlinie auftreten:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

  </TabItem>
</Tabs>

### macOS-Probleme

<Tabs>
  <TabItem value="mac-perm" label="Berechtigungsfehler">

Wenn bei der Installation globaler npm-Pakete Berechtigungsfehler auftreten, lesen Sie den Abschnitt [Globales npm-Verzeichnis konfigurieren](#globales-npm-verzeichnis-konfigurieren) oben oder verwenden Sie stattdessen nvm / fnm.

  </TabItem>
  <TabItem value="mac-path" label="Befehl nicht verfügbar">

Wenn der Befehl nach der Installation nicht verfügbar ist, starten Sie das Terminal neu und stellen Sie sicher, dass das Verzeichnis von Node.js (meist `/usr/local/bin` oder `/opt/homebrew/bin`) im `PATH` enthalten ist.

  </TabItem>
</Tabs>

### Linux-Probleme

<Tabs>
  <TabItem value="linux-perm" label="Berechtigungsfehler">

Wenn bei der Installation globaler npm-Pakete Berechtigungsfehler auftreten, lesen Sie den Abschnitt [Globales npm-Verzeichnis konfigurieren](#globales-npm-verzeichnis-konfigurieren) oben oder verwenden Sie nvm / fnm, anstatt globale Pakete mit `sudo` zu installieren.

  </TabItem>
  <TabItem value="linux-old" label="Version zu alt">

Wenn die über den System-Paketmanager installierte Node.js-Version älter als 24 ist:

1. Verwenden Sie das 24.x-Repository von NodeSource (siehe oben)
2. Oder verwenden Sie Versionsverwaltungstools (nvm / fnm)

  </TabItem>
</Tabs>

### Umgebung prüfen

Wenn die Überprüfung fehlschlägt, kontrollieren Sie Folgendes:

<Tabs>
  <TabItem value="win-check" label="Windows">

```powershell
# Prüfen, ob Node.js im PATH enthalten ist
where node

# Installationspfad prüfen
Get-Command node
```

  </TabItem>
  <TabItem value="mac-check" label="macOS">

```bash
# Prüfen, ob Node.js im PATH enthalten ist
which node

# Installationspfad prüfen
ls -l $(which node)
```

  </TabItem>
  <TabItem value="linux-check" label="Linux">

```bash
# Prüfen, ob Node.js im PATH enthalten ist
which node

# Installationspfad prüfen
ls -l $(which node)
```

  </TabItem>
</Tabs>

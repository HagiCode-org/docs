Spec Kit ist GitHubs Open-Source-Toolkit für Spec-Driven Development: Zuerst schreiben Sie die Spezifikation, dann einen Plan und Aufgaben, und zuletzt lassen Sie Ihren KI-Coding-Assistenten die Aufgaben umsetzen. Die Kommandozeile heißt `specify` und stammt aus dem Paket `specify-cli`.

Viele Anleitungen im Netz verwenden noch den alten Installationsbefehl, das Flag `--ai` und Befehlsnamen wie `/speckit.specify`, und beim Abtippen schlägt das oft fehl. Diese Seite zeigt anhand der offiziellen Dokumentation den aktuell richtigen Weg und listet auf, was sich geändert hat.

:::note[Stand der Prüfung]
Verfasst nach der [offiziellen Spec-Kit-Dokumentation](https://github.github.com/spec-kit/), geprüft am 26.10.2026. Das Projekt entwickelt sich schnell. Wenn etwas abweicht, gelten `specify --help` auf Ihrem Rechner und die offizielle Dokumentation vor dieser Seite.
:::

## Für wen diese Anleitung ist

- Für alle, die einen spezifikationsgetriebenen Ablauf in einem KI-Coding-Assistenten wie Claude Code, GitHub Copilot, Gemini CLI, CodeBuddy CLI, Pi oder Oh My Pi ausprobieren möchten.
- Für alle, die Spec Kit nach einer älteren Anleitung installiert haben und jetzt Fehler oder fehlende Befehle sehen.

## Voraussetzungen

| Punkt | Anforderung |
| --- | --- |
| Betriebssystem | Linux, macOS oder Windows (PowerShell-Skripte funktionieren ohne WSL) |
| Python | 3.11 oder höher |
| Paketmanager | uv (empfohlen) oder pipx |
| KI-Coding-Assistent | Ein beliebiger unterstützter Assistent; die offizielle Dokumentation listet Dutzende Integrationen |
| Git | Optional, nur nötig, wenn die Git-Erweiterung aktiviert ist |

Spec Kit selbst benötigt kein Node.js. Wenn Ihr Assistent über npm installiert wird, lesen Sie zuerst die [Installation von AI Agent CLI](/de-DE/related-software-installation/ai-agent-cli/).

## specify-cli installieren

### Variante 1: Von PyPI (am kürzesten)

```bash
# Empfohlen: uv
uv tool install specify-cli

# Oder pipx
pipx install specify-cli

# Oder pip
pip install specify-cli
```

Um eine Version festzulegen: `uv tool install specify-cli==0.12.11` (nehmen Sie die Version von der Releases-Seite).

### Variante 2: Aus einem GitHub-Release-Tag

Die offizielle Dokumentation nennt dies den empfohlenen reproduzierbaren Weg. Er benötigt uv:

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@vX.Y.Z
```

Ersetzen Sie `vX.Y.Z` durch einen Tag aus den [Releases](https://github.com/github/spec-kit/releases). **Das führende `v` muss bleiben**, zum Beispiel `v0.12.11`.

### Installation prüfen

```bash
specify version
specify self check
```

`specify version` bestätigt, dass der Befehl funktioniert, und gibt die Version aus. `specify self check` ist schreibgeschützt und zeigt, ob es ein neueres Release gibt.

## Projekt initialisieren

```bash
specify init my-project --integration claude
cd my-project
```

`--integration` wählt Ihren KI-Assistenten. Gängige Werte sind `claude`, `copilot`, `gemini`, `codebuddy`, `pi` und `omp`. Nützliche Optionen:

- `--script sh|ps|py`: wählt den Skripttyp. Standard ist `ps` unter Windows und `sh` sonst.
- `--here --force`: initialisiert in einem vorhandenen, nicht leeren Verzeichnis. `--force` bestätigt die Warnung zum Zusammenführen, committen oder sichern Sie lokale Änderungen daher vorher.
- `--non-interactive`: für CI. **Ohne `--integration` wird standardmäßig GitHub Copilot gewählt**, lassen Sie sich von diesem Standard nicht überraschen.

## Befehlsnamen: `/speckit-*`

Führen Sie nach der Initialisierung diese Befehle im Chat Ihres KI-Assistenten aus, nicht im Terminal:

| Schritt | Befehl | Was er tut |
| --- | --- | --- |
| 1 | `/speckit-constitution` | Schreibt die Projektprinzipien, gegen die spätere Schritte geprüft werden; einmal pro Projekt |
| 2 | `/speckit-specify` | Macht aus einer Beschreibung des Features in normaler Sprache die `spec.md` |
| 3 | `/speckit-clarify` | Fragt nach Lücken in der Spezifikation und arbeitet die Antworten ein |
| 4 | `/speckit-plan` | Erzeugt `plan.md` und weitere Entwurfsartefakte für Ihren Tech-Stack |
| 5 | `/speckit-checklist` | Erzeugt eine Checkliste zur Qualität der Anforderungen |
| 6 | `/speckit-tasks` | Erzeugt eine nach Abhängigkeiten geordnete `tasks.md` |
| 7 | `/speckit-analyze` | Schreibgeschützte Prüfung auf Widersprüche und Lücken zwischen `spec.md`, `plan.md` und `tasks.md` |
| 8 | `/speckit-implement` | Führt `tasks.md` der Reihe nach aus |
| 9 | `/speckit-converge` | Prüft den Code gegen die Spezifikation und hängt für Lücken Aufgaben an; wiederholen Sie implement und converge, bis `Converged` gemeldet wird |

Der kürzeste Weg ist specify → plan → tasks → implement → converge. Erst der vollständige Weg ergänzt constitution, clarify, checklist und analyze.

:::caution[Ihr Assistent schreibt sie möglicherweise anders]
Der offizielle Schnellstart verwendet die Namen mit Bindestrich `/speckit-*` (der Standard-Skills-Modus von GitHub Copilot). Ältere Anleitungen und die Upgrade-Hinweise zeigen noch die Schreibweise mit Punkt, etwa `/speckit.specify`. Das Aufrufformat unterscheidet sich je nach Assistent und Modus. Maßgeblich sind daher die Namen, die nach der Initialisierung tatsächlich in der Befehlsliste Ihres Assistenten erscheinen.
:::

## Was sich gegenüber älteren Anleitungen geändert hat

| In älteren Anleitungen üblich | Jetzt |
| --- | --- |
| Nur `uv tool install ... --from git+https://...` | `specify-cli` gibt es auch auf PyPI, installierbar mit uv, pipx oder pip; die Installation aus einem GitHub-Tag wird weiterhin unterstützt |
| `specify init --ai claude` | Die offizielle Dokumentation verwendet durchgehend `--integration claude` |
| `/speckit.specify`, `/speckit.plan` | Der Schnellstart nutzt `/speckit-specify` und `/speckit-plan` und ergänzt `/speckit-converge` |
| `/constitution` überträgt Änderungen in Vorlagen und Befehlsdateien | Aktualisiert jetzt nur noch `.specify/memory/constitution.md`; um die alte Weitergabe wiederherzustellen, führen Sie `specify preset add constitution-sync` aus |
| Git-Funktionen immer aktiv | Jetzt eine optionale Erweiterung: `specify extension add git` |
| Das aktive Feature wird aus dem Git-Branch abgeleitet | `.specify/feature.json` hält das aktive Feature-Verzeichnis fest |

## Upgrade

Die Kommandozeile selbst aktualisieren:

```bash
specify self check                 # schreibgeschützt: gibt es ein neueres Release?
specify self upgrade --dry-run     # Vorschau ohne Upgrade
specify self upgrade               # auf das neueste stabile Release aktualisieren
specify self upgrade --tag vX.Y.Z  # einen Release-Tag festlegen
```

Die Dateien in einem bestehenden Projekt aktualisieren, im Projektverzeichnis:

```bash
specify integration status         # installierte Integrationen und geänderte Dateien auflisten
specify integration upgrade <key>  # einmal pro installierter Integration ausführen
specify extension update           # alle Erweiterungen aktualisieren
```

Übergeben Sie `--force` an `specify integration upgrade` nur, wenn der Befehl lokal geänderte verwaltete Dateien meldet und Sie den Unterschied geprüft haben.

## Häufige Probleme

- **`command not found: uv`**: Installieren Sie zuerst uv und führen Sie den Installationsbefehl dann erneut aus.
- **`No such option: --integration`**: Ein altes `specify` (zum Beispiel 0.1.6) steht weiter vorn in Ihrem `PATH`. Installieren Sie mit demselben Werkzeug neu, das Sie ursprünglich benutzt haben, etwa `uv tool install --force specify-cli`, und bestätigen Sie mit `specify version`.
- **Zwei Kopien installiert**: Jede Installation mit uv, pipx und pip hinterlässt eine eigene Kopie. Aktualisieren Sie mit demselben Werkzeug und mischen Sie sie nicht.
- **Eine PyPI-Installation aktualisiert sich nicht selbst**: Die Version bleibt, wie sie installiert wurde, nutzen Sie also die obigen Upgrade-Befehle.
- **Init lehnt ein vorhandenes Verzeichnis ab**: Fügen Sie nach dem Committen oder Sichern `--here --force` hinzu.

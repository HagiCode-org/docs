Unabhängig davon, ob Sie HagiCode über den [Microsoft Store](/de-DE/installation/windows-store), [Desktop](/de-DE/installation/desktop) oder [Docker Compose](/de-DE/installation/docker-compose) installiert haben: Beim ersten Öffnen der HagiCode-Weboberfläche gelangen Sie in den **Initialisierungsassistenten**. Danach verfügen Sie über einen nutzbaren Standard-Hagicoder und mindestens ein Projekt und können direkt Ihre erste Sitzung starten.

:::note[Nicht zu verwechseln mit der Ersteinrichtung von Desktop]
Die „Erstmalige Einrichtung“ beim ersten Start von Desktop (Sprache auswählen, rechtliche Dokumente bestätigen, Hagicode Server herunterladen) findet statt, bevor die Weboberfläche erscheint; siehe [Desktop-Installation](/de-DE/installation/desktop#ersteinrichtung-beim-ersten-start). Diese Seite beschreibt den Initialisierungsassistenten, der danach in der Weboberfläche erscheint.
:::

## Bevor Sie beginnen

Bitte stellen Sie zuerst Folgendes sicher:

- **Mindestens eine Agent CLI ist installiert und angemeldet**. Der Assistent listet nur CLIs auf, die auf dem Rechner erkannt wurden, auf dem Hagicode Server läuft. Wird keine erkannt, können Sie keinen Hagicoder erstellen. Unterstützte CLIs und Installationswege finden Sie unter [AI Agent CLI-Installation](/de-DE/related-software-installation/ai-agent-cli/).
- **Desktop-/Store-Nutzer**: Node.js 24+ und Git sind gemäß der [Installationsanleitung](/de-DE/installation/#vorbereitung-vor-der-installation) installiert.
- **Docker-Nutzer**: API-Anbieter und Token sind im Docker Compose Builder konfiguriert.
- Halten Sie ein lokales Repository oder Arbeitsverzeichnis bereit, das Sie anbinden möchten: In Schritt 3 registrieren Sie es.

## Überblick über den Assistenten

Der Assistent besteht aus 4 Schritten; die linke Navigation zeigt den aktuellen Fortschritt:

| Schritt | Ziel | Abschlusskriterium |
| --- | --- | --- |
| 1. Grundeinrichtung | Oberflächensprache und Thema wählen | Klick auf „Weiter: Hagicoder einrichten“ |
| 2. Hagicoder einrichten | CLI und Modell wählen, Standard-Hagicoder erstellen | Klick auf „Bestätigen und Hagicoder erstellen“ oder bereits ein nutzbarer Agent vorhanden |
| 3. Projekt erstellen | Mindestens ein Projekt erstellen | Der Projektschritt zeigt „Projektschritt abgeschlossen“ an |
| 4. Community-Leitfaden | Community-Einstiegspunkte kennenlernen | Klick auf „Beginnen Sie mit der Verwendung von HagiCode“ |

## Schritt 1: Grundeinrichtung

**Ziel**: Oberflächensprache und Thema festlegen.

1. Wählen Sie unter „Oberflächensprache wählen“ eine Sprache. Dadurch ändert sich nur der Oberflächentext, nicht der Sprachstil des Hagicoders.
2. Wählen Sie unter „Thema wählen“ ein Thema. Derzeit stehen „Frühlingshell“ und „Frühlingsdunkel“ zur Verfügung.
3. Klicken Sie auf „Weiter: Hagicoder einrichten“.

## Schritt 2: Hagicoder einrichten

**Ziel**: Den Standard-Agenten erstellen; sein Name ist fest **Hagicoder**.

Wenn im System bereits ein Agent vorhanden ist, zeigt dieser Schritt „Vorhandene Agenten gefunden“ an; Sie können die vorhandene Aufstellung einfach weiterverwenden. Andernfalls gehen Sie so vor:

1. **Haupt-AgentCLI auswählen**: Die Dropdown-Liste zeigt nur CLIs, die auf diesem Rechner erkannt wurden. Wenn gemeldet wird, dass noch keine nutzbare CLI erkannt wurde, installieren Sie sie zuerst gemäß [AI Agent CLI-Installation](/de-DE/related-software-installation/ai-agent-cli/), melden Sie sich an und aktualisieren Sie dann die Ansicht.
2. **Haupt-Modell auswählen**:
   - **Vorhandene Vorlage auswählen**: Verwendet vorhandene Modellvorlagen dieser CLI erneut; Sie können nach Name oder Modell-ID suchen.
   - **Benutzerdefiniertes Modell eingeben**: Geben Sie den Modellnamen manuell ein, zum Beispiel `gpt-5.5`, `glm-5.1` oder `claude-opus-4-7`. Beim Erstellen wird die passende Vorlage automatisch wiederverwendet oder neu angelegt.
3. **(Optional) Klicken Sie auf „Verfügbarkeit testen“**: Sendet eine Ping-Pong-Prüfung an die gewählte CLI und das gewählte Modell und bestätigt, dass das Modell `pong` zurückgibt. Das Testergebnis gilt nur für die aktuelle Kombination aus CLI und Modell; nach einer Änderung muss erneut getestet werden. Zum Erstellen des Hagicoders muss der Test nicht bestanden sein.
4. **(Optional) Klicken Sie auf „Mischen“**, um das Standardaussehen zu ändern; das Porträt wird zufällig aus der Bildgalerie gezogen.
5. Klicken Sie auf „Bestätigen und Hagicoder erstellen“. Nach erfolgreicher Erstellung wird er dem Notfallteam hinzugefügt, und die gewählte CLI sowie das gewählte Modell werden in seine Standardkonfiguration geschrieben.

:::tip[Welche CLIs werden unterstützt]
Welche CLIs im Assistenten wählbar sind, hängt von den lokal installierten und erkannten Agent CLIs ab; es gibt keine Beschränkung auf eine bestimmte. Den vollständigen Unterstützungsumfang und die Installationswege finden Sie unter [AI Agent CLI-Installation](/de-DE/related-software-installation/ai-agent-cli/). Hermes, Gemini und DeepAgents erfordern zuvor eine manuelle Installation oder Authentifizierung.
:::

**Häufige Probleme**

- **Meine CLI erscheint nicht in der Liste**: Stellen Sie sicher, dass sie installiert und in der Umgebung verfügbar ist, in der Hagicode Server läuft. Desktop-Nutzer starten Desktop neu, damit der `PATH` neu eingelesen wird.
- **Der Verfügbarkeitstest schlägt fehl**: Häufige Ursachen sind eine noch nicht angemeldete CLI, ein ungültiges Token oder ein Modellname, den die CLI nicht unterstützt. Führen Sie zuerst im Terminal einen minimalen Dialog mit dieser CLI aus, um zu bestätigen, dass sie selbst funktioniert.
- **Das Hinzufügen zum Notfallteam schlägt fehl**: Die Seite bietet „Erneut zum Notfallteam hinzufügen“ an; wiederholen Sie den Vorgang einfach.

## Schritt 3: Projekt erstellen

**Ziel**: Mindestens ein Projekt registrieren, damit spätere Sitzungen ein lesbares Arbeitsverzeichnis haben. Der Assistent prüft zuerst, ob bereits ein lokales Projekt vorhanden ist: Ist eines vorhanden, zeigt er die aktuelle Projektübersicht an; falls nicht, müssen Sie zuerst eines registrieren.

1. Geben Sie unter „Registrieren Sie ein lokales Projekt“ Projektname, Ordnerpfad und optional eine Projektbeschreibung an. Felder und Pfadprüfung sind identisch mit dem Dialog „Neues Projekt“ der Hauptoberfläche.
2. Klicken Sie auf „Erstellen und fortfahren“, um zum nächsten Schritt zu wechseln. Wenn Sie in diesem Schritt bleiben und weitere Projekte hinzufügen möchten, klicken Sie auf „Projekt erstellen“.
3. Ist bereits ein Projekt vorhanden, können Sie direkt auf „Weiter zur Community“ klicken, „Erstellen Sie ein weiteres Projekt“ oder zur Grundeinrichtung zurückkehren („Zurück zum Setup“).

:::tip[Lieber zuerst mit einem Beispielprojekt ausprobieren?]
Der Assistent bietet nur das Registrieren eines lokalen Projekts an. Das „Demoprojekt“ finden Sie in der Hauptoberfläche im Dialog „Neues Projekt“ auf der Registerkarte „Demoprojekt“: Es klont und registriert automatisch das offizielle MonoSpecs-Demo-Repository. Der Standardpfad ist `data/repos/monospecs-demo`; das tatsächliche Verzeichnis richtet sich nach der Konfiguration des Laufzeit-Datenverzeichnisses (DataDir). Dieser Weg erfordert Git und Zugriff auf GitHub.
:::

**Häufige Probleme**

- **Die Pfadprüfung schlägt fehl**: Stellen Sie sicher, dass der Ordnerpfad korrekt ist und wirklich existiert. Bei einer Docker-Bereitstellung muss ein im Container erreichbares (eingebundenes) Verzeichnis angegeben werden, nicht ein Pfad auf dem Host.

## Schritt 4: Community-Leitfaden

**Ziel**: Die Community-Einstiegspunkte griffbereit halten.

Die Seite „Info“ der offiziellen Website bündelt alle Community-Einstiegspunkte. Links werden in einem neuen Tab geöffnet; kehren Sie danach zum Assistenten zurück und klicken Sie auf „Beginnen Sie mit der Verwendung von HagiCode“, um den Arbeitsbereich zu betreten. Den Assistenten können Sie auch nach diesem Schritt jederzeit erneut öffnen.

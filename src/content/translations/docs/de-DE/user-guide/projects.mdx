Ein **Projekt** ist der Ordner, in dem HagiCode arbeitet. Sitzungen, der Git-Status, Standardbegriffe und die MonoSpecs-Einstellungen gehören jeweils zu einem Projekt. Deshalb ist die Projektleiste am linken Rand des Arbeitsbereichs für die meisten Aufgaben der Ausgangspunkt.

## Projektleiste

Die Projektleiste ist standardmäßig eingeklappt, und jedes Projekt wird nur als rundes Symbol angezeigt. Zum Ausklappen klicken Sie auf den kleinen Pfeil oben in der Projektleiste.

![Ausgeklappte Projektleiste mit den Einträgen All Sessions und dem Projekt orbit-notes sowie dem Plus-Button zum Hinzufügen eines Projekts](../../img/user-guide/workbench/02-project-rail.png)

- **All Sessions** (alle Sitzungen) zeigt die Sitzungen aller Projekte auf demselben Board an.
- Wenn Sie ein Projekt anklicken, zeigt das Board nur die Sitzungen dieses Projekts an und das Projektpanel wird für dieses Projekt geöffnet.
- Der grüne Button **+** erstellt ein neues Projekt. Der Pfeil daneben klappt die Projektleiste wieder ein.

:::tip[Welche Projekte erscheinen auf dem Board „All Sessions“?]
Unter **Settings → Process & Interaction → Session List** (Einstellungen → Prozess & Interaktion → Sitzungsliste) können Sie den Umfang von *All Projects* (alle Projekte) auf *Custom Selection* (benutzerdefinierte Auswahl) umstellen und einzelne Projekte auswählen. Siehe [Einstellungen](/user-guide/settings).
:::

## Neues Projekt anlegen

Klicken Sie in der Projektleiste auf **+**, um den Dialog **New Project** (neues Projekt) zu öffnen. Er bietet drei Möglichkeiten, ein Projekt hinzuzufügen.

### Einzelnes Projekt

Diese Möglichkeit verwenden Sie, wenn der Projektordner bereits auf der Festplatte liegt. Sie entspricht dem Reiter **Single Project** (einzelnes Projekt).

![Reiter Single Project im Dialog „Neues Projekt“ mit ausgefülltem Namen, Ordnerpfad und Beschreibung](../../img/user-guide/projects/01-create-project.png)

| Feld | Beschreibung |
| --- | --- |
| **Project Name** (Projektname) | Pflichtfeld, höchstens 200 Zeichen. |
| **Folder Path** (Ordnerpfad) | Pflichtfeld, höchstens 1000 Zeichen. Geben Sie den absoluten Pfad des Ordners an, zum Beispiel `/home/user/projects/orbit-notes`. |
| **Project Description** (Projektbeschreibung) | Optional, höchstens 1000 Zeichen. |

Enthält der Pfad `.hagicode/monospecs.yaml`, erkennt der Dialog dies und zeigt für das Projekt einen Hinweis zu MonoSpecs an. Siehe [MonoSpecs](/guides/monospecs).

### Stapelweise anlegen

Diese Möglichkeit verwenden Sie, wenn mehrere Repositories in einem gemeinsamen übergeordneten Ordner liegen. Sie entspricht dem Reiter **Batch Create** (stapelweise anlegen).

![Reiter Batch Create im Dialog „Neues Projekt“, der zur Auswahl des zu durchsuchenden Ordners auffordert](../../img/user-guide/projects/02-create-project-batch.png)

Geben Sie den vollständigen Pfad des übergeordneten Ordners an. HagiCode durchsucht bis zu drei Verzeichnisebenen nach Git-Repositories und legt jedes gefundene Repository als Projekt an.

### Demoprojekt

Diese Möglichkeit verwenden Sie, wenn Sie HagiCode ausprobieren möchten, bevor Sie Ihren eigenen Code verbinden. Sie entspricht dem Reiter **Demo Project** (Demoprojekt).

![Reiter Demo Project im Dialog „Neues Projekt“ mit dem MonoSpecs-Demo-Repository und dem Zielpfad](../../img/user-guide/projects/03-create-project-demo.png)

HagiCode klont das offizielle MonoSpecs-Demo-Repository (`https://github.com/HagiCode-org/monospecs-demo`) und registriert es als Projekt. Dafür muss Git auf Ihrem Rechner installiert sein. In der Oberfläche wird der Standardpfad angezeigt. Der tatsächliche Ordner hängt von Ihrem Laufzeit-Datenverzeichnis ab.

## Projektpanel

Wenn Sie ein Projekt auswählen, wird rechts neben dem Board das Projektpanel dieses Projekts angezeigt.

![Projektpanel des Projekts orbit-notes mit Quick actions und Repository status](../../img/user-guide/workbench/06-project-panel.png)

**Quick actions** (Schnellaktionen)

| Button | Funktion |
| --- | --- |
| **Auto Super Commit** | Startet einen KI-gestützten Commit für das Projekt. Siehe [Super Commit](/guides/ai-compose-commit). |
| **Open Code Server** (Code Server öffnen) | Öffnet das Projekt im browserbasierten Code-Editor. |
| **Open Git Management** (Git-Verwaltung öffnen) | Öffnet den Git-Reiter in den Projektdetails. |
| **View Project Details** (Projektdetails anzeigen) | Öffnet die Projektdetails als Drawer. |

**Repository status** (Repository-Status) listet jedes Repository des Projekts mit seinem aktuellen Branch auf. Die farbigen Punkte zeigen den Zustand des Arbeitsverzeichnisses an. Der Punkt im Screenshot ist rot, weil `src/server.js` nicht committete Änderungen enthält. Mit dem Aktualisierungs-Button lesen Sie den Status neu ein.

Im Menü **Recent changes** (letzte Änderungen) in der Board-Werkzeugleiste werden die Repositories aufgelistet, in denen zuletzt Änderungen vorgenommen wurden. Solange keine Repositories geändert wurden, wird „Keine aktuellen Änderungen“ angezeigt.

## Projektdetails

Klicken Sie auf **View Project Details**, um den Drawer zu öffnen. Er enthält vier Reiter.

### Details

Dieser Reiter entspricht **Details**.

![Reiter Details der Projektdetails mit Einstellungen für Name, Pfad, Beschreibung und Symbol](../../img/user-guide/projects/04-project-details.png)

- **Name**, **Path** (Pfad) und **Description** (Beschreibung): die Grundinformationen des Projekts.
- **Icon Settings** (Symboleinstellungen): Wählen Sie für das Projektsymbol entweder *Game Icon* (Spielsymbol) oder *Text Abbreviation* (Textkürzel). Mit **Change Icon** (Symbol ändern) öffnen Sie die Symbolauswahl.
- **Manage DESIGN.md** (DESIGN.md verwalten): Verwalten Sie die Datei `DESIGN.md` des Projekts.
- **Delete Project** (Projekt löschen): Löschen Sie das Projekt, indem Sie seinen Namen zur Bestätigung eingeben. Der Bestätigungsdialog listet auf, was dauerhaft entfernt wird: alle Sitzungen des Projekts und alle Nachrichten in diesen Sitzungen. Dieser Vorgang kann nicht rückgängig gemacht werden.

### MonoSpecs

![Reiter MonoSpecs mit dem Hinweis, MonoSpecs für das Projekt zu initialisieren](../../img/user-guide/projects/05-project-monospecs.png)

MonoSpecs macht ein Projekt zu einem Arbeitsbereich, der Spezifikationen und mehrere Repositories koordiniert. Bei einem Projekt, das noch kein MonoSpecs-Arbeitsbereich ist, erstellt **Initialize MonoSpecs** (MonoSpecs initialisieren) nur das Nötigste und klont keine Repositories automatisch:

- `.hagicode/monospecs.yaml`
- den Ordner `repos/` für die Unter-Repositories
- `openspec/changes/archive/` und `openspec/specs/`
- eine Ergänzung in `.gitignore`, damit der Ordner `repos/` nicht versioniert wird

Lesen Sie vor der Initialisierung den [MonoSpecs-Leitfaden](/guides/monospecs).

### Standardbegriffe

Dieser Reiter entspricht **Standard Words** (Standardbegriffe).

![Reiter Standard Words mit einer leeren Gruppenliste und dem Button Add group](../../img/user-guide/projects/06-project-standard-words.png)

Standardbegriffe sind gemeinsam genutzte Fachbegriffe eines Projekts. Sie werden in `.hagicode/standard_words.yaml` gespeichert. Der Reiter zeigt die Anzahl der Gruppen, Phrasen und Tags an und bietet eine Suche, **Add group** (Gruppe hinzufügen), **Refresh** (aktualisieren) vom Datenträger sowie **Save changes** (Änderungen speichern).

### Git

![Reiter Git mit der Repository-Liste links und der Übersicht des Repositories rechts, mit den Aktionen Push, Pull und Super Commit](../../img/user-guide/projects/07-git-management.png)

Der Reiter Git ist die Git-Konsole des Projekts.

- Die **Repository-Liste** (links) zeigt die überwachten Repositories. Die Anzahl (z. B. `1 / 15`) vergleicht sie mit dem Limit für die Überwachung unter **Settings → Integration → Git** (Einstellungen → Integration → Git). Für Massenaktionen stehen **Select Changed** (geänderte auswählen), **Select All** (alle auswählen) und **Clear Selection** (Auswahl aufheben) bereit. Außerdem können Sie nach Namen suchen. Mit **Manage Super Commit All exclusions** (Ausschlüsse für Super Commit All verwalten) legen Sie fest, welche Dateien beim schnellen Commit übersprungen werden.
- Die **Repository-Übersicht** (rechts) zeigt Branch, Synchronisierungsstatus, ob nicht committete Änderungen vorliegen, das Remote-Repository und den Repository-Pfad an.
- Aktionen für das aktuell ausgewählte Repository: **Super Commit**, **Push**, **Pull**, **Rebase Upstream** (Upstream-Branch rebasen), **Open Remote Repository** (Remote-Repository öffnen), **Open Code Server** und **Manage DESIGN.md**.

Die Übersicht ersetzt hier bewusst die Vorschau der Diffs. Für weitergehende Git-Vorgänge verwenden Sie **Open Code Server**.

Git-Verhalten wie Git-Profile, die Statusüberwachung und die Standardaktion für Super Commit konfigurieren Sie unter **Settings → Integration → Git** (Einstellungen → Integration → Git).

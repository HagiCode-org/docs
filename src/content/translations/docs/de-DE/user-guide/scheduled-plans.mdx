Ein **Plan** (auch geplanter Plan oder geplante Aufgabe genannt) sorgt dafür, dass HagiCode zu einer von Ihnen festgelegten Zeit automatisch eine Sitzung startet, ohne dass Sie anwesend sein und auf „Absenden“ klicken müssen. Typische Einsatzfälle: an jedem Werktag um 2:00 Uhr ein Code-Review ausführen, jeden Morgen nach Abhängigkeits-Updates suchen oder morgen um 10:00 Uhr Release Notes entwerfen.

Ein Plan speichert zwei Dinge: **alles, was zum Erstellen der Sitzung nötig ist** (genau das, was Sie sonst in einem Erstellungsdialog ausfüllen) und einen **Zeitplan**. Wenn die Zeit gekommen ist, erstellt HagiCode die Sitzung über denselben Ablauf wie beim manuellen Absenden. Eine von einem Plan gestartete Sitzung unterscheidet sich also nicht von einer selbst angelegten.

## Konzepte

| Konzept | Bedeutung |
| --- | --- |
| **Type** (Typ) | Es gibt zwei Arten von Plänen: **Proposal** (Vorschlag; erstellt bei der Ausführung eine Vorschlagssitzung) und **HagiTask** (erstellt bei der Ausführung eine Sitzung aus einem HagiTask). Der Typ ergibt sich daraus, in welchem Erstellungsdialog Sie den Plan speichern. |
| **Run once / Recurring** (Einmal ausführen / Wiederkehrend) | Ein einmaliger Plan läuft zu genau einem Zeitpunkt. Ein wiederkehrender Plan wiederholt sich täglich oder wöchentlich zwischen einem Startdatum und einem Enddatum. |
| **Next run** (Nächste Ausführung) | Der nächste Zeitpunkt, zu dem der Plan von selbst startet, angezeigt in der von Ihnen gewählten Zeitzone. |
| **Scheduled / Completed** (Geplant / Abgeschlossen) | Der Zustand des Plans. Ein einmaliger Plan wird nach der Ausführung zu „Completed“; ein wiederkehrender Plan wird zu „Completed“, sobald sein Enddatum verstrichen ist. |
| **Enabled / Disabled** (Aktiviert / Deaktiviert) | Jeder Plan hat einen Aktivierungsschalter. Ein deaktivierter Plan bleibt in der Liste, wird aber nie automatisch ausgeführt. |

## Den Plan-Manager öffnen

Die Schaltfläche **Plans** (Pläne) in der Kopfleiste öffnet den Plan-Manager. In einem schmalen Fenster zeigt die Schaltfläche nur das Kalender-Symbol; fahren Sie mit der Maus darüber, um den Tooltip **Scheduled plans** (Geplante Pläne) zu sehen.

![HagiCode-Kopfleiste mit einer neuen Schaltfläche Plans zwischen Vault und Get Support](../../img/user-guide/workbench/03-header-navigation.png)

Beim ersten Öffnen ist die Liste leer. Der Manager dient nur dem **Ansehen und Verwalten** bestehender Pläne; hier lässt sich keiner anlegen. Pläne werden immer in dem Dialog gespeichert, der einen Vorschlag oder einen HagiTask erstellt.

![Schublade des Plan-Managers im Leerzustand, „No scheduled plans yet“, mit einem Hinweis, wie man einen Plan anlegt](../../img/user-guide/plans/01-empty-manager.png)

## Einen Plan erstellen

Sowohl der Dialog zum Erstellen eines Vorschlags als auch der zum Erstellen eines HagiTasks können von „jetzt starten“ auf „nach Zeitplan starten“ umgeschaltet werden. **Create Normal Session** hat keinen Plan-Schalter.

1. Öffnen Sie wie gewohnt einen Erstellungsdialog, zum Beispiel **New Idea**, und füllen Sie Ideenname, Projekt und Anforderung aus. Zu den Feldern siehe [Sitzungen](/de-DE/user-guide/sessions#neue-idee-vorschlag).
2. Sehen Sie unten rechts im Dialog nach. Neben der Schaltfläche zum Absenden befindet sich ein Schalter **Plan**, standardmäßig ausgeschaltet.

   ![Fußbereich der Schublade Create Proposal mit Cancel links sowie dem Schalter Plan und der Schaltfläche Submit idea rechts](../../img/user-guide/plans/02-plan-switch.png)

3. Schalten Sie **Plan** ein. Der Dialog wechselt in den Planmodus:
   - Die Beschriftung oben links ändert sich von **Create Proposal** zu **Proposal plan**.
   - Oben erscheint ein Pflichtfeld **Plan name** (Planname), zum Beispiel „Nightly code review“, bis zu 200 Zeichen.
   - Unten erscheint der Abschnitt **Schedule** (Zeitplan).
   - Die Schaltfläche zum Absenden wird zu **Save plan** (Plan speichern).

   ![Schublade Create Proposal im Planmodus: Plan name oben, darunter das ursprüngliche Formular, unten der Abschnitt Schedule und die Schaltfläche Save plan](../../img/user-guide/plans/03-plan-mode-once.png)

4. Legen Sie unter **Schedule** fest, wann der Plan läuft; siehe [Den Zeitplan festlegen](#den-zeitplan-festlegen). Ein HagiTask-Plan benötigt zusätzlich einen Agenten; siehe [Einen Agenten für einen HagiTask-Plan auswählen](#einen-agenten-für-einen-hagitask-plan-auswählen).
5. Klicken Sie auf **Save plan**. HagiCode zeigt die Meldung **Plan saved** (Plan gespeichert); mit **View plans** (Pläne ansehen) öffnen Sie sofort den Plan-Manager.

   ![Hinweis unten links auf dem Bildschirm: Plan saved, mit der Schaltfläche View plans](../../img/user-guide/plans/07-plan-saved-toast.png)

:::note
Pläne können keine Bilder enthalten. Sind dem Formular bereits Bilder angehängt, ist der Schalter **Plan** deaktiviert und weist Sie darauf hin, die Bilder zu entfernen, bevor Sie die Aufgabe als Plan speichern.
:::

## Den Zeitplan festlegen

Die beiden Schaltflächen oben im Abschnitt **Schedule** bestimmen, wie der Plan läuft: **Run once** (Einmal ausführen) oder **Recurring** (Wiederkehrend). In beiden Modi zeigt **Next run** am unteren Rand des Abschnitts live die nächste Ausführungszeit an, die sich aus den aktuellen Einstellungen ergibt. Steht dort **Not scheduled** (Nicht geplant), ist mit den aktuellen Einstellungen keine Ausführungszeit möglich; passen Sie dann Datum oder Uhrzeit an.

### Einmal ausführen

Läuft ein einziges Mal.

| Feld | Beschreibung |
| --- | --- |
| **Date** und **Time** (Datum und Uhrzeit) | Tag und Uhrzeit der Ausführung. Standard ist morgen um 09:00. Der Zeitpunkt muss in der Zukunft liegen. |
| **Run in** (Ausführen in) | Schnellschaltflächen: `+5 min`, `+10 min`, `+30 min`, `+1 hour`, gerechnet ab jetzt. |
| **Next at** (Nächstes Mal um) | Schnellschaltflächen: `02:00`, `09:00`, `12:00`, `18:00`, `22:00`. Sie wählen das nächste Auftreten dieser Uhrzeit, heute, wenn sie noch bevorsteht, sonst morgen. |
| **Time zone** (Zeitzone) | Die Zeitzone, in der Datum und Uhrzeit gelesen werden. Standard ist die aktuelle Zeitzone des Browsers. |

### Wiederkehrend

Wiederholt sich täglich oder wöchentlich zwischen einem Startdatum und einem Enddatum.

![Modus Recurring im Abschnitt Schedule: Start- und Enddatum, Uhrzeit, Every week, Montag bis Freitag, Zeitzone Asia/Shanghai und die nächste Ausführungszeit](../../img/user-guide/plans/04-recurring-schedule.png)

| Feld | Beschreibung |
| --- | --- |
| **From** und **To** (Von und Bis) | Erster und letzter Tag des Zeitraums, beide einschließlich. Standard ist ein Beginn heute und eine Dauer von einem Monat. Unter **Start** legen `Today`, `Tomorrow`, `In 1 week`, `In 1 month` und `In 3 months` das Startdatum schnell fest; unter **Length** (Dauer) legen `+1 week`, `+1 month` und `+3 months` die Dauer fest. |
| **Time** (Uhrzeit) | Die Tageszeit jeder Ausführung im Format `HH:mm`. **Quick time** (Schnellauswahl Uhrzeit) bietet `02:00`, `09:00`, `12:00`, `18:00` und `22:00`. |
| **Repeat** (Wiederholen) | **Every day** (Jeden Tag) oder **Every week** (Jede Woche). |
| **On** (An) | Erscheint, wenn Sie **Every week** wählen. Wählen Sie die Wochentage, `Mon` bis `Sun`, an denen der Plan läuft; mindestens einer ist erforderlich. |
| **Time zone** (Zeitzone) | Die Zeitzone, in der die Uhrzeit gelesen wird. Jede Ausführung folgt der Ortszeit dieser Zone; ein Plan, der täglich um 02:00 Uhr läuft, bleibt also auch bei Sommerzeitwechseln bei 02:00 Uhr. |

:::tip
Um einen Plan „langlebig“ zu machen, setzen Sie **To** weit in die Zukunft, zum Beispiel durch Klicken auf **+3 months**. Nach dem Enddatum wird der Plan **Completed** und läuft nicht mehr.
:::

## Einen Agenten für einen HagiTask-Plan auswählen

Ein Vorschlagsplan benötigt keinen Agenten. **Bei einem HagiTask-Plan muss genau ein Agent ausgewählt sein**, da beim automatischen Start niemand anwesend ist, der einen auswählen könnte:

- Im Planmodus zeigt der Dialog einen Abschnitt **Available Agents** (Verfügbare Agenten) an. Er erklärt, dass dies der Agent ist, mit dem der Plan läuft, und dass der Plan diese Auswahl beim Start beibehält. Klicken Sie auf einen Agenten, um ihn auszuwählen.
- Die untere Leiste zeigt `Agent: name`. Solange Sie nichts gewählt haben, steht dort `No agent selected yet.`, und der Plan kann nicht gespeichert werden.
- Derzeit kann ein Plan nur einen Agenten haben. Zum Erstellen von Agenten siehe [Agents](/de-DE/user-guide/agents).

## Bestehende Pläne verwalten

Öffnen Sie **Plans**, um alle Pläne zu sehen. Jede Zeile ist ein Plan.

![Plan-Manager mit fünf Plänen: ein Vorschlagsplan für Werktage, ein täglicher HagiTask-Plan, ein einmaliger Vorschlagsplan, ein deaktivierter wöchentlicher Plan und ein abgeschlossener Plan](../../img/user-guide/plans/05-plan-manager.png)

Jede Zeile enthält:

- Den **Namen**, ein Typ-Kennzeichen **Proposal** oder **HagiTask** und ein Zustandskennzeichen **Scheduled** oder **Completed**.
- Eine **Zusammenfassung des Zeitplans**, zum Beispiel `Weekly on Mon, Tue, Wed, Thu, Fri 02:00 AM, Oct 18, 2026 - Jan 18, 2027 (Asia/Shanghai)`.
- **Next run**. Ein abgeschlossener Plan zeigt `–`.

Auf der rechten Seite jeder Zeile befinden sich vier Bedienelemente:

| Bedienelement | Funktion |
| --- | --- |
| Schalter **Enabled / Disabled** (Aktiviert / Deaktiviert) | Aktiviert oder deaktiviert den Plan. Ein deaktivierter Plan läuft nicht automatisch, bleibt aber in der Liste. Beim erneuten Aktivieren berechnet HagiCode die nächste Ausführung ab der aktuellen Zeit neu; Zeitpunkte, die während der Deaktivierung verpasst wurden, werden nicht nachgeholt. |
| **Run now** (Jetzt ausführen) | Erstellt sofort eine Sitzung aus den gespeicherten Eingaben; bei Erfolg zeigt die Zeile **Session started.** (Sitzung gestartet.). Zeitplan und **Next run** des Plans ändern sich dadurch nicht, und auch ein deaktivierter oder abgeschlossener Plan kann manuell ausgeführt werden. |
| **Edit** (Bearbeiten) | Öffnet im Planmodus denselben Dialog, mit dem der Plan erstellt wurde. Ändern Sie Name, Inhalt, Agent oder Zeitplan und klicken Sie auf **Save plan**. Ein gespeicherter Plan bleibt immer ein Plan: Der Schalter **Plan** ist gesperrt und kann ihn nicht wieder in eine normale Aufgabe verwandeln. |
| **Delete** (Löschen) | Fragt zuerst nach einer Bestätigung. Das Löschen verhindert nur, dass der Plan weiter läuft; **von ihm bereits gestartete Sitzungen bleiben erhalten**. |

![Bestätigungsdialog zum Löschen: Delete this scheduled plan? Er besagt, dass „Weekly docs cleanup“ nicht mehr ausgeführt wird und bereits gestartete Sitzungen erhalten bleiben](../../img/user-guide/plans/06-delete-confirm.png)

## Wann Pläne ausgeführt werden

- **Pläne laufen nur, solange HagiCode läuft.** HagiCode prüft alle 30 Sekunden, ob Pläne fällig sind; eine Ausführung kann daher bis zu etwa 30 Sekunden nach der geplanten Zeit beginnen.
- **Verpasste Zeitpunkte werden einmal nachgeholt.** Lief HagiCode nicht, als ein Plan fällig wurde (zum Beispiel weil der Computer ausgeschaltet war), wird der Plan einmal ausgeführt, sobald HagiCode startet, und die nächste Ausführung wird danach normal geplant. Egal wie oft ein Zeitpunkt verpasst wurde, der Plan läuft nur einmal und nicht gebündelt.
- **Fehlgeschlagene Ausführungen werden nicht wiederholt.** Kann eine Ausführung ihre Sitzung nicht erstellen (zum Beispiel weil das Projekt entfernt wurde oder der gewählte Agent nicht verfügbar ist), wird diese Ausführung übersprungen, und der Plan wartet auf seinen nächsten geplanten Zeitpunkt. Beheben Sie zur Wiederherstellung das Problem und klicken Sie auf **Run now**. Schlägt eine manuelle Ausführung fehl, zeigt die Zeile **Run now failed:** und den Grund.
- **Ein einmaliger Plan wird nach der Ausführung zu „Completed“.** Um ihn erneut zu verwenden, klicken Sie auf **Edit** und legen Sie eine neue Zeit in der Zukunft fest. Das Einschalten des Schalters eines abgelaufenen einmaligen Plans wird abgelehnt, da seine Ausführungszeit bereits in der Vergangenheit liegt.
- **Jede Ausführung erstellt eine neue Sitzung.** Ein Vorschlagsplan erstellt eine Vorschlagssitzung, ein HagiTask-Plan eine HagiTask-Sitzung. Sie erscheinen auf dem Sitzungsboard wie von Hand angelegte Sitzungen.

## FAQ

**Beim Speichern eines Plans heißt es, die Ausführungszeit müsse nach der aktuellen Zeit liegen oder es müsse mindestens ein Wochentag gewählt werden.**
Das ist eine Formularvalidierung, der Grund erscheint unter dem Feld. Ein einmaliger Plan muss in der Zukunft liegen. Bei einem wiederkehrenden Plan darf das Enddatum nicht vor dem Startdatum liegen, ein wöchentlicher Plan braucht mindestens einen Wochentag, und der Zeitraum muss mindestens eine mögliche Ausführung enthalten.

**Der Schalter Plan ist ausgegraut.**
Dem Formular sind Bilder angehängt, und Pläne unterstützen keine Bilder. Entfernen Sie sie, dann funktioniert der Schalter wieder.

**Ein Plan wurde zur fälligen Zeit nicht ausgeführt.**
Prüfen Sie der Reihe nach: Der Plan ist **Enabled**; **Next run** ist die erwartete Zeit (besonders die Zeitzone); HagiCode lief in diesem Moment; das vom Plan verwendete Projekt und der Agent existieren noch.

**Wo werden Pläne gespeichert?**
Alle Pläne werden in `scheduled-plans.json` im vom System verwalteten Konfigurationsverzeichnis von HagiCode gespeichert. Sie hängen nicht vom Browser ab; wenn Sie dasselbe HagiCode in einem anderen Browser öffnen, sehen Sie dieselben Pläne.

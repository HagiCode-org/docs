**Agent** は HagiCode の中核です。セッションは Agent が実行するため、作業を始める前に少なくとも 1 つ必要です。このページは概要ガイドで、Agent が何で構成されているか、種類の異なる作業を誰が担当するか、そして Agent に関する設定がどこに分かれているかを把握できます。個々の操作手順は [Agents ワークスペースガイド](/ja-JP/user-guide/agents)をご覧ください。

## 機能概覧

- 1 つの **Agent = Agent CLI + モデル + 任意のパーソナリティテキスト** です。Agent CLI は実際に実行されるコマンドラインツール（例：Claude Code、Codex）、モデルはそれが使うモデル、パーソナリティテキスト（Trait と Soul）は作業スタイルや話し方を形づくります。
- Agent は複数作成できます。たとえば、Opus でレビュー、Haiku で素早い修正、Codex でリファクタリング、といった使い分けができます。
- 作業の種類ごとにどの Agent を使うかは**実行シナリオ**で決まります。適切なメンバーがいない場合は **Fallback Crew** が引き継ぎます。
- Agent の確認や調整は **Agents ワークスペース**と**設定**に分かれています。前者は Agent、シナリオ、CLI、モデルを管理し、後者は再試行やメモリ・CPU の上限などのランタイム動作を管理します。

## Agent 一覧

![Agents タブ：5 つの Agent が Claude Code と Codex ごとにグループ化され、それぞれアバターとモデルが表示されている](../img/screenshots/guides/agent-roster/original.png)

トップバーの **Agents** をクリックして **Agents Workspace** を開きます。**Agents** タブの **My Agents** には、Agent CLI ごとにグループ化された Agent が並び、各カードにアバター、名前、モデルが表示されます。ここでは次のことができます。

1. **New Agent** で Agent を作成します。AgentCLI と互換性のあるモデルを選び、必要に応じて Trait（知識と振る舞い）と Soul（言語スタイル）を記入します。
2. **Batch create Agents** で複数の Agent をまとめて作成したり、検索ボックスで名前・CLI・紹介文から絞り込んだりできます。
3. **Battle ready** スイッチで Agent の有効・無効を切り替えます。

作成手順の詳細は [Agents](/ja-JP/user-guide/agents#agent-の作成) をご覧ください。

## 役割分担：実行シナリオと fallback 編成

![Execution Scenarios タブ：Proposal と HagiTask の各シナリオの Agent 編成が表示され、右側に編成済みの Agent と追加可能な Agent が並んでいる](../img/screenshots/guides/agent-scenarios/original.png)

**Execution Scenarios** タブでは、作業の種類ごとにどの Agent が担当するかを決めます。シナリオは用途別にグループ化されています。

| グループ | シナリオ |
| --- | --- |
| **Proposal** | 提案の最適化、生成、実行、アーカイブ |
| **HagiTask** | Super Commit、通常セッションの作成、コード調査タスクの作成 |
| **Chat** | セッションタイトルの最適化 |

シナリオをクリックすると、右側の **Assigned Agents** にそのシナリオの編成が、**Available Agents** に追加できる Agent が表示されます。**Add** または **Remove** で調整できます。**Fallback Crew** はセーフティネットです。あるシナリオ自身の編成に適切な Agent がいない場合、HagiCode は Fallback Crew から条件に合うメンバーを選びます。**Fallback Crew に有効な Agent が少なくとも 1 つ入るまで、他のシナリオはロックされたままです。** 初期化ウィザードが最初の Agent を自動的に追加します。

よくある構成例：

1. 長いコンテキストとレビューが得意な Agent を **Generate Proposal** に入れます。
2. 実行力が高くコストが見合う Agent を **Execute Proposal** に入れます。
3. 安価で高速な Agent を **Super Commit** と **Conversation Title Optimization** に入れます。
4. Fallback Crew には、安定した汎用 Agent を 1 つ残しておきます。

## 関連設定はどこにあるか

| やりたいこと | 場所 |
| --- | --- |
| Agent の作成、編集、有効化・無効化 | **Agents** → **Agents** タブ |
| 作業の種類ごとの Agent の割り当て、Fallback Crew の管理 | **Agents** → **Execution Scenarios** |
| Agent CLI のインストール状況、正常性、有効状態の確認 | **Agents** → **AgentCLI**、ステータスバーの AI Monitoring ポップオーバー |
| CLI で使えるモデルの閲覧・追加 | **Agents** → **Model** |
| アバターやテキストテーマの変更 | **Agents** → **Avatar Gallery** / **Document Theme** |
| 失敗した実行の自動再試行 | **設定** → **Error Retry** |
| 生成 prompt に「今回の実行は非対話」と宣言するかどうか | **設定** → **AgentCLI Interactive Control** |
| 各 Agent が使えるメモリと CPU の制限 | **設定** → **Agent resource limits** |
| 複数の OpenAI 互換モデルを同じローカル gateway に接続する | **設定** → **OmniRoute** |

各設定項目の役割は[設定](/ja-JP/user-guide/settings)をご覧ください。

## 適用シーンと境界

- 段階ごとに異なるモデルや CLI を使いたい場合（例：レビューと実行を分ける）は、シナリオごとに役割を分担します。
- Agent が 1 つだけでも問題なく使えます。その Agent を Fallback Crew に入れれば、すべてのシナリオでそれが使われます。
- Agent が決めるのは**誰が実行するか**だけです。何を実行するかは、作成したセッション、提案、プランから決まります。

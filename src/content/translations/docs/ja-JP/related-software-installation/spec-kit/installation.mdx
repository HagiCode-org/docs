Spec Kit は GitHub が公開しているスペック駆動開発(Spec-Driven Development)のツールキットです。まず仕様を書き、次に計画とタスクを作り、最後に AI コーディングアシスタントにタスクを実装させます。コマンドラインツールの名前は `specify` で、`specify-cli` パッケージとして提供されています。

ネット上の多くのチュートリアルは、いまだに古いインストールコマンド、`--ai` オプション、`/speckit.specify` のようなコマンド名を使っており、そのまま写すとエラーになることがよくあります。このページでは公式ドキュメントに沿って現在の正しい手順をまとめ、何が変わったかを示します。

:::note[確認した時点]
[Spec Kit 公式ドキュメント](https://github.github.com/spec-kit/)をもとに、2026-10-26 に確認しました。このプロジェクトは更新が速いため、内容が食い違う場合は、このページよりお使いのマシンの `specify --help` と公式ドキュメントを優先してください。
:::

## 対象読者

- Claude Code、GitHub Copilot、Gemini CLI、CodeBuddy CLI、Pi、Oh My Pi などの AI コーディングアシスタントで、スペック駆動のワークフローを試したい人。
- 古いチュートリアルで Spec Kit を入れたものの、今はエラーが出る、あるいはコマンドが見つからない人。

## 前提条件

| 項目 | 要件 |
| --- | --- |
| OS | Linux、macOS、または Windows(PowerShell スクリプトは WSL なしで動作) |
| Python | 3.11 以上 |
| パッケージマネージャー | uv(推奨)または pipx |
| AI コーディングアシスタント | 対応しているものならどれでも。公式ドキュメントには数十の統合が載っています |
| Git | 任意。git 拡張を有効にするときだけ必要 |

Spec Kit 自体に Node.js は不要です。アシスタントを npm でインストールする場合は、先に [AI Agent CLI のインストール](/ja-JP/related-software-installation/ai-agent-cli/)を確認してください。

## specify-cli のインストール

### 方法 1:PyPI からインストール(最短)

```bash
# 推奨:uv
uv tool install specify-cli

# または pipx
pipx install specify-cli

# または pip
pip install specify-cli
```

バージョンを固定するには `uv tool install specify-cli==0.12.11` のようにします(バージョンはリリースページで確認してください)。

### 方法 2:GitHub のリリースタグからインストール

公式ドキュメントが、再現性のある推奨の方法として紹介しています。uv が必要です。

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@vX.Y.Z
```

`vX.Y.Z` は [Releases](https://github.com/github/spec-kit/releases) のタグに置き換えてください。**先頭の `v` は必ず残します。** 例:`v0.12.11`。

### インストールの確認

```bash
specify version
specify self check
```

`specify version` はコマンドが使えることを確認し、バージョンを表示します。`specify self check` は読み取り専用で、より新しいリリースがあるかを教えてくれます。

## プロジェクトの初期化

```bash
specify init my-project --integration claude
cd my-project
```

`--integration` で AI アシスタントを選びます。よく使う値は `claude`、`copilot`、`gemini`、`codebuddy`、`pi`、`omp` です。便利なオプションは次のとおりです。

- `--script sh|ps|py`:スクリプトの種類を選びます。既定値は Windows では `ps`、それ以外では `sh` です。
- `--here --force`:すでにある空でないディレクトリで初期化します。`--force` はマージの警告を理解したという意味なので、先にローカルの変更をコミットまたはバックアップしてください。
- `--non-interactive`:CI 用です。**`--integration` を指定しないと既定で GitHub Copilot が選ばれる**ので注意してください。

## コマンド名:`/speckit-*`

初期化後は、ターミナルではなく AI アシスタントのチャットで次のコマンドを実行します。

| ステップ | コマンド | 役割 |
| --- | --- | --- |
| 1 | `/speckit-constitution` | 後続のステップが基準にするプロジェクトの原則を書く。プロジェクトにつき 1 回 |
| 2 | `/speckit-specify` | 作りたい機能を自然な言葉で説明すると `spec.md` を作る |
| 3 | `/speckit-clarify` | 仕様の抜けを質問し、答えを仕様に反映する |
| 4 | `/speckit-plan` | 技術スタックに合わせて `plan.md` などの設計成果物を作る |
| 5 | `/speckit-checklist` | 要件の品質チェックリストを作る |
| 6 | `/speckit-tasks` | 依存関係の順に並べた `tasks.md` を作る |
| 7 | `/speckit-analyze` | 読み取り専用で、`spec.md`、`plan.md`、`tasks.md` 間の矛盾と漏れを調べる |
| 8 | `/speckit-implement` | `tasks.md` を順に実行する |
| 9 | `/speckit-converge` | コードを仕様と照合し、不足があればタスクを追加する。`Converged` と報告されるまで implement と converge を繰り返す |

最短ルートは specify → plan → tasks → implement → converge です。constitution、clarify、checklist、analyze が入るのはフルのルートだけです。

:::caution[お使いのアシスタントでは表記が違うかもしれません]
公式のクイックスタートでは、ハイフン付きの `/speckit-*` という名前を使っています(GitHub Copilot の既定のスキルモード)。古いチュートリアルやアップグレードの案内には、`/speckit.specify` のようなドット形式も残っています。呼び出し形式はアシスタントやモードによって異なるので、初期化後にアシスタントのコマンド一覧へ実際に表示される名前に従ってください。
:::

## 古いチュートリアルからの変更点

| 古いチュートリアルでよくある方法 | 現在 |
| --- | --- |
| `uv tool install ... --from git+https://...` しかなかった | `specify-cli` が PyPI にも公開され、uv、pipx、pip でインストールできる。GitHub のタグからのインストールも引き続きサポート |
| `specify init --ai claude` | 公式ドキュメントはすべて `--integration claude` を使用 |
| `/speckit.specify`、`/speckit.plan` | クイックスタートは `/speckit-specify`、`/speckit-plan` を使い、`/speckit-converge` が追加された |
| `/constitution` がテンプレートやコマンドファイルまで更新する | 現在は `.specify/memory/constitution.md` だけを更新する。以前の伝播動作に戻すには `specify preset add constitution-sync` を実行 |
| git 機能が常に有効 | 現在は任意の拡張。必要なら `specify extension add git` |
| Git のブランチから現在の機能を判断 | `.specify/feature.json` が現在の機能ディレクトリを記録する |

## アップグレード

コマンドラインツール自体をアップグレードします。

```bash
specify self check                 # 読み取り専用:新しいリリースがあるか確認
specify self upgrade --dry-run     # アップグレードせずにプレビュー
specify self upgrade               # 最新の安定版にアップグレード
specify self upgrade --tag vX.Y.Z  # リリースタグを固定
```

既存プロジェクト内のファイルをアップグレードするには、プロジェクトのディレクトリで実行します。

```bash
specify integration status         # インストール済みの統合と変更されたファイルを一覧表示
specify integration upgrade <key>  # インストール済みの統合ごとに 1 回ずつ実行
specify extension update           # すべての拡張を更新
```

`specify integration upgrade` に `--force` を付けるのは、ローカルで変更された管理対象ファイルがあると報告され、その差分を確認し終えたときだけにしてください。

## よくある問題

- **`command not found: uv`**:先に uv をインストールしてから、インストールコマンドをもう一度実行してください。
- **`No such option: --integration`**:`PATH` の前のほうに古い `specify`(たとえば 0.1.6)があります。最初にインストールしたときと同じツールで入れ直し(例:`uv tool install --force specify-cli`)、`specify version` で確認してください。
- **2 つインストールされている**:uv、pipx、pip でそれぞれインストールすると、コピーが別々に残ります。同じツールでアップグレードし、混ぜて使わないでください。
- **PyPI からのインストールは自動ではアップグレードされない**:インストールしたバージョンのままなので、上のアップグレードコマンドを使ってください。
- **既存のディレクトリでの初期化が拒否される**:コミットまたはバックアップを済ませてから `--here --force` を付けてください。

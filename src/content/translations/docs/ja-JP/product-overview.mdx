HagiCode は、AI がコードを変更するときに文脈を見失わないようにします。**まずリポジトリを理解し、範囲を決め、追跡できる形で実行します。**HagiCode はプロジェクト開発向けの AI ワークスペースで、普段使っている Agent CLI とモデルを接続するため、エディターを乗り換える必要はありません。

**[HagiCode をインストール](/ja-JP/installation/)** · [デモ動画を見る](#product-video-showcase-en)

Claude Code、Codex、GitHub Copilot など 11 種類の Agent CLI に対応 · Windows、macOS、Linux で利用可能 · 基本機能は無料

## 開発タスクの進め方

複数のリポジトリにまたがる機能を変更する場合を例にします。

1. **まず理解する：** [通常のセッション](/ja-JP/quick-start/conversation-session)で既存のコードを分析します。通常のセッションはデフォルトで読み取り専用です。ファイルの変更が必要になったら編集モードに切り替えます。
2. **範囲を決める：** 複雑な変更では、[提案セッション](/ja-JP/quick-start/proposal-session)でプロジェクトとリポジトリを選びます。目的、タスク、検証方法を整理してから実行に進みます。

   ![リポジトリの選択と提案のプレビューを表示した新規提案ドロワー](../img/screenshots/shared/create-proposal-drawser/original.png)

3. **結果を追う：** ワークスペースでセッションと実行状態を確認します。コミットを準備するときは [AI Compose Commit](/ja-JP/guides/ai-compose-commit) を利用できます。

   ![提案ワークフローの実行完了後のセッション詳細](../img/screenshots/shared/classic-proposal-view/original.png)

4. **文脈を残す：** 提案やコミット履歴は後から振り返れます。リポジトリ間で作業する場合は [MonoSpecs](/ja-JP/guides/monospecs) でリポジトリの関係と変更範囲を管理します。

毎回提案を作る必要はありません。コードを調べるだけの場合や簡単な問題に対処する場合は、通常のセッションから始められます。より多くの文脈が必要なタスクには、HagiCode が追跡しやすい進行手順を提供します。

## 対象となる人

- **向いている人：** 複数のリポジトリを保守していて、複雑な変更を実行前に計画したい開発者やチーム。すでに Claude Code や Codex などの Agent CLI を使っていて、それらを 1 つのワークスペースで扱いたい人。
- **必須ではない場合：** エディターで数行を補完できれば十分なら、現在のツールで足ります。

## 目的別に機能を探す

| やりたいこと | 概要 | 最初に読むページ |
| --- | --- | --- |
| 変更するか決める前にコードを理解する | 通常のセッション：デフォルトは読み取り専用で、必要なときに編集へ切り替え | [通常のセッションを作成](/ja-JP/quick-start/conversation-session) |
| 複雑な要件を実装前に計画する | 提案セッション：目的、タスク、検証方法を先に書き出してから AI に任せる | [提案セッションを作成](/ja-JP/quick-start/proposal-session) |
| 複数のリポジトリの関係を AI に伝える | MonoSpecs：リポジトリの関係と変更範囲を管理 | [MonoSpecs ガイド](/ja-JP/guides/monospecs) |
| 拡張機能を検索、インストール、管理する | Skills：検索してインストールできる拡張機能 | [Skills ガイド](/ja-JP/guides/skills) |
| 使い慣れた Agent CLI を利用する | Agent CLI：Claude Code や Codex などのコマンドライン AI ツール | [AI Agent CLI のインストールと対応範囲](/ja-JP/related-software-installation/ai-agent-cli/) |
| CLI とモデルの接続を別々に管理する | OmniRoute：複数の OpenAI 互換ツールを 1 つのローカルゲートウェイに接続 | [OmniRoute のインストールと起動確認](/ja-JP/related-software-installation/omniroute/) |

Vault には参照用リポジトリ、フォルダー、メモをまとめておき、後の作業に再利用できます。Code Server はブラウザーから編集するための入口です。どちらも HagiCode を使い始めるための必須機能ではありません。設計の背景については、[Vault のナレッジベース活用](/ja-JP/blog/2026-04-10-vault-system-ai-knowledge-base/)と[ブラウザー編集の統合](/ja-JP/blog/2026-04-13-vscode-web-integration-browser-editing/)を参照してください。

## 長期的な進捗を見えるようにする

HagiCode は、ヒーロー、実績、日報、Token の指標をフィードバックに変え、状況と進捗を長期的に把握しやすくします。この点が、一般的な AI コーディングツールとの違いのひとつです。[冒険チームの紹介](/ja-JP/adventure-team-introduction)では、ヒーローのグループ分けとダンジョンの進行を確認できます。設計の考え方については、[ゲーミフィケーション設計の記事](/ja-JP/blog/2026-03-16-gamifying-ai-coding/)を参照してください。これはワークスペース体験の一部であり、使わなくても通常の開発ツールとして HagiCode を利用できます。

## エディションと価格

基本機能は無料です。Desktop、Container、Microsoft Store は HagiCode の入手・導入方法の違いであり、3 段階の有料プランではありません。Microsoft Store 版では Turbo Engine も提供しています。これは別途購入する買い切りライセンスで、提案の同時実行数の上限を引き上げ、ドキュメントテーマ、署名のカスタマイズ、ブランディング、アバターなどの追加機能を利用可能にします。具体的な対象は [Turbo Engine 追加パッケージ](/ja-JP/dlc/turbo-engine-dlc/)を参照してください。

| 利用環境 | 推奨する方法 |
| --- | --- |
| Microsoft Store を利用できる Windows | [Microsoft Store からインストール](/ja-JP/installation/windows-store) |
| Windows への手動インストール、または macOS・Linux でのローカル利用 | [Desktop をインストール](/ja-JP/installation/desktop) |
| サーバー、NAS、チームでの導入 | [Docker Compose でインストール](/ja-JP/installation/docker-compose) |

Steam のメインアプリは提供を終了しており、現在のインストール方法には含まれません。詳しくは [Steam での配布状況](/ja-JP/faq/steam-distribution-status/)を参照してください。

## なぜワークスペースなのか

私は HagiCode の制作者、俞坤（Kun Yu）です。ひとつの質問と回答で目の前の問題は解決できても、実際の開発にはプロジェクトの理解、作業範囲の設定、変更の実施、結果の振り返りも必要です。これまで分かれていた工程をつなげたいと考えました。ゲーム的なフィードバックは、長期的な作業の進捗を見やすくします。必要な機能だけを使って構いません。コードを書き始める前にすべての機能を覚える必要はありません。

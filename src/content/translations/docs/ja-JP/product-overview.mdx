HagiCode はプロジェクト開発向けの AI ワークスペースです。まずセッションでリポジトリを理解し、要件と影響範囲を明確にしてから AI に変更を任せられます。同じ場所で進捗の確認、コミットの準備、プロジェクト知識の再利用もできます。特定のコードエディターへの乗り換えを求めるのではなく、普段使っている Agent CLI とモデルを接続します。

**初めて使う場合は？** [インストール方法を選び](/ja-JP/installation/)、[初期設定ウィザード](/ja-JP/quick-start/wizard-setup)を完了し、プロジェクトを作成して[通常のセッション](/ja-JP/quick-start/conversation-session)から始めてください。実装前に計画が必要なタスクには[提案セッション](/ja-JP/quick-start/proposal-session)を使います。

## 開発タスクの進め方

複数のリポジトリにまたがる機能を変更する場合を例にします。

1. **まず理解する：** [通常のセッション](/ja-JP/quick-start/conversation-session)で既存のコードを調べます。通常のセッションはデフォルトで読み取り専用です。ファイルの変更が必要になったら編集モードに切り替えます。
2. **範囲を決める：** 複雑な変更では、[提案セッション](/ja-JP/quick-start/proposal-session)でプロジェクトとリポジトリを選び、目的、タスク、検証方法を整理してから実行に進みます。
3. **結果を追う：** ワークスペースでセッションと実行状態を確認します。コミットを準備するときは [AI Compose Commit](/ja-JP/guides/ai-compose-commit) を利用できます。
4. **文脈を残す：** 提案やコミット履歴は後から振り返れます。リポジトリ間で作業する場合は [MonoSpecs](/ja-JP/guides/monospecs) でリポジトリの関係と変更範囲を管理します。

毎回提案を作る必要はありません。コードを調べるだけの場合や簡単な問題に対処する場合は、通常のセッションから始められます。より多くの文脈が必要なタスクには、HagiCode が追跡しやすい進行手順を提供します。

## 目的別に機能を探す

| やりたいこと | 最初に読むページ |
| --- | --- |
| 変更するか決める前にコードを理解する | [通常のセッションを作成](/ja-JP/quick-start/conversation-session) |
| 複雑な要件を実装前に計画する | [提案セッションを作成](/ja-JP/quick-start/proposal-session) |
| 複数のリポジトリの関係を AI に伝える | [MonoSpecs ガイド](/ja-JP/guides/monospecs) |
| 拡張機能を検索、インストール、管理する | [Skills ガイド](/ja-JP/guides/skills) |
| 使い慣れた Agent CLI を利用する | [AI Agent CLI のインストールと対応範囲](/ja-JP/related-software-installation/ai-agent-cli/) |
| CLI とモデルの接続を別々に管理する | [OmniRoute のインストールと起動確認](/ja-JP/related-software-installation/omniroute/) |

Vault には参照用リポジトリ、フォルダー、メモをまとめておき、後の作業に再利用できます。Code Server はブラウザーから編集するための入口です。どちらも HagiCode を使い始めるための必須機能ではありません。設計の背景については、[Vault のナレッジベース活用](/ja-JP/blog/2026-04-10-vault-system-ai-knowledge-base/)と[ブラウザー編集の統合](/ja-JP/blog/2026-04-13-vscode-web-integration-browser-editing/)を参照してください。

HagiCode には、ヒーロー、実績、日報、Token の指標を使ったフィードバックもあり、長期間の作業状況と進捗を把握しやすくします。これらはワークスペース体験の一部であり、通常の開発ツールとして使うための条件ではありません。[ゲーミフィケーション設計の記事](/ja-JP/blog/2026-03-16-gamifying-ai-coding/)で背景を説明しています。

## エディションと価格

**Desktop、Container、Microsoft Store は入手・導入方法の違いであり、3 段階の有料プランではありません。**基本機能は無料で利用できます。Microsoft Store で提供する Turbo Engine は別途購入する買い切りライセンスで、提案の同時実行数の上限を引き上げ、ドキュメントテーマ、署名のカスタマイズ、ブランディング、アバターなどの追加機能を利用可能にします。具体的な対象は [Turbo Engine 追加パッケージ](/ja-JP/dlc/turbo-engine-dlc/)を参照してください。

| 利用環境 | 推奨する方法 |
| --- | --- |
| Microsoft Store を利用できる Windows | [Microsoft Store からインストール](/ja-JP/installation/windows-store) |
| Windows への手動インストール、または macOS・Linux でのローカル利用 | [Desktop をインストール](/ja-JP/installation/desktop) |
| サーバー、NAS、チームでの導入 | [Docker Compose でインストール](/ja-JP/installation/docker-compose) |

Steam のメインアプリは提供を終了しており、現在のインストール方法には含まれません。詳しくは [Steam での配布状況](/ja-JP/faq/steam-distribution-status/)を参照してください。

## なぜワークスペースなのか

私は HagiCode の制作者、俞坤（Kun Yu）です。ひとつの質問と回答で目の前の問題は解決できても、実際の開発にはプロジェクトの理解、作業範囲の設定、変更の実施、結果の振り返りも必要です。これまで分かれていた工程をつなげたいと考えました。ゲーム的なフィードバックは、長期的な作業の進捗を見やすくします。必要な機能だけを使って構いません。コードを書き始める前にすべての機能を覚える必要はありません。

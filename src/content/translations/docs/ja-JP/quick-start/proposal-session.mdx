提案セッションは、1 回の自由形式のプロンプトで処理するには重要すぎるリクエストに適した入口です。すぐに編集するのではなく、HagiCode はまずリクエストを目標、スコープ、タスク、検証基準に整理し、レビューを経てから実行に進みます。

## 前提条件

提案セッションを始める前に、次の項目を確認してください。

- [インストールガイド](/ja-JP/installation)に従い、いずれかのインストール方法（Microsoft Store、Desktop、Docker Compose）を完了している
- [ウィザードセットアップ](/ja-JP/quick-start/wizard-setup)を完了している（最初の Agent と少なくとも 1 つのプロジェクトが作成されます）
- 変更内容を説明できるだけのプロジェクトコンテキストがある。足りない場合は、まず[会話セッションを作成する](/ja-JP/quick-start/conversation-session)から始めてください
- 提案セッションの背後にある OpenSpec のワークフローを理解するため、先に [OpenSpec の紹介](/ja-JP/related-software-installation/openspec/intro-openspec)を読んでください

## 提案セッションの用途

提案セッションは、次のような場合に最適です。

- 編集を始める前に、変更の明確なスコープが必要である
- 複数のリポジトリ、モジュール、成果物が関わる
- 作業をレビュー可能なステップに分解したい
- 思考と実行の経緯を後から確認できる状態にしておきたい

リポジトリの理解や軽い議論だけが目的なら、会話セッションのほうが速く済みます。構造とトレーサビリティが必要な場合は、ここから先に進んでください。

## ワークフローの概要

| 段階 | 操作 | 動作 |
| --- | --- | --- |
| アイデアを作成 | **New Idea**（新しいアイデア）をクリックし、リクエストを入力する | 提案セッションが作成され、自動最適化のキューに入ります |
| ドラフトを確認 | セッションカードを開く | HagiCode がタイトルと説明を整え、コンテキスト、問題、解決策、影響のドラフトを作成します |
| 計画を生成 | **Generate Plan** をクリックする | Agent が OpenSpec の計画ファイルを書き出します |
| 計画をレビュー | **Review** タブで計画を読む | コード変更の前に、計画を承認または修正します |
| 実行とアーカイブ | 計画を実行し、アーカイブする | Agent がタスクを実行し、完了した計画がアーカイブされます |

## ステップ 1: **New Idea** ドロワーで変更内容を記述する

プロジェクトを選択し、セッションボード上部のツールバーにある **New Idea**（新芽のアイコン）をクリックします。**Create Proposal** ドロワーが開きます。

![アイデア名、プロジェクト、スコープ、クイックリクエスト、リクエスト本文を含む Create Proposal ドロワー](../../img/quick-start/proposal-session/01-new-idea.png)

ドロワーの項目を順に入力します。

- **Idea Name** と **Project Name**（必須）– リクエストを所有するプロジェクトを確認します。
- **Scope** – **Vault** タブでは、AI が編集してよい vault にチェックを付けます（システム管理の vault は常に参照専用です）。**Projects** タブでは、他のプロジェクトをコンテキストとして追加します。
- **Quick Requests** – *No docs / tests*、*Self commit*、*Output English*、*Ask before edit*、*No backward compatibility* など、ワンクリックで追加できる定型の指示です。
- **You Request** – 実際の変更内容を自然言語で記述します（最大 14,000 文字）。上にある **Combined preview** には、AI に送信される内容がそのまま表示されます。

**Submit idea** をクリックします。作業が複数のリポジトリにまたがる場合は、実行中に追加するのではなく、この時点でその境界を定義してください。

## ステップ 2: 詳細ビューで提案を確認する

送信すると、アイデアはステータスバッジ付きのカードとして **Proposal & Review** レーンに表示されます。クリックして提案の詳細ビューを開きます。

![左にワークフローのステップ、右にドラフトされた説明を表示した提案の詳細ビュー](../../img/quick-start/proposal-session/02-proposal-detail.png)

このビューでは、計画、進捗、会話がひとまとめに管理されます。

- **Workflow steps**（左）は、提案がどの段階にあるかを示します。**Proposal preparation**（*Session Created*、*Auto Optimizing*、*Drafting Ready*）、**Review and refine**（*Generating Plan Files*、*Review Plan*）、**Execution complete**（*Executing Plan*、*Execution Completed*）、**Archive**（*Archiving*、*Archived*）にグループ化されています。
- **Planning directions** は、計画で検討する方向性（変更マップ、インタラクションフロー、アーキテクチャなど）を示します。既定値は **Settings → Process & Interaction → Planning Direction** で調整できます。
- **Info** タブ（右）には、ドラフトされた説明（*Context*、*Problem*、*Solution*、*Impact*）と、元のリクエストが **Chief Complaint** の下に表示されます。クイックアクションから **Open Proposal Folder**、**Optimize Proposal**、**Open in New Window**、**Delete Session** を実行できます。
- **Conversation** タブと **Review** タブには、Agent とのやり取りと、生成された計画のレビューが入っています。
- **Quick Chat**（左下）では、ビューを離れずに Agent へメッセージを送れます。

目標、スコープ、タスクの分解に誤りがあれば、先に進む前にここで提案を修正してください。それがこのワークフローの目的です。

## ステップ 3: 生成、レビュー、実行、アーカイブ

ドラフトが適切になったら、**Generate Plan** をクリックします。Agent が OpenSpec の計画ファイルを書き出し、セッションは **Review Plan** に移行するので、コードが変更される前に結果を確認できます。レビュー後、セッションは **Executing Plan** に進み、最後に **Archiving** と **Archived** へ移ります。

提案の生成、即時実行、アーカイブなど、元に戻しにくい操作の前には、HagiCode が確認を求めます。この確認プロンプトは **Settings → Process & Interaction → Confirm Prompts** で細かく調整できます。

実行後は、[AI Compose Commit](/ja-JP/guides/ai-compose-commit) を使うと、最終的な変更から整ったコミットメッセージを作成できます。

## ステップ 4: セッションボードで提案を追跡する

プロジェクトに複数の提案がある場合や、提案と会話が混在している場合は、セッションボードが最も見やすい概要になります。

![Proposal & Review にドラフト済みの提案、Execution に完了した会話があるセッションボード](../../img/quick-start/proposal-session/03-session-board.png)

- **Proposal & Review** には、ドラフト中、生成中、レビュー中のアイデアが入ります。
- **Execution** には、実行中または完了したセッションが入ります。
- **Archived** には、完了した作業が邪魔にならない形で保管され、いつでもレビューできます。

各カードには、*Optimizing*、*Drafted*、*Reviewing*、*Executing*、*Execution Complete* などのステータスが表示されます。ボードのレイアウトはレイアウト切り替えで変更できます。詳しくは[セッション](/ja-JP/user-guide/sessions)を参照してください。

## 提案セッションを選ぶべき場合

次のような場合は、まず提案セッションを選んでください。

- 変更が複雑で、AI に早い段階で即興的な対応をさせたくない
- 作業を後でレビューしたり、他の人と共有したりする
- 複数のリポジトリ、モジュール、ロールが関わる
- 実行履歴とその根拠を再利用できる形で残したい

タスクがまだ小さく、探索的な段階であれば、通常は会話セッションのほうが軽快です。

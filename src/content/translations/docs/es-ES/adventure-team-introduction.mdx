El **Agent** es el núcleo de HagiCode: las sesiones las ejecuta un Agent y necesita al menos uno antes de empezar a trabajar. Esta página es una visión general que le ayuda a entender de qué se compone un Agent, quién se encarga de cada tipo de trabajo y en qué lugares se reparte la configuración relacionada con los Agents. Para las operaciones paso a paso, consulte la [guía del Agents Workspace](/es-ES/user-guide/agents).

## Descripción general

- Un **Agent = Agent CLI + modelo + texto de personalidad opcional**. La Agent CLI es la herramienta de línea de comandos que ejecuta el trabajo (por ejemplo, Claude Code o Codex), el modelo es el que utiliza, y el texto de personalidad (Trait y Soul) da forma a su manera de trabajar y de expresarse.
- Puede crear varios Agents; por ejemplo, uno con Opus para revisar, otro con Haiku para cambios rápidos y otro con Codex para refactorizar.
- Qué Agent se usa para cada tipo de trabajo lo deciden los **escenarios de ejecución**; cuando no hay ningún miembro adecuado, lo asume la **Fallback Crew**.
- La revisión y el ajuste de los Agents se reparten entre el **Agents Workspace** y los **ajustes**: el primero gestiona los Agents, los escenarios, las CLI y los modelos, y los segundos gestionan el comportamiento en ejecución, como los reintentos y el límite de memoria.

## Lista de Agents

![Pestaña Agents: cinco Agents agrupados por Claude Code y Codex, cada uno con su avatar y su modelo](../img/screenshots/guides/agent-roster/original.png)

Haga clic en **Agents** en la barra superior para abrir el **Agents Workspace**. En la pestaña **Agents**, **My Agents** enumera sus Agents agrupados por Agent CLI, y cada tarjeta muestra el avatar, el nombre y el modelo. Desde aquí puede:

1. Crear un Agent con **New Agent**: elija una AgentCLI y un modelo compatible y, si lo desea, escriba un Trait (conocimientos y comportamiento) y un Soul (estilo del lenguaje).
2. Crear varios a la vez con **Batch create Agents**, o filtrar con el cuadro de búsqueda por nombre, CLI o descripción.
3. Habilitar o deshabilitar un Agent con el interruptor **Battle ready**.

La explicación completa del proceso de creación está en [Agents](/es-ES/user-guide/agents#创建-agent).

## Reparto del trabajo: escenarios de ejecución y Fallback Crew

![Pestaña Execution Scenarios: los equipos de Agents de los escenarios de propuesta y HagiTask, y a la derecha los Agents asignados y los disponibles](../img/screenshots/guides/agent-scenarios/original.png)

La pestaña **Execution Scenarios** decide qué Agents hacen cada tipo de trabajo. Los escenarios se agrupan según su finalidad:

| Grupo | Escenarios |
| --- | --- |
| **Proposal** | Optimizar, generar, ejecutar y archivar propuestas |
| **HagiTask** | Super Commit, crear una sesión normal, crear una tarea de investigación de código |
| **Chat** | Optimización del título de la sesión |

Al hacer clic en un escenario, a la derecha **Assigned Agents** muestra su equipo y **Available Agents** muestra los Agents que se pueden incorporar; use **Add** o **Remove** para ajustarlo. La **Fallback Crew** es la red de seguridad: cuando el equipo propio de un escenario no tiene ningún Agent adecuado, HagiCode elige un miembro que cumpla las condiciones de la Fallback Crew. **Hasta que la Fallback Crew tenga al menos un Agent habilitado, los demás escenarios permanecen bloqueados.** El asistente de inicialización añade automáticamente su primer Agent.

Una combinación habitual:

1. Ponga en **Generate Proposal** un Agent bueno con contextos largos y en revisión.
2. Ponga en **Execute Proposal** un Agent con buena capacidad de ejecución y un coste adecuado.
3. Ponga en **Super Commit** y **Conversation Title Optimization** Agents baratos y rápidos.
4. Deje en la Fallback Crew un Agent generalista estable.

## Dónde está la configuración relacionada

| Qué quiere hacer | Dónde |
| --- | --- |
| Crear, editar, habilitar o deshabilitar Agents | **Agents** → pestaña **Agents** |
| Asignar Agents a cada tipo de trabajo y mantener la Fallback Crew | **Agents** → **Execution Scenarios** |
| Ver si una Agent CLI está instalada, sana y habilitada | **Agents** → **AgentCLI**, y la ventana emergente AI Monitoring de la barra de estado |
| Explorar o añadir los modelos disponibles de una CLI | **Agents** → **Model** |
| Cambiar el avatar o el tema de textos | **Agents** → **Avatar Gallery** / **Document Theme** |
| Reintento automático de las ejecuciones fallidas | **Ajustes** → **Error Retry** |
| Si el prompt generado declara que "esta ejecución no es interactiva" | **Ajustes** → **AgentCLI Interactive Control** |
| Limitar la memoria que puede usar cada Agent | **Ajustes** → **Agent Memory Limit** |
| Conectar varios modelos compatibles con OpenAI a una misma pasarela local | **Ajustes** → **OmniRoute** |

Para saber qué hace cada ajuste, consulte [Ajustes](/es-ES/user-guide/settings).

## Casos de uso y límites

- Cuando quiera usar modelos o CLI distintos en cada fase (por ejemplo, separar la revisión de la ejecución), reparta el trabajo por escenarios.
- También se puede usar con un solo Agent: póngalo en la Fallback Crew y todos los escenarios lo usarán.
- El Agent solo decide **quién ejecuta**. Qué se ejecuta sigue procediendo de las sesiones, propuestas o planes que usted crea.

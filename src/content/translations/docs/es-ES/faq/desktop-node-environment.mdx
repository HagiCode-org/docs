HagiCode Desktop usa los **comandos externos `node` y `npm` instalados en su sistema**. Instale Node.js antes de iniciar Desktop por primera vez y asegúrese de que ambos comandos estén disponibles en el `PATH` del sistema.

Estas preguntas frecuentes explican cómo Desktop encuentra su entorno externo de Node, dónde se instalan los Agent CLI y cómo resolver los problemas cuando no se encuentra Node o npm.

## Requisitos de versión

Se requiere **Node.js 24 o superior** (el mínimo también es 24). `npm` se instala junto con Node.js. Para saber cómo instalarlo, consulte [Instalar Node.js](/es-ES/related-software-installation/nodejs/installation).

Git también debe instalarlo usted mismo; consulte la [Guía de instalación](/es-ES/installation/#instalar-git).

## Cómo encuentra Desktop node y npm

Desktop lee el `PATH` del sistema al iniciarse y busca en él `node`, `npm` y `git`. Esto significa que:

- La versión que ve al ejecutar `node --version` en la terminal suele ser la que usa Desktop.
- Desktop solo **usa** su entorno de Node; no lo sustituye ni lo modifica.
- Si instala o actualiza Node.js con Desktop ya abierto, ciérrelo por completo y vuelva a iniciarlo para que lea el nuevo `PATH`.

:::caution[Gestores de versiones y PATH]
En macOS y Linux, gestores de versiones como nvm y fnm suelen definir el `PATH` solo en los archivos de configuración del shell. Desktop, cuando se inicia desde el Dock, el menú de aplicaciones o un icono del escritorio, no lee esa configuración y es posible que no encuentre `node`. Inicie Desktop desde una terminal en la que `node` ya funcione, o use una instalación a nivel de sistema.
:::

## Dónde se instalan los paquetes gestionados, como los Agent CLI

La página de gestión de dependencias de Desktop detecta los `node` y `npm` del `PATH`, muestra el prefijo global de npm que se ha resuelto e instala los paquetes de CLI que figuran en el catálogo en ese directorio global **externo**.

Para cada CLI gestionado, Desktop busca el ejecutable en este orden:

1. Una ruta gestionada que ya exista
2. El directorio `bin` global de npm (en Windows, incluye los scripts de inicio `.cmd` y `.ps1`)
3. El `PATH`

La configuración del espejo de npm se aplica a las operaciones de instalación y sincronización. La desinstalación también actúa sobre el directorio global externo y requiere confirmación en la interfaz. Puede consultar el directorio global actual con el siguiente comando:

```bash
npm prefix -g
```

Si el directorio global está en una ubicación que requiere privilegios de administrador, durante la instalación puede aparecer un error de permisos; consulte [Configurar el directorio global de npm](/es-ES/related-software-installation/nodejs/installation#configurar-el-directorio-global-de-npm).

## Qué hacer si Desktop no encuentra Node o npm

1. Ejecute `node --version` en la terminal y confirme que Node.js sea la versión 24 o superior. Después, ejecute `npm --version` para confirmar que npm esté disponible.
2. Si no está instalado o la versión es demasiado antigua, instale primero Node.js fuera de Desktop.
3. Cierre Desktop por completo y vuelva a iniciarlo; después, vuelva a la página de dependencias y haga clic en actualizar.

Cuando Desktop indique que hay que instalar manualmente un paquete de CLI, ejecute el comando que muestra en una terminal ajena a Desktop y, al terminar, vuelva a Desktop y actualice una vez para que lo detecte de nuevo.

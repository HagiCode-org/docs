Un **proyecto** es la carpeta en la que trabaja HagiCode. Las sesiones, el estado de Git, los términos estándar y la configuración de MonoSpecs pertenecen a un proyecto, por eso la barra de proyectos en el borde izquierdo del espacio de trabajo es el punto de partida de la mayoría de las tareas.

## Barra de proyectos

La barra de proyectos está plegada de forma predeterminada y cada proyecto muestra solo un icono circular. Haz clic en la pequeña flecha de la parte superior de la barra para expandirla.

![Barra de proyectos expandida, con los proyectos All Sessions y orbit-notes y el botón + para añadir proyectos](../../img/user-guide/workbench/02-project-rail.png)

- **All Sessions** (Todas las sesiones) muestra en un mismo tablero las sesiones de todos los proyectos.
- Al hacer clic en un proyecto, el tablero muestra solo las sesiones de ese proyecto y lo presenta en el panel del proyecto.
- El botón verde **+** sirve para crear un proyecto nuevo. La flecha que está junto a él vuelve a plegar la barra de proyectos.

:::tip[¿Qué proyectos aparecen en el tablero "All Sessions"?]
En **Settings → Sessions and conversation → Session List** (Configuración → Proceso e interacción → Lista de sesiones), puedes cambiar el alcance de *All Projects* (Todos los proyectos) a *Custom Selection* (Selección personalizada) con algunos proyectos. Consulta [Configuración](/user-guide/settings).
:::

## Nuevo proyecto

Haz clic en **+** en la barra de proyectos para abrir el diálogo **New Project** (Nuevo proyecto). Ofrece tres formas de añadir proyectos.

### Proyecto individual

Usa esta opción cuando la carpeta del proyecto ya existe en el disco. Corresponde a la pestaña **Single Project** (Proyecto individual).

![Pestaña Single Project del diálogo de nuevo proyecto, con el nombre, la ruta de la carpeta y la descripción completados](../../img/user-guide/projects/01-create-project.png)

| Campo | Descripción |
| --- | --- |
| **Project Name** (Nombre del proyecto) | Obligatorio, hasta 200 caracteres. |
| **Folder Path** (Ruta de la carpeta) | Obligatoria, hasta 1000 caracteres. Introduce la ruta absoluta de la carpeta, por ejemplo `/home/user/projects/orbit-notes`. |
| **Project Description** (Descripción del proyecto) | Opcional, hasta 1000 caracteres. |

Cuando la ruta contiene `.hagicode/monospecs.yaml`, el diálogo lo detecta y muestra una guía de MonoSpecs para ese proyecto. Consulta [MonoSpecs](/guides/monospecs).

### Creación por lotes

Usa esta opción cuando varios repositorios están dentro de una misma carpeta principal. Corresponde a la pestaña **Batch Create** (Creación por lotes).

![Pestaña Batch Create del diálogo de nuevo proyecto, que pide seleccionar la carpeta que se va a analizar](../../img/user-guide/projects/02-create-project-batch.png)

Introduce la ruta completa de la carpeta principal. HagiCode busca repositorios Git revisando hasta tres niveles de directorios y registra cada repositorio encontrado como un proyecto.

### Proyecto de demostración

Usa esta opción si quieres probar HagiCode antes de conectar tu propio código. Corresponde a la pestaña **Demo Project** (Proyecto de demostración).

![Pestaña Demo Project del diálogo de nuevo proyecto, que muestra el repositorio MonoSpecs Demo y su ruta de destino](../../img/user-guide/projects/03-create-project-demo.png)

HagiCode clona el repositorio oficial de demostración de MonoSpecs (`https://github.com/HagiCode-org/monospecs-demo`) y lo registra como proyecto. Para ello necesitas tener Git instalado en tu equipo. La interfaz muestra la ruta predeterminada; la carpeta real depende del directorio de datos de tu entorno de ejecución.

## Panel del proyecto

Al seleccionar un proyecto, el panel del proyecto aparece a la derecha del tablero.

![Panel del proyecto orbit-notes, con Quick actions y Repository status](../../img/user-guide/workbench/06-project-panel.png)

**Quick actions** (Acciones rápidas)

| Botón | Función |
| --- | --- |
| **Auto Super Commit** | Inicia un commit asistido por IA para el proyecto. Consulta [Super Commit](/guides/ai-compose-commit). |
| **Open Code Server** (Abrir Code Server) | Abre el proyecto en un editor de código basado en navegador. |
| **Open Git Management** (Abrir gestión de Git) | Abre la pestaña Git del cajón de detalles del proyecto. |
| **View Project Details** (Ver detalles del proyecto) | Abre el cajón de detalles del proyecto. |

**Repository status** (Estado del repositorio) enumera cada repositorio del proyecto con su rama actual. El punto de color indica el estado del área de trabajo. En la captura, el punto es rojo porque `src/server.js` tiene cambios sin confirmar. Haz clic en el botón de actualizar para volver a leer el estado.

El menú **Recent changes** (Cambios recientes) de la barra del tablero enumera los repositorios con cambios recientes. Si ningún repositorio tiene cambios, muestra "Sin cambios recientes".

## Detalles del proyecto

Haz clic en **View Project Details** para abrir el cajón. Tiene cuatro pestañas.

### Detalles

Corresponde a la pestaña **Details** (Detalles).

![Pestaña Details del cajón de detalles del proyecto, con la configuración de nombre, ruta, descripción e icono](../../img/user-guide/projects/04-project-details.png)

- **Name** (Nombre), **Path** (Ruta) y **Description** (Descripción): la información básica del proyecto.
- **Icon Settings** (Configuración del icono): elige *Game Icon* (Icono de juego) o *Text Abbreviation* (Abreviatura de texto) para el avatar del proyecto. **Change Icon** (Cambiar icono) abre el selector de iconos.
- **Manage DESIGN.md** (Gestionar DESIGN.md): gestiona el archivo `DESIGN.md` del proyecto.
- **Delete Project** (Eliminar proyecto): elimina el proyecto después de escribir su nombre para confirmar. El cuadro de confirmación enumera lo que se eliminará de forma permanente: todas las sesiones del proyecto y todos los mensajes de esas sesiones. Esta acción no se puede deshacer.

### MonoSpecs

![Pestaña MonoSpecs, que indica inicializar MonoSpecs en el proyecto](../../img/user-guide/projects/05-project-monospecs.png)

MonoSpecs convierte el proyecto en un espacio de trabajo que coordina especificaciones y varios repositorios. En un proyecto que todavía no es un espacio de trabajo de MonoSpecs, **Initialize MonoSpecs** (Inicializar MonoSpecs) crea solo lo necesario y no clona ningún repositorio automáticamente:

- `.hagicode/monospecs.yaml`
- La carpeta `repos/`, donde se guardan los subrepositorios
- `openspec/changes/archive/` y `openspec/specs/`
- Una actualización de `.gitignore` para que la carpeta `repos/` quede sin seguimiento

Antes de inicializar, lee la [guía de MonoSpecs](/guides/monospecs).

### Términos estándar

Corresponde a la pestaña **Standard Words** (Términos estándar).

![Pestaña Standard Words, con la lista de grupos vacía y el botón Add group](../../img/user-guide/projects/06-project-standard-words.png)

Los términos estándar son el vocabulario compartido del proyecto y se guardan en `.hagicode/standard_words.yaml`. La pestaña muestra cuántos grupos, frases y etiquetas hay, y permite buscar, **Add group** (Añadir grupo), **Refresh** (Actualizar) desde el disco y **Save changes** (Guardar cambios).

### Git

![Pestaña Git, con la lista de repositorios a la izquierda y el resumen del repositorio a la derecha, junto con las acciones Push, Pull y Super Commit](../../img/user-guide/projects/07-git-management.png)

La pestaña Git es la consola de Git del proyecto.

- **La lista de repositorios** (a la izquierda) muestra los repositorios supervisados. El contador (por ejemplo, `1 / 15`) lo compara con el límite de supervisión definido en **Settings → Integration → Git** (Configuración → Integración → Git). Las acciones por lotes son **Select Changed** (Seleccionar repositorios con cambios), **Select All** (Seleccionar todos los repositorios) y **Clear Selection** (Borrar selección). También puedes buscar por nombre. **Manage Super Commit All exclusions** (Gestionar exclusiones de Super Commit All) controla qué archivos omite el commit rápido.
- **El resumen del repositorio** (a la derecha) muestra la rama, el estado de sincronización, si hay cambios sin confirmar, los repositorios remotos y la ruta del repositorio.
- Las acciones sobre el repositorio seleccionado son **Super Commit**, **Push** (Subir), **Pull** (Descargar), **Rebase Upstream** (Rebase sobre upstream), **Open Remote Repository** (Abrir repositorio remoto), **Open Code Server** (Abrir Code Server) y **Manage DESIGN.md** (Gestionar DESIGN.md).

Este resumen sustituye a propósito la vista previa de diferencias. Para operaciones de Git más avanzadas, usa **Open Code Server** (Abrir Code Server).

El comportamiento de Git, como el Git Profile, la supervisión del estado y la acción predeterminada de Super Commit, se configura en **Settings → Integration → Git** (Configuración → Integración → Git).

**Agent**는 HagiCode의 핵심입니다. 세션은 Agent가 실행하며, 작업을 시작하려면 최소 하나가 필요합니다. 이 페이지는 Agent가 무엇으로 구성되는지, 작업 유형별로 누가 일을 맡는지, Agent와 관련된 설정이 어디에 흩어져 있는지 파악하도록 돕는 개요입니다. 항목별 조작 방법은 [Agents 작업 공간 가이드](/ko-KR/user-guide/agents)를 참고하세요.

## 기능 개요

- 하나의 **Agent = Agent CLI + 모델 + 선택적 성격 텍스트**입니다. Agent CLI는 실제로 실행되는 명령줄 도구(예: Claude Code, Codex)이고, 모델은 그 도구가 사용하는 모델이며, 성격 텍스트(Trait와 Soul)는 작업 방식과 말투를 형성합니다.
- Agent를 여러 개 만들 수 있습니다. 예를 들어 Opus로 리뷰하는 Agent, Haiku로 빠르게 수정하는 Agent, Codex로 리팩터링하는 Agent를 따로 둘 수 있습니다.
- 각 유형의 작업에 어떤 Agent를 쓸지는 **실행 시나리오**가 결정하며, 적합한 구성원이 없으면 **Fallback Crew**가 이어받습니다.
- Agent의 확인과 조정은 **Agents 작업 공간**과 **설정**에 나뉘어 있습니다. 전자는 Agent, 시나리오, CLI, 모델을 관리하고, 후자는 재시도와 메모리 상한 같은 런타임 동작을 관리합니다.

## Agent 목록

![Agents 탭: 다섯 개의 Agent가 Claude Code와 Codex별로 묶여 있고, 각각 아바타와 모델이 표시됩니다](../img/screenshots/guides/agent-roster/original.png)

상단 바의 **Agents**를 클릭하면 **Agents Workspace**가 열립니다. **Agents** 탭의 **My Agents**는 Agent CLI별로 Agent를 묶어 보여 주며, 각 카드에는 아바타, 이름, 모델이 표시됩니다. 여기서 다음 작업을 할 수 있습니다.

1. **New Agent**로 Agent를 만듭니다. AgentCLI와 호환되는 모델을 선택하고, 필요하면 Trait(지식과 행동)와 Soul(언어 스타일)을 작성합니다.
2. **Batch create Agents**로 여러 개를 한 번에 만들거나, 검색창에서 이름, CLI, 소개로 필터링합니다.
3. **Battle ready** 스위치로 특정 Agent를 활성화하거나 비활성화합니다.

생성 과정의 전체 설명은 [Agents](/ko-KR/user-guide/agents#agent-만들기)를 참고하세요.

## 역할 분담: 실행 시나리오와 Fallback Crew

![Execution Scenarios 탭: Proposal과 HagiTask 시나리오별 Agent 편성, 오른쪽에는 편성된 Agent와 추가 가능한 Agent가 표시됩니다](../img/screenshots/guides/agent-scenarios/original.png)

**Execution Scenarios** 탭은 각 유형의 작업을 어떤 Agent가 맡을지 결정합니다. 시나리오는 용도별로 묶여 있습니다.

| 그룹 | 시나리오 |
| --- | --- |
| **Proposal** | 제안 최적화, 생성, 실행, 보관 |
| **HagiTask** | Super Commit, 일반 세션 생성, 코드 조사 작업 생성 |
| **Chat** | 세션 제목 최적화 |

시나리오를 클릭하면 오른쪽의 **Assigned Agents**에 해당 편성이, **Available Agents**에 추가할 수 있는 Agent가 표시됩니다. **Add** 또는 **Remove**를 눌러 조정하세요. **Fallback Crew**는 안전망입니다. 어떤 시나리오 자체의 편성에 적합한 Agent가 없으면 HagiCode가 Fallback Crew에서 조건에 맞는 구성원을 고릅니다. **Fallback Crew에 활성화된 Agent가 최소 하나 있어야 다른 시나리오의 잠금이 해제됩니다.** 초기 설정 마법사가 첫 번째 Agent를 자동으로 추가합니다.

일반적인 구성 예시입니다.

1. 긴 컨텍스트와 리뷰에 강한 Agent를 **Generate Proposal**에 둡니다.
2. 실행력이 좋고 비용이 적당한 Agent를 **Execute Proposal**에 둡니다.
3. 저렴하고 빠른 Agent를 **Super Commit**과 **Conversation Title Optimization**에 둡니다.
4. Fallback Crew에는 안정적인 범용 Agent 하나를 남겨 둡니다.

## 관련 설정은 어디에 있나요

| 하려는 작업 | 위치 |
| --- | --- |
| Agent 만들기, 편집, 활성화 또는 비활성화 | **Agents** → **Agents** 탭 |
| 작업 유형별 Agent 지정, Fallback Crew 관리 | **Agents** → **Execution Scenarios** |
| Agent CLI의 설치, 상태, 활성화 여부 확인 | **Agents** → **AgentCLI**, 상태 표시줄의 AI Monitoring 팝오버 |
| CLI에서 사용할 수 있는 모델 둘러보기 또는 추가 | **Agents** → **Model** |
| 아바타, 문구 테마 변경 | **Agents** → **Avatar Gallery** / **Document Theme** |
| 실패한 실행의 자동 재시도 | **설정** → **Error Retry** |
| 생성 프롬프트에 "이번 실행은 비대화형"이라고 명시할지 여부 | **설정** → **AgentCLI Interactive Control** |
| 각 Agent가 사용할 수 있는 메모리 제한 | **설정** → **Agent Memory Limit** |
| 여러 OpenAI 호환 모델을 하나의 로컬 게이트웨이에 연결 | **설정** → **OmniRoute** |

각 설정 항목의 역할은 [설정](/ko-KR/user-guide/settings)을 참고하세요.

## 적용 시나리오와 범위

- 단계마다 다른 모델이나 CLI를 쓰고 싶다면(예: 리뷰와 실행 분리) 시나리오별로 역할을 나누세요.
- Agent가 하나뿐이어도 충분히 사용할 수 있습니다. 그 Agent를 Fallback Crew에 넣으면 모든 시나리오에서 사용됩니다.
- Agent는 **누가 실행하는지**만 결정합니다. 무엇을 실행할지는 여전히 사용자가 만든 세션, 제안, 계획에서 정해집니다.

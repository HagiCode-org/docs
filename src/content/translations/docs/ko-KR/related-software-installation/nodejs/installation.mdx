이 페이지에서는 Windows, macOS, Linux에 Node.js를 설치하는 방법을 설명합니다. Desktop과 Microsoft Store 버전은 더 이상 Node.js를 내장하지 않고 시스템의 `node`와 `npm`을 그대로 사용하며, OpenSpec과 대부분의 Agent CLI도 이에 의존합니다.

:::tip[버전 요구 사항]
**Node.js 24 이상**이 필요하며, 최소 요구 사항도 24입니다. 보통은 최신 LTS 버전을 설치하면 됩니다. `npm`은 Node.js와 함께 설치되므로 따로 설치할 필요가 없습니다.
:::

:::note[이 도구가 필요한 설치 방식]
- **Microsoft Store / Desktop**: 필요합니다. 시스템 `PATH`에서 `node`와 `npm`을 찾을 수 있어야 합니다.
:::

## Node.js 설치

<Tabs>
  <TabItem value="windows" label="Windows" default>

### 방법 1: 공식 설치 프로그램(권장)

1. [Node.js 공식 웹사이트](https://nodejs.org/)에 접속합니다
2. **LTS(장기 지원)** 버전의 Windows 설치 프로그램(`.msi` 파일)을 내려받고 버전이 24 이상인지 확인합니다
3. 설치 프로그램을 더블 클릭해 실행합니다
4. 설치 마법사의 안내에 따라 설치를 진행합니다.
   - 사용 계약에 동의합니다
   - 설치 경로를 선택합니다(기본값 그대로 두어도 됩니다)
   - "Add to PATH"가 선택된 상태를 유지합니다
   - "Install"을 클릭해 설치를 시작합니다
5. 설치가 끝나면 "Finish"를 클릭합니다

### 방법 2: winget 사용

PowerShell 또는 명령 프롬프트를 열고 다음 명령을 실행합니다.

```powershell
winget install OpenJS.NodeJS.LTS
```

설치가 끝나면 변경 사항이 적용되도록 터미널을 다시 엽니다.

  </TabItem>
  <TabItem value="macos" label="macOS">

### 방법 1: 공식 설치 프로그램(권장)

1. [Node.js 공식 웹사이트](https://nodejs.org/)에 접속합니다
2. **LTS(장기 지원)** 버전의 macOS 설치 프로그램(`.pkg` 파일)을 내려받고 버전이 24 이상인지 확인합니다
3. 설치 프로그램을 더블 클릭해 실행합니다
4. 설치 마법사의 안내에 따라 설치를 진행합니다.
   - "계속"을 클릭합니다
   - 사용 계약에 동의합니다
   - 설치할 디스크를 선택합니다
   - "설치"를 클릭하고 관리자 암호를 입력합니다
5. 설치가 끝나면 "닫기"를 클릭합니다

### 방법 2: Homebrew 사용

[Homebrew](https://brew.sh/)가 이미 설치되어 있다면 터미널에서 Node.js를 설치할 수 있습니다.

```bash
brew install node
```

:::tip
Homebrew는 Node.js를 `PATH`에 자동으로 추가합니다. 명령을 사용할 수 없다면 터미널을 다시 시작하거나 다음을 실행하세요.
```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```
:::

### NodeSource 저장소 사용(권장)

배포판에 기본으로 포함된 저장소의 Node.js는 보통 24 미만이므로, NodeSource가 제공하는 24.x 저장소를 사용하세요.

```bash
# curl로 설치 스크립트 내려받기
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs
```

:::caution
`sudo apt-get install nodejs npm`으로 배포판에 포함된 버전을 그대로 설치하지 마세요. 24 이상이라는 최소 요구 사항을 충족하지 못할 가능성이 큽니다.
:::

서드파티 소프트웨어 저장소를 추가하고 싶지 않다면 아래의 [nvm 또는 fnm](#버전-관리-도구-사용)을 사용할 수도 있습니다.

  </TabItem>
  <TabItem value="centos" label="CentOS/RHEL">

### NodeSource 저장소 사용(권장)

```bash
# curl로 설치 스크립트 내려받기
curl -fsSL https://rpm.nodesource.com/setup_24.x | sudo bash -
sudo yum install -y nodejs
```

배포판에 기본으로 포함된 저장소의 Node.js는 보통 24 미만이므로 그대로 사용하는 것은 권장하지 않습니다. 아래의 [nvm 또는 fnm](#버전-관리-도구-사용)을 대신 사용할 수도 있습니다.

  </TabItem>
  <TabItem value="fedora" label="Fedora">

### dnf 패키지 관리자 사용

```bash
sudo dnf install -y nodejs npm
```

설치한 뒤 `node --version`을 실행해 버전이 24 이상인지 확인하세요. 저장소의 버전이 낮다면 NodeSource의 24.x 저장소를 사용하거나 아래의 [nvm 또는 fnm](#버전-관리-도구-사용)을 사용하세요.

## 버전 관리 도구 사용

여러 Node.js 버전 사이를 전환해야 한다면 버전 관리 도구를 사용할 수 있습니다.

:::caution[Desktop 사용자 유의 사항]
macOS와 Linux에서 nvm, fnm 같은 도구는 대개 셸 설정 파일(`.bashrc`, `.zshrc` 등)에서만 `PATH`를 설정합니다. Dock, 앱 메뉴, 바탕화면 아이콘에서 실행한 Desktop은 이 설정을 읽지 않아 `node`를 찾지 못할 수 있습니다. 버전 관리 도구를 사용한다면 이미 `node`를 실행할 수 있는 터미널에서 Desktop을 시작하거나, 위의 시스템 수준 설치 방법을 사용하세요.
:::

### nvm (Node Version Manager)

<Tabs>
  <TabItem value="nvm-install" label="nvm 설치" default>

#### Linux/macOS

[nvm 공식 저장소 README](https://github.com/nvm-sh/nvm#installing-and-updating)에 안내된 최신 설치 명령을 그대로 복사해 사용하고, 오래된 버전의 설치 스크립트 주소는 사용하지 마세요.

설치가 끝나면 셸 설정을 다시 불러옵니다.

```bash
source ~/.bashrc
# Zsh 사용자의 경우
source ~/.zshrc
```

#### Windows

Windows에서는 [nvm-windows](https://github.com/coreybutler/nvm-windows)를 사용하는 것이 좋습니다.

1. [nvm-windows releases](https://github.com/coreybutler/nvm-windows/releases)에서 최신 `nvm-setup.exe`를 내려받습니다
2. 설치 프로그램을 실행합니다
3. 명령 프롬프트 또는 PowerShell을 다시 엽니다

  </TabItem>
  <TabItem value="nvm-use" label="nvm 사용">

nvm을 설치한 뒤에는 nvm으로 Node.js 버전을 설치하고 관리할 수 있습니다.

```bash
# Node.js 24 설치
nvm install 24

# Node.js 24로 전환
nvm use 24

# 기본 버전 설정
nvm alias default 24

# 설치된 버전 목록 보기
nvm list
```

nvm-windows에서는 `alias` 명령을 사용할 수 없으므로 `nvm install 24`와 `nvm use 24`만 사용하면 됩니다.

  </TabItem>
</Tabs>

### fnm (Fast Node Manager)

fnm은 Rust로 만든, 더 빠르고 간단한 Node.js 버전 관리 도구입니다.

<Tabs>
  <TabItem value="fnm-install" label="fnm 설치" default>

#### Linux/macOS

```bash
# curl로 설치
curl -fsSL https://fnm.vercel.app/install | bash

# 설치가 끝나면 셸 설정을 다시 불러오기
source ~/.bashrc
# Zsh 사용자의 경우
source ~/.zshrc
```

#### Windows

[scoop](https://scoop.sh/) 또는 [winget](https://learn.microsoft.com/en-us/windows/package-manager/winget/)을 사용합니다.

```powershell
# scoop 사용
scoop install fnm

# 또는 winget 사용
winget install Schniz.fnm
```

  </TabItem>
  <TabItem value="fnm-use" label="fnm 사용">

```bash
# Node.js 24 설치
fnm install 24

# Node.js 24로 전환
fnm use 24

# 기본 버전 설정
fnm default 24

# 설치된 버전 목록 보기
fnm list
```

  </TabItem>
</Tabs>

## 중국 본토 사용자를 위한 가속화

중국 본토에서는 Node.js와 npm 패키지를 내려받는 속도가 느릴 수 있으며, 이때는 국내 미러를 사용할 수 있습니다.

### npm 미러

```bash
# 미러를 일시적으로 사용해 설치
npm install --registry=https://registry.npmmirror.com

# 미러를 영구적으로 설정
npm config set registry https://registry.npmmirror.com

# 미러가 올바르게 설정되었는지 확인
npm config get registry
```

### Node.js 설치 프로그램 미러

Node.js 설치 프로그램도 미러 다운로드 주소가 있습니다: [https://npmmirror.com/mirrors/node/](https://npmmirror.com/mirrors/node/). 접속한 뒤 24 이상 버전을 선택해 내려받으세요.

### Homebrew 미러

중국 본토에서 Homebrew를 사용한다면 bottle에 중국과학기술대학(USTC) 미러를 설정할 수 있습니다.

```bash
export HOMEBREW_BOTTLE_DOMAIN=https://mirrors.ustc.edu.cn/homebrew-bottles
```

## 설치 확인

설치가 끝나면 **새로 연 터미널**에서 Node.js와 npm을 사용할 수 있는지 확인합니다.

```bash
# Node.js 버전 확인(v24.0.0 이상 필요)
node --version

# npm 버전 확인
npm --version
```

정상적인 출력은 다음과 비슷합니다.

```
$ node --version
v24.3.0

$ npm --version
11.4.2
```

:::note
`node --version`이 24 미만의 버전을 표시한다면 위의 방법으로 다시 설치하거나, 버전 관리 도구로 24 이상 버전으로 전환하세요.
:::

## npm 전역 디렉터리 설정

Desktop은 Agent CLI 같은 관리 대상 패키지를 로컬 npm의 전역 디렉터리에 설치합니다. 전역 디렉터리가 관리자 권한이 필요한 위치에 있으면 설치할 때 `EACCES` 권한 오류가 발생할 수 있습니다. 시스템 디렉터리의 권한을 수정하는 대신 전역 디렉터리를 사용자 디렉터리로 옮기는 것을 권장합니다.

```bash
mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
```

그런 다음 `~/.npm-global/bin`(Windows에서는 npm 전역 디렉터리 자체)을 시스템 `PATH`에 추가하고 터미널과 Desktop을 다시 시작합니다. nvm이나 fnm을 사용한다면 전역 디렉터리가 이미 사용자 디렉터리 아래에 있으므로 이 단계는 필요하지 않습니다.

## 문제 해결

### Windows 문제

<Tabs>
  <TabItem value="win-path" label="명령을 사용할 수 없음">

설치한 뒤 `node` 또는 `npm` 명령을 사용할 수 없는 경우:

1. 명령 프롬프트 또는 PowerShell을 다시 시작합니다
2. 그래도 사용할 수 없다면 Node.js를 `PATH`에 수동으로 추가합니다.
   - "환경 변수"를 검색해 "시스템 환경 변수 편집"을 엽니다
   - "환경 변수"를 클릭합니다
   - "시스템 변수"에서 "Path"를 찾아 "편집"을 클릭합니다
   - Node.js 설치 경로를 추가합니다(기본값: `C:\Program Files\nodejs\`)
   - "확인"을 클릭해 변경 사항을 저장합니다
3. Desktop을 완전히 종료한 뒤 다시 시작합니다

  </TabItem>
  <TabItem value="win-policy" label="PowerShell 실행 정책">

nvm 또는 npm 스크립트를 사용할 때 실행 정책 오류가 발생하는 경우:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

  </TabItem>
</Tabs>

### macOS 문제

<Tabs>
  <TabItem value="mac-perm" label="권한 오류">

전역 npm 패키지를 설치할 때 권한 오류가 발생하면 위의 [npm 전역 디렉터리 설정](#npm-전역-디렉터리-설정)을 참고하거나 nvm / fnm을 대신 사용하세요.

  </TabItem>
  <TabItem value="mac-path" label="명령을 사용할 수 없음">

설치한 뒤 명령을 사용할 수 없다면 터미널을 다시 시작하고, Node.js가 있는 디렉터리(보통 `/usr/local/bin` 또는 `/opt/homebrew/bin`)가 `PATH`에 포함되어 있는지 확인하세요.

  </TabItem>
</Tabs>

### Linux 문제

<Tabs>
  <TabItem value="linux-perm" label="권한 오류">

전역 npm 패키지를 설치할 때 권한 오류가 발생하면 위의 [npm 전역 디렉터리 설정](#npm-전역-디렉터리-설정)을 참고하거나, `sudo`로 전역 패키지를 설치하는 대신 nvm / fnm을 사용하세요.

  </TabItem>
  <TabItem value="linux-old" label="버전이 너무 오래됨">

시스템 패키지 관리자로 설치한 Node.js 버전이 24 미만인 경우:

1. NodeSource의 24.x 저장소를 사용합니다(위 참고)
2. 또는 버전 관리 도구(nvm / fnm)를 사용합니다

  </TabItem>
</Tabs>

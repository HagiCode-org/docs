HagiCode는 프로젝트 개발을 위한 AI 작업 공간입니다. 세션에서 저장소를 파악한 뒤 요구 사항과 영향 범위를 정하고, AI에 변경을 맡길 수 있습니다. 같은 곳에서 진행 상황을 확인하고 커밋을 준비하며 프로젝트 지식을 재사용할 수도 있습니다. 특정 코드 편집기를 사용하도록 요구하는 대신, 이미 사용 중인 Agent CLI와 모델을 연결합니다.

**처음 사용하시나요?** [설치 방법을 선택](/ko-KR/installation/)하고 [초기 설정 마법사](/ko-KR/quick-start/wizard-setup)를 완료한 다음, 프로젝트를 만들어 [일반 세션](/ko-KR/quick-start/conversation-session)으로 시작하세요. 구현 전에 계획이 필요한 작업에는 [제안 세션](/ko-KR/quick-start/proposal-session)을 사용하세요.

## 개발 작업 진행 방법

여러 저장소에 걸친 기능을 변경하는 경우를 예로 들어 보겠습니다.

1. **먼저 이해하기:** [일반 세션](/ko-KR/quick-start/conversation-session)에서 기존 코드를 분석합니다. 일반 세션은 기본적으로 읽기 전용이며, 파일을 변경해야 할 때 편집 모드로 전환합니다.
2. **범위 정하기:** 복잡한 변경이라면 [제안 세션](/ko-KR/quick-start/proposal-session)에서 프로젝트와 저장소를 선택합니다. 실행에 앞서 목표, 작업, 검증 방법을 정리합니다.
3. **결과 추적하기:** 작업 공간에서 세션과 실행 상태를 확인합니다. 커밋을 준비할 때는 [AI Compose Commit](/ko-KR/guides/ai-compose-commit)을 사용할 수 있습니다.
4. **맥락 남기기:** 제안과 커밋 기록은 나중에 다시 볼 수 있습니다. 여러 저장소에서 함께 작업할 때는 [MonoSpecs](/ko-KR/guides/monospecs)로 저장소 관계와 변경 범위를 관리합니다.

모든 작업에 제안이 필요한 것은 아닙니다. 코드를 살펴보거나 간단한 문제를 처리할 때는 일반 세션으로 시작하세요. 더 많은 맥락이 필요한 작업에는 HagiCode가 진행 과정을 추적할 수 있는 경로를 제공합니다.

## 필요에 따라 기능 살펴보기

| 원하는 작업 | 시작할 곳 |
| --- | --- |
| 수정 여부를 결정하기 전에 코드 이해하기 | [일반 세션 만들기](/ko-KR/quick-start/conversation-session) |
| 복잡한 요구 사항을 구현 전에 계획하기 | [제안 세션 만들기](/ko-KR/quick-start/proposal-session) |
| 여러 저장소의 관계를 AI가 이해하도록 돕기 | [MonoSpecs 가이드](/ko-KR/guides/monospecs) |
| 확장 기능 검색, 설치 및 관리하기 | [Skills 가이드](/ko-KR/guides/skills) |
| 익숙한 Agent CLI 사용하기 | [AI Agent CLI 설치 및 지원 범위](/ko-KR/related-software-installation/ai-agent-cli/) |
| CLI와 모델 연결을 별도로 관리하기 | [OmniRoute 설치 및 시작 확인](/ko-KR/related-software-installation/omniroute/) |

Vault는 참조 저장소, 폴더, 메모를 모아 나중에 재사용할 수 있게 합니다. Code Server는 브라우저에서 편집할 수 있는 진입점입니다. HagiCode를 시작하기 위해 이 기능들을 먼저 사용할 필요는 없습니다. 설계 배경은 [Vault 지식 기반 활용](/ko-KR/blog/2026-04-10-vault-system-ai-knowledge-base/)과 [브라우저 편집 통합](/ko-KR/blog/2026-04-13-vscode-web-integration-browser-editing/)을 참고하세요.

HagiCode는 영웅, 업적, 일일 보고서, Token 지표를 통한 피드백도 제공하여 장기적인 작업의 상태와 진행 상황을 더 쉽게 확인할 수 있게 합니다. 이는 작업 공간 경험의 일부이며, 일반 개발 도구처럼 사용하는 데 필수는 아닙니다. [게임화 설계 글](/ko-KR/blog/2026-03-16-gamifying-ai-coding/)에서 그 배경을 설명합니다.

## 에디션 및 가격

**Desktop, Container, Microsoft Store는 HagiCode를 받거나 배포하는 서로 다른 방법이지, 세 가지 유료 요금제가 아닙니다.** 기본 기능은 무료로 사용할 수 있습니다. Microsoft Store 채널의 Turbo Engine은 별도로 구매하는 일회성 라이선스로, 제안 동시 실행 한도를 높이고 문서 테마, 사용자 지정 작성자 표시, 브랜딩, 아바타 등의 추가 기능을 제공합니다. 구체적인 제공 항목은 [Turbo Engine 추가 패키지](/ko-KR/dlc/turbo-engine-dlc/)를 확인하세요.

| 사용 환경 | 권장 방법 |
| --- | --- |
| Microsoft Store를 사용할 수 있는 Windows | [Microsoft Store에서 설치](/ko-KR/installation/windows-store) |
| Windows 수동 설치 또는 macOS·Linux에서 로컬 사용 | [Desktop 설치](/ko-KR/installation/desktop) |
| 서버, NAS 또는 팀 배포 | [Docker Compose로 설치](/ko-KR/installation/docker-compose) |

Steam 기본 앱은 서비스가 종료되어 현재 설치 경로가 아닙니다. [Steam 배포 상태](/ko-KR/faq/steam-distribution-status/)를 참고하세요.

## 작업 공간으로 만든 이유

저는 HagiCode를 만든 위쿤(Kun Yu)입니다. 한 번의 질문과 답변으로 당장의 문제를 해결할 수는 있지만, 실제 개발에는 프로젝트 이해, 작업 범위 설정, 변경 진행, 결과 확인도 필요합니다. 흩어져 있던 이 단계들을 연결하고 싶었습니다. 게임화된 피드백은 오랜 기간 진행되는 작업의 진척을 알아보기 쉽게 합니다. 필요한 기능만 사용해도 됩니다. 코딩을 시작하기 전에 모든 기능을 익힐 필요는 없습니다.

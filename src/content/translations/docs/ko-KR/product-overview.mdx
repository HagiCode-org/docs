HagiCode는 AI가 코드를 변경할 때 맥락을 잃지 않도록 합니다. **먼저 저장소를 이해하고, 범위를 정한 다음, 추적 가능한 기록을 남기며 실행합니다.** 이미 사용 중인 Agent CLI와 모델을 연결하는 프로젝트 개발용 AI 작업 공간이므로, 편집기를 바꿀 필요가 없습니다.

## 개발 작업 진행 방법

여러 저장소에 걸친 기능을 변경하는 경우를 예로 들어 보겠습니다.

1. **먼저 이해하기:** [일반 세션](/ko-KR/quick-start/conversation-session)에서 기존 코드를 분석합니다. 일반 세션은 기본적으로 읽기 전용이며, 파일을 변경해야 할 때 편집 모드로 전환합니다.
2. **범위 정하기:** 복잡한 변경이라면 [제안 세션](/ko-KR/quick-start/proposal-session)에서 프로젝트와 저장소를 선택합니다. 실행에 앞서 목표, 작업, 검증 방법을 정리합니다.

   ![저장소 선택과 제안 미리 보기가 표시된 새 제안 패널](../img/screenshots/shared/create-proposal-drawser/original.png)

3. **결과 추적하기:** 작업 공간에서 세션과 실행 상태를 확인합니다. 커밋을 준비할 때는 [AI Compose Commit](/ko-KR/guides/ai-compose-commit)을 사용하세요.

   ![제안 워크플로 실행이 끝난 후의 세션 상세 화면](../img/screenshots/shared/classic-proposal-view/original.png)

4. **맥락 남기기:** 제안과 커밋 기록은 나중에 다시 볼 수 있습니다. 여러 저장소에 걸친 작업에서는 [MonoSpecs](/ko-KR/guides/monospecs)로 저장소 관계와 변경 범위를 관리합니다.

모든 작업에 제안이 필요한 것은 아닙니다. 코드를 살펴보거나 간단한 문제를 처리할 때는 일반 세션으로 시작하세요. 더 많은 맥락이 필요한 작업에는 HagiCode가 추적 가능한 경로를 제공합니다.

## 이런 분께 적합합니다

- **적합한 경우:** 여러 저장소를 관리하면서 복잡한 변경을 실행하기 전에 계획하고 싶은 개발자와 팀, 그리고 Claude Code나 Codex 같은 Agent CLI를 이미 사용하고 있으며 이를 하나의 작업 공간에서 쓰고 싶은 분.
- **필수는 아닌 경우:** 편집기에서 몇 줄만 완성하면 된다면 지금 사용하는 도구로 충분합니다.

## 필요에 따라 기능 살펴보기

| 원하는 작업 | 기능 소개 | 시작할 곳 |
| --- | --- | --- |
| 수정 여부를 결정하기 전에 코드 이해하기 | 일반 세션: 기본적으로 읽기 전용이며, 필요할 때 편집 모드로 전환 | [일반 세션 만들기](/ko-KR/quick-start/conversation-session) |
| 복잡한 요구 사항을 구현 전에 계획하기 | 제안 세션: 목표, 작업, 검증 방법을 먼저 적은 다음 AI가 시작하도록 함 | [제안 세션 만들기](/ko-KR/quick-start/proposal-session) |
| 여러 저장소의 관계를 AI가 이해하도록 돕기 | MonoSpecs: 저장소 관계와 변경 범위를 관리 | [MonoSpecs 가이드](/ko-KR/guides/monospecs) |
| 확장 기능 검색, 설치 및 관리하기 | Skills: 검색하고 설치할 수 있는 확장 기능 | [Skills 가이드](/ko-KR/guides/skills) |
| 익숙한 Agent CLI 사용하기 | Agent CLI: Claude Code, Codex 같은 명령줄 AI 도구 | [AI Agent CLI 설치 및 지원 범위](/ko-KR/related-software-installation/ai-agent-cli/) |
| CLI와 모델 연결을 별도로 관리하기 | OmniRoute: 여러 OpenAI 호환 도구를 하나의 로컬 게이트웨이에 연결 | [OmniRoute 설치 및 시작 확인](/ko-KR/related-software-installation/omniroute/) |

Vault는 참조 저장소, 폴더, 메모를 모아 나중에 재사용할 수 있게 합니다. Code Server는 브라우저에서 편집할 수 있는 진입점을 제공합니다. HagiCode를 시작하기 위해 이 기능들이 반드시 필요한 것은 아닙니다. 설계 배경은 [Vault 지식 기반 활용](/ko-KR/blog/2026-04-10-vault-system-ai-knowledge-base/)과 [브라우저 편집 통합](/ko-KR/blog/2026-04-13-vscode-web-integration-browser-editing/)을 참고하세요.

## 장기적인 진행 상황을 눈에 보이게

HagiCode는 영웅, 업적, 일일 보고서, Token 지표를 피드백으로 바꿔 시간이 지나도 상태와 진행 상황을 더 쉽게 확인할 수 있게 합니다. 이 점이 일반적인 AI 코딩 도구와 다른 부분 중 하나입니다. [모험 팀 소개](/ko-KR/adventure-team-introduction)에서 영웅이 어떻게 팀으로 묶이고 던전이 어떻게 진행되는지 볼 수 있으며, 설계 철학은 [게임화 설계 글](/ko-KR/blog/2026-03-16-gamifying-ai-coding/)을 참고하세요. 이는 작업 공간 경험의 일부이며, 이 기능 없이도 HagiCode를 일반 개발 도구로 사용할 수 있습니다.

## 에디션 및 가격

기본 기능은 무료입니다. Desktop, Microsoft Store는 HagiCode를 받는 서로 다른 방법이지, 두 가지 유료 요금제가 아닙니다. Microsoft Store 채널에서는 별도로 일회성 구매하는 Turbo Engine도 제공하며, 제안 동시 실행 한도를 높이고 문서 테마, 사용자 지정 작성자 표시, 브랜딩, 아바타 등의 추가 기능을 사용할 수 있습니다. 구체적인 제공 항목은 [Turbo Engine 추가 패키지](/ko-KR/dlc/turbo-engine-dlc/)를 확인하세요.

| 사용 환경 | 권장 방법 |
| --- | --- |
| Microsoft Store를 사용할 수 있는 Windows | [Microsoft Store에서 설치](/ko-KR/installation/windows-store) |
| Windows 수동 설치 또는 macOS·Linux에서 로컬 사용 | [Desktop 설치](/ko-KR/installation/desktop) |

Steam 기본 앱은 서비스가 종료되어 현재 설치 경로가 아닙니다. [Steam 배포 상태](/ko-KR/faq/steam-distribution-status/)를 참고하세요.

## 왜 작업 공간으로 만들었나요?

저는 HagiCode를 만든 위쿤(Kun Yu)입니다. 한 번의 질문과 답변으로 당장의 문제를 해결할 수는 있지만, 실제 개발에는 프로젝트 이해, 작업 범위 설정, 변경 진행, 결과 확인도 필요합니다. 흩어져 있던 이 단계들을 하나로 모으고 싶었고, 게임화된 피드백은 오랜 기간 진행되는 작업의 진척을 알아보기 쉽게 합니다. 이 기능들 중 일부만 사용해도 됩니다. 코딩을 시작하기 전에 모든 모듈을 익힐 필요는 없습니다.

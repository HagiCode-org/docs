HagiCode는 AI가 코드를 변경할 때 맥락을 잃지 않도록 합니다. **먼저 저장소를 이해하고, 범위를 정한 다음, 추적 가능한 기록을 남기며 실행합니다.** 이미 사용 중인 Agent CLI와 모델을 연결하는 프로젝트 개발용 AI 작업 공간이므로, 편집기를 바꿀 필요가 없습니다. 풍부하고 편리한 UI 상호작용은 계획 수립, 에이전트 실행, 프로젝트 작업을 쉽게 시작하고 따라갈 수 있게 해 개발을 더 흥미로운 경험으로 만듭니다.

모든 작업에 제안이 필요한 것은 아닙니다. 코드를 살펴보거나 간단한 문제를 처리할 때는 일반 세션으로 시작하세요. 더 많은 맥락이 필요한 작업에는 HagiCode가 추적 가능한 경로를 제공합니다.

## 기능 자세히 보기

### 먼저 이해하고 실행하기

HagiCode는 "코드 읽기"와 "코드 변경"을 분리합니다. AI가 모든 것을 직접 수정하게 두는 대신, 작업의 규모에 맞게 선택할 수 있습니다.

- **일반 세션:** 기본적으로 읽기 전용입니다. 저장소를 살펴보거나, 문제를 조사하거나, 특정 로직이 어디에 있는지 물어볼 때 사용합니다. 파일을 변경해야 할 때만 편집 모드로 전환합니다.
- **제안 세션:** 복잡한 변경에 사용합니다. 프로젝트와 저장소 범위를 선택하고 목표, 작업, 검증 방법을 정리한 다음, 계획이 마음에 들면 실행으로 넘어갑니다.
- **세션 보드:** 제안 및 검토(Proposal & Review), 실행(Execution), 보관됨(Archived) 레인으로 각 세션의 상태를 한눈에 볼 수 있습니다. Classic, Execution Flow Kanban, Dashboard Kanban 레이아웃 사이를 전환할 수 있습니다.

### 여러 저장소를 하나의 범위로

하나의 요청이 프런트엔드, 백엔드, 문서를 동시에 건드릴 때, MonoSpecs를 사용하면 HagiCode가 이들을 하나의 프로젝트로 이해합니다.

- 하위 저장소의 위치, Git URL, 표시 이름을 `.hagicode/monospecs.yaml`에 등록합니다.
- 변경 명세(OpenSpec)는 메인 저장소에 보관되므로 하위 저장소의 코드 디렉터리는 깔끔하게 유지됩니다.
- 제안을 만들 때 관련된 하위 저장소를 선택합니다. 프로젝트 페이지에서는 각 저장소의 브랜치와 커밋되지 않은 변경 사항을 볼 수 있습니다.

### 기존 Agent CLI 그대로 사용

HagiCode는 사용 중인 도구 체인을 대체하지 않고, 하나의 작업 공간으로 모아 줍니다.

- **Agent는 CLI, 모델, 그리고 선택 사항인 성격 텍스트로 구성됩니다.** 여러 Agent를 만들어 실행 시나리오에 지정하고 백업 그룹을 설정할 수 있습니다.
- Claude Code, Codex, GitHub Copilot을 포함해 11개의 Agent CLI를 지원합니다. 작업 공간에서 각 CLI의 버전, 응답 시간, 상태를 확인할 수 있습니다.
- [OmniRoute](/ko-KR/related-software-installation/omniroute/)를 사용하면 여러 OpenAI 호환 도구와 모델을 하나의 로컬 게이트웨이에 연결할 수 있으며, CLI와 모델 연결은 별도로 관리됩니다.

### Skills

Skills 패널은 이미 내 컴퓨터에 있는 Skills와 갤러리에서 설치할 수 있는 Skills를 하나의 진입점으로 모아 줍니다.

- **Local Skills:** 이 컴퓨터에 설치된 Skills를 확인하고 업데이트를 한꺼번에 점검합니다.
- **Gallery:** 키워드와 출처로 검색하고, 이미 설치된 Skills인지 확인합니다.
- **Trusted Providers:** 설치하기 전에 출처, 신뢰 상태, 실제로 실행될 명령을 확인하고, 어떤 출처를 신뢰할지 직접 정합니다.

### Vault와 Code Server

- **Vault**는 HagiCode가 탐색할 수 있는 프로젝트 저장소 밖의 폴더입니다. 참조 문서, 메모, 조사 결과물에 사용하세요. Folder, CodeRef, Obsidian의 세 가지 유형을 지원합니다.
- 세션을 만들 때 범위에 포함할 Vault를 선택합니다. AI가 쓸 수 있도록 하나를 편집 가능으로 표시할 수 있으며, 그렇지 않으면 읽기 전용 참조로 사용됩니다.
- **Code Server**는 브라우저에서 편집할 수 있는 진입점을 제공하며, Vault나 프로젝트에서 바로 열 수 있습니다.

자세히 알아보기: [Vault 가이드](/ko-KR/user-guide/vault)

### AI Compose Commit

Git 탭에서 "AI Compose Commit"을 클릭하면 HagiCode가 현재 변경 사항을 읽고 Conventional Commits 형식으로 커밋 메시지를 작성합니다.

- 관련된 변경 사항은 하나의 뭉뚱그린 커밋이 아니라 여러 커밋으로 묶입니다.
- MonoSpecs 프로젝트에서는 변경 사항이 올바른 하위 저장소에 커밋됩니다.
- Co-Authored-By 태그가 자동으로 추가되며, 이름과 이메일은 프로젝트별 또는 전역으로 설정할 수 있습니다.

![변경된 저장소 세 개를 선택하고 Super Commit(AI Compose Commit) 버튼을 강조한 Git 탭](../img/screenshots/product/git-super-commit/original.png)

자세히 알아보기: [AI Compose Commit 가이드](/ko-KR/guides/ai-compose-commit)

### 눈에 보이는 진행 상황

풍부하고 편리한 UI 상호작용은 계획 수립, 에이전트 실행, 프로젝트 작업을 쉽게 시작하고 따라갈 수 있게 해 개발을 더 흥미로운 경험으로 만듭니다. 영웅, 업적, 일일 보고서, Token 지표는 오래 걸리는 작업을 살펴보는 보조 피드백을 제공합니다. [모험 팀 소개](/ko-KR/adventure-team-introduction)에서 Hero 시나리오 기능을 확인할 수 있습니다. 이러한 게임 요소는 작업 공간 경험을 보완하며, 사용하지 않아도 HagiCode를 일반 개발 도구로 이용할 수 있습니다.

## 이런 분께 적합합니다

- **적합한 경우:** 여러 저장소를 관리하면서 복잡한 변경을 실행하기 전에 계획하고 싶은 개발자와 팀, 그리고 Claude Code나 Codex 같은 Agent CLI를 이미 사용하고 있으며 이를 하나의 작업 공간에서 쓰고 싶은 분.
- **필수는 아닌 경우:** 편집기에서 몇 줄만 완성하면 된다면 지금 사용하는 도구로 충분합니다.

## 에디션 및 가격

기본 기능은 무료입니다. Desktop, Microsoft Store는 HagiCode를 받는 서로 다른 방법이지, 두 가지 유료 요금제가 아닙니다. Microsoft Store 채널에서는 별도로 일회성 구매하는 Turbo Engine도 제공하며, 제안 동시 실행 한도를 높이고 문서 테마, 사용자 지정 작성자 표시, 브랜딩, 사용자 지정 아바타 업로드 등의 추가 기능을 사용할 수 있습니다. 구체적인 제공 항목은 [Turbo Engine 추가 패키지](/ko-KR/dlc/turbo-engine-dlc/)를 확인하세요.

| 사용 환경 | 권장 방법 |
| --- | --- |
| Microsoft Store를 사용할 수 있는 Windows | [Microsoft Store에서 설치](/ko-KR/installation/windows-store) |
| Windows 수동 설치 또는 macOS·Linux에서 로컬 사용 | [Desktop 설치](/ko-KR/installation/desktop) |

Steam 기본 앱은 서비스가 종료되어 현재 설치 경로가 아닙니다. [Steam 배포 상태](/ko-KR/faq/steam-distribution-status/)를 참고하세요.

## 왜 작업 공간으로 만들었나요?

저는 HagiCode를 만든 위쿤(Kun Yu)입니다. 한 번의 질문과 답변으로 당장의 문제를 해결할 수는 있지만, 실제 개발에는 프로젝트 이해, 작업 범위 설정, 변경 진행, 결과 확인도 필요합니다. 흩어져 있던 이 단계들을 하나로 모으고 싶었고, 게임화된 피드백은 오랜 기간 진행되는 작업의 진척을 알아보기 쉽게 합니다. 이 기능들 중 일부만 사용해도 됩니다. 코딩을 시작하기 전에 모든 모듈을 익힐 필요는 없습니다.

**대상 독자:** HagiTask 생태계를 이해하려는 사용자, 관리자, 기여자.

**사전 준비:** 없습니다. 작업을 설치하거나 실행하려면 먼저 HagiCode 앱과 백엔드 서비스를 준비하세요.

## HagiTask란?

HagiTask는 HagiCode의 작업 패키지이자 프리셋 작업 모델입니다. 작업 패키지는 작업 식별 정보, 프런트엔드 패널, 백엔드 프롬프트, 템플릿, UI 문구, 스토어 소개를 검증 가능한 하나의 디렉터리에 담습니다. 앱은 이를 바탕으로 작업을 검색, 설치, 관리, 실행합니다.

작업 패키지는 앱 자체가 아니며 앱의 런타임 설정을 대신하지도 않습니다. 앱이 작업을 로드하고 작업에 선언된 기능을 실행합니다. 작업 패키지는 정해진 형식으로 구성된 리소스만 제공합니다.

## 생태계의 주요 역할

| 역할 | 책임 |
| --- | --- |
| HagiTask | 공통 Schema와 제품과 함께 배포되는 내장 프리셋 패키지를 관리하며, 패키지 형식의 source of truth 역할을 합니다. |
| 내장 프리셋 | 앱 또는 런타임에서 제공하는 사용 가능한 작업입니다. 예: `normal-session`, `research-investigation`. |
| Community Packages | `data/<taskId>/`에 있는 커뮤니티 작업의 원본 데이터를 관리합니다. |
| HagiTask Site | 커뮤니티 패키지 원본에서 목록, 상세 JSON, ZIP 아카이브를 생성해 Community Gallery에 게시합니다. |
| HagiCode 앱 | 작업을 표시하고 패키지를 설치하며 활성화 상태를 저장하고, 런타임에서 작업을 실행합니다. |

내장 프리셋과 커뮤니티 작업은 동일한 패키지 Schema를 사용하지만 출처와 수명 주기가 다릅니다. 내장 프리셋은 HagiTask 저장소에서, 커뮤니티 작업은 Community Packages 저장소에서 관리합니다. 사이트의 `/index.json`, 상세 문서, ZIP은 모두 생성 결과물이며 기여자가 직접 편집하는 원본 파일이 아닙니다.

## 패키지 관리와 소스 관리는 다릅니다

Gallery에서 ZIP을 설치하면 패키지가 앱의 데이터 디렉터리로 복사되고 버전, 출처, 활성화 상태가 기록됩니다. 반면 서버 소스 관리에서는 런타임이 작업을 검색할 수 있도록 서버에서 접근 가능한 디렉터리를 설정합니다. 브라우저의 로컬 폴더를 설치용 패키지로 업로드하는 기능이 아닙니다.

두 작업의 경계와 폴더 소스에 대해서는 [HagiTask 사용법](/ko-KR/guides/hagitask/usage)을 참고하세요. 설치를 시작하려면 [HagiTask 설치](/ko-KR/guides/hagitask/installation)를, 작업을 만들거나 게시하려면 [커뮤니티 기여하기](/ko-KR/guides/hagitask/community)를 읽어보세요.

## Source of truth의 책임 범위

- docs는 사용자와 기여자를 위한 설명 및 사용 가이드를 관리합니다.
- HagiTask는 공통 Schema와 내장 프리셋 원본을 관리합니다.
- Community Packages는 커뮤니티 패키지의 원본 데이터를 관리합니다.
- HagiTask Site는 패키지 원본에서 생성한 목록, 상세 정보, 아카이브를 게시합니다.

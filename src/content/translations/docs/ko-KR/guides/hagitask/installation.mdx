**대상 독자:** 커뮤니티 작업을 설치해 HagiCode에서 사용하려는 사용자.

**사전 준비:**

- 사용 중인 HagiCode 앱과 백엔드 서비스에 접근할 수 있어야 합니다.
- 앱 버전이 HagiTask 커뮤니티 작업 관리 및 Community Gallery를 지원해야 합니다.
- 작업에 필요한 agent, skills 또는 CLI 의존성을 준비해야 합니다. 요구 사항은 작업 상세 정보에서 확인할 수 있습니다.

## Community Gallery에서 설치하기

현재 지원하는 절차는 HagiTask Site의 Community Gallery에서 작업 상세 정보와 ZIP 아카이브를 가져와 앱의 커뮤니티 작업 설치 기능에 전달하는 방식입니다.

1. Gallery에서 작업 이름, 카테고리 또는 태그로 작업을 찾습니다.
2. 작업 상세 정보를 열어 버전, 게시자, 호환성, 설치 크기를 확인합니다.
3. 설치를 선택합니다. 앱은 `packageUrl`에서 ZIP을 가져와 작업 ID, 버전, SHA-256을 검증합니다.
4. 검증에 성공하면 앱이 패키지를 로컬 HagiTask 데이터 디렉터리에 저장하고 작업 목록을 새로 고칩니다.

Gallery의 검색, 상세 정보, 아카이브 경로는 각각 `/index.json`, `/tasks/<taskId>.json`, `/packages/<taskId>.zip`입니다. 설치에는 아카이브를 사용하므로 사이트 페이지의 내용을 파싱할 필요가 없습니다.

### 아카이브 파일 사용하기

지원되는 Gallery 절차를 통해 ZIP을 이미 받았다면, 앱의 커뮤니티 작업 관리 화면에서 로컬 아카이브 설치를 선택할 수 있습니다. 아카이브에는 완전한 작업 패키지 디렉터리가 들어 있어야 하며, 내부의 ID, 버전, 콘텐츠 다이제스트가 설치 요청과 일치해야 합니다.

브라우저의 로컬 폴더 업로드는 현재 Community Gallery의 설치 경로가 아닙니다. 서버 측 폴더 소스 설정은 용도가 다릅니다. 자세한 내용은 [HagiTask 사용법](/ko-KR/guides/hagitask/usage)을 참고하세요.

## 설치 성공 여부 확인하기

설치 후 커뮤니티 작업 관리 화면에서 다음을 확인하세요.

- 올바른 `taskId`, 버전, 게시자가 표시됩니다.
- 작업이 활성화되어 있거나 수동으로 활성화할 수 있습니다.
- 작업 의존성 및 호환성 안내에 충족되지 않은 항목이 없습니다.
- 목록을 새로 고친 후에도 작업이 남아 있고 작업 패널을 열 수 있습니다.

설치 기록에는 출처, 버전, 아카이브 다이제스트, 활성화 상태가 저장됩니다. 내장 작업은 읽기 전용으로 표시되며 커뮤니티 패키지처럼 제거할 수 없습니다.

## 자주 발생하는 문제

### Gallery에 접근할 수 없음

앱에 설정한 Gallery 주소가 사용 가능하고 HTTPS를 사용하는지 확인한 다음 네트워크, 시간 초과, 사이트 상태를 점검하세요. 목록을 처음 가져오는 데 실패해도 앱은 빈 목록을 만들어 보여주지 않습니다. 유효한 캐시가 있으면 이전 목록이 잠시 표시될 수 있습니다.

### 작업을 찾을 수 없거나 상세 정보가 유효하지 않음

표시용 별칭이 아닌 상세 정보의 정식 `taskId`를 사용하세요. `agentsmd`와 `portytail`은 각각 `claude-md-update`와 `ponytail`을 가리키는 사람이 쓰는 별칭일 뿐, 설치 가능한 작업 ID가 아닙니다.

### 무결성 또는 버전 검증 실패

Gallery에서 아카이브를 다시 가져오세요. ZIP이나 생성된 목록 파일을 수동으로 수정하지 마세요. 계속 실패한다면 패키지 관리자에게 문의하여 Community Packages의 원본 데이터와 버전 번호를 확인하세요.

### 설치 후 사용할 수 없음

작업 상세 정보의 agent, skills, CLI 요구 사항을 확인하고, 앱에서 작업을 활성화한 뒤 목록을 새로 고치세요. 패키지 내용 자체가 유효하지 않다면 [커뮤니티 기여 가이드](/ko-KR/guides/hagitask/community)에서 Schema와 검증 절차를 확인하세요.

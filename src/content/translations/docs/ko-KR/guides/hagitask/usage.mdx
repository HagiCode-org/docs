**대상 독자:** HagiCode를 설치했고 작업을 관리하거나 실행해야 하는 사용자.

**사전 준비:** [HagiTask 설치](/ko-KR/guides/hagitask/installation)를 완료했거나 앱에서 내장 프리셋을 제공해야 합니다.

## 작업 찾기

앱의 HagiTask/커뮤니티 작업 관리 화면을 엽니다. 앱은 내장 작업, 설치된 커뮤니티 패키지, 작업 공간 패키지, 관리 중인 소스를 통합해 보여주고 각 작업의 출처와 제거 가능 여부를 표시합니다. 커뮤니티 Gallery의 목록은 커뮤니티 패키지를 찾고 가져올 때 사용하고, 서버에서 접근 가능한 디렉터리는 런타임의 소스 검색에 사용합니다.

## 작업 설치하기

Gallery에서 작업을 선택해 설치하거나 이미 받은 지원 ZIP을 로컬 아카이브로 설치합니다. 설치에 성공하면 앱은 정식 ID, 버전, 게시자, 출처, 아카이브 다이제스트, 설치 디렉터리를 기록합니다. 같은 ID로 설치된 기존 작업을 알리지 않고 덮어쓰지 않으므로 먼저 기존 설치를 처리해야 합니다.

## 활성화와 비활성화

- **활성화:** 설치된 작업을 활성 작업 목록에 넣어 검색하고 실행할 수 있도록 합니다.
- **비활성화:** 설치 기록과 패키지 파일은 유지하되 활성 목록에서 제거합니다. 해당 작업은 실행되지 않습니다.
- **제거:** 설치 기록이 있는 커뮤니티 작업에만 적용됩니다. 내장 작업은 정보로만 표시되며 제거할 수 없습니다.

상태 변경이 완료되면 앱은 목록을 새로 고칩니다. 새로 고침에 실패하면 수명 주기 작업은 목록을 불완전하게 남겨 두는 대신 이전에 사용 가능했던 상태를 유지해야 합니다.

## 새로 고침과 실행

새로 고침 기능으로 현재 작업 목록을 다시 읽습니다. Gallery 목록을 강제로 새로 고치면 앱은 목록을 다시 가져와 검증합니다. 상위 서비스에 일시적인 장애가 생겨도 기존의 유효한 캐시를 계속 사용할 수 있습니다. 새로 고침만으로 작업의 활성화 상태나 버전이 자동 변경되지는 않습니다.

실행하기 전에 작업이 활성화되어 있고 의존성이 충족되었는지 확인한 다음 작업 패널 또는 해당 실행 메뉴에서 실행하세요. 작업이 표시되지 않으면 먼저 목록을 새로 고치고 설치 상태, 작업 ID, 호환성 안내를 확인하세요. Schema나 패키지 리소스가 유효하지 않다면 [커뮤니티 기여 가이드](/ko-KR/guides/hagitask/community)를 참고하세요.

## 패키지 관리와 서버 소스 관리

이 두 기능은 혼동하기 쉽습니다.

| 기능 | 역할 | 경로의 의미 |
| --- | --- | --- |
| 패키지 관리 | 로컬 HagiTask 패키지를 설치, 활성화, 비활성화, 제거합니다. | 앱이 관리하는 데이터 디렉터리. |
| 서버 소스 관리 | 런타임이 목록에서 작업을 검색할 소스를 설정합니다. | 서버에서 접근 가능한 디렉터리여야 합니다. |

서버 소스의 경로는 백엔드가 디렉터리 안의 작업 패키지를 검색할 때 읽습니다. 브라우저 경로도 업로드 입력란도 아닙니다. 현재 설치 절차에서는 브라우저의 로컬 폴더를 Community Gallery 패키지로 직접 업로드하지 않습니다. 패키지를 설치하려면 Gallery 또는 지원되는 로컬 ZIP 절차를 사용하세요.

## 작업을 사용할 수 없을 때

1. 작업 ID, 버전, 설치 기록이 여전히 있는지 확인합니다.
2. 작업이 활성화되어 있고 필요한 agent, skills, CLI가 준비되었는지 확인합니다.
3. 작업 목록을 새로 고치고 관리 화면을 다시 엽니다.
4. 소스가 서버 디렉터리라면 백엔드 프로세스에 해당 경로를 읽을 권한이 있는지 확인합니다.
5. 아카이브 검증이나 패키지 리소스에 문제가 있다면 [설치 문제 해결](/ko-KR/guides/hagitask/installation)로 돌아가세요. 패키지 관리자라면 [커뮤니티 기여하기](/ko-KR/guides/hagitask/community)를 읽어보세요.

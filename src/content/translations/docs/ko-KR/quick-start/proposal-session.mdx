제안 세션은 요청이 너무 중요해서 자유 형식의 단일 프롬프트로 처리하기 어려울 때 알맞은 진입점입니다. 곧바로 수정하는 대신, HagiCode가 먼저 요청을 목표, 범위, 작업, 검증 기준으로 정리하고, 사용자가 이를 검토한 뒤에야 실행 단계로 넘어갑니다.

## 사전 준비

제안 세션을 시작하기 전에 다음을 확인하세요.

- [설치 가이드](/ko-KR/installation)에 따라 설치 방법(Microsoft Store, Desktop) 중 하나를 완료했습니다
- 첫 번째 Agent와 프로젝트를 최소 하나 만들어 주는 [Wizard Setup](/ko-KR/quick-start/wizard-setup)을 완료했습니다
- 변경 사항을 설명할 만큼 프로젝트 컨텍스트를 파악했습니다. 그렇지 않다면 [대화 세션 만들기](/ko-KR/quick-start/conversation-session)부터 시작하세요
- 제안 세션의 기반이 되는 OpenSpec 워크플로를 이해하려면 먼저 [OpenSpec 소개](/ko-KR/related-software-installation/openspec/intro-openspec)를 읽어 보세요

## 제안 세션의 용도

제안 세션은 다음과 같은 경우에 가장 효과적입니다.

- 수정을 시작하기 전에 변경의 범위를 분명히 해야 할 때
- 여러 저장소, 모듈 또는 산출물이 관련될 때
- 작업을 검토 가능한 단계로 나눠야 할 때
- 추론 과정과 실행 기록을 나중에도 볼 수 있게 남기고 싶을 때

저장소를 이해하거나 가볍게 논의하는 정도라면 대화 세션이 더 빠릅니다. 구조와 추적 가능성이 필요하다면 여기서 이어가세요.

## 워크플로 개요

| 단계 | 할 일 | 일어나는 일 |
| --- | --- | --- |
| 아이디어 만들기 | **New Idea**를 클릭하고 요청을 설명합니다 | 제안 세션이 생성되고 자동 최적화 대기열에 들어갑니다 |
| 초안 검토 | 세션 카드를 엽니다 | HagiCode가 제목과 설명을 다듬고 컨텍스트, 문제, 해결책, 영향을 초안으로 작성합니다 |
| 계획 생성 | **Generate Plan**을 클릭합니다 | Agent가 OpenSpec 계획 파일을 작성합니다 |
| 계획 검토 | **Review** 탭에서 계획을 읽습니다 | 코드가 변경되기 전에 계획을 확인하거나 다듬습니다 |
| 실행 및 보관 | 계획을 실행한 다음 보관합니다 | Agent가 작업을 실행하고, 완료된 계획은 보관됩니다 |

## 1단계: **New Idea** 드로어에서 변경 내용 설명하기

프로젝트를 선택한 다음, 세션 보드 위 도구 모음에서 **New Idea**(새싹 아이콘)를 클릭합니다. **Create Proposal** 드로어가 열립니다.

![아이디어 이름, 프로젝트, 범위, 빠른 요청, 요청 텍스트가 있는 Create Proposal 드로어](../../img/quick-start/proposal-session/01-new-idea.png)

드로어를 차례로 채웁니다.

- **Idea Name**과 **Project Name**(필수) – 어느 프로젝트가 이 요청을 소유하는지 확인합니다.
- **Scope** – **Vault** 탭에서는 AI가 편집할 수 있는 vault를 표시합니다. 시스템 관리 vault는 항상 참고 전용입니다. **Projects** 탭에서는 다른 프로젝트를 컨텍스트로 추가합니다.
- **Quick Requests** – *No docs / tests*, *Self commit*, *Output English*, *Ask before edit*, *No backward compatibility* 같은 항목을 한 번의 클릭으로 추가합니다.
- **You Request** – 실제 변경 내용을 자연어로 최대 14,000자까지 설명합니다. 위쪽의 **Combined preview**에는 AI에 실제로 전송될 내용이 그대로 표시됩니다.

**Submit idea**를 클릭합니다. 작업이 여러 저장소에 걸쳐 있다면 실행 중에 추가하지 말고 이 단계에서 경계를 정의하세요.

## 2단계: 상세 보기에서 제안 검토하기

제출하면 아이디어가 상태 배지와 함께 **Proposal & Review** 레인에 카드로 나타납니다. 카드를 클릭하면 제안 상세 보기가 열립니다.

![왼쪽에 워크플로 단계, 오른쪽에 초안 설명이 있는 제안 상세 보기](../../img/quick-start/proposal-session/02-proposal-detail.png)

이 보기는 계획, 진행 상황, 대화를 한곳에 모아 보여줍니다.

- **Workflow steps**(왼쪽)는 제안이 현재 어디에 있는지 보여줍니다. 단계는 **Proposal preparation**(*Session Created*, *Auto Optimizing*, *Drafting Ready*), **Review and refine**(*Generating Plan Files*, *Review Plan*), **Execution complete**(*Executing Plan*, *Execution Completed*), **Archive**(*Archiving*, *Archived*)로 묶여 있습니다.
- **Planning directions**는 계획이 탐색해야 할 방향(예: 변경 맵, 상호작용 흐름, 아키텍처)을 보여줍니다. 기본값은 **Settings → Proposals and planning → Planning Direction**에서 조정하세요.
- **Info** 탭(오른쪽)에는 초안 설명(*Context*, *Problem*, *Solution*, *Impact*)과 **Chief Complaint** 아래에 원래 요청이 표시됩니다. 빠른 작업으로 **Open Proposal Folder**, **Optimize Proposal**, **Open in New Window**, **Delete Session**을 사용할 수 있습니다.
- **Conversation** 탭과 **Review** 탭에는 Agent와의 대화, 그리고 생성된 계획의 검토 내용이 있습니다.
- **Quick Chat**(왼쪽 아래)을 사용하면 보기를 벗어나지 않고 Agent에게 메시지를 보낼 수 있습니다.

여기서 목표, 범위 또는 작업 분해가 잘못되어 보인다면 다음 단계로 넘어가기 전에 제안을 바로잡으세요. 이것이 이 워크플로의 핵심입니다.

## 3단계: 생성, 검토, 실행, 보관

초안이 맞다면 **Generate Plan**을 클릭합니다. Agent가 OpenSpec 계획 파일을 작성하고, 세션은 **Review Plan** 단계로 이동하여 코드가 변경되기 전에 결과를 확인할 수 있습니다. 검토가 끝나면 세션은 **Executing Plan**으로 이어지고, 마지막으로 **Archiving**과 **Archived**로 진행됩니다.

HagiCode는 제안 생성, 즉시 실행, 보관처럼 되돌리기 어려운 단계 전에 확인을 요청합니다. 이러한 확인 창은 **Settings → General → Confirm Prompts**에서 세부적으로 조정할 수 있습니다.

실행이 끝난 후에는 [Super Commit](/ko-KR/guides/ai-compose-commit)을 사용해 최종 변경 사항을 깔끔한 커밋 메시지로 만드세요.

## 4단계: 세션 보드에서 제안 추적하기

프로젝트에 제안이 여러 개 있거나 제안과 대화가 섞여 있을 때는 세션 보드가 가장 명확한 개요를 제공합니다.

![Proposal & Review에 초안 제안이, Execution에 완료된 대화가 있는 세션 보드](../../img/quick-start/proposal-session/03-session-board.png)

- **Proposal & Review**에는 초안 작성, 생성, 검토 중인 아이디어가 있습니다.
- **Execution**에는 실행 중이거나 완료된 세션이 있습니다.
- **Archived**는 완료된 작업을 방해되지 않게 치워 두되 검토할 수 있도록 보관합니다.

각 카드에는 *Optimizing*, *Drafted*, *Reviewing*, *Executing*, *Execution Complete*와 같은 상태가 표시됩니다. 레이아웃 전환기로 보드 레이아웃을 바꿀 수 있습니다. [Sessions](/ko-KR/user-guide/sessions)를 참고하세요.

## 제안 세션을 선택해야 하는 경우

다음과 같은 경우에는 제안 세션을 먼저 선택하세요.

- 변경이 복잡하여 AI가 너무 일찍 즉흥적으로 작업하는 것을 원하지 않을 때
- 작업을 나중에 검토하거나 다른 사람과 공유할 때
- 여러 저장소, 모듈 또는 역할이 관련될 때
- 실행 기록과 근거를 재사용할 수 있게 남기고 싶을 때

작업이 아직 작고 탐색적인 단계라면 대화 세션이 대체로 더 가벼운 경로입니다.

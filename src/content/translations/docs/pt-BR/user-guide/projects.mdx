Um **projeto** é a pasta em que o HagiCode trabalha. Sessões, status do Git, termos padronizados e configurações do MonoSpecs pertencem a um projeto, por isso a barra de projetos na borda esquerda da área de trabalho é o ponto de partida da maior parte do trabalho.

## Barra de projetos

A barra de projetos fica recolhida por padrão, e cada projeto aparece apenas como um ícone circular. Clique na pequena seta no topo da barra para expandi-la.

![Barra de projetos expandida, listando All Sessions e o projeto orbit-notes, com o botão de adicionar projeto (+)](../../img/user-guide/workbench/02-project-rail.png)

- **All Sessions** (Todas as sessões) mostra as sessões de todos os projetos no mesmo quadro.
- Clicar em um projeto faz o quadro mostrar apenas as sessões desse projeto e exibe o projeto no painel do projeto.
- O botão verde **+** cria um novo projeto. A seta ao lado dele recolhe a barra de projetos novamente.

:::tip[Quais projetos entram no quadro "All Sessions"?]
Em **Settings → Process & Interaction → Session List** (Configurações → Processo e interação → Lista de sessões), você pode mudar o escopo de *All Projects* (Todos os projetos) para *Custom Selection* (Seleção personalizada) e escolher alguns projetos. Consulte [Configurações](/user-guide/settings).
:::

## Criar um projeto

Clique em **+** na barra de projetos para abrir a caixa de diálogo **New Project** (Novo projeto). Ela oferece três formas de adicionar projetos.

### Projeto único

Use esta opção quando a pasta do projeto já existe no disco. Corresponde à aba **Single Project** (Projeto único).

![Aba Single Project da caixa de diálogo de novo projeto, com nome, caminho da pasta e descrição preenchidos](../../img/user-guide/projects/01-create-project.png)

| Campo | Descrição |
| --- | --- |
| **Project Name** (Nome do projeto) | Obrigatório, até 200 caracteres. |
| **Folder Path** (Caminho da pasta) | Obrigatório, até 1000 caracteres. Informe o caminho absoluto da pasta, por exemplo `/home/user/projects/orbit-notes`. |
| **Project Description** (Descrição do projeto) | Opcional, até 1000 caracteres. |

Quando o caminho contém `.hagicode/monospecs.yaml`, a caixa de diálogo detecta o arquivo e exibe orientações do MonoSpecs para o projeto. Consulte [MonoSpecs](/guides/monospecs).

### Criação em lote

Use esta opção quando vários repositórios estão dentro de uma mesma pasta-pai. Corresponde à aba **Batch Create** (Criação em lote).

![Aba Batch Create da caixa de diálogo de novo projeto, pedindo para selecionar a pasta a ser verificada](../../img/user-guide/projects/02-create-project-batch.png)

Informe o caminho completo da pasta-pai. O HagiCode procura repositórios Git em até três níveis de subpastas e registra cada repositório encontrado como um projeto.

### Projeto de demonstração

Use esta opção para experimentar o HagiCode antes de conectar o seu próprio código. Corresponde à aba **Demo Project** (Projeto de demonstração).

![Aba Demo Project da caixa de diálogo de novo projeto, mostrando o repositório de demonstração do MonoSpecs e seu caminho de destino](../../img/user-guide/projects/03-create-project-demo.png)

O HagiCode clona o repositório oficial de demonstração do MonoSpecs (`https://github.com/HagiCode-org/monospecs-demo`) e o registra como projeto. Isso exige Git instalado na sua máquina. O caminho exibido na interface é o padrão; a pasta real depende do diretório de dados de execução.

## Painel do projeto

Ao selecionar um projeto, o painel do projeto dele aparece à direita do quadro.

![Painel do projeto orbit-notes, com Quick actions e Repository status](../../img/user-guide/workbench/06-project-panel.png)

**Quick actions** (Ações rápidas)

| Botão | O que faz |
| --- | --- |
| **Auto Super Commit** | Inicia um commit assistido por IA para o projeto. Consulte [Super Commit](/guides/ai-compose-commit). |
| **Open Code Server** (Abrir Code Server) | Abre o projeto em um editor de código no navegador. |
| **Open Git Management** (Abrir gerenciamento do Git) | Abre a aba Git da gaveta de detalhes do projeto. |
| **View Project Details** (Ver detalhes do projeto) | Abre a gaveta de detalhes do projeto. |

**Repository status** (Status do repositório) lista cada repositório do projeto e a branch atual dele. A bolinha colorida indica o estado do diretório de trabalho; na captura de tela ela está vermelha porque `src/server.js` tem alterações não confirmadas. Clique no botão de atualizar para reler o status.

O menu **Recent changes** (Alterações recentes), na barra de ferramentas do quadro, lista os repositórios com mudanças recentes. Enquanto nenhum repositório tiver alterações, ele mostra "Nenhuma alteração recente".

## Detalhes do projeto

Clique em **View Project Details** para abrir a gaveta. Ela tem quatro abas.

### Detalhes

Corresponde à aba **Details** (Detalhes).

![Aba Details da gaveta de detalhes do projeto, mostrando as configurações de nome, caminho, descrição e ícone](../../img/user-guide/projects/04-project-details.png)

- **Name** (Nome), **Path** (Caminho) e **Description** (Descrição): as informações básicas do projeto.
- **Icon Settings** (Configurações de ícone): escolha *Game Icon* (Ícone de jogo) ou *Text Abbreviation* (Abreviação de texto) para o avatar do projeto. **Change Icon** (Alterar ícone) abre o seletor de ícones.
- **Manage DESIGN.md** (Gerenciar DESIGN.md): gerencia o arquivo `DESIGN.md` do projeto.
- **Delete Project** (Excluir projeto): exclui o projeto depois que você digitar o nome dele para confirmar. A caixa de confirmação lista o que será excluído permanentemente: todas as sessões do projeto e todas as mensagens dessas sessões. Essa ação não pode ser desfeita.

### MonoSpecs

![Aba MonoSpecs, com a sugestão de inicializar o MonoSpecs no projeto](../../img/user-guide/projects/05-project-monospecs.png)

O MonoSpecs transforma um projeto em um espaço de trabalho que coordena especificações e vários repositórios. Para um projeto que ainda não é um espaço de trabalho do MonoSpecs, **Initialize MonoSpecs** (Inicializar MonoSpecs) cria apenas o necessário e não clona nenhum repositório automaticamente:

- `.hagicode/monospecs.yaml`
- A pasta `repos/`, onde ficam os subrepositórios
- `openspec/changes/archive/` e `openspec/specs/`
- Uma atualização do `.gitignore` para que a pasta `repos/` continue sem ser rastreada

Antes de inicializar, leia o [guia do MonoSpecs](/guides/monospecs).

### Termos padronizados

Corresponde à aba **Standard Words** (Termos padronizados).

![Aba Standard Words, com a lista de grupos vazia e o botão Add group](../../img/user-guide/projects/06-project-standard-words.png)

Os termos padronizados são o vocabulário compartilhado do projeto, armazenado em `.hagicode/standard_words.yaml`. A aba mostra a quantidade de grupos, frases e tags, e oferece busca, **Add group** (Adicionar grupo), **Refresh** (Atualizar) a partir do disco e **Save changes** (Salvar alterações).

### Git

![Aba Git, com a lista de repositórios à esquerda e o resumo do repositório à direita, com as ações Push, Pull e Super Commit](../../img/user-guide/projects/07-git-management.png)

A aba Git é o console Git do projeto.

- A **lista de repositórios** (à esquerda) mostra os repositórios monitorados. A contagem (por exemplo `1 / 15`) compara esses repositórios com o limite de monitoramento definido em **Settings → Integration → Git** (Configurações → Integração → Git). As ações em lote são **Select Changed** (Selecionar alterados), **Select All** (Selecionar todos) e **Clear Selection** (Limpar seleção), e também é possível buscar pelo nome. **Manage Super Commit All exclusions** (Gerenciar exclusões do Super Commit All) controla quais arquivos o commit rápido ignora.
- O **resumo do repositório** (à direita) mostra a branch, o estado de sincronização, se há alterações não confirmadas, o repositório remoto e o caminho do repositório.
- Ações para o repositório em foco: **Super Commit**, **Push** (Enviar), **Pull** (Puxar), **Rebase Upstream** (Fazer rebase na upstream), **Open Remote Repository** (Abrir repositório remoto), **Open Code Server** e **Manage DESIGN.md**.

O resumo aqui substitui de propósito a pré-visualização de diff. Para operações Git mais detalhadas, use **Open Code Server**.

Comportamentos do Git, como perfil do Git, monitoramento de status e a ação padrão do Super Commit, são configurados em **Settings → Integration → Git** (Configurações → Integração → Git).

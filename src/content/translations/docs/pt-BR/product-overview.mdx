O HagiCode é um espaço de trabalho com IA para desenvolvimento de projetos. Você pode começar com uma sessão para entender um repositório, definir a necessidade e o alcance da mudança, deixar a IA fazer as alterações e, no mesmo lugar, acompanhar o andamento, preparar commits e reutilizar o conhecimento do projeto. Ele conecta os Agent CLI e modelos que você usa, sem exigir um editor de código específico.

**É sua primeira vez?** [Escolha uma forma de instalação](/pt-BR/installation/), conclua o [assistente de configuração](/pt-BR/quick-start/wizard-setup), crie um projeto e comece com uma [sessão de conversa](/pt-BR/quick-start/conversation-session). Se a tarefa exigir planejamento antes da implementação, use uma [sessão de proposta](/pt-BR/quick-start/proposal-session).

## Como funciona uma tarefa de desenvolvimento

Por exemplo, considere uma mudança de funcionalidade que envolve vários repositórios:

1. **Primeiro, entenda o código:** Analise o código existente em uma [sessão de conversa](/pt-BR/quick-start/conversation-session). Essas sessões são somente leitura por padrão; mude para o modo de edição quando precisar alterar arquivos.
2. **Depois, defina o escopo:** Para uma mudança complexa, selecione o projeto e os repositórios em uma [sessão de proposta](/pt-BR/quick-start/proposal-session). Organize os objetivos, as tarefas e a forma de verificação antes de executar.
3. **Acompanhe o resultado:** Consulte as sessões e o status de execução no espaço de trabalho. Para preparar um commit, use o [AI Compose Commit](/pt-BR/guides/ai-compose-commit).
4. **Preserve o contexto:** Propostas e histórico de commits podem ser revisitados. Para trabalhar entre repositórios, use o [MonoSpecs](/pt-BR/guides/monospecs) para gerenciar as relações entre eles e o escopo das mudanças.

Você não precisa criar uma proposta para toda tarefa: se quiser apenas explorar o código ou resolver algo simples, comece com uma sessão de conversa. Quando a tarefa exigir mais contexto, o HagiCode oferece um caminho que você pode acompanhar.

O Vault reúne repositórios de referência, pastas e anotações para uso futuro; o Code Server oferece acesso à edição pelo navegador. Nenhum dos dois é necessário para começar com o HagiCode. Para conhecer o contexto do projeto, leia sobre [a base de conhecimento Vault](/pt-BR/blog/2026-04-10-vault-system-ai-knowledge-base/) e [a integração da edição no navegador](/pt-BR/blog/2026-04-13-vscode-web-integration-browser-editing/).

O HagiCode também oferece feedback por meio de heróis, conquistas, relatórios diários e métricas de Token para tornar o status e o progresso mais visíveis ao longo do tempo. Esses recursos fazem parte da experiência do espaço de trabalho, mas não são necessários para usá-lo como uma ferramenta de desenvolvimento comum. Veja o [artigo sobre o design da gamificação](/pt-BR/blog/2026-03-16-gamifying-ai-coding/).

## Edições e preços

**Desktop, Container e Microsoft Store são formas diferentes de obter ou implantar o HagiCode, não três planos pagos.** Os recursos básicos podem ser usados gratuitamente. O Turbo Engine no canal da Microsoft Store é uma licença separada, de compra única, que aumenta o limite de propostas simultâneas e desbloqueia melhorias como temas de documentação, atribuição personalizada, identidade visual e avatares. Consulte o [complemento Turbo Engine](/pt-BR/dlc/turbo-engine-dlc/) para saber exatamente o que ele desbloqueia.

| Seu ambiente | Opção recomendada |
| --- | --- |
| Windows com acesso à Microsoft Store | [Instalar pela Microsoft Store](/pt-BR/installation/windows-store) |
| Instalação manual no Windows ou uso local no macOS ou Linux | [Instalar o Desktop](/pt-BR/installation/desktop) |
| Servidor, NAS ou implantação em equipe | [Instalar com Docker Compose](/pt-BR/installation/docker-compose) |

O aplicativo principal na Steam foi descontinuado e não é mais um canal de instalação. Veja o [status da distribuição na Steam](/pt-BR/faq/steam-distribution-status/).

## Por que criar um espaço de trabalho?

Sou Kun Yu, criador do HagiCode. Uma pergunta e sua resposta podem resolver um problema imediato, mas o desenvolvimento real também exige entender o projeto, definir limites, levar mudanças adiante e revisar os resultados. Quis reunir essas etapas antes dispersas; o feedback gamificado ajuda a visualizar o progresso do trabalho de longo prazo. Você pode usar apenas parte dos recursos. Não precisa aprender todos os módulos antes de começar a programar.

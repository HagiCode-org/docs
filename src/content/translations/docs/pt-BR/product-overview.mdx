O HagiCode evita que a IA perca o contexto ao alterar seu código: **entenda primeiro o repositório, defina o escopo e execute com um registro rastreável.** É um espaço de trabalho com IA para o desenvolvimento de projetos que conecta os Agent CLI e os modelos que você já usa, para que você não precise trocar de editor. Interações de interface ricas e práticas tornam o planejamento, a execução de agentes e o trabalho em projetos mais acessíveis e fáceis de acompanhar, criando uma experiência de desenvolvimento envolvente.

Você não precisa criar uma proposta para toda tarefa. Comece com uma sessão de conversa quando quiser apenas explorar o código ou resolver algo simples. O HagiCode oferece um caminho rastreável quando a tarefa exige mais contexto.

## Recursos em detalhe

### Entender antes de agir

O HagiCode separa "ler o código" de "alterar o código", para que você escolha conforme o tamanho da tarefa, em vez de deixar a IA editar tudo diretamente.

- **Sessão de conversa:** Somente leitura por padrão. Use-a para explorar um repositório, investigar um problema ou perguntar onde está determinada lógica. Mude para o modo de edição apenas quando precisar alterar arquivos.
- **Sessão de proposta:** Para mudanças complexas. Escolha o projeto e o escopo dos repositórios, organize os objetivos, as tarefas e as etapas de verificação e passe à execução quando estiver satisfeito com o plano.
- **Quadro de sessões:** As raias Proposal & Review (proposta e revisão), Execution (execução) e Archived (arquivadas) mostram de relance em que ponto está cada sessão. É possível alternar entre os layouts Classic, Execution Flow Kanban e Dashboard Kanban.

### Um escopo para vários repositórios

Quando uma solicitação envolve ao mesmo tempo o frontend, o backend e a documentação, o MonoSpecs permite que o HagiCode os entenda como um único projeto.

- Registre os locais dos subrepositórios, as URLs Git e os nomes de exibição em `.hagicode/monospecs.yaml`.
- As especificações de mudança (OpenSpec) ficam no repositório principal, de modo que os diretórios de código dos subrepositórios permanecem limpos.
- Ao criar uma proposta, escolha quais subrepositórios ela envolve. A página do projeto mostra a branch e as alterações não commitadas de cada repositório.

### Mantenha seu Agent CLI

O HagiCode não substitui suas ferramentas. Ele as reúne em um único espaço de trabalho.

- **Um Agent é um CLI, um modelo e, opcionalmente, um texto de personalidade.** Crie vários Agents, atribua-os a cenários de execução e configure grupos de reserva.
- Compatível com 11 Agent CLI, incluindo Claude Code, Codex e GitHub Copilot. O espaço de trabalho mostra a versão, o tempo de resposta e a saúde de cada CLI.
- Com o [OmniRoute](/pt-BR/related-software-installation/omniroute/), você conecta várias ferramentas e modelos compatíveis com OpenAI a um único gateway local, enquanto as conexões de CLI e de modelo continuam sendo gerenciadas separadamente.

### Skills

O painel de Skills reúne em uma única entrada as skills que já estão na sua máquina e as que você pode instalar pela galeria.

- **Local Skills:** Veja o que está instalado nesta máquina e verifique atualizações em lote.
- **Gallery:** Busque por palavra-chave e origem e veja se uma skill já está instalada.
- **Trusted Providers:** Antes de instalar, confirme a origem, o status de confiança e o comando que realmente será executado, e decida quais origens são consideradas confiáveis.

### Vault e Code Server

- Um **Vault** é uma pasta fora dos repositórios do seu projeto que o HagiCode pode consultar. Use-o para documentos de referência, anotações e resultados de pesquisa. Há três tipos: Folder, CodeRef e Obsidian.
- Ao criar uma sessão, escolha quais Vaults incluir no escopo dela. Marque um como editável para que a IA possa escrever nele; caso contrário, ele serve apenas como referência somente leitura.
- O **Code Server** oferece um ponto de entrada de edição no navegador, que você pode abrir diretamente a partir de um Vault ou de um projeto.

![Painel do Vault com Vaults de usuário e de sistema, uma árvore de arquivos e a prévia em Markdown de uma nota de arquitetura](../img/screenshots/product/vault-browser/original.png)

Saiba mais: [Guia do Vault](/pt-BR/user-guide/vault)

### Super Commit

Clique em "Super Commit" na aba Git e o HagiCode lê suas alterações atuais e escreve as mensagens de commit no formato Conventional Commits.

- As alterações relacionadas são agrupadas em vários commits, em vez de um único commit genérico.
- Em projetos MonoSpecs, as alterações são commitadas no subrepositório correto.
- Uma tag Co-Authored-By é adicionada automaticamente, e o nome e o e-mail podem ser definidos por projeto ou de forma global.

## Para quem é

- **Uma boa escolha:** Desenvolvedores e equipes que mantêm vários repositórios e querem planejar mudanças complexas antes de executá-las, e pessoas que já usam Agent CLI como Claude Code ou Codex e querem tê-los em um único espaço de trabalho.
- **Não essencial:** Se você só precisa completar algumas linhas no seu editor, as ferramentas que você já usa são suficientes.

## Edições e preços

Os recursos básicos são gratuitos. Desktop e Microsoft Store são duas formas diferentes de obter o HagiCode, não dois planos pagos. O canal da Microsoft Store também oferece o Turbo Engine, uma compra única separada que aumenta o limite de propostas simultâneas e desbloqueia melhorias como temas de documentação, atribuição personalizada, identidade visual e upload de avatares personalizados. Consulte o [complemento Turbo Engine](/pt-BR/dlc/turbo-engine-dlc/) para saber exatamente o que ele desbloqueia.

| Seu ambiente | Opção recomendada |
| --- | --- |
| Windows com acesso à Microsoft Store | [Instalar pela Microsoft Store](/pt-BR/installation/windows-store) |
| Instalação manual no Windows ou uso local no macOS ou Linux | [Instalar o Desktop](/pt-BR/installation/desktop) |

O aplicativo principal na Steam foi descontinuado e não é mais um canal de instalação. Veja o [status da distribuição na Steam](/pt-BR/faq/steam-distribution-status/).

## Por que criar um espaço de trabalho?

Sou Kun Yu, criador do HagiCode. Uma pergunta e sua resposta podem resolver um problema imediato, mas o desenvolvimento real também exige entender o projeto, definir limites, levar mudanças adiante e revisar os resultados. Quis reunir essas etapas antes dispersas; o feedback gamificado ajuda a visualizar o progresso do trabalho de longo prazo. Você pode usar apenas parte dos recursos. Não precisa aprender todos os módulos antes de começar a programar.

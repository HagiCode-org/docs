The official Desktop app is now the recommended path: download the Windows, macOS, or Linux installer from [OmniRoute GitHub Releases](https://github.com/diegosouzapw/OmniRoute/releases). The npm procedure below remains available for headless environments.

Esta página apresenta o caminho local recomendado do OmniRoute: `npm install -g omniroute`, seguido de `omniroute start`, com o Dashboard em `http://localhost:20128` e a URL base compatível com OpenAI em `http://localhost:20128/v1`.

:::tip[Caminho recomendado]
O Dashboard está em `http://localhost:20128` e a URL base compatível com OpenAI está em `http://localhost:20128/v1`. Docker e modos avançados são opcionais.
:::

## Pré-requisitos

- O Node.js deve ser `>=22.0.0 <23` ou `>=24.0.0 <27`. Node.js 21 e 23 não são compatíveis. Completo [Instalando Node.js](/pt-BR/related-software-installation/nodejs/installation) primeiro, se necessário.
- As portas locais `20128` e `20129` estão disponíveis e ainda não estão ocupadas.
- Você tem pelo menos uma conta de provedor de modelo upstream que planeja rotear por meio do OmniRoute.
- Antes de integrar o HagiCode, uma CLI ou um SDK, mantenha estes dois endereços separados:
  - Painel: `http://localhost:20128`
  - URL base compatível com OpenAI: `http://localhost:  20128/v1`

## Instale e execute localmente

Comece com o caminho npm global recomendado:

```bash
npm install -g omniroute
omniroute start
```

Após o início do serviço, valide-o nesta ordem:

1. Abrir `http://localhost:20128` em um navegador e confirme se o Dashboard é carregado.
2. Vá para o `Endpoints` página no Painel e crie ou copie uma chave de API.
3. Observe o URL base que você entregará às ferramentas posteriormente: `http://localhost:20128/v1`.

:::note[Por que começar com o Dashboard]
Para a primeira configuração, o Dashboard é a maneira mais rápida de confirmar se o OmniRoute está em execução, se seus provedores estão conectados e se existe uma chave de API. Se uma chamada de cliente posterior falhar, verificar primeiro o Dashboard geralmente é mais rápido do que depurar o código SDK imediatamente.
:::

## Valide o serviço em execução

### Validação 1: confirme se o catálogo do modelo está legível

Coloque a chave do `Endpoints` página em uma variável de ambiente:

```bash
export OMNIROUTE_API_KEY="replace-with-the-key-you-copied-from-the-Endpoints-page"
```

Então solicite `/v1/models`:

```bash
curl http://localhost:20128/v1/models \
  -H "Authorization: Bearer ${OMNIROUTE_API_KEY}"
```

Se você receber uma lista de modelos de volta, o endpoint compatível com OpenAI e o fluxo de autenticação estão funcionando.

### Validação 2: envie uma solicitação mínima de chat

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer ${OMNIROUTE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "replace-with-a-model-id-from-v1-models",
    "messages": [
      { "role": "user", "content": "Reply with ok." }
    ]
  }'
```

O objetivo aqui não é a qualidade imediata. É para provar que o modelo escolhido já pode ser roteado com sucesso através do OmniRoute.

O HagiCode Desktop não fornece mais o Node.js nem o npm junto com o aplicativo, e também não inclui nenhum outro conjunto de ferramentas Node. O pacote de instalação do Desktop traz apenas o runtime .NET necessário para executar o Hagicode Server; sempre que o Node é necessário, ele usa o **`node` e o `npm` que já estão instalados no seu sistema**.

Este FAQ é útil quando você quer saber qual `node` o Desktop realmente usa, onde os Agent CLIs foram instalados, o que fazer quando o Desktop avisa que não encontrou o Node e o que é o diretório `portable-fixed/toolchain` que sobrou depois de atualizar de uma versão antiga.

## Requisitos de versão

É necessário o **Node.js 24 ou superior** (o requisito mínimo também é 24). O `npm` é instalado junto com o Node.js. Para instalar, veja [Instalar o Node.js](/pt-BR/related-software-installation/nodejs/installation).

O Git também precisa ser instalado por você; veja o [Guia de instalação](/pt-BR/installation/#instalar-o-git).

## Como o Desktop encontra o node e o npm

Ao iniciar, o Desktop lê o `PATH` do sistema e procura nele `node`, `npm` e `git`. Isso significa que:

- A versão que você vê ao executar `node --version` no terminal normalmente é a que o Desktop usa.
- O Desktop apenas **usa** o seu ambiente Node; ele não o substitui nem o modifica.
- Se você instalar ou atualizar o Node.js com o Desktop já aberto, feche-o por completo e abra-o novamente para que ele leia o novo `PATH`.

:::caution[Gerenciadores de versões e PATH]
No macOS e no Linux, gerenciadores de versões como nvm e fnm costumam definir o `PATH` apenas nos arquivos de configuração do shell. O Desktop aberto pelo Dock, pelo menu de aplicativos ou por um ícone da área de trabalho não lê essas configurações e pode não encontrar o `node`. Abra o Desktop a partir de um terminal em que o `node` já funcione ou use uma instalação em nível de sistema.
:::

## Onde os pacotes gerenciados, como os Agent CLIs, são instalados

A página de gerenciamento de dependências do Desktop descobre o `node` e o `npm` no `PATH`, exibe o prefixo global do npm resolvido e instala os pacotes de CLI listados no catálogo nesse diretório global **externo**.

Para cada CLI gerenciado, o Desktop procura o executável na seguinte ordem:

1. Um caminho gerenciado já existente
2. O diretório `bin` global do npm (no Windows, inclui os scripts de inicialização `.cmd` e `.ps1`)
3. O `PATH`

As configurações de espelho do npm se aplicam às operações de instalação e de sincronização. A desinstalação também atua no diretório global externo e exige confirmação na interface. Você pode usar o comando abaixo para ver o diretório global atual:

```bash
npm prefix -g
```

Se o diretório global estiver em um local que exige privilégios de administrador, podem ocorrer erros de permissão durante a instalação; consulte [Configurar o diretório global do npm](/pt-BR/related-software-installation/nodejs/installation#configurar-o-diretório-global-do-npm).

## O que fazer se aparecer que o Node ou o npm não foi encontrado

1. Execute `node --version` e `npm --version` no terminal e confirme que a versão não é inferior a 24.
2. Se não estiverem instalados ou a versão for muito antiga, instale primeiro o Node.js fora do Desktop.
3. Feche o Desktop por completo e abra-o novamente; depois, volte à página de dependências e clique em atualizar.

Quando o Desktop avisar que um pacote de CLI precisa ser instalado manualmente, execute o comando indicado em um terminal fora do Desktop e, ao terminar, volte ao Desktop e atualize uma vez para que ele detecte novamente.

## O que é o `portable-fixed/toolchain` que aparece depois da atualização

Versões mais antigas do Desktop empacotavam um conjunto de ferramentas Node junto com o aplicativo; por isso, as informações de diagnóstico mostravam o caminho `portable-fixed/toolchain` ou a variável `HAGICODE_PORTABLE_TOOLCHAIN_ROOT`, e os pacotes gerenciados ficavam em locais como `node22/npmGlobal`, dentro do diretório de dados do usuário.

A versão atual removeu esse conjunto de ferramentas incluído:

- As novas versões não usam mais esses caminhos, e o Desktop verifica apenas o diretório global do npm da sua máquina.
- As novas versões não leem os CLIs já instalados no diretório antigo. Se a página de dependências mostrar que algum CLI não está instalado, reinstale-o no novo diretório global do npm.

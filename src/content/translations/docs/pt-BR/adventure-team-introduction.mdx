O **Agent** é o núcleo do HagiCode: as sessões são executadas por Agents, e é preciso ter pelo menos um antes de começar a trabalhar. Esta página é uma visão geral para ajudar você a entender o que compõe um Agent, quem faz cada tipo de trabalho e em quais lugares ficam as configurações relacionadas a Agents. Para as operações passo a passo, consulte o [guia do Agents Workspace](/pt-BR/user-guide/agents).

## Visão geral dos recursos

- Um **Agent = Agent CLI + modelo + texto de personalidade opcional**. A Agent CLI é a ferramenta de linha de comando que realmente executa o trabalho (por exemplo, Claude Code ou Codex), o modelo é o que ela usa, e o texto de personalidade (Trait e Soul) molda a forma de trabalhar e o estilo de fala.
- Você pode criar vários Agents, por exemplo um que usa Opus para revisão, outro que usa Haiku para alterações rápidas e outro que usa Codex para refatoração.
- Qual Agent faz cada tipo de trabalho é definido pelos **cenários de execução**; quando não há um membro adequado, a **Fallback Crew** assume.
- A inspeção e o ajuste dos Agents ficam distribuídos entre o **Agents Workspace** e as **configurações**: o primeiro cuida de Agents, cenários, CLIs e modelos, e as segundas cuidam de comportamentos de runtime, como novas tentativas e limites de memória e CPU.

## Lista de Agents

![Aba Agents: cinco Agents agrupados por Claude Code e Codex, cada um com avatar e modelo](../img/screenshots/guides/agent-roster/original.png)

Clique em **Agents** na barra superior para abrir o **Agents Workspace**. Em **My Agents**, na aba **Agents**, seus Agents são listados e agrupados por Agent CLI, e cada cartão mostra avatar, nome e modelo. Aqui você pode:

1. Criar um Agent com **New Agent**: escolha a AgentCLI e um modelo compatível e, opcionalmente, escreva um Trait (conhecimento e comportamento) e um Soul (estilo de linguagem).
2. Criar vários de uma vez com **Batch create Agents**, ou filtrar pela caixa de pesquisa por nome, CLI ou descrição.
3. Habilitar ou desabilitar um Agent com a chave **Battle ready**.

Para a explicação completa do processo de criação, consulte [Agents](/pt-BR/user-guide/agents#criar-agent).

## Divisão do trabalho: cenários de execução e Fallback Crew

![Aba Execution Scenarios: grupos de Agents dos cenários Proposal e HagiTask, com os Agents já atribuídos e os disponíveis à direita](../img/screenshots/guides/agent-scenarios/original.png)

A aba **Execution Scenarios** define quais Agents fazem cada tipo de trabalho. Os cenários são agrupados por finalidade:

| Grupo | Cenários |
| --- | --- |
| **Proposal** | Otimizar, gerar, executar e arquivar propostas |
| **HagiTask** | Super Commit, criar sessão comum, criar tarefa de pesquisa de código |
| **Chat** | Otimização do título da conversa |

Ao clicar em um cenário, **Assigned Agents** mostra à direita o grupo atribuído a ele e **Available Agents** mostra os Agents que podem ser adicionados; use **Add** ou **Remove** para ajustar. A **Fallback Crew** é a rede de segurança: quando o grupo de um cenário não tem um Agent adequado, o HagiCode escolhe um membro elegível da Fallback Crew. **Enquanto a Fallback Crew não tiver pelo menos um Agent habilitado, todos os outros cenários permanecem bloqueados.** O assistente de inicialização adiciona automaticamente o seu primeiro Agent a ela.

Uma combinação comum:

1. Coloque em **Generate Proposal** um Agent bom em contexto longo e revisão.
2. Coloque em **Execute Proposal** um Agent com boa capacidade de execução e custo adequado.
3. Coloque em **Super Commit** e **Conversation Title Optimization** um Agent barato e rápido.
4. Mantenha na Fallback Crew um Agent de uso geral estável.

## Onde ficam as configurações relacionadas

| O que você quer fazer | Onde ir |
| --- | --- |
| Criar, editar, habilitar ou desabilitar um Agent | **Agents** → aba **Agents** |
| Atribuir Agents a cada tipo de trabalho e manter a Fallback Crew | **Agents** → **Execution Scenarios** |
| Ver se uma Agent CLI está instalada, saudável e habilitada | **Agents** → **AgentCLI**, popover de AI Monitoring na barra de status |
| Navegar ou adicionar modelos disponíveis para uma CLI | **Agents** → **Model** |
| Trocar o avatar ou o tema de texto | **Agents** → **Avatar Gallery** / **Document Theme** |
| Novas tentativas automáticas de execuções com falha | **Configurações** → **Error Retry** |
| Declarar ou não no prompt gerado que "esta execução não é interativa" | **Configurações** → **AgentCLI Interactive Control** |
| Limitar a memória e a CPU que cada Agent pode usar | **Configurações** → **Agent resource limits** |
| Conectar vários modelos compatíveis com OpenAI a um mesmo gateway local | **Configurações** → **OmniRoute** |

Para a função de cada item, consulte [Configurações](/pt-BR/user-guide/settings).

## Cenários de uso e limites

- Quando você quer usar modelos ou CLIs diferentes em etapas diferentes (por exemplo, separar revisão e execução), divida o trabalho por cenários.
- Usar um único Agent também funciona perfeitamente: coloque-o na Fallback Crew e todos os cenários vão usá-lo.
- O Agent decide apenas **quem executa**. O que executar continua vindo das sessões, propostas ou planos que você cria.

На этой странице описано, как установить Node.js в Windows, macOS и Linux. Desktop и версия из Microsoft Store больше не включают Node.js: они напрямую используют `node` и `npm` из вашей системы, и от них же зависят OpenSpec и большинство Agent CLI.

:::tip[Требования к версии]
Нужен **Node.js 24 или выше**, минимально допустимая версия — тоже 24. Обычно достаточно установить последнюю LTS-версию. `npm` устанавливается вместе с Node.js, отдельно устанавливать его не нужно.
:::

:::note[Для каких способов установки он нужен]
- **Microsoft Store / Desktop**: нужен, причем `node` и `npm` должны находиться в системной переменной `PATH`.
- **Docker Compose**: на хосте не нужен.
:::

## Установка Node.js

<Tabs>
  <TabItem value="windows" label="Windows" default>

### Способ первый: официальный установщик (рекомендуется)

1. Откройте [официальный сайт Node.js](https://nodejs.org/)
2. Скачайте установщик Windows (файл `.msi`) версии **LTS (долгосрочная поддержка)** и убедитесь, что номер версии не ниже 24
3. Дважды щелкните, чтобы запустить установщик
4. Следуйте подсказкам мастера установки:
   - Примите лицензионное соглашение
   - Выберите путь установки (подойдет значение по умолчанию)
   - Оставьте флажок «Add to PATH» установленным
   - Нажмите «Install», чтобы начать установку
5. После завершения установки нажмите «Finish»

### Способ второй: использование winget

Откройте PowerShell или командную строку и выполните следующую команду:

```powershell
winget install OpenJS.NodeJS.LTS
```

После установки заново откройте терминал, чтобы изменения вступили в силу.

  </TabItem>
  <TabItem value="macos" label="macOS">

### Способ первый: официальный установщик (рекомендуется)

1. Откройте [официальный сайт Node.js](https://nodejs.org/)
2. Скачайте установщик macOS (файл `.pkg`) версии **LTS (долгосрочная поддержка)** и убедитесь, что номер версии не ниже 24
3. Дважды щелкните, чтобы запустить установщик
4. Следуйте подсказкам мастера установки:
   - Нажмите «Продолжить»
   - Примите лицензионное соглашение
   - Выберите диск для установки
   - Нажмите «Установить» и введите пароль администратора
5. После завершения установки нажмите «Закрыть»

### Способ второй: использование Homebrew

Если у вас уже установлен [Homebrew](https://brew.sh/), Node.js можно установить через терминал:

```bash
brew install node
```

:::tip
Homebrew автоматически добавляет Node.js в ваш PATH. Если команда недоступна, перезапустите терминал или выполните:
```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```
:::

### Использование репозитория NodeSource (рекомендуется)

Версия Node.js в собственных репозиториях дистрибутива обычно ниже 24, поэтому используйте репозиторий 24.x от NodeSource:

```bash
# Скачайте скрипт установки с помощью curl
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs
```

:::caution
Не устанавливайте версию из репозитория дистрибутива напрямую командой `sudo apt-get install nodejs npm`: с большой вероятностью она не удовлетворяет минимальному требованию — версии 24.
:::

Если вы не хотите добавлять стороннего источника пакетов, можно использовать [nvm или fnm](#использование-менеджеров-версий), описанные ниже.

  </TabItem>
  <TabItem value="centos" label="CentOS/RHEL">

### Использование репозитория NodeSource (рекомендуется)

```bash
# Скачайте скрипт установки с помощью curl
curl -fsSL https://rpm.nodesource.com/setup_24.x | sudo bash -
sudo yum install -y nodejs
```

Версия Node.js в собственных репозиториях дистрибутива обычно ниже 24, поэтому напрямую использовать ее не рекомендуется. Можно также воспользоваться [nvm или fnm](#использование-менеджеров-версий), описанными ниже.

  </TabItem>
  <TabItem value="fedora" label="Fedora">

### Использование менеджера пакетов dnf

```bash
sudo dnf install -y nodejs npm
```

После установки выполните `node --version` и убедитесь, что версия не ниже 24. Если версия в репозитории ниже, используйте репозиторий 24.x от NodeSource или [nvm или fnm](#использование-менеджеров-версий), описанные ниже.

  </TabItem>

## Использование менеджеров версий

Если вам нужно переключаться между несколькими версиями Node.js, можно использовать менеджеры версий.

:::caution[Пользователям Desktop на заметку]
В macOS и Linux такие инструменты, как nvm и fnm, обычно задают `PATH` только в файлах конфигурации оболочки (например, `.bashrc`, `.zshrc`). Desktop, запущенный из Dock, меню приложений или с ярлыка на рабочем столе, эти файлы не читает и может не найти `node`. Если вы используете менеджер версий, запускайте Desktop из терминала, в котором уже работает `node`, либо воспользуйтесь описанной выше установкой на уровне системы.
:::

### nvm (Node Version Manager)

<Tabs>
  <TabItem value="nvm-install" label="Установка nvm" default>

#### Linux/macOS

Скопируйте актуальную команду установки прямо из [README официального репозитория nvm](https://github.com/nvm-sh/nvm#installing-and-updating) и не используйте адреса скриптов старых версий.

После установки перезагрузите конфигурацию оболочки:

```bash
source ~/.bashrc
# Или для пользователей Zsh
source ~/.zshrc
```

#### Windows

В Windows рекомендуется использовать [nvm-windows](https://github.com/coreybutler/nvm-windows):

1. Скачайте последнюю версию `nvm-setup.exe` со страницы [nvm-windows releases](https://github.com/coreybutler/nvm-windows/releases)
2. Запустите установщик
3. Заново откройте командную строку или PowerShell

  </TabItem>
  <TabItem value="nvm-use" label="Использование nvm">

После установки nvm с его помощью можно устанавливать версии Node.js и управлять ими:

```bash
# Установить Node.js 24
nvm install 24

# Переключиться на Node.js 24
nvm use 24

# Задать версию по умолчанию
nvm alias default 24

# Показать список установленных версий
nvm list
```

В nvm-windows команда `alias` недоступна, достаточно `nvm install 24` и `nvm use 24`.

  </TabItem>
</Tabs>

### fnm (Fast Node Manager)

fnm — это более быстрый и простой инструмент управления версиями Node.js, написанный на Rust.

<Tabs>
  <TabItem value="fnm-install" label="Установка fnm" default>

#### Linux/macOS

```bash
# Установка с помощью curl
curl -fsSL https://fnm.vercel.app/install | bash

# После установки перезагрузите конфигурацию оболочки
source ~/.bashrc
# Или для пользователей Zsh
source ~/.zshrc
```

#### Windows

Используйте [scoop](https://scoop.sh/) или [winget](https://learn.microsoft.com/en-us/windows/package-manager/winget/):

```powershell
# Через scoop
scoop install fnm

# Или через winget
winget install Schniz.fnm
```

  </TabItem>
  <TabItem value="fnm-use" label="Использование fnm">

```bash
# Установить Node.js 24
fnm install 24

# Переключиться на Node.js 24
fnm use 24

# Задать версию по умолчанию
fnm default 24

# Показать список установленных версий
fnm list
```

  </TabItem>
</Tabs>

## Ускорение для пользователей из материкового Китая

Если вы находитесь в материковом Китае, пакеты Node.js и npm могут скачиваться медленно — в этом случае можно использовать отечественные зеркала.

### Зеркало npm

```bash
# Временно использовать зеркало при установке
npm install --registry=https://registry.npmmirror.com

# Задать зеркало на постоянной основе
npm config set registry https://registry.npmmirror.com

# Проверить, что зеркало задано успешно
npm config get registry
```

### Зеркало установочных пакетов Node.js

У установочных пакетов Node.js тоже есть зеркало для скачивания: [https://npmmirror.com/mirrors/node/](https://npmmirror.com/mirrors/node/). Откройте его и выберите версию не ниже 24.

### Зеркало Homebrew

Если вы используете Homebrew в материковом Китае, для bottle можно настроить зеркало USTC:

```bash
export HOMEBREW_BOTTLE_DOMAIN=https://mirrors.ustc.edu.cn/homebrew-bottles
```

## Проверка установки

После установки проверьте, что Node.js и npm работают, в **заново открытом терминале**:

```bash
# Проверьте версию Node.js: нужна v24.0.0 или выше
node --version

# Проверьте версию npm
npm --version
```

Успешный вывод должен выглядеть примерно так:

```
$ node --version
v24.3.0

$ npm --version
11.4.2
```

:::note
Если `node --version` показывает версию ниже 24, переустановите Node.js одним из описанных выше способов или переключитесь на версию 24 и выше с помощью менеджера версий.
:::

## Настройка глобального каталога npm

Desktop устанавливает управляемые пакеты, например Agent CLI, в глобальный каталог npm на вашем компьютере. Если глобальный каталог находится в месте, где нужны права администратора, при установке может возникнуть ошибка доступа `EACCES`. Рекомендуется перенести глобальный каталог в пользовательский каталог, а не менять права доступа к системным каталогам:

```bash
mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
```

Затем добавьте `~/.npm-global/bin` (в Windows — сам глобальный каталог npm) в системную переменную `PATH` и перезапустите терминал и Desktop. Если вы используете nvm или fnm, глобальный каталог уже находится в пользовательском каталоге, и этот шаг не нужен.

## Устранение неполадок

### Проблемы в Windows

<Tabs>
  <TabItem value="win-path" label="Команда недоступна">

Если после установки команды `node` или `npm` недоступны:

1. Заново откройте командную строку или PowerShell
2. Если они по-прежнему недоступны, добавьте Node.js в PATH вручную:
   - Найдите «Переменные среды» и откройте «Изменение системных переменных среды»
   - Нажмите «Переменные среды»
   - В разделе «Системные переменные» найдите «Path» и нажмите «Изменить»
   - Добавьте путь установки Node.js (по умолчанию: `C:\Program Files\nodejs\`)
   - Нажмите «ОК», чтобы сохранить изменения
3. Полностью закройте Desktop и запустите его заново

  </TabItem>
  <TabItem value="win-policy" label="Политика выполнения PowerShell">

Если при использовании nvm или скриптов npm возникают ошибки политики выполнения:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

  </TabItem>
</Tabs>

### Проблемы в macOS

<Tabs>
  <TabItem value="mac-perm" label="Ошибки доступа">

Если при установке глобальных пакетов npm возникают ошибки доступа, см. раздел [Настройка глобального каталога npm](#настройка-глобального-каталога-npm) выше или используйте nvm / fnm.

  </TabItem>
  <TabItem value="mac-path" label="Команда недоступна">

Если после установки команда недоступна, перезапустите терминал и убедитесь, что каталог с Node.js (обычно `/usr/local/bin` или `/opt/homebrew/bin`) есть в `PATH`.

  </TabItem>
</Tabs>

### Проблемы в Linux

<Tabs>
  <TabItem value="linux-perm" label="Ошибки доступа">

Если при установке глобальных пакетов npm возникают ошибки доступа, см. раздел [Настройка глобального каталога npm](#настройка-глобального-каталога-npm) выше или используйте nvm / fnm вместо установки глобальных пакетов через `sudo`.

  </TabItem>
  <TabItem value="linux-old" label="Версия слишком старая">

Если версия Node.js, установленная через системный менеджер пакетов, ниже 24:

1. Используйте репозиторий 24.x от NodeSource (см. выше)
2. Или используйте менеджеры версий (nvm / fnm)

  </TabItem>
</Tabs>

### Проверка среды

Если проверка не удалась, проверьте следующее:

<Tabs>
  <TabItem value="win-check" label="Windows">

```powershell
# Проверьте, есть ли Node.js в PATH
where node

# Проверьте путь установки
Get-Command node
```

  </TabItem>
  <TabItem value="mac-check" label="macOS">

```bash
# Проверьте, есть ли Node.js в PATH
which node

# Проверьте путь установки
ls -l $(which node)
```

  </TabItem>
  <TabItem value="linux-check" label="Linux">

```bash
# Проверьте, есть ли Node.js в PATH
which node

# Проверьте путь установки
ls -l $(which node)
```

  </TabItem>
</Tabs>

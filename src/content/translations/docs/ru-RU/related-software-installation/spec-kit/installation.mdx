Spec Kit — это открытый набор инструментов от GitHub для разработки на основе спецификаций (Spec-Driven Development): сначала пишется спецификация, затем план и задачи, и только потом ИИ-ассистент реализует задачи. Его командная строка называется `specify` и поставляется пакетом `specify-cli`.

Многие руководства в сети до сих пор используют старую команду установки, флаг `--ai` и имена команд вроде `/speckit.specify`, и при копировании всё это нередко не работает. Здесь по официальной документации описан актуальный способ и перечислено, что изменилось.

:::note[Когда это проверялось]
Страница составлена по [официальной документации Spec Kit](https://github.github.com/spec-kit/) и проверена 2026-10-26. Проект быстро развивается, поэтому при расхождениях ориентируйтесь на `specify --help` на вашей машине и на официальную документацию.

## Для кого эта страница

- Для тех, кто хочет попробовать процесс на основе спецификаций в ИИ-ассистенте: Claude Code, GitHub Copilot, Gemini CLI, CodeBuddy CLI, Pi или Oh My Pi.
- Для тех, кто поставил Spec Kit по старому руководству, а теперь получает ошибки или не находит команды.

## Требования

| Что | Требование |
| --- | --- |
| ОС | Linux, macOS или Windows (скрипты PowerShell работают без WSL) |
| Python | 3.11 или новее |
| Менеджер пакетов | uv (рекомендуется) или pipx |
| ИИ-ассистент | Любой поддерживаемый; в официальной документации перечислены десятки интеграций |
| Git | Необязателен, нужен только при включённом расширении git |

Сам Spec Kit не требует Node.js. Если ваш ассистент ставится через npm, сначала прочитайте [Установка AI Agent CLI](/ru-RU/related-software-installation/ai-agent-cli/).

## Установка specify-cli

### Способ 1: из PyPI (самый короткий)

```bash
# Рекомендуется: uv
uv tool install specify-cli

# Или pipx
pipx install specify-cli

# Или pip
pip install specify-cli
```

Чтобы зафиксировать версию: `uv tool install specify-cli==0.12.11` (подставьте версию со страницы релизов).

### Способ 2: из тега релиза на GitHub

Официальная документация называет это рекомендуемым воспроизводимым способом. Нужен uv:

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@vX.Y.Z
```

Замените `vX.Y.Z` тегом со страницы [Releases](https://github.com/github/spec-kit/releases). **Начальную букву `v` оставляйте**, например `v0.12.11`.

### Проверка установки

```bash
specify version
specify self check
```

`specify version` подтверждает, что команда доступна, и показывает версию. `specify self check` только читает данные и сообщает, есть ли более новый релиз.

## Инициализация проекта

```bash
specify init my-project --integration claude
cd my-project
```

`--integration` выбирает вашего ИИ-ассистента. Частые значения: `claude`, `copilot`, `gemini`, `codebuddy`, `pi`, `omp`. Полезные параметры:

- `--script sh|ps|py` — тип скриптов. По умолчанию `ps` в Windows и `sh` в остальных системах.
- `--here --force` — инициализация в уже существующем непустом каталоге. `--force` означает, что вы приняли предупреждение о слиянии, поэтому заранее закоммитьте или сохраните локальные изменения.
- `--non-interactive` — для CI. **Без `--integration` по умолчанию выбирается GitHub Copilot**, не попадитесь на это.

## Имена команд: `/speckit-*`

После инициализации эти команды запускаются в чате ИИ-ассистента, а не в терминале:

| Шаг | Команда | Что делает |
| --- | --- | --- |
| 1 | `/speckit-constitution` | Записывает принципы проекта, по которым проверяются следующие шаги; один раз на проект |
| 2 | `/speckit-specify` | Превращает описание функции обычными словами в `spec.md` |
| 3 | `/speckit-clarify` | Задаёт вопросы о пробелах в спецификации и вносит ответы в неё |
| 4 | `/speckit-plan` | Создаёт `plan.md` и другие артефакты проектирования под ваш стек |
| 5 | `/speckit-checklist` | Создаёт чек-лист качества требований |
| 6 | `/speckit-tasks` | Создаёт `tasks.md` с учётом зависимостей |
| 7 | `/speckit-analyze` | Только чтение: ищет противоречия и пробелы между `spec.md`, `plan.md` и `tasks.md` |
| 8 | `/speckit-implement` | Выполняет `tasks.md` по порядку |
| 9 | `/speckit-converge` | Сверяет код со спецификацией и добавляет задачи для найденных пробелов; повторяйте implement и converge, пока не появится `Converged` |

Короткий путь: specify → plan → tasks → implement → converge. Constitution, clarify, checklist и analyze входят только в полный путь.

:::caution[В вашем ассистенте имена могут выглядеть иначе]
В официальном быстром старте используются имена с дефисом `/speckit-*` (режим навыков по умолчанию в GitHub Copilot). В старых руководствах и заметках об обновлении ещё встречается запись через точку, например `/speckit.specify`. Формат вызова зависит от ассистента и режима, поэтому ориентируйтесь на имена, которые реально появились в списке команд вашего ассистента после инициализации.
:::

## Что изменилось по сравнению со старыми руководствами

| Часто встречается в старых руководствах | Сейчас |
| --- | --- |
| Только `uv tool install ... --from git+https://...` | `specify-cli` есть и в PyPI, ставится через uv, pipx или pip; установка из тега GitHub по-прежнему поддерживается |
| `specify init --ai claude` | В официальной документации везде `--integration claude` |
| `/speckit.specify`, `/speckit.plan` | В быстром старте `/speckit-specify` и `/speckit-plan`, а также новая `/speckit-converge` |
| `/constitution` распространяет изменения на шаблоны и файлы команд | Теперь обновляет только `.specify/memory/constitution.md`; чтобы вернуть прежнее поведение, выполните `specify preset add constitution-sync` |
| Возможности git всегда включены | Теперь это необязательное расширение: `specify extension add git` |
| Текущая функция определяется по ветке Git | Каталог текущей функции записан в `.specify/feature.json` |

## Обновление

Обновление самой командной строки:

```bash
specify self check                 # только чтение: есть ли новый релиз
specify self upgrade --dry-run     # предварительный просмотр без обновления
specify self upgrade               # обновление до последней стабильной версии
specify self upgrade --tag vX.Y.Z  # закрепить тег релиза
```

Обновление файлов внутри существующего проекта, из каталога проекта:

```bash
specify integration status         # установленные интеграции и изменённые файлы
specify integration upgrade <key>  # по одному разу для каждой установленной интеграции
specify extension update           # обновить все расширения
```

Флаг `--force` для `specify integration upgrade` добавляйте только тогда, когда команда сообщает о локально изменённых управляемых файлах и вы уже просмотрели различия.

## Частые проблемы

- **`command not found: uv`**: сначала установите uv, затем повторите команду установки.
- **`No such option: --integration`**: в `PATH` раньше стоит старый `specify` (например, 0.1.6). Переустановите тем же инструментом, которым ставили, например `uv tool install --force specify-cli`, и проверьте `specify version`.
- **Установлено две копии**: установка через uv, pipx и pip оставляет отдельные копии. Обновляйте тем же инструментом и не смешивайте их.
- **Установка из PyPI сама не обновляется**: версия остаётся той, что вы поставили, поэтому используйте команды обновления выше.
- **Инициализация отказывается работать в существующем каталоге**: после коммита или резервной копии добавьте `--here --force`.

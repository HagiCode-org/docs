The official Desktop app is now the recommended path: download the Windows, macOS, or Linux installer from [OmniRoute GitHub Releases](https://github.com/diegosouzapw/OmniRoute/releases). The npm procedure below remains available for headless environments.

На этой странице описан рекомендуемый локальный путь OmniRoute: `npm install -g omniroute`, затем `omniroute start`; панель управления доступна по адресу `http://localhost:20128`, а базовый URL OpenAI — по адресу `http://localhost:20128/v1`.

:::tip[Рекомендуемый путь]
Панель управления находится по адресу `http://localhost:20128`, а базовый URL OpenAI — по адресу `http://localhost:20128/v1`. Docker и расширенные режимы развертывания являются необязательными.
:::

## Предварительные условия

- Node.js должен быть версии `>=22.0.0 <23` или `>=24.0.0 <27`. Node.js 21 и 23 не поддерживаются. Завершить [Установка Node.js](/ru-RU/related-software-installation/nodejs/installation) сначала, если нужно.
- Локальные порты `20128` и `20129` свободны и еще не заняты.
- У вас есть по крайней мере одна учетная запись поставщика вышестоящей модели, которую вы планируете маршрутизировать через OmniRoute.
- Перед интеграцией HagiCode, CLI или SDK разделите эти два адреса:
  - Панель управления: `http://localhost:20128`
  - Базовый URL-адрес, совместимый с OpenAI: `http://localhost:  20128/v1`

## Установить и запустить локально

Начните с рекомендуемого глобального пути npm:

```bash
npm install -g omniroute
omniroute start
```

После запуска службы проверьте ее в следующем порядке:

1. Открыть `http://localhost:20128` в браузере и убедитесь, что панель мониторинга загружается.
2. Перейти к `Endpoints` на панели инструментов и создайте или скопируйте ключ API.
3. Запишите базовый URL-адрес, который вы передадите инструментам позже: `http://localhost:20128/v1`.

:::note[Зачем начинать с панели управления]
При первой настройке Dashboard — это самый быстрый способ убедиться, что OmniRoute работает, ваши провайдеры подключены и существует ключ API. Если последующий вызов клиента завершается неудачей, первая проверка панели мониторинга обычно оказывается быстрее, чем немедленная отладка кода SDK.
:::

## Проверка работающей службы

### Проверка 1: убедитесь, что каталог моделей доступен для чтения.

Положите ключ от `Endpoints` страницу в переменную среды:

```bash
export OMNIROUTE_API_KEY="replace-with-the-key-you-copied-from-the-Endpoints-page"
```

Затем запросите `/v1/models`:

```bash
curl http://localhost:20128/v1/models \
  -H "Authorization: Bearer ${OMNIROUTE_API_KEY}"
```

Если вы получите обратно список моделей, значит, конечная точка, совместимая с OpenAI, и поток аутентификации работают.

### Проверка 2: отправьте минимальный запрос в чат.

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer ${OMNIROUTE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "replace-with-a-model-id-from-v1-models",
    "messages": [
      { "role": "user", "content": "Reply with ok." }
    ]
  }'
```

Целью здесь не является быстрое качество. Это значит, что выбранная вами модель уже может быть успешно маршрутизирована через OmniRoute.

HagiCode — рабочее пространство с ИИ для разработки проектов. Сначала в сеансе можно изучить репозиторий, затем уточнить задачу и область изменений, поручить ИИ внести правки и в том же месте отслеживать ход работы, готовить коммиты и повторно использовать знания о проекте. HagiCode подключает привычные вам Agent CLI и модели, не требуя перехода на определённый редактор кода.

**Пользуетесь впервые?** [Выберите способ установки](/ru-RU/installation/), пройдите [мастер первоначальной настройки](/ru-RU/quick-start/wizard-setup), создайте проект и начните с [обычного сеанса](/ru-RU/quick-start/conversation-session). Если задачу нужно сначала спланировать, воспользуйтесь [сеансом предложений](/ru-RU/quick-start/proposal-session).

## Как проходит работа над задачей

Предположим, нужно изменить функцию, затрагивающую несколько репозиториев:

1. **Сначала разобраться:** Изучите существующий код в [обычном сеансе](/ru-RU/quick-start/conversation-session). По умолчанию такие сеансы доступны только для чтения; переключитесь в режим редактирования, когда потребуется изменить файлы.
2. **Затем определить границы:** Для сложного изменения выберите проект и репозитории в [сеансе предложений](/ru-RU/quick-start/proposal-session). Прежде чем перейти к выполнению, опишите цели, задачи и способы проверки.
3. **Следить за результатом:** Просматривайте сеансы и состояние выполнения в рабочем пространстве. Подготовить коммит поможет [AI Compose Commit](/ru-RU/guides/ai-compose-commit).
4. **Сохранить контекст:** К предложениям и истории коммитов можно вернуться позже. При работе с несколькими репозиториями используйте [MonoSpecs](/ru-RU/guides/monospecs) для управления связями между ними и областью изменений.

Не для каждой задачи нужно создавать предложение: если вы хотите просто изучить код или решить несложный вопрос, начните с обычного сеанса. Если задаче требуется больше контекста, HagiCode помогает выстроить отслеживаемый процесс работы.

## Возможности по задачам

| Если вы хотите… | Начните здесь |
| --- | --- |
| Разобраться в коде, прежде чем решать, менять ли его | [Создать обычный сеанс](/ru-RU/quick-start/conversation-session) |
| Спланировать сложную задачу перед реализацией | [Создать сеанс предложений](/ru-RU/quick-start/proposal-session) |
| Помочь ИИ разобраться в связях между репозиториями | [Руководство по MonoSpecs](/ru-RU/guides/monospecs) |
| Находить, устанавливать и управлять расширениями | [Руководство по Skills](/ru-RU/guides/skills) |
| Пользоваться привычным Agent CLI | [Установка AI Agent CLI и поддерживаемые варианты](/ru-RU/related-software-installation/ai-agent-cli/) |
| Управлять подключениями CLI и моделей по отдельности | [Установка OmniRoute и проверка запуска](/ru-RU/related-software-installation/omniroute/) |

Vault собирает справочные репозитории, папки и заметки для дальнейшего использования; Code Server даёт возможность редактировать код через браузер. Для начала работы с HagiCode ни то ни другое не требуется. Подробнее об этих решениях читайте в статьях о [базе знаний Vault](/ru-RU/blog/2026-04-10-vault-system-ai-knowledge-base/) и [редактировании в браузере](/ru-RU/blog/2026-04-13-vscode-web-integration-browser-editing/).

HagiCode также показывает обратную связь через героев, достижения, ежедневные отчёты и метрики Token, чтобы состояние и прогресс длительной работы были заметнее. Это часть рабочего пространства, но использовать HagiCode как обычный инструмент разработки можно и без этих возможностей. Подробнее — в [статье о геймификации](/ru-RU/blog/2026-03-16-gamifying-ai-coding/).

## Редакции и цены

**Desktop, Container и Microsoft Store — разные способы получения или развёртывания HagiCode, а не три платных тарифа.** Базовые возможности бесплатны. Turbo Engine в канале Microsoft Store — отдельная лицензия с разовой оплатой: она повышает предел одновременно выполняемых предложений и открывает дополнительные возможности, включая темы документации, собственную подпись, оформление бренда и аватары. Точный список приведён на странице [дополнения Turbo Engine](/ru-RU/dlc/turbo-engine-dlc/).

| Ваша среда | Рекомендуемый вариант |
| --- | --- |
| Windows с доступом к Microsoft Store | [Установка через Microsoft Store](/ru-RU/installation/windows-store) |
| Ручная установка в Windows или локальное использование на macOS либо Linux | [Установка Desktop](/ru-RU/installation/desktop) |
| Сервер, NAS или развёртывание для команды | [Установка через Docker Compose](/ru-RU/installation/docker-compose) |

Основное приложение в Steam снято с распространения и больше не служит способом установки. См. [статус распространения в Steam](/ru-RU/faq/steam-distribution-status/).

## Зачем нужно рабочее пространство?

Я Кунь Юй, создатель HagiCode. Один вопрос и ответ могут решить текущую проблему, но при разработке также приходится разбираться в проекте, определять границы задачи, вносить изменения и оценивать результат. Мне хотелось связать эти разрозненные этапы; игровые элементы обратной связи помогают видеть прогресс длительной работы. Можно пользоваться только нужными возможностями: изучать все модули перед тем, как начать писать код, необязательно.

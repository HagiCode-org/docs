HagiCode не даёт ИИ терять контекст при изменении вашего кода: **сначала изучить репозиторий, затем определить границы, после чего выполнять работу с отслеживаемой историей.** Это рабочее пространство с ИИ для разработки проектов, которое подключает привычные вам Agent CLI и модели, поэтому переключаться между редакторами не нужно. Насыщенные и удобные взаимодействия с интерфейсом делают планирование, работу агентов и проектные задачи понятными и доступными.

Не для каждой задачи нужно создавать предложение. Начните с обычного сеанса, если вы хотите просто изучить код или решить несложный вопрос. Если задаче требуется больше контекста, HagiCode предоставляет отслеживаемый путь работы.

## Возможности подробнее

### Сначала разобраться, затем действовать

HagiCode разделяет «чтение кода» и «изменение кода», чтобы вы выбирали подход по масштабу задачи, а не позволяли ИИ сразу править всё подряд.

- **Обычный сеанс:** по умолчанию только чтение. Используйте его, чтобы изучить репозиторий, разобраться в проблеме или узнать, где находится та или иная логика. В режим редактирования переключайтесь, только когда нужно изменить файлы.
- **Сеанс предложений:** для сложных изменений. Выберите проект и репозитории, опишите цели, задачи и способы проверки и переходите к выполнению, когда план вас устроит.
- **Доска сеансов:** колонки Proposal & Review, Execution и Archived (предложения и проверка, выполнение, архив) показывают состояние каждого сеанса с первого взгляда. Можно переключаться между раскладками Classic, Execution Flow Kanban и Dashboard Kanban.

### Единые границы для нескольких репозиториев

Когда запрос затрагивает сразу фронтенд, бэкенд и документацию, MonoSpecs позволяет HagiCode воспринимать их как один проект.

- Расположение дочерних репозиториев, адреса Git и отображаемые имена задаются в `.hagicode/monospecs.yaml`.
- Спецификации изменений (OpenSpec) хранятся в основном репозитории, поэтому каталоги кода дочерних репозиториев остаются чистыми.
- При создании предложения выберите, какие дочерние репозитории оно затрагивает. На странице проекта видны ветка и незафиксированные изменения каждого репозитория.

### Свой Agent CLI

HagiCode не заменяет ваш набор инструментов, а собирает его в одном рабочем пространстве.

- **Агент — это CLI, модель и необязательный текст с описанием характера.** Создайте несколько агентов, назначьте их на разные сценарии выполнения и настройте резервные группы.
- Поддерживаются 11 Agent CLI, включая Claude Code, Codex и GitHub Copilot. Рабочее пространство показывает версию, время отклика и состояние каждого CLI.
- С помощью [OmniRoute](/ru-RU/related-software-installation/omniroute/) можно подключить несколько OpenAI-совместимых инструментов и моделей к одному локальному шлюзу, а подключениями CLI и моделей управлять по отдельности.

### Skills

Панель Skills объединяет в одном месте навыки, уже установленные на вашем компьютере, и навыки, которые можно установить из галереи.

- **Local Skills (локальные):** посмотрите, что установлено на этом компьютере, и проверьте обновления сразу для всех.
- **Gallery (галерея):** ищите по ключевому слову и источнику и сразу видите, установлен ли навык.
- **Trusted Providers (доверенные источники):** перед установкой проверьте источник, статус доверия и команду, которая реально будет выполнена, и решите, какие источники считать доверенными.

### Vault и Code Server

- **Vault** — это папка за пределами репозиториев вашего проекта, которую HagiCode может просматривать. Используйте её для справочных документов, заметок и результатов исследований. Поддерживаются три типа: Folder, CodeRef и Obsidian.
- При создании сеанса выберите, какие Vault включить в его область. Один из них можно отметить как доступный для записи, чтобы ИИ мог в него писать; иначе он остаётся справочным и доступным только для чтения.
- **Code Server** даёт точку входа для редактирования в браузере, которую можно открыть прямо из Vault или проекта.

### AI Compose Commit

Нажмите «AI Compose Commit» на вкладке Git, и HagiCode прочитает ваши текущие изменения и составит сообщения коммитов в формате Conventional Commits.

- Связанные изменения группируются в несколько коммитов, а не в один общий.
- В проектах MonoSpecs изменения попадают в нужный дочерний репозиторий.
- Метка Co-Authored-By добавляется автоматически; имя и адрес электронной почты можно задать для проекта или глобально.

![Вкладка Git с тремя выбранными репозиториями с изменениями и выделенной кнопкой Super Commit (AI Compose Commit)](../img/screenshots/product/git-super-commit/original.png)

Герои, достижения, ежедневные отчёты и метрики Token дополняют это обратной связью при длительной работе. ## Для кого это подходит

- **Хорошо подходит:** разработчикам и командам, которые поддерживают несколько репозиториев и хотят планировать сложные изменения до их выполнения, а также тем, кто уже пользуется Agent CLI, такими как Claude Code или Codex, и хочет собрать их в одном рабочем пространстве.
- **Не обязательно:** если вам нужно лишь дописать несколько строк в редакторе, вам хватит текущих инструментов.

## Редакции и цены

Базовые возможности бесплатны. Desktop и Microsoft Store — два разных способа получения HagiCode, а не два платных тарифа. В канале Microsoft Store также доступен Turbo Engine — отдельная покупка с разовой оплатой: она повышает предел одновременно выполняемых предложений и открывает дополнительные возможности, включая темы документации, собственную подпись, оформление бренда и загрузку пользовательских аватаров. Какие именно функции он открывает, см. на странице [дополнения Turbo Engine](/ru-RU/dlc/turbo-engine-dlc/).

| Ваша среда | Рекомендуемый вариант |
| --- | --- |
| Windows с доступом к Microsoft Store | [Установка через Microsoft Store](/ru-RU/installation/windows-store) |
| Ручная установка в Windows или локальное использование на macOS либо Linux | [Установка Desktop](/ru-RU/installation/desktop) |

Основное приложение в Steam снято с распространения и больше не служит способом установки. См. [статус распространения в Steam](/ru-RU/faq/steam-distribution-status/).

## Зачем нужно рабочее пространство?

Я Кунь Юй, создатель HagiCode. Один вопрос и ответ могут решить текущую проблему, но при разработке также приходится разбираться в проекте, определять границы задачи, доводить изменения до конца и оценивать результат. Мне хотелось связать эти разрозненные этапы; игровые элементы обратной связи помогают видеть прогресс длительной работы. Можно пользоваться только частью этих возможностей: изучать все модули перед тем, как начать писать код, необязательно.

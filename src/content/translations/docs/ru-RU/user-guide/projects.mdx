**Проект** — это папка, в которой работает HagiCode. Сессии, состояние Git, стандартные термины и настройки MonoSpecs относятся к конкретному проекту, поэтому панель проектов на левом краю рабочего пространства — обычно отправная точка для большей части работы.

## Панель проектов

Панель проектов по умолчанию свёрнута, и каждый проект отображается одной круглой иконкой. Чтобы развернуть её, нажмите небольшую стрелку в верхней части панели.

![Развёрнутая панель проектов со списком All Sessions и проектом orbit-notes, с кнопкой «плюс» для добавления проекта](../../img/user-guide/workbench/02-project-rail.png)

- **All Sessions** (все сессии) показывает сессии всех проектов на одной доске.
- Нажмите на проект, и доска покажет только сессии этого проекта, а на панели проекта отобразится его информация.
- Зелёная кнопка **+** используется для создания проекта. Стрелка рядом с ней снова сворачивает панель проектов.

:::tip[Какие проекты попадают на доску «All Sessions»?]
В разделе **Settings → Sessions and conversation → Session List** (Настройки → Процесс и взаимодействие → Список сессий) можно переключить область с *All Projects* (все проекты) на *Custom Selection* (выбор проектов вручную). См. [Настройки](/user-guide/settings).
:::

## Создание проекта

Нажмите **+** на панели проектов, чтобы открыть диалог **New Project** (новый проект). Он предлагает три способа добавить проект.

### Один проект

Используйте этот способ, если папка проекта уже есть на диске. Соответствует вкладке **Single Project** (один проект).

![Вкладка Single Project диалога создания проекта с заполненными названием, путём к папке и описанием](../../img/user-guide/projects/01-create-project.png)

| Поле | Описание |
| --- | --- |
| **Project Name** (название проекта) | Обязательное, до 200 символов. |
| **Folder Path** (путь к папке) | Обязательное, до 1000 символов. Укажите абсолютный путь к папке, например `/home/user/projects/orbit-notes`. |
| **Project Description** (описание проекта) | Необязательное, до 1000 символов. |

Если в пути есть файл `.hagicode/monospecs.yaml`, диалог его распознает и покажет для проекта подсказки по MonoSpecs. См. [MonoSpecs](/guides/monospecs).

### Пакетное создание

Используйте этот способ, если несколько репозиториев лежат в одной родительской папке. Соответствует вкладке **Batch Create** (пакетное создание).

![Вкладка Batch Create диалога создания проекта с запросом выбрать папку для сканирования](../../img/user-guide/projects/02-create-project-batch.png)

Укажите полный путь к родительской папке. HagiCode просканирует до трёх уровней вложенности в поисках Git-репозиториев и зарегистрирует каждый найденный как проект.

### Демо-проект

Используйте этот способ, если хотите попробовать HagiCode до подключения собственного кода. Соответствует вкладке **Demo Project** (демо-проект).

![Вкладка Demo Project диалога создания проекта с репозиторием MonoSpecs Demo и целевым путём](../../img/user-guide/projects/03-create-project-demo.png)

HagiCode клонирует официальный репозиторий MonoSpecs Demo (`https://github.com/HagiCode-org/monospecs-demo`) и регистрирует его как проект. Для этого на вашей машине должен быть установлен Git. В интерфейсе показан путь по умолчанию; фактическая папка зависит от каталога данных среды выполнения.

## Панель проекта

Когда проект выбран, справа от доски отображается панель проекта.

![Панель проекта orbit-notes с Quick actions и Repository status](../../img/user-guide/workbench/06-project-panel.png)

**Quick actions** (быстрые действия)

| Кнопка | Действие |
| --- | --- |
| **Auto Super Commit** | Запускает коммит с помощью ИИ для проекта. См. [Super Commit](/guides/ai-compose-commit). |
| **Open Code Server** (открыть Code Server) | Открывает проект в браузерном редакторе кода. |
| **Open Git Management** (открыть управление Git) | Открывает вкладку Git в детальной панели проекта. |
| **View Project Details** (подробнее о проекте) | Открывает детальную панель проекта. |

**Repository status** (состояние репозиториев) перечисляет каждый репозиторий проекта и его текущую ветку. Цветная точка показывает состояние рабочей копии; точка на скриншоте красная, потому что в `src/server.js` есть незафиксированные изменения. Нажмите кнопку обновления, чтобы заново считать состояние.

Меню **Recent changes** (недавние изменения) на панели инструментов доски показывает репозитории с недавними изменениями. Пока изменений нет, там выводится «Нет недавних изменений».

## Детали проекта

Нажмите **View Project Details**, чтобы открыть детальную панель. В ней четыре вкладки.

### Details (сведения)

Соответствует вкладке **Details** (сведения).

![Вкладка Details детальной панели проекта с настройками названия, пути, описания и иконки](../../img/user-guide/projects/04-project-details.png)

- **Name** (название), **Path** (путь) и **Description** (описание): основные сведения о проекте.
- **Icon Settings** (настройки иконки): выберите для аватара проекта *Game Icon* (игровую иконку) или *Text Abbreviation* (текстовую аббревиатуру). **Change Icon** (сменить иконку) открывает выбор иконки.
- **Manage DESIGN.md** (управление DESIGN.md): управление файлом `DESIGN.md` проекта.
- **Delete Project** (удалить проект): удаление проекта после ввода его названия для подтверждения. В окне подтверждения перечислено, что будет удалено безвозвратно: все сессии проекта и все сообщения в них. Это действие нельзя отменить.

### MonoSpecs

![Вкладка MonoSpecs с предложением инициализировать MonoSpecs для проекта](../../img/user-guide/projects/05-project-monospecs.png)

MonoSpecs превращает проект в рабочее пространство, которое координирует спецификации и несколько репозиториев. Для проекта, который ещё не является рабочим пространством MonoSpecs, **Initialize MonoSpecs** (инициализировать MonoSpecs) создаёт только необходимое и ничего не клонирует автоматически:

- `.hagicode/monospecs.yaml`
- папку `repos/` для вложенных репозиториев
- `openspec/changes/archive/` и `openspec/specs/`
- обновление `.gitignore`, чтобы папка `repos/` не отслеживалась

Перед инициализацией прочитайте [руководство по MonoSpecs](/guides/monospecs).

### Standard Words (стандартные термины)

Соответствует вкладке **Standard Words** (стандартные термины).

![Вкладка Standard Words со пустым списком групп и кнопкой Add group](../../img/user-guide/projects/06-project-standard-words.png)

Стандартные термины — это общие для проекта термины, которые хранятся в `.hagicode/standard_words.yaml`. На вкладке показано количество групп, фраз и тегов, а также доступны поиск, **Add group** (добавить группу), **Refresh** (обновить с диска) и **Save changes** (сохранить изменения).

### Git

![Вкладка Git: слева список репозиториев, справа сводка репозитория и действия Push, Pull и Super Commit](../../img/user-guide/projects/07-git-management.png)

Вкладка Git — это консоль Git для проекта.

- **Список репозиториев** (слева) показывает отслеживаемые репозитории. Счётчик (например, `1 / 15`) сравнивает их с лимитом отслеживания в **Settings → Integration → Git** (Настройки → Интеграция → Git). Для массовых действий доступны **Select Changed** (выбрать репозитории с изменениями), **Select All** (выбрать все) и **Clear Selection** (снять выбор); можно также искать по названию. **Manage Super Commit All exclusions** (управление исключениями Super Commit All) задаёт, какие файлы быстрый коммит пропускает.
- **Сводка репозитория** (справа) показывает ветку, состояние синхронизации, наличие незафиксированных изменений, удалённый репозиторий и путь к репозиторию.
- Действия для выбранного в фокусе репозитория: **Super Commit**, **Push** (отправить), **Pull** (получить), **Rebase Upstream** (перебазировать на upstream), **Open Remote Repository** (открыть удалённый репозиторий), **Open Code Server** и **Manage DESIGN.md**.

Сводка здесь намеренно заменяет предпросмотр диффов. Для более глубоких операций Git используйте **Open Code Server**.

Поведение Git, например профиль Git (Git Profile), мониторинг состояния и действие ИИ-коммита по умолчанию, настраивается в **Settings → Integration → Git**.

**Agent** — основа HagiCode: сессии выполняются Agent, и перед началом работы нужен хотя бы один из них. Эта страница — обзор: она помогает понять, из чего состоит Agent, кто выполняет разные типы работы и в каких местах находятся настройки, связанные с Agent. Пошаговые действия описаны в [руководстве по рабочему пространству Agents](/ru-RU/user-guide/agents).

## Обзор возможностей

- Один **Agent = Agent CLI + модель + необязательный текст характера**. Agent CLI — это инструмент командной строки, который реально выполняет работу (например, Claude Code, Codex), модель — то, что он использует, а текст характера (Trait и Soul) формирует стиль работы и манеру речи.
- Вы можете создать несколько Agent, например одного на Opus для ревью, другого на Haiku для быстрых правок и третьего на Codex для рефакторинга.
- Какой Agent выполняет каждый тип работы, определяют **сценарии выполнения**; если подходящего участника нет, работу берёт на себя **Fallback Crew**.
- Проверка и настройка Agent распределены между **рабочим пространством Agents** и **настройками**: первое отвечает за Agent, сценарии, CLI и модели, вторые — за поведение во время выполнения, такое как повторные попытки и лимит памяти.

## Список Agent

![Вкладка Agents: пять Agent, сгруппированных по Claude Code и Codex, у каждого есть аватар и модель](../img/screenshots/guides/agent-roster/original.png)

Нажмите **Agents** в верхней панели, чтобы открыть **Agents Workspace**. На вкладке **Agents** раздел **My Agents** перечисляет ваших Agent, сгруппированных по Agent CLI; на каждой карточке показаны аватар, имя и модель. Здесь можно:

1. Создать Agent кнопкой **New Agent**: выберите AgentCLI и совместимую модель и при желании добавьте Trait (знания и поведение) и Soul (стиль речи).
2. Создать сразу нескольких через **Batch create Agents** или отфильтровать список в поле поиска по имени, CLI или описанию.
3. Включить или отключить Agent переключателем **Battle ready**.

Полное описание процесса создания см. в разделе [Agents](/ru-RU/user-guide/agents#создание-агента).

## Распределение работы: сценарии выполнения и Fallback Crew

![Вкладка Execution Scenarios: группы Agent для сценариев предложений и HagiTask; справа — Agent, уже включённые в группу, и доступные для добавления](../img/screenshots/guides/agent-scenarios/original.png)

Вкладка **Execution Scenarios** определяет, какие Agent выполняют каждый тип работы. Сценарии сгруппированы по назначению:

| Группа | Сценарии |
| --- | --- |
| **Proposal** | Оптимизация, создание, выполнение и архивация предложений |
| **HagiTask** | Super Commit, создание обычной сессии, создание задачи исследования кода |
| **Chat** | Оптимизация заголовка сессии |

Нажмите на сценарий — справа **Assigned Agents** покажет его группу, а **Available Agents** — Agent, которых можно добавить; для изменения состава используйте **Add** или **Remove**. **Fallback Crew** — это страховочная сетка: если в группе самого сценария нет подходящего Agent, HagiCode выбирает подходящего участника из Fallback Crew. **Пока в Fallback Crew нет хотя бы одного включённого Agent, остальные сценарии остаются заблокированными.** Мастер инициализации автоматически добавляет туда вашего первого Agent.

Типичная схема:

1. Поместите в **Generate Proposal** Agent, сильного в длинном контексте и ревью.
2. Поместите в **Execute Proposal** Agent с хорошей исполнительностью и приемлемой стоимостью.
3. Поместите в **Super Commit** и **Conversation Title Optimization** дешёвого и быстрого Agent.
4. Оставьте в Fallback Crew один надёжный универсальный Agent.

## Где находятся связанные настройки

| Что нужно сделать | Куда идти |
| --- | --- |
| Создать, изменить, включить или отключить Agent | **Agents** → вкладка **Agents** |
| Назначить Agent на каждый тип работы, настроить Fallback Crew | **Agents** → **Execution Scenarios** |
| Проверить, установлен ли Agent CLI, исправен ли он и включён ли | **Agents** → **AgentCLI**, всплывающая панель AI Monitoring в строке состояния |
| Просмотреть или добавить модели, доступные для CLI | **Agents** → **Model** |
| Сменить аватар или тематику текстов | **Agents** → **Avatar Gallery** / **Document Theme** |
| Автоматические повторные попытки после сбоя | **Настройки** → **Error Retry** |
| Указывать ли в генерируемом промпте, что «этот запуск неинтерактивный» | **Настройки** → **AgentCLI Interactive Control** |
| Ограничить память, доступную каждому Agent | **Настройки** → **Agent Memory Limit** |
| Подключить несколько OpenAI-совместимых моделей к одному локальному шлюзу | **Настройки** → **OmniRoute** |

Назначение каждого параметра описано в разделе [Настройки](/ru-RU/user-guide/settings).

## Сценарии применения и границы

- Если вы хотите использовать разные модели или CLI на разных этапах (например, отдельно для ревью и выполнения), распределяйте работу по сценариям.
- Можно работать и с единственным Agent: поместите его в Fallback Crew, и он будет использоваться во всех сценариях.
- Agent определяет только то, **кто выполняет**. Что именно выполнять, по-прежнему определяют созданные вами сессии, предложения или планы.

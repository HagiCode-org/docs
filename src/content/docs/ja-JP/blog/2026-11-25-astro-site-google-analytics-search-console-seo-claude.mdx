[前回のガイド](/ja-JP/blog/2026-11-23-mac-astro-site-claude-github-cloudflare/)では、まっさらな Mac から出発して、GitHub Pages と Cloudflare にデプロイされた Astro サイトを作りました。サイトの公開は半分まで終わっています。残りは、誰が訪れているか、訪問者が何をしたか、そして Google がサイトを見つけられるかどうかを把握することです。

このガイドではその部分を補います。Google Analytics と Google Search Console に登録し、Claude にトラッキング、サイトマップ、ソーシャルタグ、favicon を追加してもらいます。各ステップの最後には確認できる結果があるので、それを確かめてから次に進んでください。

全体の流れは次のとおりです。

1. Google Analytics のプロパティを作成し、測定 ID をコピーする。
2. Claude にサイトへ Google Analytics を組み込んでもらい、プッシュ、デプロイの完了待ち、本番環境にコードが実際にあることの確認までを任せる。
3. Google Analytics で、自分のアクセスがリアルタイムに表示されることを確認する。
4. Google Search Console にサイトを登録する。
5. Search Console と Google Analytics をリンクする。
6. Claude にサイトに合ったイベント追跡を設計・追加してもらい、公開して検証する。
7. Claude に基本的な SEO レイヤーを追加してもらう。サイトマップ、`robots.txt`、canonical リンク、Open Graph と Twitter のタグが対象です。
8. Search Console でサイトマップを送信する。
9. Claude に各ページのタイトル、説明、キーワードを最適化してもらい、Mac のコマンドラインツールで複数サイズの favicon を生成する。

## このガイドの対象者

前回のガイドを終えた方が対象です。GitHub リポジトリに置かれた Astro プロジェクトがあり、`main` へのプッシュのたびに自動デプロイされ、公開ドメインを持っている状態を想定しています。分析ツールの経験は必要ありませんが、短いプロンプトを Claude Code に貼り付けることと、いくつかの Google の画面でクリック操作をすることはできる必要があります。

## 前提条件

- 前回のガイドで公開済みの、独自ドメインが使える Astro サイト。このガイドではリポジトリを `my-astro-site`、ドメインを `example.com` と呼びます。ご自身の名前に置き換えてください。
- Google アカウント。
- Claude Code がインストールされ、ログイン済みであること。また `gh` でログイン済みであること（`gh auth status`）。
- ドメインの DNS を変更できること。ドメインが Cloudflare にあるなら、この条件はすでに満たしています。

## ステップ 1：Google Analytics のプロパティを作成し、測定 ID を取得する

Google Analytics 4（GA4）は、アカウントの中に 1 つ以上のプロパティがあり、プロパティの中にデータストリームがある構造です。1 つのサイトには Web データストリームを 1 つ作り、そのデータストリームには `G-` で始まる測定 ID が割り当てられます。

1. [analytics.google.com](https://analytics.google.com) を開き、Google アカウントでログインします。
2. **測定を開始**をクリックします（すでに Analytics を使っている場合は、**管理 → 作成 → アカウント**を選びます）。アカウントに `My sites` などの名前を付けます。
3. プロパティを作成します。サイト名を付け、レポートのタイムゾーンと通貨を選び、ビジネスに関する質問に答えます。
4. プラットフォームは **ウェブ** を選びます。
5. サイトの URL（`https://example.com`）とデータストリーム名を入力します。**拡張計測機能**はオンのままにしてください。コードを書かなくても、ページビュー、スクロール、外部リンクのクリック、ファイルのダウンロードを記録してくれます。
6. データストリームを作成します。Google がデータストリームの詳細を表示し、その中に **測定 ID** が含まれます。

測定 ID をコピーします。形式は `G-ABCD123456` のようになります。後から **管理 → データの収集と修正 → データストリーム → データストリームの名前** で再確認できます。

測定 ID は秘密情報ではありません。これを使うサイトのページソースには必ずそのまま表示されるので、リポジトリにコミットしても問題ありません。

確認：`G-` で始まる測定 ID を入手できている。

## ステップ 2：Claude に Google Analytics を組み込んでもらう

プロジェクトのフォルダで Claude を起動します。

```bash
cd ~/Sites/my-astro-site
claude
```

次に、プッシュと検証を含めた作業全体を 1 つのリクエストで伝えます。最終状態をできるだけ正確に書くほど、後で修正が必要になる回数が減ります。

```text
この Astro サイトに Google Analytics 4 を組み込んでください。測定 ID は G-ABCD123456 です。

要件:
- gtag.js のローダーと config 呼び出しは共通レイアウトの <head> に置き、どのページにも必ず 1 回だけ出力されるようにしてください。
- 通常のインラインスクリプト（is:inline）を使い、window.gtag が本当のグローバル関数になるようにしてください。Astro は通常の <script> をモジュールとしてバンドルするため、そのままだと後のコードから gtag にアクセスできなくなります。
- タグは本番ビルドでのみ出力し、`npm run dev` では出力しないでください。
- 測定 ID は 1 つの定数または環境変数から読み込み、複数箇所にコピーしないでください。
- `npm run build` を実行し、dist/index.html にそのタグが含まれていることを確認してください。

ビルドが通ったら、わかりやすいコミットメッセージでコミットし、main にプッシュしてください。その後、GitHub Pages のワークフローと Cloudflare のビルドの両方が完了するまで待ってください。最後に https://example.com/ を curl で取得し、本番の HTML に測定 ID が含まれていることを確認してください。何を確認したかを報告してください。
```

Claude がレイアウトに生成するスニペットは、だいたい次のような形になります。

```astro
---
const GA_ID = 'G-ABCD123456';
const isProd = import.meta.env.PROD;
---
<head>
  {isProd && (
    <>
      <script is:inline async src={`https://www.googletagmanager.com/gtag/js?id=${GA_ID}`}></script>
      <script is:inline define:vars={{ GA_ID }}>
        window.dataLayer = window.dataLayer || [];
        window.gtag = function () { dataLayer.push(arguments); };
        gtag('js', new Date());
        gtag('config', GA_ID);
      </script>
    </>
  )}
</head>
```

「タグを入れたのに何も反応しない」という問題の最も一般的な原因になる箇所なので、次の 2 点を理解しておいてください。

- **`window.gtag` はグローバル関数でなければなりません。** スクリプトがクロージャで囲まれていると、ページビューは記録されるかもしれませんが、`window.gtag` は未定義のままです。ステップ 6 で追加するカスタムイベントはすべて、エラーも出さずに失敗します。`window.gtag` を明示的に代入しておくと、この問題を避けられます。
- **本番環境でのみ有効にします。** `localhost` でもタグが動くと、開発中の自分のクリックがデータを汚してしまいます。

デプロイの完了を待つ間、Claude は次のようなコマンドを使います。

```bash
gh run watch
curl -s https://example.com/ | grep -o 'googletagmanager.com/gtag/js?id=G-[A-Z0-9]*'
```

`gh run watch` は GitHub Actions の実行が終わるまで追跡します。`curl` の行は、本番ページに実際にローダーの URL が含まれているときだけ出力されます。

確認：Claude の報告で、両方のプラットフォームのデプロイが成功したこと、本番の HTML に測定 ID が見つかったことが示されている。`curl` が何も出力しない場合は、デプロイがまだ終わっていないか、キャッシュが古いページを返しています。1 分後にもう一度試すよう Claude に伝えてください。それでも古いページが表示される場合は、Cloudflare のキャッシュを削除します。

## ステップ 3：Google Analytics でサイトがオンラインであることを確認する

自分側だけでなく、Google 側からも確認しましょう。

1. ブラウザで `https://example.com` を開きます。広告ブロッカーやプライバシー重視のブラウザを使っている場合は、この確認の間だけオフにしてください。Google Analytics をブロックしてしまうためです。
2. Google Analytics で **レポート → リアルタイム** を開きます。
3. 1 分ほどすると、**過去 30 分間のユーザー数: 1** と、イベント一覧に `page_view` が表示されるはずです。
4. 2、3 ページ開くと、そのページのタイトルがリアルタイムビューに表示されます。

**管理 → データストリーム → データストリームの名前** を開いて確認することもできます。緑のチェックマークと、データが流入していることを示すメッセージが表示されていれば、データストリームはトラフィックを受信しています。

確認：自分のアクセスが **リアルタイム** に表示されている。**獲得** などの標準レポートは数時間から 1 日ほど遅れるので、まだ空でも心配はいりません。

## ステップ 4：Google Search Console にサイトを登録する

Google Analytics は、訪問者が到着した後に何をしたかを示します。Google Search Console は、Google がサイトをどう見ているかを示します。どの検索語句から訪問者が来たか、どのページがインデックスされたか、Google がどのようなエラーを見つけたかがわかります。

1. [search.google.com/search-console](https://search.google.com/search-console) を開き、Analytics と同じ Google アカウントでログインします。同じアカウントを使うと、後のリンクが簡単になります。
2. **プロパティを追加** をクリックします。プロパティには 2 種類あります。
   - **ドメイン** は `example.com` と、そのすべてのサブドメインおよびプロトコルを対象にします。DNS レコードが 1 つ必要です。
   - **URL プレフィックス** は `https://example.com/` のような 1 つの正確なアドレスだけを対象にし、複数の確認方法があります。
3. DNS を Cloudflare で管理している場合は、**ドメイン** を選び、`example.com` を入力します。
4. Search Console が `TXT` レコードを表示します。その値をコピーします。値は `google-site-verification=` で始まります。
5. Cloudflare のダッシュボードでドメインを開き、**DNS → レコード → レコードを追加** に進みます。タイプは `TXT`、名前は `@` を選び、値を貼り付けて保存します。
6. Search Console に戻り、**確認** をクリックします。DNS の変更は通常数分で反映されますが、それ以上かかることもあります。確認に失敗した場合は、少し待ってからもう一度 **確認** をクリックしてください。

**URL プレフィックス** を選んだ場合は、Google Analytics を使った確認が最も簡単です。同じ Google アカウントを使っていれば、Search Console はステップ 2 で入れたタグを所有権の証明として使えます。

確認：Search Console に「所有権が確認されました」と表示され、そのプロパティの概要ページが開く。しばらくの間は「データがありません」と表示されることがありますが、これは正常です。

## ステップ 5：Search Console と Google Analytics をリンクする

リンクすると、検索語句とランディングページのデータが Analytics のレポートに表示されるようになります。検索から来たトラフィックと、その訪問者の行動を一緒に見ることができます。

1. Google Analytics で **管理** を開きます。
2. **プロダクトのリンク** の下にある **Search Console のリンク** を選びます。
3. **リンク** をクリックし、**アカウントを選択** をクリックして、Search Console のプロパティを選びます。そのためには、Search Console プロパティのオーナーであり、かつこの Analytics プロパティの編集者である必要があります。
4. **次へ** をクリックし、ウェブのデータストリームを選んで、**送信** をクリックします。

Search Console のデータが流入し始めるまでには数日かかり、データ自体も約 2 日遅れて届きます。ここで待つ必要のあることはないので、次のステップに進んでください。

リンクを作成すると、関連するレポートは **レポート → ライブラリ** で見つけられます。Search Console のレポートは左側のメニューには自動的に追加されません。メニューに表示したい場合は、ライブラリで **Search Console** コレクションを公開してください。

確認：**管理 → プロダクトのリンク → Search Console のリンク** に、あなたのプロパティが一覧表示されている。

## ステップ 6：サイトに合ったイベント追跡を追加する

拡張計測機能は、ページビュー、スクロール、外部リンクのクリック、サイト内検索、ファイルのダウンロードをすでに記録しているので、これらを重複して実装しないでください。イベントは、あなたのビジネス固有の操作に使います。主要な行動を促すボタンのクリック、ニュースレターの登録、お問い合わせフォームの送信、料金ページの閲覧などです。

最も役立つ指示は「イベントを追加して」ではなく、「まずサイトを見て、イベントの案を提示し、私が承認する」です。こうすれば、何を計測するかを常にコントロールできます。

```text
この Astro サイトの構造を確認してください。ページ、レイアウト、コンポーネント、行動を促すボタン、フォーム、外部リンクを対象にしてください。

ステップ 1: コードを変更する前に、イベント案を提示してください。表にして、イベント名、発火するタイミング、パラメータ、そのイベントで答えられるビジネス上の問いを含めてください。適切な GA4 の推奨イベント名がある場合はそれを優先し（例: generate_lead、sign_up、select_content）、ない場合は snake_case のカスタム名を使ってください。�拡張計測機能がすでに記録しているもの（ページビュー、スクロール、外部リンクのクリック、ファイルのダウンロード）は重複させないでください。最大 10 個までにしてください。

ステップ 2: 私が承認したら、その案を実装してください。
- 要素には data-ga-event、data-ga-label、data-ga-location の属性を付けてください。
- document に 1 つの委譲されたクリックリスナーを置き、これらの属性を読み取って gtag('event', ...) を呼び出してください。インラインの onclick ハンドラは追加しないでください。
- パラメータには安定した id と位置だけを送ってください。リンクの文字列、フォームの入力内容、メールアドレス、訪問者を特定できる情報は絶対に送らないでください。
- ページ遷移を遅らせたり、キャンセルしたりしないでください。

ステップ 3: ビルドを実行し、コミットし、プッシュしてから、両方のデプロイが完了するのを待ち、curl でリスナースクリプトが本番サイトに含まれていることを確認してください。その後、GA4 の DebugView で検証するために、どこをクリックすればよいかを教えてください。
```

Claude はまず表で回答します。小規模なサイトに適した案は、次のようなものになるはずです。

| イベント | 発火するタイミング | パラメータ | 答えられる問い |
| --- | --- | --- | --- |
| `cta_click` | 訪問者が主要な行動を促すボタンをクリックしたとき | `label`、`location` | どのボタンやページのどの領域が行動につながっているか？ |
| `generate_lead` | お問い合わせフォームの送信が成功したとき | `form_id` | 何人の訪問者が問い合わせ客になったか？ |
| `nav_click` | ヘッダーまたはフッターのリンクをクリックしたとき | `label`、`location` | どのナビゲーション項目が使われているか？ |
| `theme_toggle` | テーマ切り替えを使ったとき | `value` | ダークモードの切り替えを残す価値はあるか？ |

この表は批判的に読んでください。誰も見ないイベントは削除し、判断ではなく機能の名前になっているイベントは名前を変えます。そのうえで「承認します。ただし `theme_toggle` は除外してください」と返信し、実装を依頼します。

Claude が書くリスナーは、おおむね次のようなものです。

```js
document.addEventListener(
  'click',
  (event) => {
    const el = event.target.closest('[data-ga-event]');
    if (!el || typeof window.gtag !== 'function') return;
    window.gtag('event', el.dataset.gaEvent, {
      label: el.dataset.gaLabel,
      location: el.dataset.gaLocation,
      transport_type: 'beacon',
    });
  },
  true,
);
```

計測対象の要素はこのようにマークします。

```astro
<a href="/contact" data-ga-event="cta_click" data-ga-label="hero_contact" data-ga-location="home_hero">
  お問い合わせ
</a>
```

### イベントを検証する

1. Google Analytics で **管理 → データの表示 → DebugView** を開きます。DebugView には、届いたイベントが数秒以内に表示されます。
2. ブラウザをデバッグモードにするには、Chrome 拡張機能 **Google Analytics Debugger** をインストールするか、Claude に `config` 呼び出しへ一時的に `debug_mode: true` を追加してもらいます。
3. 本番サイトを開き、Claude が挙げたクリックを実行します。
4. クリックするたびに、DebugView のタイムラインに、期待どおりのパラメータを持つイベントが 1 件ずつ表示されるはずです。

イベントが 1 回届くと、**管理 → データの表示 → イベント** にも表示されます。`label` や `location` を標準レポートで使いたい場合は、**管理 → データの表示 → カスタム定義 → カスタムディメンションを作成** で登録してください。スコープは **イベント** を選びます。この方法で登録したパラメータだけが標準レポートに表示されます。

一時的な `debug_mode` の設定はすべて削除し、Claude にクリーンなバージョンをプッシュしてもらいます。

確認：追跡されたクリックがすべて、正しいイベント名とパラメータで DebugView に表示され、最終的なコードが `main` にある。

## ステップ 7：基本的な SEO レイヤーを追加する

検索エンジンには、ページの地図、クロールの範囲に関する指示、そしてページが共有されたときに人々が目にする説明文が必要です。最初の項目である Astro には公式インテグレーションがあり、残りはレイアウトに数行のコードを追加するだけです。Claude は関連する Astro のコンポーネントとインテグレーションを導入して、これらを素早く完成させられます。

```text
この Astro サイトに基本的な SEO を追加してください。

1. サイトマップ: `npx astro add sitemap` で公式の @astrojs/sitemap インテグレーションをインストールしてください。astro.config.mjs の `site` が本番ドメイン https://example.com になっていることを確認し、GitHub Pages のプロジェクトホスティングの名残である `base` は削除してください。
2. robots.txt: src/pages/robots.txt.ts を作成し、"User-agent: *"、"Allow: /"、そして https://example.com/sitemap-index.xml を指す Sitemap の行を返すようにしてください。URL は `site` の設定から生成し、ハードコードしないでください。
3. 共通レイアウトで使う再利用可能な SEO コンポーネントを作成し、次の要素を出力してください。<title>、meta description、現在の URL と `site` から生成した canonical リンク、Open Graph タグ（og:type、og:title、og:description、og:url、og:image、og:site_name、og:locale）、Twitter カードタグ（twitter:card summary_large_image、twitter:title、twitter:description、twitter:image）、theme-color の meta タグ。各ページは自分のタイトルと説明を props で渡してください。
4. 1200x630 のデフォルトの共有画像を public/og-default.png に用意し、ページが画像を指定しない場合に使ってください。
5. サイト全体に WebSite 型の JSON-LD 構造化データを追加してください。サイトにブログがある場合は、記事に Article 型も追加してください。
6. `npm run build` を実行し、dist/sitemap-index.xml の内容を一覧表示し、dist/robots.txt を表示して、トップページのビルド済み HTML に上記のタグがすべて含まれていることを確認してください。

すべて正しければ、コミットし、プッシュし、両方のデプロイが完了するのを待ってください。その後、curl で https://example.com/sitemap-index.xml と https://example.com/robots.txt がどちらも 200 を返し、内容が正しいことを確認してください。
```

各部分の役割は次のとおりです。

- **サイトマップ。** `@astrojs/sitemap` はビルド時に `sitemap-index.xml` と 1 つ以上の `sitemap-0.xml` を生成します。絶対 URL を作るために `site` の設定が必要です。
- **`robots.txt`。** クローラーがアクセスしてよい範囲と、サイトマップの場所を伝えます。特定のページをインデックスさせたくない場合は、`robots.txt` に書くだけでは不十分で、`noindex` を使ってください。
- **Canonical リンク。** 同じページに複数の URL でアクセスできる場合に、どれが正式な URL かを Google に伝えます。
- **Open Graph と Twitter のタグ。** リンクが SNS やチャットアプリで共有されたときに表示される、タイトル、説明文、画像を決めます。
- **JSON-LD。** 構造化データは、検索エンジンがページの内容を理解するのに役立ちます。リッチリザルトの表示を保証するものではありませんが、追加のコストはわずかです。

確認：公開されている `sitemap-index.xml` にページが一覧されている。`robots.txt` に `Sitemap:` の行がある。ページのソースに canonical、Open Graph、Twitter のタグが見える。URL をソーシャルカードの検証ツールに貼り付けるか、チャットアプリで共有して、プレビューを確認することもできます。

## ステップ 8：Search Console でサイトマップを送信する

Search Console に伝えるまで、サイトマップの存在は認識されません。

1. Search Console でプロパティを開き、左側のメニューから **サイトマップ** を選びます。
2. **新しいサイトマップの追加** に `sitemap-index.xml` と入力します。
3. **送信** をクリックします。
4. ステータスが **成功** になり、検出されたページ数が表示されるはずです。**取得できませんでした** と表示された場合は、まずサイトマップの URL をブラウザで開いてください。開ければ、数分待ってから更新してください。初回の取得には遅延が生じることがあります。

次に、最も重要なページを Google にすぐ確認してもらいます。

1. Search Console 上部の検索バーに、トップページの URL を貼り付けます。
2. そのページがまだインデックスされていない場合は、**インデックス登録をリクエスト** をクリックします。

インデックスには、まだ数日かかります。Search Console のレポートにも遅れがあるため、1 週間後に戻って確認してください。

確認：**サイトマップ** に `sitemap-index.xml` が一覧され、ステータスが **成功** になっている。

## ステップ 9：各ページのメタデータを最適化し、複数サイズの favicon を追加する

基本レイヤーは、どのページにも共通のメタデータを与えます。タイトルと説明文は検索結果で人々が読む文章なので、ページごとに手を入れる価値があります。favicon は、ブラウザ、スマートフォン、ブックマークがそれぞれ異なるファイルを要求するため、複数のサイズが必要です。

### タイトル、説明文、キーワード

```text
このサイトの各ページを確認し、検索用メタデータを最適化してください。

各ページについて、タイトル、meta description、キーワードの変更前後を比較する表を作成してから、変更を適用してください。ルールは次のとおりです。
- タイトル: ページごとに一意にし、約 60 文字以内にしてください。主要なトピックを先頭に、サイト名を後ろに置いてください。
- 説明文: ページごとに一意にし、120〜160 文字にしてください。訪問者が何を得られるかを自然な一文で説明し、クリックを促してください。キーワードを詰め込まず、ページ間で文章をコピーしないでください。
- キーワード: ページの実際の内容から 5〜8 語を抽出してください。レイアウトがすでに対応している場合にのみ keywords の meta タグを残し、ページが扱っていないトピックを作り出さないでください。
- 各ページに、タイトルの意味と一致する <h1> がちょうど 1 つあること、すべての画像に alt 属性があることを確認してください。

その後ビルドを実行し、まだタイトルや説明文を他のページと共有しているページを列挙した短いレポートを書いてください。
```

あらかじめ知っておくべき点として、検索エンジンは keywords の meta タグをほぼ無視します。キーワードを書くことは、各ページが何についてのものかを明確にする訓練として役立ちます。実際に検索結果に表示されるのは、タイトルと説明文です。

### 複数サイズの favicon

`favicon.svg` 1 つでも良いスタートですが、特定のファイルが必要な場面もあります。古いブラウザやブックマークは `favicon.ico` を使い、iOS のホーム画面は `apple-touch-icon` を使い、Android と Web アプリマニフェストは 192 と 512 ピクセルの PNG を使います。

macOS には、PNG のリサイズに使える `sips` が標準で入っています。`.ico` を生成するには ImageMagick が必要で、Homebrew でインストールできます。Claude に Mac 上でこれらを直接使ってもらいましょう。

```text
元画像 public/logo-source.png（少なくとも 512x512 の正方形 PNG）から、favicon の一式を生成してください。

1. macOS の `sips` コマンドを使って、public/icon-192.png、public/icon-512.png、public/apple-touch-icon.png（180x180）を作成してください。
2. ImageMagick がインストールされていなければ、`brew install imagemagick` でインストールしてください。`magick` を使い、16x16、32x32、48x48 の画像を含む public/favicon.ico を生成してください。
3. public/favicon.svg が既にあれば、それを残してください。なければ、ロゴに合わせたシンプルなバージョンを作成してください。
4. icon-192.png と icon-512.png を列挙する public/site.webmanifest を追加してください。
5. レイアウトの <head> を更新し、対応する <link> タグを追加してください。SVG アイコン、.ico のフォールバック、apple-touch-icon、マニフェストです。
6. 生成した各画像に `file` を実行して実際のサイズを確認し、ビルドを実行して、これらのファイルが dist/ に含まれていることを確かめてください。
```

Claude が実行するコマンドは、おおむね次のようになります。

```bash
sips -z 192 192 public/logo-source.png --out public/icon-192.png
sips -z 512 512 public/logo-source.png --out public/icon-512.png
sips -z 180 180 public/logo-source.png --out public/apple-touch-icon.png
brew install imagemagick
magick public/logo-source.png -define icon:auto-resize=48,32,16 public/favicon.ico
file public/*.png public/favicon.ico
```

head に入るリンクは次のとおりです。

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="icon" href="/favicon.ico" sizes="48x48" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<link rel="manifest" href="/site.webmanifest" />
```

最後に、これまでのステップと同じく、結果まで確認して閉じます。

```text
変更をすべて、わかりやすいコミットメッセージでコミットし、main にプッシュしてください。両方のデプロイが完了するのを待ち、本番サイトの /favicon.ico、/apple-touch-icon.png、/site.webmanifest がすべて 200 を返すことを curl で確認してください。
```

ブラウザで確認します。タブにアイコンが表示され、ブックマークや iOS の「ホーム画面に追加」では大きい方のアイコンが使われます。ブラウザは favicon を積極的にキャッシュするので、古いアイコンが表示され続ける場合は、プライベートウィンドウでサイトを開いてください。

## 1 週間後に確認すること

- **Search Console → ページ** で、インデックスされているページの数と、インデックスされていないページの理由を確認します。
- **Search Console → パフォーマンス** で、検索語句、クリック数、平均掲載順位を確認します。これらの検索語句を使って、タイトルと説明文を改善します。
- **Analytics → レポート → エンゲージメント → イベント** で、カスタムイベントがどれくらいの頻度で発生しているかを確認します。
- **Analytics → レポート → ライブラリ** は、データが届いた後に Search Console のコレクションが表示される場所です。

## よくある問題

- **リアルタイムレポートに何も表示されない。** 広告ブロッカーやプライバシー重視のブラウザがタグをブロックしています。拡張機能を無効にしたプライベートウィンドウでテストし、本番 HTML に測定 ID があることを確認してください。
- **ページビューは計測されるが、カスタムイベントが動かない。** 本番サイトでブラウザのコンソールを開き、`typeof window.gtag` を実行してください。出力は `function` でなければなりません。`undefined` と表示される場合は、タグのスクリプトがモジュールとしてバンドルされています。Claude に `is:inline` を使い、`window.gtag` を明示的に代入するよう依頼してください。
- **イベントは DebugView には表示されるが、レポートには表示されない。** 標準レポートには最大 1 日の遅れがあります。また、カスタムパラメータは、カスタムディメンションとして登録されるまでレポートに表示されません。
- **Search Console でドメインを確認できない。** TXT レコードがルート（`@`）にあるか、値が完全にコピーされているか、Cloudflare のプロキシを使っていないか（TXT レコードはプロキシされません）を確認してください。その後、少し待ってから再試行します。
- **サイトマップが「取得できませんでした」と表示される。** `https://example.com/sitemap-index.xml` を自分で開いてください。404 が返る場合は、`astro.config.mjs` の `site` が本番ドメインになっているか、サイトマップのインテグレーションが `integrations` に記載されているかを確認してください。
- **ソーシャルプレビューが古い。** 各プラットフォームはプレビューをキャッシュします。タグを変更したら、それぞれのデバッグツールでキャッシュを更新してください。

## プライバシーと同意

分析は訪問者のデータを収集します。訪問者の所在地によっては、Google Analytics を読み込む前に同意を得る必要がある場合があります。たとえば EU の GDPR や ePrivacy の規則です。また、プライバシーポリシーに記載が必要な場合もあります。このガイドでは手順を簡潔にするため、タグを無条件にインストールしています。同意を求める地域から訪問者が来るサイトでは、同意を得た後にだけタグを読み込む同意バナーを Claude に追加してもらってください。以上は一般的な情報であり、法的助言ではありません。

ここでのすべてのステップは同じパターンに従っており、それ自体が習慣にする価値があります。最終状態を Claude に説明し、変更を任せ、プッシュとデプロイの完了を待たせ、`curl` で本番サイト上の結果を証明させ、最後に Google Analytics や Search Console などの外部ツールで確認します。今後機能を追加するときも、同じサイクルを繰り返してください。

このガイドでは、何もない状態の Mac から、インターネット上で公開されているウェブサイトを作るまでの手順を説明します。作業は2か所で行います。ツールをインストールするターミナルと、繰り返しのコマンド実行やファイルの編集を代わりに行ってくれる Claude Code です。各ステップの最後には確認方法を書いてあるので、次に進む前に正しく動いたかを確かめられます。

完成までの流れは次のとおりです。

1. Node.js をインストールします。
2. GitHub CLI (`gh`) をインストールして、ログインします。
3. Claude に非公開リポジトリの作成とクローンを依頼します。
4. Claude に、ヘッダー、フッター、レスポンシブ対応レイアウトを備えた Astro サイトの作成を依頼し、コミットしてプッシュします。
5. impeccable スキルをインストールし、その `overdrive` コマンドでトップページを仕上げます。
6. GitHub Actions のワークフローで GitHub Pages に公開します。
7. Cloudflare でドメインを接続し、同じブランチを Workers でデプロイします。
8. 新しいページを追加してプッシュし、両方のデプロイが完了するのを確認します。

## このガイドの対象者

このガイドは、Mac と GitHub アカウントを持っていて、サーバーを用意せずにシンプルな静的ウェブサイトを公開したい方を対象としています。事前に Astro、GitHub Actions、Cloudflare を知っている必要はありません。ただし、ターミナルを開いてコマンドを貼り付けることには慣れている必要があります。

## 事前に必要なもの

- 最新版の macOS が動作する Mac。
- GitHub アカウント。
- Cloudflare アカウント。
- ドメイン名。Cloudflare で取得するか、すでに所有しているものを使えます。
- Claude Code のインストールとサインイン。ターミナルで `claude` を一度実行し、起動することを確認してください。

## ステップ 1: Node.js をインストールする

Astro と impeccable のインストーラーはどちらも Node.js 上で動作します。現在の LTS 版を使ってください。

いちばん簡単な方法は、[nodejs.org](https://nodejs.org) の公式インストーラーを使うことです。macOS 用のパッケージをダウンロードして実行し、初期設定のまま進めてください。

すでに Homebrew を使っている場合は、代わりにターミナルからインストールできます。

```bash
brew install node
```

新しいターミナルウィンドウを開き、両方のツールを確認します。

```bash
node --version
npm --version
```

どちらのコマンドもバージョン番号が表示されるはずです。`node` が見つからない場合は、ターミナルを一度閉じてから開き直し、新しい `PATH` を読み込ませてください。

## ステップ 2: GitHub CLI をインストールしてログインする

`gh` と呼ばれる GitHub CLI を使うと、Web サイトで操作しなくても、Claude がリポジトリを作成して管理できるようになります。

```bash
brew install gh
gh --version
```

続いてログインします。

```bash
gh auth login
```

質問には次のように答えてください。

- **Where do you use GitHub?**（どこで GitHub を使いますか?） `GitHub.com`
- **Preferred protocol?**（優先するプロトコルは?） `HTTPS`
- **Authenticate Git with your GitHub credentials?**（GitHub の認証情報を使って Git を認証しますか?） `Yes`
- **How would you like to authenticate?**（認証方法はどうしますか?） `Login with a web browser`

ターミナルに表示された一度限りのコードをコピーし、Enter キーを押して、ブラウザでサインインを完了してください。終わったら、結果を確認します。

```bash
gh auth status
```

出力に `github.com` にログインしていることが表示されるはずです。

## ステップ 3: Claude に非公開リポジトリの作成を依頼する

プロジェクトを置きたいフォルダを選びます（例: `~/Sites`）。存在しない場合は作成してください。

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

続けて、Claude に次のような依頼をします。

```text
GitHub CLI を使って、自分の GitHub アカウントに my-astro-site という名前の非公開リポジトリを作成してください。
README 付きで初期化して main ブランチを作成し、このフォルダにクローンしてください。
完了したらリポジトリの URL を教えてください。
```

Claude は次と同等のコマンドを実行するはずです。

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

完了すると、`README.md` を含む `~/Sites/my-astro-site` フォルダができていて、GitHub 上のリポジトリは非公開になっているはずです。既定のブランチを確認します。

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

`main` と表示されるはずです。

## ステップ 4: Astro サイトの土台を作る

リポジトリのフォルダにいたまま、そこで Claude を起動します。

```bash
cd ~/Sites/my-astro-site
claude
```

Claude に基本的なサイトの作成を依頼します。

```text
Astro の公式 basics スターターを使って、このリポジトリに基本的な Astro ウェブサイトを作成してください。
サイト名とナビゲーションリンクを含むサイトヘッダー、著作権表示のテキストを含むフッター、
スマートフォン、タブレット、横長のデスクトップ画面のいずれでも使えるレイアウトを追加してください。
デザインはシンプルにしてください。開発サーバーを起動してページを確認し、表示方法も教えてください。
```

Claude の作業が終わったら、ご自身でローカルのプレビューを開きます。

```bash
npm install
npm run dev
```

Astro はローカルのアドレスを表示します（通常は `http://localhost:4321`）。ブラウザでそのアドレスを開き、ウィンドウのサイズを変えてレイアウトを確認してから、`Control+C` でサーバーを停止してください。

コミットする前に、本番用ビルドが成功することを確認してください。

```bash
npm run build
```

### 最初のバージョンをコミットしてプッシュする

Claude に作業内容の保存を依頼します。

```text
分かりやすいメッセージを付けて Astro サイトをコミットし、origin の main ブランチにプッシュしてください。
```

Claude は次のようなコマンドを実行するはずです。

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

GitHub 上で、リポジトリの `main` ブランチに最新のコミットが表示されていることを確認してください。

## ステップ 5: impeccable をインストールして、トップページに overdrive を適用する

[impeccable](https://impeccable.style) は、コーディングエージェント向けのデザインスキルです。`polish`、`critique`、`overdrive` などの、デザイン作業で共通して使える言葉を Claude に与えます。`overdrive` コマンドは、シェーダー、スプリング物理、スクロールに連動したアニメーションなど、より大胆で表現力のある効果を追加します。

このプロジェクト用にスキルをインストールするよう Claude に依頼します。

```text
公式インストーラーを使って、このプロジェクトに impeccable スキルをインストールしてください。
インストール範囲はプロジェクトに、プロバイダーは Claude Code を使ってください。Claude Code を再起動する必要がある場合は教えてください。
```

Claude はプロジェクトのルートで次を実行するはずです。

```bash
npx impeccable install
```

インストーラーは、このプロジェクトだけに入れるか全体に入れるかを尋ねるほか、デザインフック（design hook）の導入も提案します。フックは承認してから、Claude Code を再起動して新しいスキルを読み込ませてください。

再起動したセッションで、デザインのコンテキストを初期化します。

```text
/impeccable init
```

次に、トップページに overdrive を適用します。

```text
/impeccable overdrive the homepage
```

コミットする前に、Claude が変更した内容を確認してください。Overdrive は大量の動きを追加することがあるため、ページの内容を読者が理解するのに役立つ効果だけを残すとよいでしょう。Claude に再度ビルドを実行させ、結果をプッシュするよう依頼してください。

```text
npm run build を実行し、エラーがあれば修正してから、overdrive による変更をコミットして main にプッシュしてください。
```

## ステップ 6: GitHub Actions で GitHub Pages に公開する

GitHub Pages では、ビルドしたサイトを無料で公開できます。Astro には、サイトをビルドしてデプロイする公式の GitHub Action が用意されています。

### Pages を有効にする

GitHub でリポジトリを開き、**設定（Settings） → Pages** に進みます。**ビルドとデプロイ（Build and deployment）** の下にある **ソース（Source）** を **GitHub Actions** に設定してください。

### Claude にワークフローを追加してもらう

```text
.github/workflows/deploy.yml に GitHub Actions のワークフローを追加してください。actions/checkout と withastro/action を使って、この Astro サイトをビルドし、GitHub Pages にデプロイしてください。
Astro のテンプレートに含まれている permissions のブロックは残してください。
```

Claude が作成するワークフローは、Astro の公式ドキュメントの例と似た内容になります。

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### サイトのアドレスを設定する

GitHub Pages では、プロジェクトのサイトはパス配下で公開されます（例: `https://<your-username>.github.io/my-astro-site`）。Astro はそのパスを知っておく必要があります。知らないままだと、リンクや素材が正しく読み込まれなくなります。`astro.config.mjs` を更新するよう Claude に依頼してください。

```text
astro.config.mjs の site を https://<your-username>.github.io に、base を /my-astro-site に設定してください。
それぞれの設定が何をするのかも説明してください。
```

結果は次のようになるはずです。

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

`<your-username>` は、ご自身の GitHub ユーザー名に置き換えてください。後で独自ドメインに移行するときは、`base` を削除します。

ワークフローと設定の変更をコミットしてプッシュします。

```text
Pages 用のワークフローと Astro の設定変更をコミットし、main にプッシュしてください。
```

### 最初のデプロイが終わるまで待つ

リポジトリの **アクション（Actions）** タブを開きます。`Deploy to GitHub Pages` の実行が1〜2分ほどで緑色（成功）になるはずです。その後、**設定（Settings） → Pages** に表示されている Pages の URL を開いてください。

## ステップ 7: Cloudflare でドメインを接続する

Cloudflare の手順にはドメインが必要です。よくある方法は次の2つです。

- Cloudflare ダッシュボードの Cloudflare Registrar から、**新しいドメインを登録**します。
- **すでに所有しているドメインを使う。** そのドメインを Cloudflare にサイトとして追加し、ドメイン取得元（レジストラ）でネームサーバーを、Cloudflare が指定する2つのネームサーバーに変更してください。

[Cloudflare ダッシュボード](https://dash.cloudflare.com) にサインインし、ドメインを登録するか、既存のドメインを追加します。Cloudflare でそのドメインが有効（active）と表示されるまで待ってください。ネームサーバーを変更した後は、数分かかることがあります。

## ステップ 8: GitHub のブランチから Worker プロジェクトを作成する

Cloudflare の現在の Astro 向けガイドでは Workers を使います。ダッシュボードでは、Pages 形式の Git の流れも同じ **Workers & Pages** の項目に表示されますが、以下の手順は Workers の方法に従います。

まず、静的な Astro ビルド用の Wrangler 設定を追加するよう Claude に依頼します。Wrangler は Cloudflare のコマンドラインツールです。

```text
静的な Astro サイト用の wrangler.jsonc ファイルを、プロジェクトのルートに追加してください。
name は my-astro-site に、compatibility_date は今日の日付に設定し、./dist フォルダを静的アセットとして配信してください。main のエントリーポイントは追加しないでください。
```

内容は次のようになるはずです。

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

ファイルをコミットしてプッシュします。その後、Cloudflare のプロジェクトを作成します。

1. Cloudflare ダッシュボードで **Workers & Pages** を開きます。
2. **アプリケーションを作成（Create application）** を選び、GitHub からリポジトリをインポートするオプションを選択します。
3. Cloudflare から求められたら、**Cloudflare Workers & Pages** の GitHub アプリを承認します。すべてのリポジトリか、`my-astro-site` のみかを選んでください。
4. `my-astro-site` と `main` ブランチを選択します。
5. ビルドコマンドを `npm run build`（または `npx astro build`）に、デプロイコマンドを `npx wrangler deploy` に設定します。
6. デプロイを開始します。

Cloudflare は、接続したブランチにプッシュされるたびにサイトをビルドします。そのため、今後のコミットは自動的にデプロイされます。

### ドメインを接続する

ダッシュボードで新しい Worker を開き、**ドメインとルート（Domains & Routes）** に進んで、ドメイン、または `www` のようなサブドメインを追加します。ドメインがすでに同じアカウントにある場合、Cloudflare が DNS レコードを自動で作成します。

## ステップ 9: Cloudflare でサイトを確認する

最初のビルドが終わったら、Cloudflare ダッシュボードの次の場所を確認してください。

- **デプロイ（Deployments）:** 最新のビルドが成功と表示されているはずです。失敗していた場合は、ビルドログを開いて最初のエラーを読んでください。
- **ドメインとルート（Domains & Routes）:** 独自ドメインが有効（active）と表示されているはずです。
- **設定:** 接続されているリポジトリとブランチが想定どおりか確認してください。

次に、ブラウザでご自身のドメインを開きます。スマートフォンと、横長のデスクトップウィンドウの両方で、ヘッダー、フッター、レイアウトを確認してください。

## ステップ 10: 新しいページを追加して公開されるまで見届ける

これで一連の流れが揃いました。手元で編集し、GitHub にプッシュすると、ホスティングサービスがビルドして変更をデプロイします。

プロジェクトのフォルダで Claude を起動し、新しいページを依頼します。

```text
src/pages/about.astro に新しいページを作成してください。タイトル、短い段落、トップページに戻るリンクを含めてください。
他のページと同じヘッダーとフッターを使ってください。npm run build を実行してから、main にコミットしてプッシュしてください。
```

Claude は、ファイルを作成し、サイトをビルドして、コミットしてプッシュするはずです。その後、2つのデプロイを確認します。

- **GitHub:** **アクション**タブを開きます。Pages のワークフローが再び実行されます。
- **Cloudflare:** **Workers & Pages → プロジェクト → デプロイ** を開きます。新しいビルドが自動的に始まります。

両方とも成功と表示されたら、ブラウザで `https://<your-domain>/about` を開きます。ページが表示されない場合は、ファイルが `src/pages/about.astro` にあるか、最新のデプロイが完了しているか、ブラウザに古いキャッシュが表示されていないかを確認してください。

## よくある問題

- **`node: command not found`:** Node.js をインストールした後、新しいターミナルウィンドウを開いてください。
- **`gh` でリポジトリを作成できない:** `gh auth status` を実行し、そのログインがご自身のアカウントにアクセスできるか確認してください。
- **GitHub Pages で白い画面になる、またはスタイルが表示されない:** `astro.config.mjs` の `site` と `base` を確認してください。`base` の値はリポジトリ名と一致している必要があります。
- **Cloudflare のビルドが失敗する:** ビルドログの最初のエラーを読んでください。多くの失敗は、スクリプトの不足、ビルドコマンドの誤り、または Wrangler 設定が誤ったフォルダを指していることが原因です。
- **ドメインが有効にならない:** ネームサーバーの変更が反映されるまで時間がかかることがあります。Cloudflare のドメインの概要ページで状態を確認してください。

## 次のステップ

サイトが公開されたら、同じ流れを本格的なコンテンツにも使い続けられます。Claude にページを追加してもらったり、`/impeccable critique` を実行してデザインのレビューを受けたり、プレビュー用に2つ目の Cloudflare 環境を追加したりできます。大切な習慣はシンプルです。小さな変更を加え、手元でビルドして、コミットし、ホスティングサービスに公開させることです。

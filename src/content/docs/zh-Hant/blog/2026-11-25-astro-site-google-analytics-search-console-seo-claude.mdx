在[上一篇指南](/zh-Hant/blog/2026-11-23-mac-astro-site-claude-github-cloudflare/)中，你從一台乾淨的 Mac 出發，做出了部署在 GitHub Pages 和 Cloudflare 上的 Astro 網站。網站上線只完成了一半：你還需要知道有沒有人造訪、造訪者做了什麼，以及 Google 能不能找到它。

本指南補上這一層。你會註冊 Google Analytics 和 Google Search Console，然後讓 Claude 接入追蹤、網站地圖、社群標籤和 favicon。每個步驟結束時都有可以檢查的結果，確認後再繼續。

完整流程如下：

1. 建立 Google Analytics 資源，並複製它的測量 ID。
2. 讓 Claude 為網站接入 Google Analytics、推送、等待部署完成，並證明線上確實存在該程式碼。
3. 在 Google Analytics 中確認你的造訪即時出現。
4. 在 Google Search Console 中註冊網站。
5. 把 Search Console 與 Google Analytics 連結。
6. 讓 Claude 設計並加入符合你網站的事件追蹤，然後發布並驗證。
7. 讓 Claude 加入基礎 SEO 層：網站地圖、`robots.txt`、canonical 連結、Open Graph 和 Twitter 標籤。
8. 在 Search Console 中提交網站地圖。
9. 讓 Claude 最佳化每個頁面的標題、描述和關鍵字，並使用 Mac 上的命令列工具產生多尺寸 favicon。

## 本指南適合誰

適合完成了上一篇指南的人：你有一個位於 GitHub 儲存庫中的 Astro 專案，每次推送到 `main` 都會自動部署，並且有一個公開網域。你不需要任何分析工具的使用經驗，但需要能把簡短的提示詞貼到 Claude Code 中，並在幾個 Google 頁面上點擊操作。

## 前提條件

- 上一篇指南中已經上線、自訂網域可用的 Astro 網站。本文把儲存庫稱為 `my-astro-site`，把網域稱為 `example.com`，請替換成你自己的。
- 一個 Google 帳號。
- 已安裝並登入的 Claude Code，以及已登入的 `gh`（`gh auth status`）。
- 能夠修改網域 DNS 的權限。如果網域在 Cloudflare，你已經具備。

## 步驟 1：建立 Google Analytics 資源並取得測量 ID

Google Analytics 4（GA4）的結構是：帳戶包含一個或多個資源，資源包含資料串流。一個網站對應一個網頁資料串流，資料串流有一個以 `G-` 開頭的測量 ID。

1. 開啟 [analytics.google.com](https://analytics.google.com)，用你的 Google 帳號登入。
2. 點擊 **開始衡量**（如果你已經在使用 Analytics，則選擇 **管理 → 建立 → 帳戶**）。替帳戶取個名字，例如 `My sites`。
3. 建立資源。用網站名稱命名，選擇報表時區和貨幣，並完成後面的業務問題。
4. 選擇平台時，選 **網頁**。
5. 輸入網站位址（`https://example.com`）和資料串流名稱，保持 **加強型評估** 開啟。它無需任何程式碼就能記錄網頁瀏覽、捲動、外部連結點擊和檔案下載。
6. 建立資料串流。Google 會顯示資料串流詳細資訊，其中包含 **測量 ID**。

複製測量 ID，它形如 `G-ABCD123456`。之後可以在 **管理 → 資料收集和修改 → 資料串流 → 你的資料串流** 中再次找到它。

測量 ID 不是機密。每個使用它的網站，其網頁原始碼裡都會直接顯示，所以可以放心提交到儲存庫中。

檢查：你已經得到一個以 `G-` 開頭的測量 ID。

## 步驟 2：讓 Claude 接入 Google Analytics

在專案資料夾中啟動 Claude：

```bash
cd ~/Sites/my-astro-site
claude
```

然後用一個請求描述完整的任務，包括推送和驗證。你對最終狀態描述得越準確，之後需要修正的就越少。

```text
請為這個 Astro 網站接入 Google Analytics 4，測量 ID 是 G-ABCD123456。

要求：
- 把 gtag.js 載入器和 config 呼叫放在共用版面配置的 <head> 中，使每個頁面恰好有一份。
- 使用普通的內聯腳本（is:inline），讓 window.gtag 成為真正的全域函式。Astro 會把普通的 <script> 打包成模組，這會讓後續程式碼存取不到 gtag。
- 只在正式建置中渲染該標籤，`npm run dev` 中不渲染。
- 測量 ID 從一個常數或環境變數讀取，不要分散地複製多份。
- 執行 `npm run build`，並檢查 dist/index.html 中包含該標籤。

建置通過後，用清楚的說明提交並推送到 main。然後等待兩處部署，即 GitHub Pages 工作流程和 Cloudflare 建置，都完成。最後用 curl 取得 https://example.com/，確認線上的 HTML 包含該測量 ID。請彙報你檢查了什麼。
```

Claude 在版面配置中產生的片段應該與下面接近：

```astro
---
const GA_ID = 'G-ABCD123456';
const isProd = import.meta.env.PROD;
---
<head>
  {isProd && (
    <>
      <script is:inline async src={`https://www.googletagmanager.com/gtag/js?id=${GA_ID}`}></script>
      <script is:inline define:vars={{ GA_ID }}>
        window.dataLayer = window.dataLayer || [];
        window.gtag = function () { dataLayer.push(arguments); };
        gtag('js', new Date());
        gtag('config', GA_ID);
      </script>
    </>
  )}
</head>
```

有兩個細節值得理解，因為它們是「我加了標籤卻沒有反應」最常見的原因。

- **`window.gtag` 必須是全域函式。** 如果腳本被包進閉包，網頁瀏覽可能仍然正常，但 `window.gtag` 是未定義的。步驟 6 中你加入的所有自訂事件都會靜默失敗。明確地給 `window.gtag` 賦值可以避免這個問題。
- **只在正式環境啟用。** 如果標籤也在 `localhost` 上執行，你自己開發時的點擊會汙染資料。

等待部署時，Claude 會使用類似下面的命令：

```bash
gh run watch
curl -s https://example.com/ | grep -o 'googletagmanager.com/gtag/js?id=G-[A-Z0-9]*'
```

`gh run watch` 會追蹤 GitHub Actions 的執行直到結束。只有線上網頁真的包含載入器位址時，`curl` 那一行才會輸出內容。

檢查：Claude 的彙報顯示兩個平台都部署成功，並且在線上 HTML 中找到了測量 ID。如果 `curl` 沒有輸出，說明部署尚未完成或快取還在提供舊頁面；讓 Claude 一分鐘後重試，舊頁面仍然存在時清除 Cloudflare 快取。

## 步驟 3：在 Google Analytics 中驗證網站在線

現在從 Google 的一側確認，而不只是你自己這一側。

1. 在瀏覽器中開啟 `https://example.com`。如果你使用廣告攔截器或隱私瀏覽器，請在這次檢查中關閉它們，它們會攔截 Google Analytics。
2. 在 Google Analytics 中開啟 **報表 → 即時**。
3. 大約一分鐘內，你應該會看到 **過去 30 分鐘內有 1 位使用者**，事件列表中有 `page_view` 事件。
4. 點開兩三個頁面，頁面標題會出現在即時檢視中。

你也可以開啟 **管理 → 資料串流 → 你的資料串流**。出現綠色勾號，並提示資料正在流入，說明資料串流正在接收流量。

檢查：你自己的造訪出現在 **即時** 中。**取得** 等標準報表會落後幾個小時到一天，所以它們仍然為空時不必擔心。

## 步驟 4：在 Google Search Console 中註冊網站

Google Analytics 告訴你造訪者抵達之後做了什麼。Google Search Console 告訴你 Google 如何看待你的網站：哪些搜尋字詞帶來了造訪者，哪些頁面被收錄，以及 Google 發現了哪些錯誤。

1. 開啟 [search.google.com/search-console](https://search.google.com/search-console)，用與 Analytics 相同的 Google 帳號登入。使用同一個帳號，之後的連結會更容易。
2. 點擊 **新增資源**。你會看到兩種類型。
   - **網域** 涵蓋 `example.com` 及其所有子網域和通訊協定，需要一筆 DNS 記錄。
   - **網址前置字元** 只涵蓋一個精確的位址，例如 `https://example.com/`，提供多種驗證方式。
3. 如果你的 DNS 在 Cloudflare，選擇 **網域**，輸入 `example.com`。
4. Search Console 會顯示一筆 `TXT` 記錄。複製它的值，它以 `google-site-verification=` 開頭。
5. 在 Cloudflare 主控台中開啟你的網域，進入 **DNS → 記錄 → 新增記錄**。類型選 `TXT`，名稱填 `@`，把值貼到內容中並儲存。
6. 回到 Search Console，點擊 **驗證**。DNS 的變更通常幾分鐘內生效，但也可能更久。如果驗證失敗，請稍等後再次點擊 **驗證**。

如果你選擇的是 **網址前置字元** 類型，最簡單的方式是使用 Google Analytics 驗證：只要使用同一個 Google 帳號，Search Console 就可以把你在步驟 2 中安裝的標籤作為擁有權證明。

檢查：Search Console 顯示「擁有權已驗證」，並開啟該資源的概覽頁面。一段時間內它會顯示「暫無資料」，這是正常的。

## 步驟 5：把 Search Console 與 Google Analytics 連結

連結之後，搜尋字詞和著陸頁成效會進入 Analytics 報表，你就能把來自搜尋的流量和這些造訪者的行為放在一起看。

1. 在 Google Analytics 中開啟 **管理**。
2. 在 **產品連結** 下選擇 **Search Console 連結**。
3. 點擊 **連結**，再點擊 **選擇帳戶**，選中你的 Search Console 資源。你需要是該 Search Console 資源的擁有者，並且是該 Analytics 資源的編輯者。
4. 點擊 **下一步**，選擇網頁資料串流，然後點擊 **提交**。

Search Console 的資料需要幾天才會開始流入，而且會延遲大約兩天。這裡沒有什麼需要等待的事情，直接繼續下一步即可。

連結建立後，可以在 **報表 → 資源庫** 中找到相關報表。Search Console 報表不會自動加入左側選單。想讓它們出現在選單中時，請在資源庫裡發布 **Search Console** 集合。

檢查：**管理 → 產品連結 → Search Console 連結** 中列出了你的資源。

## 步驟 6：加入符合你網站的事件追蹤

加強型評估已經記錄了網頁瀏覽、捲動、外部連結點擊、站內搜尋和檔案下載，不要重複實作它們。事件用於你自己業務特有的內容：主要行動呼籲的點擊、訂閱電子報、聯絡表單、定價頁的瀏覽。

最有用的指令不是「加一些事件」，而是「先看我的網站，提出事件方案，由我核准」。這樣你始終掌握要衡量什麼。

```text
請查看這個 Astro 網站的結構：頁面、版面配置、元件、行動呼籲、表單和外部連結。

第 1 步：在修改任何程式碼之前，先提出事件方案。給我一張表，包含：事件名稱、觸發時機、參數，以及它回答的業務問題。有合適的 GA4 建議事件名稱時優先使用（例如 generate_lead、sign_up、select_content），否則使用 snake_case 的自訂名稱。不要重複加強型評估已經追蹤的內容：網頁瀏覽、捲動、外部連結點擊、檔案下載。最多 10 個事件。

第 2 步：我核准之後，實作該方案：
- 用 data-ga-event、data-ga-label 和 data-ga-location 屬性標記元素。
- 在 document 上使用一個委派的點擊監聽器，讀取這些屬性並呼叫 gtag('event', ...)。不要加入內聯的 onclick 處理器。
- 參數只傳送穩定的 id 和位置。絕不傳送連結文字、表單輸入、電子郵件位址或任何能辨識造訪者的內容。
- 不要延遲或取消頁面跳轉。

第 3 步：執行建置、提交、推送，等待兩處部署完成，並用 curl 驗證線上網站包含該監聽器腳本。然後告訴我應該點擊哪些位置，以便我在 GA4 DebugView 中驗證。
```

Claude 會先回覆一張表。一個小型網站的合理方案類似這樣：

| 事件 | 觸發時機 | 參數 | 回答的問題 |
| --- | --- | --- | --- |
| `cta_click` | 造訪者點擊主要的行動呼籲按鈕 | `label`、`location` | 哪些按鈕、頁面的哪些區域帶來行動？ |
| `generate_lead` | 聯絡表單提交成功 | `form_id` | 有多少造訪者變成了聯絡人？ |
| `nav_click` | 點擊頁首或頁尾連結 | `label`、`location` | 哪些導覽項目被使用？ |
| `theme_toggle` | 使用主題切換 | `value` | 深色模式開關值得保留嗎？ |

要帶著批判的眼光讀這張表。刪掉沒人會看的事件，把以功能命名而不是以決策命名的事件改名。然後回覆「核准，但去掉 `theme_toggle`」，讓它去實作。

Claude 寫出的監聽器大致如下：

```js
document.addEventListener(
  'click',
  (event) => {
    const el = event.target.closest('[data-ga-event]');
    if (!el || typeof window.gtag !== 'function') return;
    window.gtag('event', el.dataset.gaEvent, {
      label: el.dataset.gaLabel,
      location: el.dataset.gaLocation,
      transport_type: 'beacon',
    });
  },
  true,
);
```

被標記的按鈕：

```astro
<a href="/contact" data-ga-event="cta_click" data-ga-label="hero_contact" data-ga-location="home_hero">
  聯絡我們
</a>
```

### 驗證事件

1. 在 Google Analytics 中開啟 **管理 → 資料顯示 → DebugView**。DebugView 會在幾秒內顯示抵達的事件。
2. 要讓瀏覽器進入除錯模式，請安裝 Chrome 擴充功能 **Google Analytics Debugger**，或者讓 Claude 暫時在 `config` 呼叫中加入 `debug_mode: true`。
3. 造訪線上網站，執行 Claude 列出的點擊。
4. 每次點擊都應在 DebugView 時間軸中顯示為一個事件，帶有你預期的參數。

事件抵達一次之後，也會出現在 **管理 → 資料顯示 → 事件** 中。如果想在標準報表中使用 `label` 或 `location`，請在 **管理 → 資料顯示 → 自訂定義 → 建立自訂維度** 中註冊它們，範圍選擇 **事件**。只有這樣註冊的參數才會出現在標準報表裡。

移除所有暫時的 `debug_mode` 設定，然後讓 Claude 推送乾淨的版本。

檢查：每個被追蹤的點擊都以正確的事件名稱和參數出現在 DebugView 中，並且最終程式碼已經在 `main` 上。

## 步驟 7：加入基礎 SEO 層

搜尋引擎需要一份頁面地圖、關於抓取範圍的說明，以及頁面被分享時人們看到的描述。第一項 Astro 有官方整合套件，其餘只是版面配置裡的幾行程式碼。Claude 可以引入相關的 Astro 元件和整合套件來快速完成。

```text
請為這個 Astro 網站加入基礎 SEO。

1. 網站地圖：用 `npx astro add sitemap` 安裝官方的 @astrojs/sitemap 整合套件。確保 astro.config.mjs 中的 `site` 是正式網域 https://example.com，並刪除 GitHub Pages 專案託管遺留的 `base`。
2. robots.txt：建立 src/pages/robots.txt.ts，回傳 "User-agent: *"、"Allow: /" 以及一行指向 https://example.com/sitemap-index.xml 的 Sitemap，該位址由 `site` 設定產生，不要寫死。
3. 一個可重複使用的 SEO 元件，供共用版面配置使用，輸出：<title>；meta description；根據目前 URL 和 `site` 產生的 canonical 連結；Open Graph 標籤（og:type、og:title、og:description、og:url、og:image、og:site_name、og:locale）；Twitter 卡片標籤（twitter:card summary_large_image、twitter:title、twitter:description、twitter:image）；以及 theme-color meta 標籤。每個頁面透過 props 傳入自己的標題和描述。
4. 在 public/og-default.png 提供一張預設的 1200x630 社群分享圖，頁面沒有提供時使用。
5. 為網站加入 WebSite 類型的 JSON-LD 結構化資料，如果網站有部落格，再為文章加入 Article 類型。
6. 執行 `npm run build`，然後列出 dist/sitemap-index.xml，顯示 dist/robots.txt，並確認首頁建置出的 HTML 包含以上所有標籤。

全部正確後，提交、推送，等待兩處部署完成，並用 curl 確認 https://example.com/sitemap-index.xml 和 https://example.com/robots.txt 都回傳 200 且內容正確。
```

每一部分的作用：

- **網站地圖。** `@astrojs/sitemap` 在建置時產生 `sitemap-index.xml` 和一個或多個 `sitemap-0.xml` 檔案，並且需要 `site` 設定來產生絕對 URL。
- **`robots.txt`。** 它告訴爬蟲可以抓取什麼，以及網站地圖在哪裡。想讓某個頁面不被收錄，應該使用 `noindex`，而不是只寫在 `robots.txt` 裡。
- **Canonical 連結。** 當同一個頁面可以透過多個位址存取時，它告訴 Google 哪個是正式位址。
- **Open Graph 和 Twitter 標籤。** 它們決定連結在社群網路或聊天應用程式中被分享時顯示的標題、描述和圖片。
- **JSON-LD。** 結構化資料幫助搜尋引擎理解頁面是什麼。它不保證出現富媒體結果，但加入成本很低。

檢查：線上的 `sitemap-index.xml` 列出了你的頁面，`robots.txt` 包含 `Sitemap:` 行，頁面原始碼中能看到 canonical、Open Graph 和 Twitter 標籤。你也可以把網址貼到社群卡片驗證工具，或在聊天應用程式裡分享，查看預覽。

## 步驟 8：在 Search Console 中提交網站地圖

在你告訴 Search Console 之前，它並不知道你的網站地圖存在。

1. 在 Search Console 中開啟你的資源，在左側選單中選擇 **網站地圖**。
2. 在 **新增網站地圖** 下，輸入 `sitemap-index.xml`。
3. 點擊 **提交**。
4. 狀態應變為 **成功**，並顯示發現的頁面數量。如果顯示 **無法擷取**，請先在瀏覽器中開啟該網站地圖位址；如果能開啟，等幾分鐘再重新整理，因為首次擷取可能會延遲。

接下來，請 Google 立即查看你最重要的頁面：

1. 把首頁 URL 貼到 Search Console 頂部的搜尋列。
2. 如果該頁面尚未被收錄，點擊 **要求建立索引**。

收錄仍然需要幾天，Search Console 的報表也有延遲，一週後再回來查看。

檢查：**網站地圖** 中列出了 `sitemap-index.xml`，狀態為 **成功**。

## 步驟 9：最佳化每個頁面的中繼資料並加入多尺寸 favicon

基礎層給每個頁面提供的是通用的中繼資料。標題和描述是人們在搜尋結果中讀到的文字，值得逐頁處理。Favicon 需要多個尺寸，因為瀏覽器、手機和書籤各自請求不同的檔案。

### 標題、描述和關鍵字

```text
請檢查這個網站的每個頁面，並最佳化它的搜尋中繼資料。

對每個頁面，給我一張包含標題、meta description 和關鍵字的前後對比表，然後套用修改。規則：
- 標題：每頁唯一，不超過約 60 個字元，主要主題在前，網站名稱在後。
- 描述：每頁唯一，120 到 160 個字元，用一句通順的話說明造訪者能得到什麼並邀請點擊。不要堆砌關鍵字，也不要在頁面之間複製文字。
- 關鍵字：從頁面真實內容中提取 5 到 8 個詞。只有當版面配置已經支援時才保留 keywords meta 標籤，不要編造頁面沒有涉及的主題。
- 檢查每個頁面恰好有一個與標題含義一致的 <h1>，並且每張圖片都有 alt 屬性。

然後執行建置，並寫一份簡短的報告，列出仍然共用標題或描述的頁面。
```

先把預期擺正：搜尋引擎基本上忽略 keywords meta 標籤。關鍵字對你自己有幫助，因為寫下它們會迫使你說清楚每個頁面是關於什麼的。真正出現在搜尋結果裡的是標題和描述。

### 各種尺寸的 favicon

一個 `favicon.svg` 是不錯的開始，但有些地方需要特定的檔案：舊版瀏覽器和書籤使用 `favicon.ico`，iOS 主畫面使用 `apple-touch-icon`，Android 和 Web 應用程式清單使用 192 和 512 像素的 PNG。

macOS 自帶用於縮放 PNG 的 `sips`。產生 `.ico` 則需要 ImageMagick，可以透過 Homebrew 安裝。讓 Claude 直接在你的 Mac 上使用它們：

```text
請用我的來源圖片 public/logo-source.png（至少 512x512 的正方形 PNG）產生一套完整的 favicon。

1. 使用 macOS 的 `sips` 命令建立 public/icon-192.png、public/icon-512.png 和 public/apple-touch-icon.png（180x180）。
2. 如果沒有安裝 ImageMagick，用 `brew install imagemagick` 安裝。使用 `magick` 產生包含 16x16、32x32 和 48x48 影像的 public/favicon.ico。
3. 如果我已經有 public/favicon.svg，請保留；如果沒有，建立一個與 logo 相符的簡單版本。
4. 加入 public/site.webmanifest，列出 icon-192.png 和 icon-512.png。
5. 更新版面配置的 <head>，加上對應的 <link> 標籤：SVG 圖示、.ico 備援、apple-touch-icon 和清單。
6. 對每張產生的圖片執行 `file` 確認真實尺寸，執行建置，並確保這些檔案出現在 dist/ 中。
```

Claude 執行的命令與下面接近：

```bash
sips -z 192 192 public/logo-source.png --out public/icon-192.png
sips -z 512 512 public/logo-source.png --out public/icon-512.png
sips -z 180 180 public/logo-source.png --out public/apple-touch-icon.png
brew install imagemagick
magick public/logo-source.png -define icon:auto-resize=48,32,16 public/favicon.ico
file public/*.png public/favicon.ico
```

head 中的連結如下：

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="icon" href="/favicon.ico" sizes="48x48" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<link rel="manifest" href="/site.webmanifest" />
```

最後，像之前的每一步一樣閉環：

```text
請用清楚的說明提交所有改動，推送到 main，等待兩處部署完成，並用 curl 驗證線上的 /favicon.ico、/apple-touch-icon.png 和 /site.webmanifest 都回傳 200。
```

在瀏覽器中檢查：分頁顯示你的圖示，書籤或 iOS 的「加入主畫面」使用較大的那一張。瀏覽器會積極快取 favicon，如果仍然看到舊圖示，請在隱私視窗中開啟網站。

## 一週之後要檢查什麼

- **Search Console → 網頁** 顯示有多少頁面被收錄，以及其他頁面未被收錄的原因。
- **Search Console → 成效** 顯示搜尋字詞、點擊次數和平均排名。用這些搜尋字詞改進標題和描述。
- **Analytics → 報表 → 互動 → 事件** 顯示你的自訂事件觸發的頻率。
- **Analytics → 報表 → 資源庫** 是資料抵達之後 Search Console 集合出現的位置。

## 常見問題

- **即時報表什麼都沒有。** 廣告攔截器或隱私瀏覽器攔截了標籤。請在關閉擴充功能的隱私視窗中測試，並確認線上 HTML 中的測量 ID。
- **網頁瀏覽正常但自訂事件不運作。** 在線上網站開啟瀏覽器主控台並執行 `typeof window.gtag`，它必須輸出 `function`。如果輸出 `undefined`，說明標籤腳本被打包成了模組；讓 Claude 使用 `is:inline` 並明確給 `window.gtag` 賦值。
- **事件出現在 DebugView 中但不在報表裡。** 標準報表會落後最多一天，而且自訂參數只有註冊為自訂維度之後才會出現在報表中。
- **Search Console 無法驗證網域。** 檢查 `TXT` 記錄是否在根網域（`@`），值是否完整複製，以及是否沒有使用 Cloudflare 代理（TXT 記錄不會被代理）。然後稍等再重試。
- **網站地圖顯示「無法擷取」。** 自己開啟 `https://example.com/sitemap-index.xml`。如果回傳 404，請檢查 `astro.config.mjs` 中的 `site` 是否為正式網域，以及網站地圖整合套件是否列在 `integrations` 中。
- **社群預覽是舊的。** 各平台會快取預覽。修改標籤後，請使用它們的除錯工具重新整理快取。

## 隱私與同意

分析會收集造訪者的資料。根據造訪者所在的地區，你可能需要在載入 Google Analytics 之前取得同意，例如歐盟的 GDPR 和 ePrivacy 規則，並且可能需要在隱私權政策中說明。為了讓步驟簡潔，本指南無條件地安裝了該標籤。如果你的網站有來自要求同意地區的造訪者，請讓 Claude 加入同意橫幅，只有在造訪者同意之後才載入該標籤。以上是一般性資訊，不構成法律意見。

## 值得保持的循環

這裡的每一步都遵循同一個模式，也是值得保持的習慣：向 Claude 描述最終狀態，讓它做出修改，讓它推送並等待部署完成，讓它用 `curl` 在線上網站證明結果，然後用 Google Analytics 或 Search Console 之類的外部工具確認。以後每當你加入功能，都重複同樣的循環。

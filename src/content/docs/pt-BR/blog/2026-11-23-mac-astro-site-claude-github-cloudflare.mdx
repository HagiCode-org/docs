Este guia leva você de um Mac limpo até um site que está no ar na internet. Você fará o trabalho em dois lugares: no Terminal, onde instala as ferramentas, e no Claude Code, que executa os comandos repetitivos e edita os arquivos para você. Cada passo termina com algo que você pode conferir, para saber que deu certo antes de seguir em frente.

O caminho completo fica assim:

1. Instalar o Node.js.
2. Instalar o GitHub CLI (`gh`) e fazer login.
3. Pedir ao Claude para criar um repositório privado e cloná-lo.
4. Pedir ao Claude para montar um site Astro com cabeçalho, rodapé e layout responsivo, depois fazer o commit e o push.
5. Instalar a skill impeccable e usar o comando `overdrive` para caprichar na página inicial.
6. Publicar o site no GitHub Pages com um workflow do GitHub Actions.
7. Conectar um domínio na Cloudflare e implantar o mesmo branch com Workers.
8. Adicionar uma nova página, enviar e acompanhar as duas implantações até o fim.

## Para quem é este guia

Este guia é para quem tem um Mac e uma conta no GitHub e quer publicar um site estático simples sem configurar um servidor. Você não precisa conhecer Astro, GitHub Actions nem Cloudflare antes. Só precisa estar à vontade para abrir o Terminal e colar comandos.

## Pré-requisitos

- Um Mac com uma versão atual do macOS.
- Uma conta no GitHub.
- Uma conta na Cloudflare.
- Um nome de domínio. Você pode registrar um pela Cloudflare ou usar um que já tenha.
- Claude Code instalado e com login feito. Execute `claude` no Terminal uma vez para confirmar que ele inicia.

## Passo 1: Instalar o Node.js

O Astro e o instalador do impeccable rodam sobre o Node.js. Use a versão LTS atual.

O caminho mais simples é o instalador oficial em [nodejs.org](https://nodejs.org). Baixe o pacote para macOS, execute-o e aceite as opções padrão.

Se você já usa o Homebrew, pode instalar pelo Terminal:

```bash
brew install node
```

Abra uma nova janela do Terminal e verifique as duas ferramentas:

```bash
node --version
npm --version
```

Os dois comandos devem mostrar um número de versão. Se o `node` não for encontrado, feche e abra o Terminal de novo para que o novo `PATH` seja carregado.

## Passo 2: Instalar o GitHub CLI e fazer login

O GitHub CLI, chamado `gh`, permite que o Claude crie repositórios e os gerencie sem que você precise clicar pelo site.

```bash
brew install gh
gh --version
```

Depois, faça login:

```bash
gh auth login
```

Responda às perguntas assim:

- **Onde você usa o GitHub?** `GitHub.com`
- **Protocolo preferido?** `HTTPS`
- **Autenticar o Git com as suas credenciais do GitHub?** `Yes`
- **Como você quer se autenticar?** `Login with a web browser`

Copie o código de uso único que o Terminal mostrar, pressione Enter e conclua o login no seu navegador. Quando terminar, confira o resultado:

```bash
gh auth status
```

A saída deve dizer que você está conectado ao `github.com`.

## Passo 3: Pedir ao Claude para criar um repositório privado

Escolha uma pasta onde você quer guardar os seus projetos, por exemplo `~/Sites`, e crie-a se ela ainda não existir:

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

Depois, envie ao Claude um pedido como este:

```text
Use a GitHub CLI para criar um repositório privado chamado my-astro-site na minha conta do GitHub.
Inicialize-o com um README para que o branch main exista, e clone-o nesta pasta.
Mostre-me a URL do repositório quando terminar.
```

O Claude deve executar algo equivalente a:

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

Quando terminar, você deve ter uma pasta `~/Sites/my-astro-site` com um `README.md` dentro, e o repositório deve estar privado no GitHub. Confira o branch padrão:

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

Ele deve mostrar `main`.

## Passo 4: Montar o site Astro

Permaneça na pasta do repositório e inicie o Claude nela:

```bash
cd ~/Sites/my-astro-site
claude
```

Peça ao Claude para criar um site básico:

```text
Crie um site básico em Astro neste repositório usando o starter oficial de basics do Astro.
Adicione um cabeçalho com o nome do site e links de navegação, um rodapé com texto de direitos autorais,
e um layout que funcione em celulares, tablets e telas grandes de desktop.
Mantenha o design simples. Execute o servidor de desenvolvimento, verifique a página e me mostre como visualizá-la.
```

Quando o Claude terminar, abra você mesmo a visualização local:

```bash
npm install
npm run dev
```

O Astro mostra um endereço local, geralmente `http://localhost:4321`. Abra-o no navegador, redimensione a janela para conferir o layout e depois pare o servidor com `Control+C`.

Antes de fazer o commit, confirme que a build de produção passa:

```bash
npm run build
```

### Faça o commit e envie a primeira versão

Peça ao Claude para salvar o trabalho:

```text
Faça o commit do site Astro com uma mensagem clara e envie-o para o branch main no origin.
```

O Claude deve executar comandos como:

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

Confirme no GitHub que o seu commit mais recente aparece no branch `main` do repositório.

## Passo 5: Instalar o impeccable e caprichar na página inicial

[impeccable](https://impeccable.style) é uma skill de design para agentes de programação. Ela dá ao Claude um vocabulário comum para trabalhos de design, como `polish`, `critique` e `overdrive`. O comando `overdrive` acrescenta efeitos mais ousados e expressivos, como shaders, física de molas e animações guiadas pela rolagem.

Peça ao Claude para instalar a skill neste projeto:

```text
Instale a skill impeccable neste projeto usando o instalador oficial dela.
Use o escopo do projeto e o provedor Claude Code. Me avise quando eu precisar reiniciar o Claude Code.
```

O Claude deve executar isto a partir da raiz do projeto:

```bash
npx impeccable install
```

O instalador pergunta se a instalação deve ser só para este projeto ou global, e oferece um hook de design. Aceite o hook e depois reinicie o Claude Code para que a nova skill seja carregada.

Na sessão reiniciada, inicialize o contexto de design:

```text
/impeccable init
```

Depois, aplique a passada de overdrive na página inicial:

```text
/impeccable overdrive a página inicial
```

Revise o que o Claude alterou antes de fazer o commit. O overdrive pode acrescentar muita animação, então talvez você queira manter só os efeitos que ajudam o leitor a entender a página. Peça ao Claude para executar a build de novo e enviar o resultado:

```text
Execute npm run build, corrija os erros que aparecerem, depois faça o commit das alterações do overdrive e envie-as para main.
```

## Passo 6: Publicar no GitHub Pages com GitHub Actions

O GitHub Pages pode hospedar o site gerado sem custo. O Astro oferece uma GitHub Action oficial que faz a build do site e o implanta.

### Ative o Pages

Abra o seu repositório no GitHub e vá em **Configurações (Settings) → Pages**. Em **Compilação e implantação (Build and deployment)**, defina **Origem (Source)** como **GitHub Actions**.

### Peça ao Claude para adicionar o workflow

```text
Adicione um workflow do GitHub Actions em .github/workflows/deploy.yml que use actions/checkout
e withastro/action para fazer a build deste site Astro e implantá-lo no GitHub Pages.
Mantenha o bloco de permissions que o template do Astro inclui.
```

O workflow que o Claude criar será parecido com o exemplo documentado pelo Astro:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### Defina o endereço do site

O GitHub Pages serve um site de projeto em um caminho, como `https://<your-username>.github.io/my-astro-site`. O Astro precisa conhecer esse caminho, senão os links e os recursos do site vão quebrar. Peça ao Claude para atualizar o `astro.config.mjs`:

```text
Defina site como https://<your-username>.github.io e base como /my-astro-site no astro.config.mjs.
Explique o que cada configuração faz.
```

O resultado deve ficar parecido com isto:

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

Substitua `<your-username>` pelo seu nome de usuário do GitHub. Quando você depois passar a usar o seu próprio domínio, vai remover `base`.

Faça o commit e envie o workflow e a alteração de configuração:

```text
Faça o commit do workflow do Pages e da alteração no config do Astro, depois envie para main.
```

### Aguarde a primeira implantação

Abra a aba **Actions** do seu repositório. A execução `Deploy to GitHub Pages` deve ficar verde em um ou dois minutos. Depois, abra o endereço do Pages que aparece em **Configurações → Pages**.

## Passo 7: Conectar um domínio na Cloudflare

Você precisa de um domínio para este passo na Cloudflare. Há duas opções comuns:

- **Registrar um domínio novo** pelo Cloudflare Registrar, no painel da Cloudflare.
- **Usar um domínio que você já tem.** Adicione-o à Cloudflare como um site e depois troque os nameservers do domínio no seu registrador pelos dois nameservers que a Cloudflare fornecer.

Entre no [painel da Cloudflare](https://dash.cloudflare.com) e registre o domínio ou adicione o domínio que você já tem. Aguarde até a Cloudflare mostrar o domínio como ativo. Isso pode levar alguns minutos depois de uma troca de nameservers.

## Passo 8: Criar um projeto Worker a partir do branch do GitHub

A orientação atual da Cloudflare para Astro usa Workers. No painel, o fluxo de Git no estilo Pages ainda aparece na mesma seção **Workers & Pages**, mas os passos abaixo seguem o caminho dos Workers.

Primeiro, peça ao Claude para adicionar uma configuração do Wrangler para uma build estática do Astro. O Wrangler é a ferramenta de linha de comando da Cloudflare.

```text
Adicione um arquivo wrangler.jsonc na raiz do projeto para um site estático em Astro.
Defina o name como my-astro-site, defina compatibility_date como a data de hoje,
e sirva a pasta ./dist como arquivos estáticos. Não adicione um ponto de entrada main.
```

Ele deve ficar assim:

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

Faça o commit e envie o arquivo. Depois, crie o projeto na Cloudflare:

1. No painel da Cloudflare, vá em **Workers & Pages**.
2. Selecione **Criar aplicação (Create application)** e escolha a opção de importar um repositório do GitHub.
3. Autorize o app **Cloudflare Workers & Pages** no GitHub quando a Cloudflare pedir. Escolha todos os repositórios ou somente `my-astro-site`.
4. Selecione `my-astro-site` e o branch `main`.
5. Defina o comando de build como `npm run build` (ou `npx astro build`) e o comando de deploy como `npx wrangler deploy`.
6. Inicie a implantação.

A Cloudflare faz a build do site a cada envio para o branch conectado, então os próximos commits serão implantados automaticamente.

### Associe o seu domínio

Abra o novo Worker no painel, vá em **Domínios e rotas (Domains & Routes)** e adicione o seu domínio ou um subdomínio, como `www`. A Cloudflare cria o registro DNS para você quando o domínio já está na mesma conta.

## Passo 9: Conferir o site na Cloudflare

Depois que a primeira build terminar, confira estes lugares no painel da Cloudflare:

- **Deployments:** a build mais recente deve estar marcada como bem-sucedida. Se ela falhou, abra o log da build e leia o primeiro erro.
- **Domínios e rotas (Domains & Routes):** o seu domínio personalizado deve aparecer como ativo.
- **Settings (Configurações):** confirme se o repositório e o branch conectados são os que você espera.

Depois, abra o seu domínio no navegador. Confira o cabeçalho, o rodapé e o layout no celular e também em uma janela grande de desktop.

## Passo 10: Adicionar uma nova página e acompanhar a publicação

Agora você tem o ciclo completo: edite localmente, envie para o GitHub e deixe as plataformas fazerem a build e implantarem a alteração.

Inicie o Claude na pasta do projeto e peça uma nova página:

```text
Crie uma nova página em src/pages/about.astro com um título, um parágrafo curto e um link de volta para a página inicial.
Use o mesmo cabeçalho e rodapé das outras páginas. Execute npm run build e depois faça o commit e envie para main.
```

O Claude deve criar o arquivo, fazer a build do site, o commit e o envio. Depois, acompanhe as duas implantações:

- **GitHub:** abra a aba **Actions**. O workflow do Pages roda de novo.
- **Cloudflare:** abra **Workers & Pages → seu projeto → Deployments**. Uma nova build começa automaticamente.

Quando as duas mostrarem sucesso, abra `https://<your-domain>/about` no navegador. Se a página não aparecer, confira se o arquivo está em `src/pages/about.astro`, se a implantação mais recente terminou e se o navegador não está mostrando uma cópia antiga em cache.

## Problemas comuns

- **`node: command not found`:** abra uma nova janela do Terminal depois de instalar o Node.js.
- **`gh` não consegue criar o repositório:** execute `gh auth status` e confirme se o login tem acesso à sua conta.
- **O GitHub Pages mostra uma página em branco ou sem estilos:** confira `site` e `base` no `astro.config.mjs`. O valor de `base` precisa ser igual ao nome do repositório.
- **A build da Cloudflare falha:** leia o primeiro erro no log da build. A maioria das falhas vem de um script ausente, de um comando de build errado ou de uma configuração do Wrangler que aponta para a pasta errada.
- **O domínio não está ativo:** a troca de nameservers pode levar algum tempo para se propagar. Confira o status na página de visão geral do domínio na Cloudflare.

## Próximos passos

Depois que o site estiver no ar, você pode manter o mesmo ciclo para conteúdo de verdade. Peça ao Claude para adicionar páginas, execute `/impeccable critique` para uma revisão de design ou crie um segundo ambiente na Cloudflare para pré-visualizações. O hábito principal é simples: faça uma pequena mudança, gere a build localmente, faça o commit e deixe as plataformas publicarem.

No [guia anterior](/pt-BR/blog/2026-11-23-mac-astro-site-claude-github-cloudflare/), você partiu de um Mac limpo e criou um site Astro implantado no GitHub Pages e na Cloudflare. O site já está no ar, mas isso só resolve metade do problema: você ainda precisa saber se alguém o visita, o que os visitantes fazem e se o Google consegue encontrá-lo.

Este guia cobre essa parte. Você vai se cadastrar no Google Analytics e no Google Search Console e pedir ao Claude que configure o rastreamento, o sitemap, as tags sociais e o favicon. Cada etapa termina com um resultado que você pode verificar antes de seguir em frente.

O fluxo completo é este:

1. Criar uma propriedade no Google Analytics e copiar o ID de medição.
2. Pedir ao Claude que adicione o Google Analytics ao site, envie as alterações, aguarde a implantação e prove que o código está realmente no ar.
3. Confirmar no Google Analytics que suas visitas aparecem em tempo real.
4. Cadastrar o site no Google Search Console.
5. Vincular o Search Console ao Google Analytics.
6. Pedir ao Claude que desenhe e adicione o rastreamento de eventos adequado ao seu site, depois publicar e validar.
7. Pedir ao Claude que adicione a camada básica de SEO: sitemap, `robots.txt`, link canonical, Open Graph e tags do Twitter.
8. Enviar o sitemap no Search Console.
9. Pedir ao Claude que otimize o título, a descrição e as palavras-chave de cada página e gerar favicons em vários tamanhos com ferramentas de linha de comando no Mac.

## Para quem é este guia

Este guia é para quem concluiu o guia anterior: você tem um projeto Astro em um repositório do GitHub, que é implantado automaticamente a cada push para `main`, e um domínio público. Você não precisa ter experiência com ferramentas de análise, mas precisa conseguir colar prompts curtos no Claude Code e clicar em algumas páginas do Google.

## Pré-requisitos

- Um site Astro já no ar, com seu domínio personalizado funcionando, criado no guia anterior. Este texto chama o repositório de `my-astro-site` e o domínio de `example.com`. Substitua pelos seus.
- Uma conta Google.
- O Claude Code instalado e conectado, e o `gh` conectado (`gh auth status`).
- Acesso para alterar o DNS do domínio. Se o domínio estiver na Cloudflare, você já tem esse acesso.

## Etapa 1: criar a propriedade no Google Analytics e obter o ID de medição

O Google Analytics 4 (GA4) tem esta estrutura: uma conta contém uma ou mais propriedades, e cada propriedade contém fluxos de dados. Um site corresponde a um fluxo de dados da Web, e esse fluxo tem um ID de medição que começa com `G-`.

1. Abra [analytics.google.com](https://analytics.google.com) e entre com sua conta Google.
2. Clique em **Começar a medir** (se você já usa o Analytics, escolha **Administrador → Criar → Conta**). Dê um nome à conta, por exemplo `My sites`.
3. Crie a propriedade. Use o nome do site, escolha o fuso horário e a moeda dos relatórios e responda às perguntas sobre seus objetivos de negócio.
4. Ao escolher a plataforma, selecione **Web**.
5. Informe o endereço do site (`https://example.com`) e um nome para o fluxo de dados, e mantenha a **Medição avançada** ativada. Ela registra visualizações de página, rolagem, cliques em links externos e downloads de arquivos sem nenhum código.
6. Crie o fluxo de dados. O Google mostrará os detalhes do fluxo, incluindo o **ID de medição**.

Copie o ID de medição, que tem a forma `G-ABCD123456`. Depois, você pode encontrá-lo novamente em **Administrador → Coleta e modificação de dados → Fluxos de dados → seu fluxo**.

O ID de medição não é segredo. Ele aparece no código-fonte de cada página que o utiliza, então pode ser versionado no repositório sem problema.

Verificação: você tem um ID de medição que começa com `G-`.

## Etapa 2: pedir ao Claude que adicione o Google Analytics

Abra o Claude na pasta do projeto:

```bash
cd ~/Sites/my-astro-site
claude
```

Em seguida, descreva a tarefa completa em um único pedido, incluindo o push e a verificação. Quanto mais precisa for a descrição do estado final, menos correções você terá de fazer depois.

```text
Adicione o Google Analytics 4 a este site Astro. O ID de medição é G-ABCD123456.

Requisitos:
- Coloque o carregador gtag.js e a chamada config no <head> do layout compartilhado, para que cada página tenha exatamente uma cópia.
- Use um script inline simples (is:inline), para que window.gtag seja uma função global de verdade. O Astro empacota <script> comuns como módulos, e isso deixaria o gtag inacessível para o código posterior.
- Renderize a tag apenas no build de produção, e não em `npm run dev`.
- Leia o ID de medição de uma constante ou variável de ambiente, sem copiá-lo em vários lugares.
- Execute `npm run build` e confirme que dist/index.html contém a tag.

Quando o build passar, faça commit com uma mensagem clara e envie para main. Depois aguarde a conclusão das duas implantações: o workflow do GitHub Pages e o build da Cloudflare. Por fim, use curl em https://example.com/ e confirme que o HTML publicado contém o ID de medição. Informe o que você verificou.
```

O trecho gerado pelo Claude no layout deve ser parecido com este:

```astro
---
const GA_ID = 'G-ABCD123456';
const isProd = import.meta.env.PROD;
---
<head>
  {isProd && (
    <>
      <script is:inline async src={`https://www.googletagmanager.com/gtag/js?id=${GA_ID}`}></script>
      <script is:inline define:vars={{ GA_ID }}>
        window.dataLayer = window.dataLayer || [];
        window.gtag = function () { dataLayer.push(arguments); };
        gtag('js', new Date());
        gtag('config', GA_ID);
      </script>
    </>
  )}
</head>
```

Há dois detalhes importantes, porque são a causa mais comum de "adicionei a tag e nada acontece".

- **`window.gtag` precisa ser uma função global.** Se o script ficar dentro de uma closure, as visualizações de página podem continuar funcionando, mas `window.gtag` ficará indefinido. Todos os eventos personalizados que você adicionar na etapa 6 falharão silenciosamente. Atribuir `window.gtag` explicitamente evita esse problema.
- **Ative apenas em produção.** Se a tag também rodar em `localhost`, seus próprios cliques durante o desenvolvimento vão poluir os dados.

Enquanto espera a implantação, o Claude vai usar comandos parecidos com estes:

```bash
gh run watch
curl -s https://example.com/ | grep -o 'googletagmanager.com/gtag/js?id=G-[A-Z0-9]*'
```

`gh run watch` acompanha a execução do GitHub Actions até o fim. A linha com `curl` só produz saída quando a página publicada realmente contém o endereço do carregador.

Verificação: o relatório do Claude mostra que as duas plataformas foram implantadas com sucesso e que o ID de medição foi encontrado no HTML publicado. Se o `curl` não produzir saída, a implantação ainda não terminou ou o cache está servindo uma página antiga. Peça ao Claude que tente novamente em um minuto e limpe o cache da Cloudflare se a página antiga continuar aparecendo.

## Etapa 3: confirmar no Google Analytics que o site está no ar

Agora, confirme pelo lado do Google, e não apenas pelo seu.

1. No navegador, abra `https://example.com`. Se você usa bloqueador de anúncios ou navegador focado em privacidade, desative-os durante esta verificação, porque eles bloqueiam o Google Analytics.
2. No Google Analytics, abra **Relatórios → Tempo real**.
3. Em cerca de um minuto, você deve ver **1 usuário nos últimos 30 minutos** e o evento `page_view` na lista de eventos.
4. Abra duas ou três páginas. Os títulos delas aparecerão na visualização em tempo real.

Você também pode abrir **Administrador → Fluxos de dados → seu fluxo**. Um visto verde com a mensagem de que os dados estão chegando indica que o fluxo está recebendo tráfego.

Verificação: sua própria visita aparece em **Tempo real**. Relatórios padrão, como **Aquisição**, têm atraso de algumas horas a um dia, então não se preocupe se eles ainda estiverem vazios.

## Etapa 4: cadastrar o site no Google Search Console

O Google Analytics mostra o que os visitantes fazem depois de chegar ao site. O Google Search Console mostra como o Google enxerga o seu site: quais termos de busca trazem visitantes, quais páginas estão indexadas e quais erros o Google encontrou.

1. Abra [search.google.com/search-console](https://search.google.com/search-console) e entre com a mesma conta Google que você usou no Analytics. Usar a mesma conta facilita a vinculação na etapa 5.
2. Clique em **Adicionar propriedade**. Há dois tipos.
   - **Domínio** cobre `example.com` e todos os subdomínios e protocolos. Exige um registro DNS.
   - **Prefixo do URL** cobre um endereço exato, como `https://example.com/`, e oferece vários métodos de verificação.
3. Se o seu DNS estiver na Cloudflare, escolha **Domínio** e informe `example.com`.
4. O Search Console mostrará um registro `TXT`. Copie o valor, que começa com `google-site-verification=`.
5. No painel da Cloudflare, abra seu domínio e vá em **DNS → Registros → Adicionar registro**. Escolha o tipo `TXT`, use `@` como nome, cole o valor no conteúdo e salve.
6. Volte ao Search Console e clique em **Verificar**. As alterações de DNS costumam valer em alguns minutos, mas podem demorar mais. Se a verificação falhar, aguarde um pouco e clique em **Verificar** de novo.

Se você escolheu o tipo **Prefixo do URL**, a forma mais simples é verificar pelo Google Analytics: desde que use a mesma conta Google, o Search Console pode usar a tag que você instalou na etapa 2 como prova de propriedade.

Verificação: o Search Console mostra "Propriedade verificada" e abre a página de visão geral do recurso. Durante um tempo, ele pode exibir "Sem dados", o que é normal.

## Etapa 5: vincular o Search Console ao Google Analytics

Depois do vínculo, os dados de termos de busca e de páginas de entrada passam a aparecer nos relatórios do Analytics. Assim, você pode comparar o tráfego vindo da busca com o comportamento desses visitantes.

1. No Google Analytics, abra **Administrador**.
2. Em **Associações de produtos**, escolha **Associação do Search Console**.
3. Clique em **Associar**, depois em **Escolher contas** e selecione seu recurso do Search Console. Você precisa ser proprietário desse recurso e editor da propriedade do Analytics.
4. Clique em **Próximo**, escolha o fluxo de dados da Web e clique em **Enviar**.

Os dados do Search Console levam alguns dias para começar a chegar e têm atraso de cerca de dois dias. Não há nada a fazer enquanto isso, então siga para a próxima etapa.

Depois que a associação for criada, os relatórios relacionados ficam em **Relatórios → Biblioteca**. Os relatórios do Search Console não entram automaticamente no menu lateral. Para que apareçam no menu, publique a coleção **Search Console** na biblioteca.

Verificação: em **Administrador → Associações de produtos → Associação do Search Console**, seu recurso aparece na lista.

## Etapa 6: adicionar rastreamento de eventos adequado ao seu site

A medição avançada já registra visualizações de página, rolagem, cliques em links externos, buscas no site e downloads de arquivos, então não os implemente de novo. Os eventos servem para o que é específico do seu negócio: cliques na principal chamada para ação, inscrição em newsletter, formulário de contato e visualizações da página de preços.

A instrução mais útil não é "adicione alguns eventos", e sim "primeiro analise meu site, proponha um plano de eventos e espere minha aprovação". Assim, você continua no controle do que é medido.

```text
Analise a estrutura deste site Astro: páginas, layouts, componentes, chamadas para ação, formulários e links externos.

Etapa 1: antes de alterar qualquer código, proponha um plano de eventos. Mostre uma tabela com: nome do evento, momento em que é disparado, parâmetros e a pergunta de negócio que ele responde. Prefira os nomes de eventos recomendados do GA4 quando fizerem sentido (por exemplo generate_lead, sign_up, select_content); caso contrário, use nomes personalizados em snake_case. Não repita o que a medição avançada já registra: visualizações de página, rolagem, cliques em links externos e downloads de arquivos. No máximo 10 eventos.

Etapa 2: depois da minha aprovação, implemente o plano:
- Marque os elementos com os atributos data-ga-event, data-ga-label e data-ga-location.
- Use um único ouvinte de clique delegado no document, que leia esses atributos e chame gtag('event', ...). Não adicione manipuladores onclick inline.
- Nos parâmetros, envie somente IDs estáveis e a localização. Nunca envie o texto do link, dados digitados em formulários, endereços de e-mail ou qualquer informação que identifique o visitante.
- Não atrase nem cancele a navegação da página.

Etapa 3: execute o build, faça commit, envie para main, aguarde a conclusão das duas implantações e use curl para confirmar que o site publicado contém o script do ouvinte. Depois me diga quais locais devo clicar para verificar os eventos no DebugView do GA4.
```

O Claude vai primeiro responder com uma tabela. Para um site pequeno, um plano razoável seria parecido com este:

| Evento | Quando é disparado | Parâmetros | Pergunta que responde |
| --- | --- | --- | --- |
| `cta_click` | O visitante clica no botão principal de chamada para ação | `label`, `location` | Quais botões e áreas da página levam à ação? |
| `generate_lead` | O formulário de contato é enviado com sucesso | `form_id` | Quantos visitantes se tornam contatos? |
| `nav_click` | Clique em um link do cabeçalho ou do rodapé | `label`, `location` | Quais itens de navegação são usados? |
| `theme_toggle` | Uso do alternador de tema | `value` | Vale manter o alternador de modo escuro? |

Leia essa tabela com senso crítico. Remova eventos que ninguém vai analisar e renomeie eventos nomeados pela função técnica, e não pela decisão que ajudam a tomar. Depois responda algo como "aprovado, mas remova `theme_toggle`" para o Claude implementar.

O ouvinte escrito pelo Claude fica mais ou menos assim:

```js
document.addEventListener(
  'click',
  (event) => {
    const el = event.target.closest('[data-ga-event]');
    if (!el || typeof window.gtag !== 'function') return;
    window.gtag('event', el.dataset.gaEvent, {
      label: el.dataset.gaLabel,
      location: el.dataset.gaLocation,
      transport_type: 'beacon',
    });
  },
  true,
);
```

Botão marcado:

```astro
<a href="/contact" data-ga-event="cta_click" data-ga-label="hero_contact" data-ga-location="home_hero">
  Fale conosco
</a>
```

### Verificar os eventos

1. No Google Analytics, abra **Administrador → Exibição de dados → DebugView**. O DebugView mostra os eventos recebidos em alguns segundos.
2. Para colocar o navegador em modo de depuração, instale a extensão do Chrome **Google Analytics Debugger** ou peça ao Claude que adicione `debug_mode: true` temporariamente à chamada `config`.
3. Acesse o site publicado e execute os cliques que o Claude listou.
4. Cada clique deve aparecer como um evento na linha do tempo do DebugView, com os parâmetros esperados.

Depois que um evento chega pelo menos uma vez, ele também aparece em **Administrador → Exibição de dados → Eventos**. Para usar `label` ou `location` nos relatórios padrão, registre-os em **Administrador → Exibição de dados → Definições personalizadas → Criar definição personalizada** com o escopo **Evento**. Somente parâmetros registrados dessa forma aparecem nos relatórios padrão.

Remova todas as configurações temporárias de `debug_mode` e peça ao Claude para enviar a versão limpa.

Verificação: cada clique rastreado aparece no DebugView com o nome e os parâmetros corretos, e o código final já está em `main`.

## Etapa 7: adicionar a camada básica de SEO

Os buscadores precisam de um mapa das páginas, de instruções sobre o que podem rastrear e de uma descrição que as pessoas veem quando o site é compartilhado. O primeiro item tem integração oficial no Astro, e o restante são algumas linhas no layout. O Claude pode adicionar os componentes e as integrações do Astro necessários de forma rápida.

```text
Adicione SEO básico a este site Astro.

1. Sitemap: instale a integração oficial @astrojs/sitemap com `npx astro add sitemap`. Confirme que `site` em astro.config.mjs é o domínio de produção https://example.com e remova o `base` que restou da hospedagem de projeto do GitHub Pages.
2. robots.txt: crie src/pages/robots.txt.ts, que retorne "User-agent: *", "Allow: /" e uma linha Sitemap apontando para https://example.com/sitemap-index.xml. Esse endereço deve ser gerado a partir da configuração `site`, e não escrito de forma fixa.
3. Um componente de SEO reutilizável para o layout compartilhado, que gere: <title>; meta description; link canonical gerado a partir da URL atual e de `site`; tags Open Graph (og:type, og:title, og:description, og:url, og:image, og:site_name, og:locale); tags de cartão do Twitter (twitter:card summary_large_image, twitter:title, twitter:description, twitter:image); e a meta tag theme-color. Cada página deve passar seu próprio título e descrição por props.
4. Uma imagem padrão de compartilhamento social de 1200x630 em public/og-default.png, usada quando a página não fornecer uma.
5. Dados estruturados JSON-LD do tipo WebSite para o site inteiro e, se houver blog, do tipo Article para os artigos.
6. Execute `npm run build`, liste dist/sitemap-index.xml, mostre dist/robots.txt e confirme que o HTML gerado da página inicial contém todas as tags acima.

Quando tudo estiver correto, faça commit, envie, aguarde a conclusão das duas implantações e use curl para confirmar que https://example.com/sitemap-index.xml e https://example.com/robots.txt retornam 200 com o conteúdo esperado.
```

O que cada parte faz:

- **Sitemap.** O `@astrojs/sitemap` gera `sitemap-index.xml` e um ou mais arquivos `sitemap-0.xml` durante o build. Para criar URLs absolutas, ele precisa da configuração `site`.
- **`robots.txt`.** Ele informa aos rastreadores o que podem acessar e onde está o sitemap. Para impedir que uma página seja indexada, use `noindex`. Colocá-la apenas no `robots.txt` não basta.
- **Link canonical.** Quando a mesma página pode ser acessada por mais de um endereço, ele indica ao Google qual é o endereço oficial.
- **Tags Open Graph e Twitter.** Elas determinam o título, a descrição e a imagem exibidos quando um link é compartilhado em redes sociais ou aplicativos de mensagem.
- **JSON-LD.** Os dados estruturados ajudam os buscadores a entender do que se trata a página. Eles não garantem resultados enriquecidos, mas custam pouco para adicionar.

Verificação: o `sitemap-index.xml` publicado lista suas páginas, o `robots.txt` contém a linha `Sitemap:`, e o código-fonte das páginas mostra as tags canonical, Open Graph e Twitter. Você também pode colar a URL em uma ferramenta de validação de cartões sociais ou compartilhá-la em um aplicativo de mensagens para ver a prévia.

## Etapa 8: enviar o sitemap no Search Console

O Search Console não sabe que o sitemap existe até você informá-lo.

1. No Search Console, abra seu recurso e escolha **Sitemaps** no menu lateral.
2. Em **Adicionar um novo sitemap**, digite `sitemap-index.xml`.
3. Clique em **Enviar**.
4. O status deve mudar para **Sucesso** e mostrar o número de páginas descobertas. Se aparecer **Não foi possível buscar**, abra primeiro o endereço do sitemap no navegador. Se ele abrir, aguarde alguns minutos e atualize, porque a primeira busca pode demorar.

Em seguida, peça ao Google que examine suas páginas mais importantes agora:

1. Cole a URL da página inicial na barra de pesquisa no topo do Search Console.
2. Se a página ainda não estiver indexada, clique em **Solicitar indexação**.

A indexação ainda leva alguns dias, e os relatórios do Search Console têm atraso. Volte para conferir uma semana depois.

Verificação: **Sitemaps** lista `sitemap-index.xml` com o status **Sucesso**.

## Etapa 9: otimizar os metadados de cada página e adicionar favicons em vários tamanhos

A camada básica fornece metadados genéricos para cada página. Título e descrição são o texto que as pessoas leem nos resultados de busca, então vale ajustá-los página por página. O favicon precisa de vários tamanhos, porque navegadores, celulares e favoritos pedem arquivos diferentes.

### Títulos, descrições e palavras-chave

```text
Revise cada página deste site e otimize os metadados de busca.

Para cada página, mostre uma tabela com antes e depois de título, meta description e palavras-chave, e depois aplique as mudanças. Regras:
- Título: exclusivo em cada página, com no máximo cerca de 60 caracteres, com o tema principal no início e o nome do site no final.
- Descrição: exclusiva em cada página, entre 120 e 160 caracteres, em uma frase clara que explique o que o visitante vai encontrar e convide ao clique. Não encha de palavras-chave nem copie texto entre páginas.
- Palavras-chave: 5 a 8 termos extraídos do conteúdo real da página. Mantenha a meta tag keywords somente se o layout já a suportar, e não invente temas que a página não aborda.
- Confirme que cada página tem exatamente um <h1> compatível com o título e que todas as imagens têm atributo alt.

Depois execute o build e escreva um relatório curto listando as páginas que ainda compartilham título ou descrição com outras.
```

Vale ajustar as expectativas: os buscadores ignoram em grande parte a meta tag keywords. As palavras-chave ajudam você, porque escrevê-las obriga a deixar claro o assunto de cada página. O que realmente aparece nos resultados de busca são o título e a descrição.

### Favicons em vários tamanhos

Um `favicon.svg` é um bom começo, mas alguns lugares exigem arquivos específicos: navegadores antigos e favoritos usam `favicon.ico`, a tela inicial do iOS usa `apple-touch-icon`, e o Android e o manifesto de aplicativos Web usam PNGs de 192 e 512 pixels.

O macOS já inclui o `sips`, que redimensiona PNGs. Para gerar `.ico`, você precisa do ImageMagick, que pode ser instalado pelo Homebrew. Peça ao Claude que use essas ferramentas diretamente no seu Mac:

```text
Gere um conjunto completo de favicons a partir da minha imagem de origem public/logo-source.png (PNG quadrado de pelo menos 512x512).

1. Use o comando `sips` do macOS para criar public/icon-192.png, public/icon-512.png e public/apple-touch-icon.png (180x180).
2. Se o ImageMagick não estiver instalado, instale com `brew install imagemagick`. Use `magick` para gerar public/favicon.ico com imagens de 16x16, 32x32 e 48x48.
3. Se eu já tiver public/favicon.svg, mantenha-o. Se não tiver, crie uma versão simples que combine com o logo.
4. Adicione public/site.webmanifest listando icon-192.png e icon-512.png.
5. Atualize o <head> do layout com as tags <link> correspondentes: ícone SVG, fallback .ico, apple-touch-icon e manifesto.
6. Execute `file` em cada imagem gerada para confirmar as dimensões reais, execute o build e confirme que esses arquivos aparecem em dist/.
```

O Claude vai executar comandos parecidos com estes:

```bash
sips -z 192 192 public/logo-source.png --out public/icon-192.png
sips -z 512 512 public/logo-source.png --out public/icon-512.png
sips -z 180 180 public/logo-source.png --out public/apple-touch-icon.png
brew install imagemagick
magick public/logo-source.png -define icon:auto-resize=48,32,16 public/favicon.ico
file public/*.png public/favicon.ico
```

Os links no head ficam assim:

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="icon" href="/favicon.ico" sizes="48x48" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<link rel="manifest" href="/site.webmanifest" />
```

Por fim, feche o ciclo como nas etapas anteriores:

```text
Faça commit de todas as mudanças com uma mensagem clara, envie para main, aguarde a conclusão das duas implantações e use curl para confirmar que /favicon.ico, /apple-touch-icon.png e /site.webmanifest retornam 200 no site publicado.
```

## Problemas comuns

- **O relatório em tempo real não mostra nada.** Um bloqueador de anúncios ou um navegador focado em privacidade está bloqueando a tag. Teste em uma janela privada com as extensões desativadas e confirme que o ID de medição está no HTML publicado.
- **As visualizações de página funcionam, mas os eventos personalizados não.** No site publicado, abra o console do navegador e execute `typeof window.gtag`. O resultado precisa ser `function`. Se for `undefined`, o script da tag foi empacotado como módulo. Peça ao Claude para usar `is:inline` e atribuir `window.gtag` explicitamente.
- **Os eventos aparecem no DebugView, mas não nos relatórios.** Os relatórios padrão têm atraso de até um dia, e parâmetros personalizados só aparecem depois de registrados como definições personalizadas.
- **O Search Console não consegue verificar o domínio.** Confira se o registro `TXT` está no domínio raiz (`@`), se o valor foi copiado por completo e se o proxy da Cloudflare não está ativado para ele (registros TXT não passam pelo proxy). Depois aguarde e tente de novo.
- **O sitemap mostra "Não foi possível buscar".** Abra `https://example.com/sitemap-index.xml` no navegador. Se retornar 404, verifique se `site` em `astro.config.mjs` é o domínio de produção e se a integração do sitemap está listada em `integrations`.
- **A prévia social está desatualizada.** As plataformas guardam prévias em cache. Depois de alterar as tags, use as ferramentas de depuração delas para atualizar o cache.

## Privacidade e consentimento

A análise coleta dados dos visitantes. Dependendo da região de onde eles acessam, você pode precisar obter consentimento antes de carregar o Google Analytics, como exigem as regras do GDPR e da ePrivacy na União Europeia, e pode precisar mencionar isso na sua política de privacidade. Para manter o guia simples, a tag foi instalada sem condições. Se o seu site recebe visitantes de regiões que exigem consentimento, peça ao Claude que adicione um banner de consentimento e carregue a tag apenas depois que o visitante aceitar. Estas são informações gerais, não aconselhamento jurídico.

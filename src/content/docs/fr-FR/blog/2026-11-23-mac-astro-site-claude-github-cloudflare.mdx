Ce guide vous mène d'un Mac vierge à un site web en ligne sur Internet. Vous travaillerez à deux endroits : dans votre Terminal, où vous installez les outils, et dans Claude Code, qui exécute à votre place les commandes répétitives et modifie les fichiers à votre place. Chaque étape se termine par un élément que vous pouvez vérifier, afin de savoir que tout a fonctionné avant de passer à la suite.

Le parcours complet ressemble à ceci :

1. Installer Node.js.
2. Installer GitHub CLI (`gh`) et vous connecter.
3. Demander à Claude de créer un dépôt privé et de le cloner.
4. Demander à Claude de générer un site Astro avec un en-tête, un pied de page et une mise en page adaptative, puis de l'enregistrer (commit) et de l'envoyer (push).
5. Installer la compétence impeccable et utiliser sa commande `overdrive` pour peaufiner la page d'accueil.
6. Publier le site sur GitHub Pages avec un workflow GitHub Actions.
7. Connecter un domaine dans Cloudflare et déployer la même branche avec Workers.
8. Ajouter une nouvelle page, l'envoyer et suivre la fin des deux déploiements.

## À qui s'adresse ce guide

Ce guide s'adresse aux personnes qui possèdent un Mac et un compte GitHub, et qui souhaitent publier un site web statique simple sans mettre en place de serveur. Vous n'avez pas besoin de connaître Astro, GitHub Actions ou Cloudflare au préalable. Il vous faut en revanche être à l'aise pour ouvrir le Terminal et coller des commandes.

## Prérequis

- Un Mac équipé d'une version récente de macOS.
- Un compte GitHub.
- Un compte Cloudflare.
- Un nom de domaine. Vous pouvez en enregistrer un via Cloudflare ou utiliser un domaine que vous possédez déjà.
- Claude Code installé et connecté. Lancez `claude` une fois dans le Terminal pour vérifier qu'il démarre.

## Étape 1 : installer Node.js

Astro et le programme d'installation d'impeccable fonctionnent tous deux avec Node.js. Utilisez la version LTS actuelle.

La méthode la plus simple consiste à utiliser le programme d'installation officiel disponible sur [nodejs.org](https://nodejs.org). Téléchargez le paquet macOS, lancez-le et acceptez les options par défaut.

Si vous utilisez déjà Homebrew, vous pouvez l'installer depuis le Terminal à la place :

```bash
brew install node
```

Ouvrez une nouvelle fenêtre du Terminal et vérifiez les deux outils :

```bash
node --version
npm --version
```

Les deux commandes doivent afficher un numéro de version. Si `node` est introuvable, fermez puis rouvrez le Terminal afin que le nouveau `PATH` soit chargé.

## Étape 2 : installer GitHub CLI et vous connecter

GitHub CLI, appelé `gh`, permet à Claude de créer des dépôts et de les gérer sans que vous ayez à cliquer sur le site web.

```bash
brew install gh
gh --version
```

Connectez-vous ensuite :

```bash
gh auth login
```

Répondez aux questions comme ceci :

- **Où utilisez-vous GitHub ?** (Where do you use GitHub?) `GitHub.com`
- **Quel protocole préférez-vous ?** (Preferred protocol?) `HTTPS`
- **Authentifier Git avec vos identifiants GitHub ?** (Authenticate Git with your GitHub credentials?) `Yes`
- **Comment souhaitez-vous vous authentifier ?** (How would you like to authenticate?) `Login with a web browser`

Copiez le code à usage unique affiché par le Terminal, appuyez sur Entrée et terminez la connexion dans votre navigateur. Une fois fait, vérifiez le résultat :

```bash
gh auth status
```

La sortie doit indiquer que vous êtes connecté à `github.com`.

## Étape 3 : demander à Claude de créer un dépôt privé

Choisissez un dossier où vous voulez ranger vos projets, par exemple `~/Sites`, et créez-le s'il n'existe pas :

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

Donnez ensuite à Claude une demande de ce type :

```text
Utilisez GitHub CLI pour créer un dépôt privé nommé my-astro-site sur votre compte GitHub.
Initialisez-le avec un README afin que la branche main existe, puis clonez-le dans ce dossier.
Montrez-moi l'URL du dépôt une fois terminé.
```

Claude devrait exécuter une commande équivalente à :

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

Une fois terminé, vous devriez avoir un dossier `~/Sites/my-astro-site` contenant un `README.md`, et le dépôt doit être privé sur GitHub. Vérifiez la branche par défaut :

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

Elle doit afficher `main`.

## Étape 4 : générer le site Astro

Restez dans le dossier du dépôt et lancez Claude depuis celui-ci :

```bash
cd ~/Sites/my-astro-site
claude
```

Demandez à Claude de créer un site de base :

```text
Créez un site web Astro de base dans ce dépôt en utilisant le starter officiel basics d'Astro.
Ajoutez un en-tête de site avec le nom du site et des liens de navigation, un pied de page avec un texte de droit d'auteur,
et une mise en page qui fonctionne sur les téléphones, les tablettes et les grands écrans de bureau.
Gardez un design simple. Lancez le serveur de développement, vérifiez la page et indiquez-moi comment la consulter.
```

Une fois que Claude a terminé, ouvrez vous-même l'aperçu local :

```bash
npm install
npm run dev
```

Astro affiche une adresse locale, en général `http://localhost:4321`. Ouvrez-la dans votre navigateur, redimensionnez la fenêtre pour vérifier la mise en page, puis arrêtez le serveur avec `Control+C`.

Avant d'enregistrer, vérifiez que la version de production se compile correctement :

```bash
npm run build
```

### Enregistrer et envoyer la première version

Demandez à Claude d'enregistrer le travail :

```text
Enregistrez le site Astro avec un message de commit clair, puis envoyez-le sur la branche main de origin.
```

Claude devrait exécuter des commandes telles que :

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

Vérifiez sur GitHub que votre dernier commit apparaît sur la branche `main` du dépôt.

## Étape 5 : installer impeccable et appliquer overdrive à la page d'accueil

[impeccable](https://impeccable.style) est une compétence de conception pour les agents de programmation. Elle donne à Claude un vocabulaire commun pour le travail de design, avec des termes comme `polish`, `critique` et `overdrive`. La commande `overdrive` ajoute des effets plus audacieux et expressifs, comme des shaders, une physique à ressorts et des animations pilotées par le défilement.

Demandez à Claude d'installer la compétence pour ce projet :

```text
Installez la compétence impeccable dans ce projet à l'aide de son programme d'installation officiel.
Utilisez la portée projet et le fournisseur Claude Code. Dites-moi quand je dois redémarrer Claude Code.
```

Claude devrait exécuter cette commande depuis la racine du projet :

```bash
npx impeccable install
```

Le programme d'installation demande s'il faut installer pour ce projet ou globalement, et propose un hook de design. Acceptez le hook, puis redémarrez Claude Code pour que la nouvelle compétence soit chargée.

Dans la session redémarrée, initialisez le contexte de design :

```text
/impeccable init
```

Appliquez ensuite la passe overdrive à la page d'accueil :

```text
/impeccable overdrive la page d'accueil
```

Relisez les modifications de Claude avant d'enregistrer. Overdrive peut ajouter beaucoup de mouvement : vous voudrez peut-être ne garder que les effets qui aident le lecteur à comprendre la page. Demandez à Claude de relancer la compilation et d'envoyer le résultat :

```text
Lancez npm run build, corrigez les erreurs éventuelles, puis enregistrez les modifications overdrive et envoyez-les sur main.
```

## Étape 6 : publier sur GitHub Pages avec GitHub Actions

GitHub Pages peut héberger gratuitement le site compilé. Astro fournit une action GitHub officielle qui compile le site et le déploie.

### Activer Pages

Ouvrez votre dépôt sur GitHub, puis allez dans **Paramètres (Settings) → Pages**. Sous **Compilation et déploiement (Build and deployment)**, réglez **Source** sur **GitHub Actions**.

### Demander à Claude d'ajouter le workflow

```text
Ajoutez un workflow GitHub Actions dans .github/workflows/deploy.yml qui utilise actions/checkout
et withastro/action pour compiler ce site Astro et le déployer sur GitHub Pages.
Conservez le bloc permissions que le modèle d'Astro inclut.
```

Le workflow créé par Claude ressemblera à l'exemple documenté par Astro :

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### Définir l'adresse du site

GitHub Pages sert un site de projet sous un chemin, par exemple `https://<your-username>.github.io/my-astro-site`. Astro doit connaître ce chemin, sinon ses liens et ses ressources ne fonctionneront plus. Demandez à Claude de mettre à jour `astro.config.mjs` :

```text
Définissez site sur https://<your-username>.github.io et base sur /my-astro-site dans astro.config.mjs.
Expliquez-moi ce que fait chaque réglage.
```

Le résultat doit ressembler à ceci :

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

Remplacez `<your-username>` par votre nom d'utilisateur GitHub. Plus tard, lorsque vous passerez à votre propre domaine, vous supprimerez `base`.

Enregistrez et envoyez le workflow et la modification de la configuration :

```text
Enregistrez le workflow Pages et la modification de la configuration Astro, puis envoyez le tout sur main.
```

### Attendre le premier déploiement

Ouvrez l'onglet **Actions** de votre dépôt. L'exécution `Deploy to GitHub Pages` doit passer au vert après une minute ou deux. Ouvrez ensuite l'adresse Pages affichée sous **Paramètres → Pages**.

## Étape 7 : connecter un domaine dans Cloudflare

Il vous faut un domaine pour cette étape. Il existe deux options courantes :

- **Enregistrer un nouveau domaine** via Cloudflare Registrar depuis le tableau de bord Cloudflare.
- **Utiliser un domaine que vous possédez déjà.** Ajoutez-le à Cloudflare comme site, puis remplacez les serveurs de noms du domaine chez votre registraire par les deux serveurs de noms que Cloudflare vous indique.

Connectez-vous au [tableau de bord Cloudflare](https://dash.cloudflare.com), puis enregistrez le domaine ou ajoutez votre domaine existant. Attendez que Cloudflare affiche le domaine comme actif. Cela peut prendre quelques minutes après un changement de serveurs de noms.

## Étape 8 : créer un projet Worker à partir de la branche GitHub

La documentation actuelle de Cloudflare pour Astro utilise Workers. Dans le tableau de bord, le flux Git de type Pages apparaît toujours sous la même section **Workers & Pages**, mais les étapes ci-dessous suivent la voie Workers.

D'abord, demandez à Claude d'ajouter une configuration Wrangler pour un site Astro statique. Wrangler est l'outil en ligne de commande de Cloudflare.

```text
Ajoutez un fichier wrangler.jsonc à la racine du projet pour un site Astro statique.
Définissez le name sur my-astro-site, définissez compatibility_date sur la date du jour,
et servez le dossier ./dist comme ressources statiques. N'ajoutez pas de point d'entrée main.
```

Il doit ressembler à ceci :

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

Enregistrez et envoyez le fichier. Créez ensuite le projet Cloudflare :

1. Dans le tableau de bord Cloudflare, allez dans **Workers & Pages**.
2. Sélectionnez **Créer une application (Create application)**, puis choisissez l'option d'importer un dépôt depuis GitHub.
3. Autorisez l'application GitHub **Cloudflare Workers & Pages** lorsque Cloudflare le demande. Choisissez soit tous les dépôts, soit uniquement `my-astro-site`.
4. Sélectionnez `my-astro-site` et la branche `main`.
5. Définissez la commande de compilation sur `npm run build` (ou `npx astro build`) et la commande de déploiement sur `npx wrangler deploy`.
6. Lancez le déploiement.

Cloudflare compile le site à chaque envoi vers la branche connectée, donc les prochains commits se déploieront automatiquement.

### Associer votre domaine

Ouvrez le nouveau Worker dans le tableau de bord, allez dans **Domaines et routes (Domains & Routes)**, puis ajoutez votre domaine ou un sous-domaine comme `www`. Cloudflare crée l'enregistrement DNS pour vous lorsque le domaine se trouve déjà dans le même compte.

## Étape 9 : vérifier le site dans Cloudflare

Une fois la première compilation terminée, consultez ces emplacements dans le tableau de bord Cloudflare :

- **Déploiements (Deployments) :** la dernière compilation doit être marquée comme réussie. En cas d'échec, ouvrez le journal de compilation et lisez la première erreur.
- **Domaines et routes :** votre domaine personnalisé doit apparaître comme actif.
- **Paramètres (Settings) :** vérifiez que le dépôt et la branche connectés sont bien ceux que vous attendez.

Ouvrez ensuite votre domaine dans un navigateur. Vérifiez l'en-tête, le pied de page et la mise en page sur votre téléphone, ainsi que dans une fenêtre de bureau large.

## Étape 10 : ajouter une nouvelle page et suivre sa mise en ligne

Vous disposez maintenant de la boucle complète : modifier en local, envoyer sur GitHub, puis laisser les hébergeurs compiler et déployer le changement.

Lancez Claude dans le dossier du projet et demandez une nouvelle page :

```text
Créez une nouvelle page dans src/pages/about.astro avec un titre, un court paragraphe et un lien de retour vers la page d'accueil.
Utilisez le même en-tête et le même pied de page que les autres pages. Lancez npm run build, puis enregistrez et envoyez sur main.
```

Claude doit créer le fichier, compiler le site, enregistrer et envoyer. Suivez ensuite les deux déploiements :

- **GitHub :** ouvrez l'onglet **Actions**. Le workflow Pages s'exécute à nouveau.
- **Cloudflare :** ouvrez **Workers & Pages → votre projet → Déploiements (Deployments)**. Une nouvelle compilation démarre automatiquement.

Lorsque les deux affichent un succès, ouvrez `https://<your-domain>/about` dans votre navigateur. Si la page est introuvable, vérifiez que le fichier se trouve bien dans `src/pages/about.astro`, que le dernier déploiement est terminé, et que votre navigateur n'affiche pas une ancienne copie en cache.

## Problèmes fréquents

- **`node: command not found` :** ouvrez une nouvelle fenêtre du Terminal après avoir installé Node.js.
- **`gh` ne parvient pas à créer le dépôt :** exécutez `gh auth status` et vérifiez que la connexion a accès à votre compte.
- **GitHub Pages affiche une page blanche ou des styles manquants :** vérifiez `site` et `base` dans `astro.config.mjs`. La valeur de `base` doit correspondre au nom du dépôt.
- **La compilation Cloudflare échoue :** lisez la première erreur dans le journal de compilation. La plupart des échecs viennent d'un script manquant, d'une mauvaise commande de compilation ou d'un fichier de configuration Wrangler qui pointe vers le mauvais dossier.
- **Le domaine n'est pas actif :** les changements de serveurs de noms peuvent mettre du temps à se propager. Vérifiez l'état sur la page de vue d'ensemble du domaine dans Cloudflare.

## Prochaines étapes

Une fois le site en ligne, vous pouvez garder la même boucle pour du contenu réel. Demandez à Claude d'ajouter des pages, de lancer `/impeccable critique` pour une revue de design, ou d'ajouter un second environnement Cloudflare pour les aperçus. L'habitude principale à garder est simple : faites une petite modification, compilez-la en local, enregistrez-la, puis laissez les hébergeurs la publier.

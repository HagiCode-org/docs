在[上一篇指南](/blog/2026-11-23-mac-astro-site-claude-github-cloudflare/)中，你从一台干净的 Mac 出发，做出了部署在 GitHub Pages 和 Cloudflare 上的 Astro 网站。网站上线只完成了一半：你还需要知道有没有人访问、访客做了什么，以及 Google 能不能找到它。

本指南补上这一层。你会注册 Google Analytics 和 Google Search Console，然后让 Claude 接入追踪、站点地图、社交标签和 favicon。每个步骤结束时都有可以检查的结果，确认后再继续。

完整流程如下：

1. 创建 Google Analytics 属性，并复制它的测量 ID。
2. 让 Claude 为网站接入 Google Analytics、推送、等待部署完成，并证明线上确实存在该代码。
3. 在 Google Analytics 中确认你的访问实时出现。
4. 在 Google Search Console 中注册网站。
5. 把 Search Console 与 Google Analytics 绑定。
6. 让 Claude 设计并添加符合你网站的事件追踪，然后发布并验证。
7. 让 Claude 添加基础 SEO 层：站点地图、`robots.txt`、canonical 链接、Open Graph 和 Twitter 标签。
8. 在 Search Console 中提交站点地图。
9. 让 Claude 优化每个页面的标题、描述和关键词，并使用 Mac 上的命令行工具生成多尺寸 favicon。

## 本指南适合谁

适合完成了上一篇指南的人：你有一个位于 GitHub 仓库中的 Astro 项目，每次推送到 `main` 都会自动部署，并且有一个公开域名。你不需要任何分析工具的使用经验，但需要能把简短的提示词粘贴到 Claude Code 中，并在几个 Google 页面上点击操作。

## 前提条件

- 上一篇指南中已经上线、自定义域名可用的 Astro 网站。本文把仓库称为 `my-astro-site`，把域名称为 `example.com`，请替换成你自己的。
- 一个 Google 账号。
- 已安装并登录的 Claude Code，以及已登录的 `gh`（`gh auth status`）。
- 能够修改域名的 DNS。如果域名在 Cloudflare，你已经具备。

## 步骤 1：创建 Google Analytics 属性并获取测量 ID

Google Analytics 4（GA4）的结构是：账号包含一个或多个属性，属性包含数据流。一个网站对应一个 Web 数据流，数据流有一个以 `G-` 开头的测量 ID。

1. 打开 [analytics.google.com](https://analytics.google.com)，用你的 Google 账号登录。
2. 点击 **开始衡量**（如果你已经在用 Analytics，则选择 **管理 → 创建 → 账号**）。给账号起个名字，例如 `My sites`。
3. 创建属性。用网站名称命名，选择报告时区和货币，并完成后面的业务问题。
4. 选择平台时，选 **Web**。
5. 输入网站地址（`https://example.com`）和数据流名称，保持 **增强型衡量** 开启。它无需任何代码就能记录页面浏览、滚动、出站点击和文件下载。
6. 创建数据流。Google 会显示数据流详情，其中包含 **测量 ID**。

复制测量 ID，它形如 `G-ABCD123456`。之后可以在 **管理 → 数据收集和修改 → 数据流 → 你的数据流** 中再次找到它。

测量 ID 不是机密。每个使用它的网站，其页面源代码里都会直接显示，所以可以放心提交到仓库中。

检查：你已经得到一个以 `G-` 开头的测量 ID。

## 步骤 2：让 Claude 接入 Google Analytics

在项目文件夹中启动 Claude：

```bash
cd ~/Sites/my-astro-site
claude
```

然后用一个请求描述完整的任务，包括推送和验证。你对最终状态描述得越准确，之后需要纠正的就越少。

```text
请为这个 Astro 网站接入 Google Analytics 4，测量 ID 是 G-ABCD123456。

要求：
- 把 gtag.js 加载器和 config 调用放在共享布局的 <head> 中，使每个页面恰好有一份。
- 使用普通的内联脚本（is:inline），让 window.gtag 成为真正的全局函数。Astro 会把普通的 <script> 打包成模块，这会让后续代码访问不到 gtag。
- 只在生产构建中渲染该标签，`npm run dev` 中不渲染。
- 测量 ID 从一个常量或环境变量读取，不要分散地复制多份。
- 运行 `npm run build`，并检查 dist/index.html 中包含该标签。

构建通过后，用清晰的说明提交并推送到 main。然后等待两处部署，即 GitHub Pages 工作流和 Cloudflare 构建，都完成。最后用 curl 获取 https://example.com/，确认线上的 HTML 包含该测量 ID。请汇报你检查了什么。
```

Claude 在布局中生成的片段应该与下面接近：

```astro
---
const GA_ID = 'G-ABCD123456';
const isProd = import.meta.env.PROD;
---
<head>
  {isProd && (
    <>
      <script is:inline async src={`https://www.googletagmanager.com/gtag/js?id=${GA_ID}`}></script>
      <script is:inline define:vars={{ GA_ID }}>
        window.dataLayer = window.dataLayer || [];
        window.gtag = function () { dataLayer.push(arguments); };
        gtag('js', new Date());
        gtag('config', GA_ID);
      </script>
    </>
  )}
</head>
```

有两个细节值得理解，因为它们是“我加了标签却没有反应”最常见的原因。

- **`window.gtag` 必须是全局函数。** 如果脚本被包进闭包，页面浏览可能仍然正常，但 `window.gtag` 是未定义的。步骤 6 中你添加的所有自定义事件都会静默失败。显式地给 `window.gtag` 赋值可以避免这个问题。
- **只在生产环境启用。** 如果标签也在 `localhost` 上运行，你自己开发时的点击会污染数据。

等待部署时，Claude 会用类似下面的命令：

```bash
gh run watch
curl -s https://example.com/ | grep -o 'googletagmanager.com/gtag/js?id=G-[A-Z0-9]*'
```

`gh run watch` 会跟踪 GitHub Actions 的运行直到结束。只有线上页面真的包含加载器地址时，`curl` 那一行才会输出内容。

检查：Claude 的汇报显示两个平台都部署成功，并且在线上 HTML 中找到了测量 ID。如果 `curl` 没有输出，说明部署尚未完成或缓存还在提供旧页面；让 Claude 一分钟后重试，旧页面仍然存在时清除 Cloudflare 缓存。

## 步骤 3：在 Google Analytics 中验证网站在线

现在从 Google 的一侧确认，而不仅仅是你自己这一侧。

1. 在浏览器中打开 `https://example.com`。如果你使用广告拦截器或隐私浏览器，请在这次检查中关闭它们，它们会拦截 Google Analytics。
2. 在 Google Analytics 中打开 **报告 → 实时**。
3. 大约一分钟内，你应该会看到 **过去 30 分钟内有 1 位用户**，事件列表中有 `page_view` 事件。
4. 点开两三个页面，页面标题会出现在实时视图中。

你也可以打开 **管理 → 数据流 → 你的数据流**。出现绿色对勾，并提示数据正在流入，说明数据流正在接收流量。

检查：你自己的访问出现在 **实时** 中。**获取** 等标准报告会滞后几个小时到一天，所以它们仍然为空时不必担心。

## 步骤 4：在 Google Search Console 中注册网站

Google Analytics 告诉你访客到达之后做了什么。Google Search Console 告诉你 Google 如何看待你的网站：哪些搜索词带来了访客，哪些页面被收录，以及 Google 发现了哪些错误。

1. 打开 [search.google.com/search-console](https://search.google.com/search-console)，用与 Analytics 相同的 Google 账号登录。使用同一个账号，之后的绑定会更容易。
2. 点击 **添加资源**。你会看到两种类型。
   - **网域** 涵盖 `example.com` 及其所有子网域和协议，需要一条 DNS 记录。
   - **网址前缀** 只涵盖一个精确的地址，例如 `https://example.com/`，提供多种验证方式。
3. 如果你的 DNS 在 Cloudflare，选择 **网域**，输入 `example.com`。
4. Search Console 会显示一条 `TXT` 记录。复制它的值，它以 `google-site-verification=` 开头。
5. 在 Cloudflare 控制台中打开你的域名，进入 **DNS → 记录 → 添加记录**。类型选 `TXT`，名称填 `@`，把值粘贴到内容中并保存。
6. 回到 Search Console，点击 **验证**。DNS 的更改通常几分钟内生效，但也可能更久。如果验证失败，请稍等后再次点击 **验证**。

如果你选择的是 **网址前缀** 类型，最简单的方式是使用 Google Analytics 验证：只要使用同一个 Google 账号，Search Console 就可以把你在步骤 2 中安装的标签作为所有权证明。

检查：Search Console 显示“所有权已验证”，并打开该资源的概览页面。一段时间内它会显示“暂无数据”，这是正常的。

## 步骤 5：把 Search Console 与 Google Analytics 绑定

绑定之后，搜索词和着陆页表现会进入 Analytics 报告，你就能把来自搜索的流量和这些访客的行为放在一起看。

1. 在 Google Analytics 中打开 **管理**。
2. 在 **产品关联** 下选择 **Search Console 关联**。
3. 点击 **关联**，再点击 **选择账号**，选中你的 Search Console 资源。你需要是该 Search Console 资源的所有者，并且是该 Analytics 属性的编辑者。
4. 点击 **下一步**，选择 Web 数据流，然后点击 **提交**。

Search Console 的数据需要几天才会开始流入，而且会延迟大约两天。这里没有什么需要等待的事情，直接继续下一步即可。

关联创建后，可以在 **报告 → 资源库** 中找到相关报告。Search Console 报告不会自动加入左侧菜单。想让它们出现在菜单中时，请在资源库里发布 **Search Console** 集合。

检查：**管理 → 产品关联 → Search Console 关联** 中列出了你的资源。

## 步骤 6：添加符合你网站的事件追踪

增强型衡量已经记录了页面浏览、滚动、出站链接点击、站内搜索和文件下载，不要重复实现它们。事件用于你自己业务特有的内容：主要行动号召的点击、订阅简报、联系表单、定价页的浏览。

最有用的指令不是“加一些事件”，而是“先看我的网站，提出事件方案，由我批准”。这样你始终掌握要衡量什么。

```text
请查看这个 Astro 网站的结构：页面、布局、组件、行动号召、表单和出站链接。

第 1 步：在修改任何代码之前，先提出事件方案。给我一张表，包含：事件名称、触发时机、参数，以及它回答的业务问题。有合适的 GA4 推荐事件名时优先使用（例如 generate_lead、sign_up、select_content），否则使用 snake_case 的自定义名称。不要重复增强型衡量已经追踪的内容：页面浏览、滚动、出站点击、文件下载。最多 10 个事件。

第 2 步：我批准之后，实现该方案：
- 用 data-ga-event、data-ga-label 和 data-ga-location 属性标记元素。
- 在 document 上使用一个委托的点击监听器，读取这些属性并调用 gtag('event', ...)。不要添加内联的 onclick 处理器。
- 参数只发送稳定的 id 和位置。绝不发送链接文字、表单输入、邮箱地址或任何能识别访客的内容。
- 不要延迟或取消页面跳转。

第 3 步：运行构建、提交、推送，等待两处部署完成，并用 curl 验证线上网站包含该监听器脚本。然后告诉我应该点击哪些位置，以便我在 GA4 DebugView 中验证。
```

Claude 会先回复一张表。一个小型网站的合理方案类似这样：

| 事件 | 触发时机 | 参数 | 回答的问题 |
| --- | --- | --- | --- |
| `cta_click` | 访客点击主要的行动号召按钮 | `label`、`location` | 哪些按钮、页面的哪些区域带来行动？ |
| `generate_lead` | 联系表单提交成功 | `form_id` | 有多少访客变成了联系人？ |
| `nav_click` | 点击页眉或页脚链接 | `label`、`location` | 哪些导航项被使用？ |
| `theme_toggle` | 使用主题切换 | `value` | 深色模式开关值得保留吗？ |

要带着批判的眼光读这张表。删掉没人会看的事件，把以功能命名而不是以决策命名的事件改名。然后回复“批准，但去掉 `theme_toggle`”，让它去实现。

Claude 写出的监听器大致如下：

```js
document.addEventListener(
  'click',
  (event) => {
    const el = event.target.closest('[data-ga-event]');
    if (!el || typeof window.gtag !== 'function') return;
    window.gtag('event', el.dataset.gaEvent, {
      label: el.dataset.gaLabel,
      location: el.dataset.gaLocation,
      transport_type: 'beacon',
    });
  },
  true,
);
```

被标记的按钮：

```astro
<a href="/contact" data-ga-event="cta_click" data-ga-label="hero_contact" data-ga-location="home_hero">
  联系我们
</a>
```

### 验证事件

1. 在 Google Analytics 中打开 **管理 → 数据展示 → DebugView**。DebugView 会在几秒内显示到达的事件。
2. 要让浏览器进入调试模式，请安装 Chrome 扩展 **Google Analytics Debugger**，或者让 Claude 临时在 `config` 调用中加入 `debug_mode: true`。
3. 访问线上网站，执行 Claude 列出的点击。
4. 每次点击都应在 DebugView 时间线中显示为一个事件，带有你预期的参数。

事件到达一次之后，也会出现在 **管理 → 数据展示 → 事件** 中。如果想在标准报告中使用 `label` 或 `location`，请在 **管理 → 数据展示 → 自定义定义 → 创建自定义维度** 中注册它们，范围选择 **事件**。只有这样注册的参数才会出现在标准报告里。

移除所有临时的 `debug_mode` 设置，然后让 Claude 推送干净的版本。

检查：每个被追踪的点击都以正确的事件名和参数出现在 DebugView 中，并且最终代码已经在 `main` 上。

## 步骤 7：添加基础 SEO 层

搜索引擎需要一份页面地图、关于抓取范围的说明，以及页面被分享时人们看到的描述。第一项 Astro 有官方集成，其余只是布局里的几行代码。Claude 可以引入相关的 Astro 组件和集成来快速完成。

```text
请为这个 Astro 网站添加基础 SEO。

1. 站点地图：用 `npx astro add sitemap` 安装官方的 @astrojs/sitemap 集成。确保 astro.config.mjs 中的 `site` 是生产域名 https://example.com，并删除 GitHub Pages 项目托管遗留的 `base`。
2. robots.txt：创建 src/pages/robots.txt.ts，返回 "User-agent: *"、"Allow: /" 以及一行指向 https://example.com/sitemap-index.xml 的 Sitemap，该地址由 `site` 配置生成，不要写死。
3. 一个可复用的 SEO 组件，供共享布局使用，输出：<title>；meta description；根据当前 URL 和 `site` 生成的 canonical 链接；Open Graph 标签（og:type、og:title、og:description、og:url、og:image、og:site_name、og:locale）；Twitter 卡片标签（twitter:card summary_large_image、twitter:title、twitter:description、twitter:image）；以及 theme-color meta 标签。每个页面通过 props 传入自己的标题和描述。
4. 在 public/og-default.png 提供一张默认的 1200x630 社交分享图，页面没有提供时使用。
5. 为网站添加 WebSite 类型的 JSON-LD 结构化数据，如果网站有博客，再给文章添加 Article 类型。
6. 运行 `npm run build`，然后列出 dist/sitemap-index.xml，显示 dist/robots.txt，并确认首页构建出的 HTML 包含以上所有标签。

全部正确后，提交、推送，等待两处部署完成，并用 curl 确认 https://example.com/sitemap-index.xml 和 https://example.com/robots.txt 都返回 200 且内容正确。
```

每一部分的作用：

- **站点地图。** `@astrojs/sitemap` 在构建时生成 `sitemap-index.xml` 和一个或多个 `sitemap-0.xml` 文件，并且需要 `site` 配置来生成绝对 URL。
- **`robots.txt`。** 它告诉爬虫可以抓取什么，以及站点地图在哪里。想让某个页面不被收录，应该使用 `noindex`，而不是只写在 `robots.txt` 里。
- **Canonical 链接。** 当同一个页面可以通过多个地址访问时，它告诉 Google 哪个是正式地址。
- **Open Graph 和 Twitter 标签。** 它们决定链接在社交网络或聊天应用中被分享时显示的标题、描述和图片。
- **JSON-LD。** 结构化数据帮助搜索引擎理解页面是什么。它不保证出现富媒体结果，但添加成本很低。

检查：线上的 `sitemap-index.xml` 列出了你的页面，`robots.txt` 包含 `Sitemap:` 行，页面源代码中能看到 canonical、Open Graph 和 Twitter 标签。你也可以把网址粘贴到社交卡片验证工具，或在聊天应用里分享，查看预览。

## 步骤 8：在 Search Console 中提交站点地图

在你告诉 Search Console 之前，它并不知道你的站点地图存在。

1. 在 Search Console 中打开你的资源，在左侧菜单中选择 **站点地图**。
2. 在 **添加新的站点地图** 下，输入 `sitemap-index.xml`。
3. 点击 **提交**。
4. 状态应变为 **成功**，并显示发现的页面数量。如果显示 **无法获取**，请先在浏览器中打开该站点地图地址；如果能打开，等几分钟再刷新，因为首次获取可能会延迟。

接下来，请 Google 立即查看你最重要的页面：

1. 把首页 URL 粘贴到 Search Console 顶部的搜索栏。
2. 如果该页面尚未被收录，点击 **请求编入索引**。

收录仍然需要几天，Search Console 的报告也有延迟，一周后再回来查看。

检查：**站点地图** 中列出了 `sitemap-index.xml`，状态为 **成功**。

## 步骤 9：优化每个页面的元数据并添加多尺寸 favicon

基础层给每个页面提供的是通用的元数据。标题和描述是人们在搜索结果中读到的文字，值得逐页处理。Favicon 需要多个尺寸，因为浏览器、手机和书签各自请求不同的文件。

### 标题、描述和关键词

```text
请检查这个网站的每个页面，并优化它的搜索元数据。

对每个页面，给我一张包含标题、meta description 和关键词的前后对比表，然后应用修改。规则：
- 标题：每页唯一，不超过约 60 个字符，主要主题在前，网站名称在后。
- 描述：每页唯一，120 到 160 个字符，用一句通顺的话说明访客能得到什么并邀请点击。不要堆砌关键词，也不要在页面之间复制文字。
- 关键词：从页面真实内容中提取 5 到 8 个词。只有当布局已经支持时才保留 keywords meta 标签，不要编造页面没有涉及的主题。
- 检查每个页面恰好有一个与标题含义一致的 <h1>，并且每张图片都有 alt 属性。

然后运行构建，并写一份简短的报告，列出仍然共用标题或描述的页面。
```

先把预期摆正：搜索引擎基本上忽略 keywords meta 标签。关键词对你自己有帮助，因为写下它们会迫使你说清楚每个页面是关于什么的。真正出现在搜索结果里的是标题和描述。

### 各种尺寸的 favicon

一个 `favicon.svg` 是不错的开始，但有些地方需要特定的文件：旧版浏览器和书签使用 `favicon.ico`，iOS 主屏幕使用 `apple-touch-icon`，Android 和 Web 应用清单使用 192 和 512 像素的 PNG。

macOS 自带用于缩放 PNG 的 `sips`。生成 `.ico` 则需要 ImageMagick，可以通过 Homebrew 安装。让 Claude 直接在你的 Mac 上使用它们：

```text
请用我的源图片 public/logo-source.png（至少 512x512 的正方形 PNG）生成一套完整的 favicon。

1. 使用 macOS 的 `sips` 命令创建 public/icon-192.png、public/icon-512.png 和 public/apple-touch-icon.png（180x180）。
2. 如果没有安装 ImageMagick，用 `brew install imagemagick` 安装。使用 `magick` 生成包含 16x16、32x32 和 48x48 图像的 public/favicon.ico。
3. 如果我已经有 public/favicon.svg，请保留；如果没有，创建一个与 logo 匹配的简单版本。
4. 添加 public/site.webmanifest，列出 icon-192.png 和 icon-512.png。
5. 更新布局的 <head>，加上对应的 <link> 标签：SVG 图标、.ico 后备、apple-touch-icon 和清单。
6. 对每张生成的图片运行 `file` 确认真实尺寸，运行构建，并确保这些文件出现在 dist/ 中。
```

Claude 运行的命令与下面接近：

```bash
sips -z 192 192 public/logo-source.png --out public/icon-192.png
sips -z 512 512 public/logo-source.png --out public/icon-512.png
sips -z 180 180 public/logo-source.png --out public/apple-touch-icon.png
brew install imagemagick
magick public/logo-source.png -define icon:auto-resize=48,32,16 public/favicon.ico
file public/*.png public/favicon.ico
```

head 中的链接如下：

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="icon" href="/favicon.ico" sizes="48x48" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<link rel="manifest" href="/site.webmanifest" />
```

最后，像之前的每一步一样闭环：

```text
请用清晰的说明提交所有改动，推送到 main，等待两处部署完成，并用 curl 验证线上的 /favicon.ico、/apple-touch-icon.png 和 /site.webmanifest 都返回 200。
```

在浏览器中检查：标签页显示你的图标，书签或 iOS 的“添加到主屏幕”使用较大的那一张。浏览器会积极缓存 favicon，如果仍然看到旧图标，请在隐私窗口中打开网站。

## 一周之后要检查什么

- **Search Console → 网页** 显示有多少页面被收录，以及其他页面未被收录的原因。
- **Search Console → 效果** 显示搜索词、点击次数和平均排名。用这些搜索词改进标题和描述。
- **Analytics → 报告 → 互动 → 事件** 显示你的自定义事件触发的频率。
- **Analytics → 报告 → 资源库** 是数据到达之后 Search Console 集合出现的位置。

## 常见问题

- **实时报告什么都没有。** 广告拦截器或隐私浏览器拦截了标签。请在关闭扩展的隐私窗口中测试，并确认线上 HTML 中的测量 ID。
- **页面浏览正常但自定义事件不工作。** 在线上网站打开浏览器控制台并运行 `typeof window.gtag`，它必须输出 `function`。如果输出 `undefined`，说明标签脚本被打包成了模块；让 Claude 使用 `is:inline` 并显式给 `window.gtag` 赋值。
- **事件出现在 DebugView 中但不在报告里。** 标准报告会滞后最多一天，而且自定义参数只有注册为自定义维度之后才会出现在报告中。
- **Search Console 无法验证域名。** 检查 `TXT` 记录是否在根域名（`@`），值是否完整复制，以及是否没有使用 Cloudflare 代理（TXT 记录不会被代理）。然后稍等再重试。
- **站点地图显示“无法获取”。** 自己打开 `https://example.com/sitemap-index.xml`。如果返回 404，请检查 `astro.config.mjs` 中的 `site` 是否为生产域名，以及站点地图集成是否列在 `integrations` 中。
- **社交预览是旧的。** 各平台会缓存预览。修改标签后，请使用它们的调试工具刷新缓存。

## 隐私与同意

分析会收集访客的数据。根据访客所在的地区，你可能需要在加载 Google Analytics 之前征得同意，例如欧盟的 GDPR 和 ePrivacy 规则，并且可能需要在隐私政策中说明。为了让步骤简洁，本指南无条件地安装了该标签。如果你的网站有来自要求同意的地区的访客，请让 Claude 添加一个同意横幅，只有在访客同意之后才加载该标签。以上是一般性信息，不构成法律意见。

## 值得保持的循环

这里的每一步都遵循同一个模式，也是值得保持的习惯：向 Claude 描述最终状态，让它做出修改，让它推送并等待部署完成，让它用 `curl` 在线上网站证明结果，然后用 Google Analytics 或 Search Console 之类的外部工具确认。以后每当你添加功能，都重复同样的循环。

本指南会带你从一台干净的 Mac 出发，做出一个已经上线、可以在互联网上访问的网站。你会在两个地方工作：终端（用来安装工具），以及 Claude Code（它会替你运行重复的命令并编辑文件）。每个步骤结束时都有一个可以检查的结果，确认成功后再进入下一步。

完成后的整体流程如下：

1. 安装 Node.js。
2. 安装 GitHub CLI（`gh`）并登录。
3. 让 Claude 创建一个私有仓库并克隆到本地。
4. 让 Claude 搭建一个带页头、页脚和响应式布局的 Astro 网站，然后提交并推送。
5. 安装 impeccable 技能，并使用它的 `overdrive` 命令打磨首页。
6. 通过 GitHub Actions 工作流把网站发布到 GitHub Pages。
7. 在 Cloudflare 中绑定域名，并用 Workers 部署同一个分支。
8. 添加一个新页面，推送它，然后观察两处部署都完成。

## 本指南适合谁

本指南适合有一台 Mac 和一个 GitHub 账号、想发布一个简单静态网站但不想自己架设服务器的人。你不需要事先了解 Astro、GitHub Actions 或 Cloudflare。但你需要会打开终端，并且会粘贴命令。

## 前提条件

- 运行较新版本 macOS 的 Mac。
- 一个 GitHub 账号。
- 一个 Cloudflare 账号。
- 一个域名。你可以通过 Cloudflare 注册，也可以使用你已经拥有的域名。
- 已安装并登录的 Claude Code。在终端中运行一次 `claude`，确认它能正常启动。

## 步骤 1：安装 Node.js

Astro 和 impeccable 安装程序都运行在 Node.js 上。请使用当前的 LTS 版本。

最简单的方法是从 [nodejs.org](https://nodejs.org) 下载官方安装程序。下载 macOS 安装包，运行并保持默认选项即可。

如果你已经在使用 Homebrew，也可以在终端中安装：

```bash
brew install node
```

打开一个新的终端窗口，检查这两个工具：

```bash
node --version
npm --version
```

两条命令都应该输出一个版本号。如果提示找不到 `node`，请关闭并重新打开终端，让新的 `PATH` 生效。

## 步骤 2：安装 GitHub CLI 并登录

GitHub CLI（命令名为 `gh`）让 Claude 无需你在网站上点来点去，就能替你创建和管理仓库。

```bash
brew install gh
gh --version
```

然后登录：

```bash
gh auth login
```

按以下方式回答提示：

- **你在哪里使用 GitHub？**（Where do you use GitHub?）：`GitHub.com`
- **首选协议？**（Preferred protocol?）：`HTTPS`
- **要用你的 GitHub 凭据为 Git 进行身份验证吗？**（Authenticate Git with your GitHub credentials?）：`Yes`
- **你想用哪种方式进行身份验证？**（How would you like to authenticate?）：`Login with a web browser`

复制终端显示的一次性验证码，按回车，然后在浏览器中完成登录。完成后，检查结果：

```bash
gh auth status
```

输出内容应显示你已登录到 `github.com`。

## 步骤 3：让 Claude 创建私有仓库

选择一个你想存放项目的文件夹，例如 `~/Sites`，如果它不存在就先创建：

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

然后给 Claude 一个这样的请求：

```text
请使用 GitHub CLI 在我的 GitHub 账号下创建一个名为 my-astro-site 的私有仓库。
用一个 README 进行初始化，使 main 分支存在，并把它克隆到这个文件夹中。
完成后把仓库地址显示给我。
```

Claude 应该会运行与下面等效的命令：

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

完成后，你应该会得到一个包含 `README.md` 的 `~/Sites/my-astro-site` 文件夹，并且 GitHub 上该仓库是私有的。检查默认分支：

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

它应该输出 `main`。

## 步骤 4：搭建 Astro 网站

留在仓库文件夹中，并在那里启动 Claude：

```bash
cd ~/Sites/my-astro-site
claude
```

让 Claude 搭建一个基础网站：

```text
请在这个仓库中使用 Astro 官方的 basics starter 创建一个基础 Astro 网站。
添加一个网站页头，包含网站名称和导航链接；添加一个页脚，包含版权文字；
并提供一个在手机、平板和宽屏桌面上都能正常显示的布局。
设计保持简单。请运行开发服务器，检查页面，并告诉我如何查看。
```

Claude 完成后，你自己打开本地预览：

```bash
npm install
npm run dev
```

Astro 会输出一个本地地址，通常是 `http://localhost:4321`。在浏览器中打开它，调整窗口大小检查布局，然后按 `Control+C` 停止服务器。

提交之前，请确保生产构建可以通过：

```bash
npm run build
```

### 提交并推送第一个版本

让 Claude 保存这次的工作：

```text
请用清晰的说明提交这个 Astro 网站，并推送到 origin 上的 main 分支。
```

Claude 应该会运行类似下面的命令：

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

在 GitHub 上确认你最新的提交出现在仓库的 `main` 分支上。

## 步骤 5：安装 impeccable 并为首页加上 Overdrive 效果

[impeccable](https://impeccable.style) 是一个面向编程智能体的设计技能。它为 Claude 提供了一套共享的设计工作词汇，例如 `polish`、`critique` 和 `overdrive`。`overdrive` 命令会添加更大胆、更有表现力的效果，例如着色器、弹簧物理和滚动驱动的动效。

让 Claude 为这个项目安装该技能：

```text
请使用官方安装程序，在这个项目中安装 impeccable 技能。
使用项目范围和 Claude Code 提供方。如果需要我重启 Claude Code，请告诉我。
```

Claude 应该会在项目根目录运行：

```bash
npx impeccable install
```

安装程序会询问是为当前项目安装还是全局安装，并提供一个设计钩子。接受该钩子，然后重启 Claude Code，让新技能加载。

在重启后的会话中，初始化设计上下文：

```text
/impeccable init
```

然后对首页应用 overdrive 处理：

```text
/impeccable overdrive the homepage
```

提交之前，请检查 Claude 做了哪些改动。Overdrive 可能会添加大量动效，所以你可能只想保留那些能帮助读者理解页面的效果。让 Claude 再次运行构建并推送结果：

```text
请运行 npm run build，修复所有错误，然后提交 overdrive 的改动并推送到 main。
```

## 步骤 6：通过 GitHub Actions 发布到 GitHub Pages

GitHub Pages 可以免费托管构建后的网站。Astro 提供了一个官方的 GitHub Action，可以构建网站并完成部署。

### 开启 Pages

在 GitHub 上打开你的仓库，然后进入 **设置 (Settings) → Pages**。在 **构建和部署 (Build and deployment)** 下，把 **来源 (Source)** 设置为 **GitHub Actions**。

### 让 Claude 添加工作流

```text
请在 .github/workflows/deploy.yml 中添加一个 GitHub Actions 工作流，使用 actions/checkout
和 withastro/action 构建这个 Astro 网站，并将其部署到 GitHub Pages。
保留 Astro 模板中自带的 permissions 配置块。
```

Claude 创建的工作流看起来会与 Astro 官方文档中的示例相似：

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### 设置网站地址

GitHub Pages 会把项目网站放在一个路径下，例如 `https://<your-username>.github.io/my-astro-site`。Astro 需要知道这个路径，否则它的链接和资源会失效。请让 Claude 更新 `astro.config.mjs`：

```text
在 astro.config.mjs 中把 site 设置为 https://<your-username>.github.io，把 base 设置为 /my-astro-site。
请解释每个设置的作用。
```

结果应该类似这样：

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

把 `<your-username>` 替换为你的 GitHub 用户名。以后当你迁移到自己的域名时，需要删除 `base`。

提交并推送工作流和配置更改：

```text
请提交 Pages 工作流和 Astro 配置更改，然后推送到 main。
```

### 等待首次部署

打开仓库中的 **Actions** 标签页。`Deploy to GitHub Pages` 的运行应在一两分钟后变为绿色。然后打开 **设置 (Settings) → Pages** 中显示的 Pages 地址。

## 步骤 7：在 Cloudflare 中绑定域名

这一步需要一个域名。常见的有两种方式：

- **注册一个新域名**：在 Cloudflare 控制台中通过 Cloudflare Registrar 注册。
- **使用你已经拥有的域名。** 把它添加到 Cloudflare 作为一个站点，然后在你的域名注册商处，把域名的域名服务器（nameserver）改为 Cloudflare 提供的两个 nameserver。

登录 [Cloudflare 控制台](https://dash.cloudflare.com)，然后注册域名或添加你已有的域名。等待 Cloudflare 把该域名显示为已激活（active）。修改 nameserver 之后，这可能需要几分钟。

## 步骤 8：从 GitHub 分支创建 Worker 项目

Cloudflare 目前针对 Astro 的指南使用 Workers。在控制台中，类似 Pages 的 Git 流程仍然出现在同一个 **Workers & Pages** 区域下，但下面的步骤遵循 Workers 的路径。

首先，让 Claude 为静态 Astro 构建添加一个 Wrangler 配置。Wrangler 是 Cloudflare 的命令行工具。

```text
请在项目根目录添加一个 wrangler.jsonc 文件，用于静态 Astro 网站。
将 name 设置为 my-astro-site，将 compatibility_date 设置为今天的日期，
并把 ./dist 文件夹作为静态资源提供。不要添加 main 入口点。
```

它应该类似这样：

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

提交并推送该文件。然后创建 Cloudflare 项目：

1. 在 Cloudflare 控制台中，进入 **Workers & Pages**。
2. 选择 **创建应用 (Create application)**，然后选择从 GitHub 导入仓库的选项。
3. 当 Cloudflare 请求授权时，授权 **Cloudflare Workers & Pages** GitHub 应用。你可以选择所有仓库，也可以只选择 `my-astro-site`。
4. 选择 `my-astro-site` 和 `main` 分支。
5. 把构建命令设置为 `npm run build`（或 `npx astro build`），把部署命令设置为 `npx wrangler deploy`。
6. 开始部署。

Cloudflare 会在每次推送到所连接的分支时构建网站，因此之后的提交都会自动部署。

### 绑定你的域名

在控制台中打开新建的 Worker，进入 **域名和路由 (Domains & Routes)**，添加你的域名，或者像 `www` 这样的子域名。如果该域名已经在同一个账号中，Cloudflare 会自动为你创建 DNS 记录。

## 步骤 9：在 Cloudflare 中检查网站

第一次构建完成后，请在 Cloudflare 控制台中查看以下位置：

- **部署 (Deployments)：** 最新的构建应标记为成功。如果失败了，请打开构建日志，阅读第一条错误信息。
- **域名和路由 (Domains & Routes)：** 你的自定义域名应显示为已激活。
- **设置 (Settings)：** 确认连接的仓库和分支是你预期的那些。

然后在浏览器中打开你的域名。分别在手机和宽屏桌面窗口中检查页头、页脚和布局。

## 步骤 10：添加新页面并观察它上线

现在你已经掌握了完整的循环：在本地编辑，推送到 GitHub，然后让托管平台构建并部署这些更改。

在项目文件夹中启动 Claude，并请它添加一个新页面：

```text
请在 src/pages/about.astro 创建一个新页面，包含标题、一段简短的文字和一个返回首页的链接。
使用与其他页面相同的页头和页脚。运行 npm run build，然后提交并推送到 main。
```

Claude 应该会创建文件、构建网站、提交并推送。然后观察两处部署：

- **GitHub：** 打开 **Actions** 标签页。Pages 工作流会再次运行。
- **Cloudflare：** 打开 **Workers & Pages → 你的项目 → 部署 (Deployments)**。新的构建会自动开始。

两处都显示成功后，在浏览器中打开 `https://<your-domain>/about`。如果页面缺失，请检查文件是否位于 `src/pages/about.astro`，最新的部署是否已完成，以及你的浏览器是否显示了旧的缓存副本。

## 常见问题

- **`node: command not found`：** 安装 Node.js 后，请打开一个新的终端窗口。
- **`gh` 无法创建仓库：** 运行 `gh auth status`，并确认登录的账号有权访问你的账号。
- **GitHub Pages 显示空白页或样式缺失：** 检查 `astro.config.mjs` 中的 `site` 和 `base`。`base` 的值必须与仓库名称一致。
- **Cloudflare 构建失败：** 阅读构建日志中的第一条错误。大多数失败来自缺少脚本、构建命令错误，或者 Wrangler 配置指向了错误的文件夹。
- **域名没有激活：** nameserver 的更改可能需要一段时间才会生效。请在 Cloudflare 中该域名的概览页面查看状态。

## 后续步骤

网站上线后，你可以用同样的循环来管理真正的内容。让 Claude 添加页面，运行 `/impeccable critique` 进行设计评审，或者为预览添加第二个 Cloudflare 环境。需要养成的主要习惯很简单：做一个小改动，在本地构建，提交，然后让托管平台发布它。

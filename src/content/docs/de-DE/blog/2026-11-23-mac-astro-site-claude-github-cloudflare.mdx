Diese Anleitung führt dich von einem sauberen Mac zu einer Website, die im Internet erreichbar ist. Du arbeitest an zwei Stellen: im Terminal, wo du Werkzeuge installierst, und in Claude Code, das die sich wiederholenden Befehle ausführt und die Dateien für dich bearbeitet. Jeder Schritt endet mit etwas, das du prüfen kannst, damit du weißt, dass es funktioniert hat, bevor du weitergehst.

Der fertige Weg sieht so aus:

1. Node.js installieren.
2. GitHub CLI (`gh`) installieren und anmelden.
3. Claude bitten, ein privates Repository zu erstellen und zu klonen.
4. Claude bitten, eine Astro-Website mit Kopfbereich, Fußbereich und responsivem Layout aufzusetzen, und sie dann committen und pushen.
5. Den impeccable-Skill installieren und mit seinem Befehl `overdrive` die Startseite verfeinern.
6. Die Website mit einem GitHub-Actions-Workflow auf GitHub Pages veröffentlichen.
7. Eine Domain in Cloudflare verbinden und denselben Branch mit Workers bereitstellen.
8. Eine neue Seite hinzufügen, pushen und zusehen, wie beide Bereitstellungen abgeschlossen werden.

## Für wen diese Anleitung gedacht ist

Diese Anleitung richtet sich an Menschen, die einen Mac und ein GitHub-Konto haben und eine einfache statische Website veröffentlichen möchten, ohne einen Server einzurichten. Du musst vorher weder Astro, GitHub Actions noch Cloudflare kennen. Du solltest aber damit zurechtkommen, das Terminal zu öffnen und Befehle einzufügen.

## Voraussetzungen

- Ein Mac mit einer aktuellen Version von macOS.
- Ein GitHub-Konto.
- Ein Cloudflare-Konto.
- Ein Domainname. Du kannst einen über Cloudflare registrieren oder eine Domain verwenden, die dir bereits gehört.
- Claude Code ist installiert und angemeldet. Starte `claude` einmal im Terminal, um zu prüfen, dass es startet.

## Schritt 1: Node.js installieren

Astro und der impeccable-Installer laufen beide mit Node.js. Verwende die aktuelle LTS-Version.

Der einfachste Weg ist der offizielle Installer von [nodejs.org](https://nodejs.org). Lade das macOS-Paket herunter, starte es und übernimm die Standardeinstellungen.

Wenn du bereits Homebrew nutzt, kannst du Node.js stattdessen im Terminal installieren:

```bash
brew install node
```

Öffne ein neues Terminal-Fenster und prüfe beide Werkzeuge:

```bash
node --version
npm --version
```

Beide Befehle sollten eine Versionsnummer ausgeben. Wenn `node` nicht gefunden wird, schließe das Terminal und öffne es neu, damit der neue `PATH` geladen wird.

## Schritt 2: GitHub CLI installieren und anmelden

GitHub CLI, kurz `gh`, ermöglicht es Claude, Repositories zu erstellen und zu verwalten, ohne dass du dich durch die Website klickst.

```bash
brew install gh
gh --version
```

Melde dich dann an:

```bash
gh auth login
```

Beantworte die Fragen so:

- **Wo nutzt du GitHub?** (Where do you use GitHub?) `GitHub.com`
- **Bevorzugtes Protokoll?** (Preferred protocol?) `HTTPS`
- **Git mit deinen GitHub-Zugangsdaten authentifizieren?** (Authenticate Git with your GitHub credentials?) `Yes`
- **Wie möchtest du dich authentifizieren?** (How would you like to authenticate?) `Login with a web browser`

Kopiere den einmaligen Code, den das Terminal anzeigt, drücke Enter und schließe die Anmeldung in deinem Browser ab. Wenn du fertig bist, prüfe das Ergebnis:

```bash
gh auth status
```

Die Ausgabe sollte besagen, dass du bei `github.com` angemeldet bist.

## Schritt 3: Claude bitten, ein privates Repository zu erstellen

Wähle einen Ordner, in dem deine Projekte liegen sollen, zum Beispiel `~/Sites`, und lege ihn an, falls er noch nicht existiert:

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

Gib Claude dann eine Anfrage wie diese:

```text
Verwende die GitHub CLI, um auf meinem GitHub-Konto ein privates Repository namens my-astro-site zu erstellen.
Initialisiere es mit einer README, damit der Branch main existiert, und klone es in diesen Ordner.
Zeige mir die Repository-URL, wenn du fertig bist.
```

Claude sollte etwa diesen Befehl ausführen:

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

Wenn das fertig ist, solltest du einen Ordner `~/Sites/my-astro-site` haben, der eine `README.md` enthält, und das Repository sollte auf GitHub privat sein. Prüfe den Standard-Branch:

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

Er sollte `main` ausgeben.

## Schritt 4: Das Astro-Grundgerüst anlegen

Bleibe im Repository-Ordner und starte Claude dort:

```bash
cd ~/Sites/my-astro-site
claude
```

Bitte Claude, eine einfache Website zu bauen:

```text
Erstelle in diesem Repository eine einfache Astro-Website mit dem offiziellen Basics-Starter von Astro.
Füge einen Seitenkopf mit dem Namen der Website und Navigationslinks hinzu, einen Fußbereich mit Copyright-Text
und ein Layout, das auf Handys, Tablets und breiten Desktop-Bildschirmen funktioniert.
Halte das Design einfach. Starte den Dev-Server, prüfe die Seite und zeige mir, wie ich sie aufrufe.
```

Wenn Claude fertig ist, öffne die lokale Vorschau selbst:

```bash
npm install
npm run dev
```

Astro gibt eine lokale Adresse aus, meist `http://localhost:4321`. Öffne sie in deinem Browser, ändere die Fenstergröße, um das Layout zu prüfen, und beende den Server dann mit `Control+C`.

Bevor du committest, stelle sicher, dass der Produktions-Build durchläuft:

```bash
npm run build
```

### Die erste Version committen und pushen

Bitte Claude, die Arbeit zu speichern:

```text
Committe die Astro-Website mit einer klaren Commit-Nachricht und pushe sie auf den Branch main auf origin.
```

Claude sollte Befehle wie diese ausführen:

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

Prüfe auf GitHub, ob dein letzter Commit im Branch `main` des Repositorys erscheint.

## Schritt 5: impeccable installieren und die Startseite mit Overdrive verfeinern

[impeccable](https://impeccable.style) ist ein Design-Skill für Coding-Agenten. Er gibt Claude ein gemeinsames Vokabular für Designarbeit, etwa `polish`, `critique` und `overdrive`. Der Befehl `overdrive` fügt kräftigere, ausdrucksstärkere Effekte hinzu, etwa Shader, Federphysik und scrollgesteuerte Bewegung.

Bitte Claude, den Skill für dieses Projekt zu installieren:

```text
Installiere den impeccable-Skill in diesem Projekt mit seinem offiziellen Installer.
Verwende den Geltungsbereich Projekt und den Anbieter Claude Code. Sag mir, wann ich Claude Code neu starten muss.
```

Claude sollte dies im Projektstammverzeichnis ausführen:

```bash
npx impeccable install
```

Der Installer fragt, ob er für dieses Projekt oder global installieren soll, und bietet einen Design-Hook an. Bestätige den Hook und starte Claude Code danach neu, damit der neue Skill geladen wird.

Initialisiere in der neu gestarteten Sitzung den Design-Kontext:

```text
/impeccable init
```

Wende dann den Overdrive-Durchgang auf die Startseite an:

```text
/impeccable overdrive die Startseite
```

Prüfe, was Claude geändert hat, bevor du committest. Overdrive kann viel Bewegung hinzufügen, deshalb möchtest du vielleicht nur die Effekte behalten, die dem Leser helfen, die Seite zu verstehen. Bitte Claude, den Build erneut auszuführen und das Ergebnis zu pushen:

```text
Führe npm run build aus, behebe alle Fehler, committe dann die Overdrive-Änderungen und pushe sie auf main.
```

## Schritt 6: Auf GitHub Pages mit GitHub Actions veröffentlichen

GitHub Pages kann die fertige Website kostenlos hosten. Astro stellt eine offizielle GitHub Action bereit, die die Website baut und bereitstellt.

### Pages einschalten

Öffne dein Repository auf GitHub und gehe zu **Einstellungen (Settings) → Pages**. Setze unter **Erstellung und Bereitstellung (Build and deployment)** die **Quelle (Source)** auf **GitHub Actions**.

### Claude den Workflow hinzufügen lassen

```text
Füge einen GitHub-Actions-Workflow unter .github/workflows/deploy.yml hinzu, der actions/checkout
und withastro/action verwendet, um diese Astro-Website zu bauen und auf GitHub Pages bereitzustellen.
Behalte den Block permissions bei, den die Astro-Vorlage enthält.
```

Der Workflow, den Claude erstellt, wird dem dokumentierten Beispiel von Astro ähnlich sehen:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### Die Website-Adresse festlegen

GitHub Pages stellt eine Projektseite unter einem Pfad bereit, etwa `https://<your-username>.github.io/my-astro-site`. Astro muss diesen Pfad kennen, sonst funktionieren Links und Dateien nicht mehr. Bitte Claude, `astro.config.mjs` anzupassen:

```text
Setze site auf https://<your-username>.github.io und base auf /my-astro-site in astro.config.mjs.
Erkläre, was jede Einstellung bewirkt.
```

Das Ergebnis sollte so aussehen:

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

Ersetze `<your-username>` durch deinen GitHub-Benutzernamen. Wenn du später zu deiner eigenen Domain wechselst, entfernst du `base` wieder.

Committe und pushe den Workflow und die Konfigurationsänderung:

```text
Committe den Pages-Workflow und die Änderung an der Astro-Konfiguration und pushe sie auf main.
```

### Auf die erste Bereitstellung warten

Öffne den Reiter **Aktionen (Actions)** in deinem Repository. Der Lauf `Deploy to GitHub Pages` sollte nach ein bis zwei Minuten grün werden. Öffne dann die Pages-URL, die unter **Einstellungen (Settings) → Pages** angezeigt wird.

## Schritt 7: Eine Domain in Cloudflare verbinden

Für den Cloudflare-Schritt brauchst du eine Domain. Es gibt zwei gängige Möglichkeiten:

- **Eine neue Domain registrieren** über den Cloudflare Registrar im Cloudflare-Dashboard.
- **Eine Domain verwenden, die dir bereits gehört.** Füge sie in Cloudflare als Website hinzu und ändere dann beim Registrar die Nameserver der Domain auf die beiden Nameserver, die Cloudflare dir nennt.

Melde dich im [Cloudflare-Dashboard](https://dash.cloudflare.com) an und registriere dann die Domain oder füge deine bestehende Domain hinzu. Warte, bis Cloudflare die Domain als aktiv anzeigt. Nach einer Änderung der Nameserver kann das einige Minuten dauern.

## Schritt 8: Ein Worker-Projekt aus dem GitHub-Branch erstellen

Die aktuelle Anleitung von Cloudflare für Astro verwendet Workers. Im Dashboard erscheint der Git-Ablauf im Stil von Pages weiterhin im selben Bereich **Workers & Pages**, aber die folgenden Schritte folgen dem Workers-Weg.

Bitte Claude zuerst, eine Wrangler-Konfiguration für einen statischen Astro-Build hinzuzufügen. Wrangler ist das Kommandozeilenwerkzeug von Cloudflare.

```text
Füge im Projektstammverzeichnis eine Datei wrangler.jsonc für eine statische Astro-Website hinzu.
Setze name auf my-astro-site, setze compatibility_date auf das heutige Datum
und liefere den Ordner ./dist als statische Assets aus. Füge keinen main-Einstiegspunkt hinzu.
```

Sie sollte so aussehen:

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

Committe und pushe die Datei. Lege dann das Cloudflare-Projekt an:

1. Gehe im Cloudflare-Dashboard zu **Workers & Pages**.
2. Wähle **Anwendung erstellen (Create application)** und dann die Option, ein Repository aus GitHub zu importieren.
3. Autorisiere die GitHub-App **Cloudflare Workers & Pages**, wenn Cloudflare danach fragt. Wähle entweder alle Repositories oder nur `my-astro-site`.
4. Wähle `my-astro-site` und den Branch `main`.
5. Setze den Build-Befehl auf `npm run build` (oder `npx astro build`) und den Deploy-Befehl auf `npx wrangler deploy`.
6. Starte die Bereitstellung.

Cloudflare baut die Website bei jedem Push auf den verbundenen Branch. Künftige Commits werden also automatisch bereitgestellt.

### Domain anbinden

Öffne den neuen Worker im Dashboard, gehe zu **Domains & Routen (Domains & Routes)** und füge deine Domain oder eine Subdomain wie `www` hinzu. Wenn die Domain bereits im selben Konto liegt, legt Cloudflare den DNS-Eintrag für dich an.

## Schritt 9: Die Website in Cloudflare prüfen

Wenn der erste Build abgeschlossen ist, schau dir diese Stellen im Cloudflare-Dashboard an:

- **Bereitstellungen (Deployments):** Der neueste Build sollte als erfolgreich markiert sein. Wenn er fehlgeschlagen ist, öffne das Build-Protokoll und lies den ersten Fehler.
- **Domains & Routen:** Deine eigene Domain sollte als aktiv angezeigt werden.
- **Einstellungen:** Prüfe, ob das verbundene Repository und der Branch die sind, die du erwartest.

Öffne dann deine Domain im Browser. Prüfe Kopfbereich, Fußbereich und Layout auf deinem Handy sowie in einem breiten Desktop-Fenster.

## Schritt 10: Eine neue Seite hinzufügen und zusehen, wie sie live geht

Jetzt hast du den vollständigen Kreislauf: lokal bearbeiten, zu GitHub pushen und dann die Hosting-Dienste den Build und die Bereitstellung der Änderung übernehmen lassen.

Starte Claude im Projektordner und bitte um eine neue Seite:

```text
Erstelle eine neue Seite unter src/pages/about.astro mit einem Titel, einem kurzen Absatz und einem Link zurück zur Startseite.
Verwende denselben Kopfbereich und Fußbereich wie die anderen Seiten. Führe npm run build aus und committe dann und pushe auf main.
```

Claude sollte die Datei erstellen, die Website bauen, committen und pushen. Beobachte dann die beiden Bereitstellungen:

- **GitHub:** Öffne den Reiter **Aktionen**. Der Pages-Workflow läuft erneut.
- **Cloudflare:** Öffne **Workers & Pages → dein Projekt → Bereitstellungen**. Ein neuer Build startet automatisch.

Wenn beide Erfolg anzeigen, öffne `https://<your-domain>/about` in deinem Browser. Wenn die Seite fehlt, prüfe, ob die Datei unter `src/pages/about.astro` liegt, ob die neueste Bereitstellung abgeschlossen ist und ob dein Browser nicht eine alte, zwischengespeicherte Version anzeigt.

## Häufige Probleme

- **`node: command not found`:** Öffne nach der Installation von Node.js ein neues Terminal-Fenster.
- **`gh` kann das Repository nicht erstellen:** Führe `gh auth status` aus und stelle sicher, dass die Anmeldung Zugriff auf dein Konto hat.
- **GitHub Pages zeigt eine leere Seite oder fehlende Styles:** Prüfe `site` und `base` in `astro.config.mjs`. Der Wert von `base` muss zum Namen des Repositorys passen.
- **Der Cloudflare-Build schlägt fehl:** Lies den ersten Fehler im Build-Protokoll. Die meisten Fehler kommen von einem fehlenden Skript, einem falschen Build-Befehl oder einer Wrangler-Konfiguration, die auf den falschen Ordner zeigt.
- **Die Domain ist nicht aktiv:** Änderungen an den Nameservern brauchen manchmal Zeit, bis sie überall übernommen sind. Prüfe den Status auf der Übersichtsseite der Domain in Cloudflare.

## Nächste Schritte

Sobald die Website live ist, kannst du denselben Kreislauf für echte Inhalte nutzen. Du kannst Claude bitten, weitere Seiten hinzuzufügen, `/impeccable critique` für eine Design-Prüfung ausführen lassen oder eine zweite Cloudflare-Umgebung für Vorschauen anlegen. Die wichtigste Gewohnheit ist einfach: eine kleine Änderung machen, lokal bauen, committen und die Hosting-Dienste die Veröffentlichung übernehmen lassen.

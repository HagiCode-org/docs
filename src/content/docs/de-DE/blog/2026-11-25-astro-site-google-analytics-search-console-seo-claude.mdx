Im [vorherigen Leitfaden](/de-DE/blog/2026-11-23-mac-astro-site-claude-github-cloudflare/) hast du auf einem sauberen Mac eine Astro-Website gebaut, die auf GitHub Pages und Cloudflare läuft. Mit dem Livegang ist erst die halbe Arbeit getan. Du musst noch wissen, ob Menschen die Seite besuchen, was Besucher dort tun und ob Google sie finden kann.

Dieser Leitfaden schließt diese Lücke. Du richtest Google Analytics und die Google Search Console ein und lässt Claude Tracking, Sitemap, Social-Tags und Favicon ergänzen. Jeder Schritt endet mit einem Ergebnis, das du prüfen kannst, bevor du weitermachst.

Der vollständige Ablauf:

1. Eine Google-Analytics-Property anlegen und ihre Mess-ID kopieren.
2. Claude Google Analytics in die Website einbauen, pushen, auf das Ende der Deployments warten und nachweisen lassen, dass der Code live ist.
3. In Google Analytics bestätigen, dass deine Besuche in Echtzeit erscheinen.
4. Die Website in der Google Search Console registrieren.
5. Search Console mit Google Analytics verknüpfen.
6. Claude passende Ereignisverfolgung für deine Website entwerfen und einbauen lassen, dann veröffentlichen und prüfen.
7. Claude eine grundlegende SEO-Schicht hinzufügen lassen: Sitemap, `robots.txt`, Canonical-Link, Open Graph und Twitter-Tags.
8. Die Sitemap in der Search Console einreichen.
9. Claude Titel, Beschreibungen und Keywords jeder Seite optimieren lassen und mit den Kommandozeilenwerkzeugen auf dem Mac Favicons in mehreren Größen erzeugen lassen.

## Für wen dieser Leitfaden gedacht ist

Er ist für alle, die den vorherigen Leitfaden abgeschlossen haben: Du hast ein Astro-Projekt in einem GitHub-Repository, jeder Push auf `main` wird automatisch deployt, und du hast eine öffentliche Domain. Du brauchst keine Vorkenntnisse mit Analysetools, solltest aber kurze Prompts in Claude Code einfügen können und auf einigen Google-Seiten klicken.

## Voraussetzungen

- Eine Astro-Website aus dem vorherigen Leitfaden, die live ist und unter einer eigenen Domain erreichbar ist. Dieser Text nennt das Repository `my-astro-site` und die Domain `example.com`. Ersetze beides durch deine eigenen Werte.
- Ein Google-Konto.
- Claude Code, installiert und angemeldet, sowie das angemeldete `gh` (prüfbar mit `gh auth status`).
- Zugriff auf die DNS-Einstellungen deiner Domain. Wenn die Domain bei Cloudflare liegt, hast du ihn bereits.

## Schritt 1: Google-Analytics-Property anlegen und Mess-ID holen

Google Analytics 4 (GA4) ist so aufgebaut: Ein Konto enthält eine oder mehrere Properties, und eine Property enthält Datenströme. Eine Website entspricht einem Web-Datenstrom, und dieser hat eine Mess-ID, die mit `G-` beginnt.

1. Öffne [analytics.google.com](https://analytics.google.com) und melde dich mit deinem Google-Konto an.
2. Klicke auf **Messung starten**. Wenn du Analytics schon nutzt, wähle stattdessen **Verwaltung → Erstellen → Konto**. Gib dem Konto einen Namen, zum Beispiel `My sites`.
3. Lege die Property an. Benenne sie nach deiner Website, wähle Zeitzone und Währung für die Berichte und beantworte die geschäftlichen Fragen.
4. Wähle als Plattform **Web**.
5. Gib die Adresse der Website (`https://example.com`) und einen Namen für den Datenstrom ein. Lass **Verbesserte Messung** eingeschaltet. Damit werden Seitenaufrufe, Scrollen, Klicks auf externe Links und Datei-Downloads ohne eigenen Code erfasst.
6. Erstelle den Datenstrom. Google zeigt die Details des Streams an, darunter die **Mess-ID**.

Kopiere die Mess-ID. Sie sieht aus wie `G-ABCD123456`. Später findest du sie unter **Verwaltung → Datenerfassung und -änderung → Datenströme → dein Datenstrom** wieder.

Die Mess-ID ist kein Geheimnis. Jede Website, die sie verwendet, zeigt sie im Quellcode der Seite an. Du kannst sie daher bedenkenlos ins Repository committen.

Prüfung: Du hast eine Mess-ID, die mit `G-` beginnt.

## Schritt 2: Claude Google Analytics einbauen lassen

Starte Claude im Projektordner:

```bash
cd ~/Sites/my-astro-site
claude
```

Beschreibe dann die gesamte Aufgabe in einer einzigen Anfrage, einschließlich Push und Prüfung. Je genauer du den Endzustand beschreibst, desto weniger musst du später korrigieren.

```text
请为这个 Astro 网站接入 Google Analytics 4，测量 ID 是 G-ABCD123456。

要求：
- 把 gtag.js 加载器和 config 调用放在共享布局的 <head> 中，使每个页面恰好有一份。
- 使用普通的内联脚本（is:inline），让 window.gtag 成为真正的全局函数。Astro 会把普通的 <script> 打包成模块，这会让后续代码访问不到 gtag。
- 只在生产构建中渲染该标签，`npm run dev` 中不渲染。
- 测量 ID 从一个常量或环境变量读取，不要分散地复制多份。
- 运行 `npm run build`，并检查 dist/index.html 中包含该标签。

构建通过后，用清晰的说明提交并推送到 main。然后等待两处部署，即 GitHub Pages 工作流和 Cloudflare 构建，都完成。最后用 curl 获取 https://example.com/，确认线上的 HTML 包含该测量 ID。请汇报你检查了什么。
```

Der Code, den Claude im Layout erzeugt, sollte etwa so aussehen:

```astro
---
const GA_ID = 'G-ABCD123456';
const isProd = import.meta.env.PROD;
---
<head>
  {isProd && (
    <>
      <script is:inline async src={`https://www.googletagmanager.com/gtag/js?id=${GA_ID}`}></script>
      <script is:inline define:vars={{ GA_ID }}>
        window.dataLayer = window.dataLayer || [];
        window.gtag = function () { dataLayer.push(arguments); };
        gtag('js', new Date());
        gtag('config', GA_ID);
      </script>
    </>
  )}
</head>
```

Zwei Details sind wichtig, weil sie die häufigsten Gründe sind, warum ein Tag „nichts tut“.

- **`window.gtag` muss eine globale Funktion sein.** Wird das Skript in eine Closure verpackt, funktionieren Seitenaufrufe womöglich weiter, aber `window.gtag` ist undefiniert. Alle benutzerdefinierten Ereignisse aus Schritt 6 würden dann stillschweigend scheitern. Die explizite Zuweisung an `window.gtag` verhindert das.
- **Nur in Produktion aktivieren.** Läuft das Tag auch auf `localhost`, verfälschen deine eigenen Klicks während der Entwicklung die Daten.

Während des Wartens nutzt Claude Befehle wie diese:

```bash
gh run watch
curl -s https://example.com/ | grep -o 'googletagmanager.com/gtag/js?id=G-[A-Z0-9]*'
```

`gh run watch` verfolgt den GitHub-Actions-Lauf bis zum Ende. Die `curl`-Zeile gibt nur dann etwas aus, wenn die Live-Seite die Adresse des Loaders tatsächlich enthält.

Prüfung: Claudes Bericht zeigt, dass beide Plattformen erfolgreich deployt wurden, und die Mess-ID steht im Live-HTML. Gibt `curl` nichts aus, ist das Deployment noch nicht fertig oder ein Cache liefert noch die alte Seite. Lass Claude es nach einer Minute erneut versuchen. Liefert der Cache weiterhin die alte Seite, leere den Cloudflare-Cache.

## Schritt 3: In Google Analytics bestätigen, dass die Website online ist

Prüfe nun von der Google-Seite aus, nicht nur von deiner eigenen.

1. Öffne `https://example.com` im Browser. Wenn du einen Werbeblocker oder einen Datenschutzbrowser nutzt, deaktiviere ihn für diese Prüfung, denn er blockiert Google Analytics.
2. Öffne in Google Analytics **Berichte → Echtzeit**.
3. Innerhalb etwa einer Minute solltest du **1 Nutzer in den letzten 30 Minuten** sehen, und in der Ereignisliste erscheint das Ereignis `page_view`.
4. Öffne zwei oder drei Seiten. Ihre Titel erscheinen in der Echtzeitansicht.

Du kannst auch **Verwaltung → Datenströme → dein Datenstrom** öffnen. Ein grünes Häkchen mit dem Hinweis, dass Daten eingehen, zeigt, dass der Datenstrom Besuche empfängt.

Prüfung: Dein eigener Besuch erscheint unter **Echtzeit**. Standardberichte wie **Akquisition** hinken einige Stunden bis einen Tag hinterher. Wenn sie noch leer sind, ist das kein Problem.

## Schritt 4: Website in der Google Search Console registrieren

Google Analytics zeigt, was Besucher nach der Ankunft tun. Die Google Search Console zeigt, wie Google deine Website sieht: welche Suchanfragen Besucher bringen, welche Seiten indexiert sind und welche Fehler Google findet.

1. Öffne [search.google.com/search-console](https://search.google.com/search-console) und melde dich mit demselben Google-Konto an wie bei Analytics. Dieses Konto zu verwenden, macht die spätere Verknüpfung einfacher.
2. Klicke auf **Property hinzufügen**. Du siehst zwei Typen.
   - **Domain** umfasst `example.com` mit allen Subdomains und Protokollen. Dafür brauchst du einen DNS-Eintrag.
   - **URL-Präfix** umfasst genau eine Adresse, zum Beispiel `https://example.com/`, und bietet mehrere Bestätigungsmethoden.
3. Wenn dein DNS bei Cloudflare liegt, wähle **Domain** und gib `example.com` ein.
4. Die Search Console zeigt dir einen `TXT`-Eintrag. Kopiere seinen Wert. Er beginnt mit `google-site-verification=`.
5. Öffne im Cloudflare-Dashboard deine Domain und gehe zu **DNS → Einträge → Eintrag hinzufügen**. Wähle den Typ `TXT`, trage bei Name `@` ein, füge den Wert im Feld Inhalt ein und speichere.
6. Kehre zur Search Console zurück und klicke auf **Bestätigen**. DNS-Änderungen wirken meist innerhalb weniger Minuten, manchmal dauert es länger. Schlägt die Bestätigung fehl, warte und klicke erneut auf **Bestätigen**.

Wenn du den Typ **URL-Präfix** gewählt hast, ist der einfachste Weg die Bestätigung über Google Analytics. Solange du dasselbe Google-Konto verwendest, kann die Search Console das Tag aus Schritt 2 als Nachweis der Inhaberschaft nutzen.

Prüfung: Die Search Console zeigt „Inhaberschaft bestätigt“ und öffnet die Übersicht der Property. Eine Zeit lang steht dort „Noch keine Daten“. Das ist normal.

## Schritt 5: Search Console mit Google Analytics verknüpfen

Nach der Verknüpfung fließen Suchbegriffe und Zielseiten in die Analytics-Berichte ein. So kannst du Suchverkehr und das Verhalten dieser Besucher gemeinsam betrachten.

1. Öffne in Google Analytics **Verwaltung**.
2. Wähle unter **Produktverknüpfungen** die Option **Search Console-Verknüpfungen**.
3. Klicke auf **Verknüpfen**, dann auf **Konten auswählen** und markiere deine Search-Console-Property. Du musst Inhaber dieser Search-Console-Property und Bearbeiter der Analytics-Property sein.
4. Klicke auf **Weiter**, wähle den Web-Datenstrom und klicke auf **Senden**.

Search-Console-Daten brauchen einige Tage, bis sie eintreffen, und sind rund zwei Tage verzögert. Du musst also nichts abwarten und kannst direkt mit dem nächsten Schritt weitermachen.

Nach der Verknüpfung findest du die zugehörigen Berichte unter **Berichte → Bibliothek**. Search-Console-Berichte erscheinen nicht automatisch im linken Menü. Wenn du sie dort haben möchtest, veröffentliche in der Bibliothek die Sammlung **Search Console**.

Prüfung: Unter **Verwaltung → Produktverknüpfungen → Search Console-Verknüpfungen** ist deine Property aufgelistet.

## Schritt 6: Ereignisverfolgung passend zu deiner Website hinzufügen

Die verbesserte Messung erfasst bereits Seitenaufrufe, Scrollen, Klicks auf externe Links, interne Suchen und Datei-Downloads. Diese Ereignisse solltest du nicht noch einmal selbst implementieren. Eigene Ereignisse brauchst du für das, was für dein Geschäft spezifisch ist: Klicks auf den wichtigsten Call-to-Action, Anmeldungen zum Newsletter, Kontaktformulare und Aufrufe der Preisseite.

Der nützlichste Auftrag lautet nicht „füge ein paar Ereignisse hinzu“, sondern „sieh dir meine Website an, schlage ein Ereigniskonzept vor und warte auf meine Freigabe“. So behältst du die Kontrolle darüber, was gemessen wird.

```text
请查看这个 Astro 网站的结构：页面、布局、组件、行动号召、表单和出站链接。

第 1 步：在修改任何代码之前，先提出事件方案。给我一张表，包含：事件名称、触发时机、参数，以及它回答的业务问题。有合适的 GA4 推荐事件名时优先使用（例如 generate_lead、sign_up、select_content），否则使用 snake_case 的自定义名称。不要重复增强型衡量已经追踪的内容：页面浏览、滚动、出站点击、文件下载。最多 10 个事件。

第 2 步：我批准之后，实现该方案：
- 用 data-ga-event、data-ga-label 和 data-ga-location 属性标记元素。
- 在 document 上使用一个委托的点击监听器，读取这些属性并调用 gtag('event', ...)。不要添加内联的 onclick 处理器。
- 参数只发送稳定的 id 和位置。绝不发送链接文字、表单输入、邮箱地址或任何能识别访客的内容。
- 不要延迟或取消页面跳转。

第 3 步：运行构建、提交、推送，等待两处部署完成，并用 curl 验证线上网站包含该监听器脚本。然后告诉我应该点击哪些位置，以便我在 GA4 DebugView 中验证。
```

Claude antwortet zuerst mit einer Tabelle. Für eine kleine Website sieht ein sinnvoller Vorschlag etwa so aus:

| Ereignis | Auslöser | Parameter | Beantwortete Frage |
| --- | --- | --- | --- |
| `cta_click` | Besucher klickt auf den wichtigsten Call-to-Action-Button | `label`, `location` | Welche Buttons und Bereiche der Seite bewegen Besucher zum Handeln? |
| `generate_lead` | Kontaktformular wurde erfolgreich abgeschickt | `form_id` | Wie viele Besucher werden zu Kontakten? |
| `nav_click` | Klick auf einen Link in Kopf- oder Fußzeile | `label`, `location` | Welche Navigationspunkte werden genutzt? |
| `theme_toggle` | Umschalten des Designs | `value` | Lohnt sich der Schalter für den Dunkelmodus? |

Lies die Tabelle kritisch. Streiche Ereignisse, die niemand auswerten wird, und benenne Ereignisse, die nach einer Funktion statt nach einer Entscheidung benannt sind, um. Antworte dann mit „Freigegeben, aber ohne `theme_toggle`“, damit Claude es umsetzt.

Der Listener, den Claude schreibt, sieht ungefähr so aus:

```js
document.addEventListener(
  'click',
  (event) => {
    const el = event.target.closest('[data-ga-event]');
    if (!el || typeof window.gtag !== 'function') return;
    window.gtag('event', el.dataset.gaEvent, {
      label: el.dataset.gaLabel,
      location: el.dataset.gaLocation,
      transport_type: 'beacon',
    });
  },
  true,
);
```

Der markierte Button:

```astro
<a href="/contact" data-ga-event="cta_click" data-ga-label="hero_contact" data-ga-location="home_hero">
  Kontakt aufnehmen
</a>
```

### Ereignisse prüfen

1. Öffne in Google Analytics **Verwaltung → Datendarstellung → DebugView**. DebugView zeigt eintreffende Ereignisse innerhalb weniger Sekunden.
2. Um den Browser in den Debug-Modus zu versetzen, installiere die Chrome-Erweiterung **Google Analytics Debugger** oder lass Claude vorübergehend `debug_mode: true` im `config`-Aufruf ergänzen.
3. Besuche die Live-Website und führe die Klicks aus, die Claude dir genannt hat.
4. Jeder Klick sollte als Ereignis mit den erwarteten Parametern auf der Zeitleiste der DebugView erscheinen.

Sobald ein Ereignis einmal eingetroffen ist, erscheint es auch unter **Verwaltung → Datendarstellung → Ereignisse**. Möchtest du `label` oder `location` in Standardberichten nutzen, registriere sie unter **Verwaltung → Datendarstellung → Benutzerdefinierte Definitionen → Benutzerdefinierte Dimension erstellen** mit dem Bereich **Ereignis**. Nur so registrierte Parameter tauchen in den Standardberichten auf.

Entferne alle vorübergehenden `debug_mode`-Einstellungen und lass Claude dann die saubere Version pushen.

Prüfung: Jeder erfasste Klick erscheint in der DebugView mit dem richtigen Ereignisnamen und den richtigen Parametern, und der endgültige Code liegt auf `main`.

## Schritt 7: Grundlegende SEO-Schicht hinzufügen

Suchmaschinen brauchen eine Karte der Seiten, Hinweise dazu, was sie crawlen dürfen, und eine Beschreibung, die Menschen sehen, wenn die Seite geteilt wird. Für die Sitemap gibt es eine offizielle Astro-Integration. Der Rest sind ein paar Zeilen im Layout. Claude kann die passenden Astro-Komponenten und Integrationen schnell einbinden.

```text
请为这个 Astro 网站添加基础 SEO。

1. 站点地图：用 `npx astro add sitemap` 安装官方的 @astrojs/sitemap 集成。确保 astro.config.mjs 中的 `site` 是生产域名 https://example.com，并删除 GitHub Pages 项目托管遗留的 `base`。
2. robots.txt：创建 src/pages/robots.txt.ts，返回 "User-agent: *"、"Allow: /" 以及一行指向 https://example.com/sitemap-index.xml 的 Sitemap，该地址由 `site` 配置生成，不要写死。
3. 一个可复用的 SEO 组件，供共享布局使用，输出：<title>；meta description；根据当前 URL 和 `site` 生成的 canonical 链接；Open Graph 标签（og:type、og:title、og:description、og:url、og:image、og:site_name、og:locale）；Twitter 卡片标签（twitter:card summary_large_image、twitter:title、twitter:description、twitter:image）；以及 theme-color meta 标签。每个页面通过 props 传入自己的标题和描述。
4. 在 public/og-default.png 提供一张默认的 1200x630 社交分享图，页面没有提供时使用。
5. 为网站添加 WebSite 类型的 JSON-LD 结构化数据，如果网站有博客，再给文章添加 Article 类型。
6. 运行 `npm run build`，然后列出 dist/sitemap-index.xml，显示 dist/robots.txt，并确认首页构建出的 HTML 包含以上所有标签。

全部正确后，提交、推送，等待两处部署完成，并用 curl 确认 https://example.com/sitemap-index.xml 和 https://example.com/robots.txt 都返回 200 且内容正确。
```

Was die einzelnen Teile bewirken:

- **Sitemap.** `@astrojs/sitemap` erzeugt beim Build `sitemap-index.xml` und eine oder mehrere `sitemap-0.xml`-Dateien. Dafür braucht es die Einstellung `site`, damit absolute URLs entstehen.
- **`robots.txt`.** Sie sagt Crawlern, was sie abrufen dürfen, und verweist auf die Sitemap. Möchtest du, dass eine Seite nicht in der Suche erscheint, verwende `noindex`. Ein Eintrag in `robots.txt` allein reicht dafür nicht.
- **Canonical-Link.** Ist dieselbe Seite über mehrere Adressen erreichbar, teilt er Google mit, welche die offizielle ist.
- **Open-Graph- und Twitter-Tags.** Sie bestimmen Titel, Beschreibung und Bild, die angezeigt werden, wenn ein Link in sozialen Netzwerken oder Chat-Apps geteilt wird.
- **JSON-LD.** Strukturierte Daten helfen Suchmaschinen zu verstehen, worum es auf der Seite geht. Sie garantieren keine erweiterten Suchergebnisse, kosten aber wenig Aufwand.

Prüfung: Die Live-Datei `sitemap-index.xml` listet deine Seiten auf, `robots.txt` enthält die Zeile `Sitemap:`, und im Quellcode der Seiten findest du Canonical-, Open-Graph- und Twitter-Tags. Du kannst die URL auch in einen Validator für Social-Cards einfügen oder in einer Chat-App teilen, um die Vorschau zu sehen.

## Schritt 8: Sitemap in der Search Console einreichen

Die Search Console weiß nichts von deiner Sitemap, solange du sie ihr nicht mitteilst.

1. Öffne in der Search Console deine Property und wähle im linken Menü **Sitemaps**.
2. Gib unter **Neue Sitemap hinzufügen** `sitemap-index.xml` ein.
3. Klicke auf **Senden**.
4. Der Status sollte auf **Erfolgreich** wechseln und die Anzahl gefundener Seiten anzeigen. Zeigt er **Konnte nicht abgerufen werden**, öffne zuerst die Adresse der Sitemap im Browser. Funktioniert sie dort, warte einige Minuten und aktualisiere, denn der erste Abruf kann verzögert sein.

Bitte Google als Nächstes, deine wichtigsten Seiten sofort anzusehen:

1. Füge die URL der Startseite in die Suchleiste oben in der Search Console ein.
2. Ist die Seite noch nicht indexiert, klicke auf **Indexierung beantragen**.

Die Aufnahme in den Index dauert trotzdem einige Tage, und die Berichte der Search Console sind verzögert. Schau nach einer Woche wieder nach.

Prüfung: Unter **Sitemaps** steht `sitemap-index.xml` mit dem Status **Erfolgreich**.

## Schritt 9: Metadaten jeder Seite optimieren und Favicons in mehreren Größen hinzufügen

Die Basisschicht liefert jeder Seite generische Metadaten. Titel und Beschreibung sind der Text, den Menschen in den Suchergebnissen lesen. Sie verdienen deshalb seitenweise Aufmerksamkeit. Favicons brauchen mehrere Größen, weil Browser, Smartphones und Lesezeichen jeweils andere Dateien anfordern.

### Titel, Beschreibungen und Keywords

```text
请检查这个网站的每个页面，并优化它的搜索元数据。

对每个页面，给我一张包含标题、meta description 和关键词的前后对比表，然后应用修改。规则：
- 标题：每页唯一，不超过约 60 个字符，主要主题在前，网站名称在后。
- 描述：每页唯一，120 到 160 个字符，用一句通顺的话说明访客能得到什么并邀请点击。不要堆砌关键词，也不要在页面之间复制文字。
- 关键词：从页面真实内容中提取 5 到 8 个词。只有当布局已经支持时才保留 keywords meta 标签，不要编造页面没有涉及的主题。
- 检查每个页面恰好有一个与标题含义一致的 <h1>，并且每张图片都有 alt 属性。

然后运行构建，并写一份简短的报告，列出仍然共用标题或描述的页面。
```

Setze die Erwartungen richtig: Suchmaschinen ignorieren das Meta-Tag `keywords` weitgehend. Keywords sind trotzdem nützlich, weil du dich beim Aufschreiben zwingst, genau zu sagen, worum es auf jeder Seite geht. In den Suchergebnissen erscheinen tatsächlich Titel und Beschreibung.

### Favicons in verschiedenen Größen

Eine `favicon.svg` ist ein guter Anfang, aber an manchen Stellen braucht es bestimmte Dateien. Ältere Browser und Lesezeichen verwenden `favicon.ico`, das iOS-Home-Bildschirm-Symbol nutzt `apple-touch-icon`, und Android sowie Web-App-Manifeste verwenden PNGs mit 192 und 512 Pixeln.

macOS bringt `sips` mit, um PNGs zu skalieren. Für die Erzeugung einer `.ico`-Datei braucht es ImageMagick, das du über Homebrew installieren kannst. Lass Claude diese Werkzeuge direkt auf deinem Mac verwenden:

```text
请用我的源图片 public/logo-source.png（至少 512x512 的正方形 PNG）生成一套完整的 favicon。

1. 使用 macOS 的 `sips` 命令创建 public/icon-192.png、public/icon-512.png 和 public/apple-touch-icon.png（180x180）。
2. 如果没有安装 ImageMagick，用 `brew install imagemagick` 安装。使用 `magick` 生成包含 16x16、32x32 和 48x48 图像的 public/favicon.ico。
```

## Was du nach einer Woche prüfen solltest

- **Search Console → Seiten** zeigt, wie viele Seiten indexiert sind und warum andere nicht aufgenommen wurden.
- **Search Console → Leistung** zeigt Suchanfragen, Klicks und die durchschnittliche Position. Nutze diese Suchanfragen, um Titel und Beschreibungen zu verbessern.
- **Analytics → Berichte → Interaktion → Ereignisse** zeigt, wie oft deine eigenen Ereignisse ausgelöst werden.
- **Analytics → Berichte → Bibliothek** ist der Ort, an dem die Search-Console-Sammlung erscheint, sobald Daten eintreffen.

## Häufige Probleme

- **Die Echtzeitberichte sind leer.** Ein Werbeblocker oder Datenschutzbrowser blockiert das Tag. Teste in einem privaten Fenster ohne Erweiterungen und prüfe die Mess-ID im Live-HTML.
- **Seitenaufrufe funktionieren, eigene Ereignisse aber nicht.** Öffne die Browser-Konsole auf der Live-Website und führe `typeof window.gtag` aus. Das Ergebnis muss `function` sein. Gibt es `undefined` aus, wurde das Tag-Skript als Modul gebündelt. Lass Claude `is:inline` verwenden und `window.gtag` explizit zuweisen.
- **Ereignisse erscheinen in der DebugView, aber nicht in den Berichten.** Standardberichte hinken bis zu einem Tag hinterher, und benutzerdefinierte Parameter erscheinen erst, wenn sie als benutzerdefinierte Dimension registriert sind.
- **Die Search Console kann die Domain nicht bestätigen.** Prüfe, ob der `TXT`-Eintrag am Root (`@`) liegt, ob der Wert vollständig kopiert wurde und ob kein Cloudflare-Proxy im Spiel ist (TXT-Einträge werden nicht proxied). Warte dann ein wenig und versuche es erneut.
- **Die Sitemap zeigt „Konnte nicht abgerufen werden“.** Öffne `https://example.com/sitemap-index.xml` selbst im Browser. Liefert die Adresse einen 404-Fehler, prüfe, ob `site` in `astro.config.mjs` die Produktionsdomain ist und ob die Sitemap-Integration in `integrations` eingetragen ist.
- **Die Social-Vorschau ist veraltet.** Die Plattformen cachen Vorschauen. Nach Änderungen an den Tags aktualisierst du den Cache mit deren Debug-Werkzeugen.

## Datenschutz und Einwilligung

Analysen erfassen Daten über Besucher. Je nach Region deiner Besucher musst du Google Analytics womöglich erst nach einer Einwilligung laden, zum Beispiel nach der DSGVO und der ePrivacy-Richtlinie in der EU. Außerdem solltest du es in deiner Datenschutzerklärung erwähnen. Der Einfachheit halber installiert dieser Leitfaden das Tag ohne Einwilligungsabfrage. Hat deine Website Besucher aus Regionen mit Einwilligungspflicht, lass Claude einen Cookie-Banner ergänzen, der das Tag erst nach Zustimmung lädt. Dies sind allgemeine Informationen und keine Rechtsberatung.

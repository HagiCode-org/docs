无论通过 [Microsoft Store](/installation/windows-store)、[Desktop](/installation/desktop) 还是 [Docker Compose](/installation/docker-compose) 安装，首次打开 HagiCode 的 Web 界面时都会进入 **初始化向导**。完成它之后，您会拥有一个可用的默认 Hagicoder 和至少一个项目，可以直接开始第一次会话。

:::note[它与 Desktop 的首次使用引导不同]
Desktop 首次启动时的“首次使用引导”（选择语言、确认法律文档、下载 Hagicode Server）发生在 Web 界面出现之前，见 [Desktop 安装](/installation/desktop#首次启动引导)。本页说明的是之后在 Web 界面里出现的初始化向导。
:::

## 开始之前

请先确认：

- **已安装并登录至少一个 Agent CLI**。向导只会列出运行 Hagicode Server 的这台机器上已检测到的 CLI，没有检测到时无法继续创建 Hagicoder。支持的 CLI 与安装方式见 [AI Agent CLI 安装](/related-software-installation/ai-agent-cli/)。
- **Desktop / Store 用户**：已按 [安装指南](/installation/#安装前准备) 安装 Node.js 24+ 与 Git。
- **Docker 用户**：已在 Docker Compose Builder 中配置好 API 提供商与 Token。
- 准备好一个要接入的本地仓库或工作目录：步骤 3 会让您登记它。

## 向导总览

向导由 4 个步骤组成，左侧导航会显示当前进度：

| 步骤 | 目标 | 完成标志 |
| --- | --- | --- |
| 1. 基础设置 | 选择界面语言与主题 | 点击“下一步：设置 Hagicoder” |
| 2. 设置 Hagicoder | 选择 CLI 与模型，创建默认 Hagicoder | 点击“确认并创建 Hagicoder”，或已有可用的 Agent |
| 3. 创建项目 | 至少创建一个项目 | 项目步骤显示“已完成” |
| 4. 社区引导 | 了解社区入口 | 点击“开始使用 HagiCode” |

## 步骤 1：基础设置

**目标**：确定界面语言和主题。

1. 在“选择界面语言”中选一种语言。这只切换界面文本，不会改变 Hagicoder 的语言风格。
2. 在“选择主题”中选一套主题。当前提供“春季亮色”和“春季暗色”。
3. 点击“下一步：设置 Hagicoder”。

## 步骤 2：设置 Hagicoder

**目标**：创建默认 Agent，名字固定为 **Hagicoder**。

如果系统已经存在 Agent，这一步会提示“已检测到现有 Agents”，直接沿用现有编组即可。否则：

1. **选择最常用的 AgentCLI**：下拉列表只显示本机已检测到的 CLI。如果提示没有检测到可用的 CLI，请先按 [AI Agent CLI 安装](/related-software-installation/ai-agent-cli/) 完成安装与登录，再回来刷新。
2. **选择最常用的模型**：
   - **选择现有模板**：复用该 CLI 下已有的模型模板，可按名称或模型 ID 搜索。
   - **自定义模型**：手动输入模型名，例如 `gpt-5.5`、`glm-5.1`、`claude-opus-4-7`，创建时会自动复用或新建对应模板。
3. **（可选）点击“测试可用性”**：向所选 CLI 与模型发送一次 ping-pong 验证，确认模型能返回 `pong`。测试结果只对当前的 CLI 与模型组合有效，修改后需要重新测试；创建 Hagicoder 并不要求测试通过。
4. **（可选）点击“换一组”** 更换默认形象，头像会从图片库随机抽取。
5. 点击“确认并创建 Hagicoder”。创建成功后，它会被加入应急队，所选 CLI 与模型会写入它的默认配置。

:::tip[支持哪些 CLI]
向导里能选的 CLI 取决于本机已安装并被检测到的 Agent CLI，不限于某一种。完整的支持范围与安装方式以 [AI Agent CLI 安装](/related-software-installation/ai-agent-cli/) 为准；其中 Hermes、Gemini、DeepAgents 需要先完成手动安装或认证。
:::

**常见问题**

- **列表里没有我的 CLI**：确认它已安装并在运行 Hagicode Server 的环境中可用；Desktop 用户请重启 Desktop 以刷新 `PATH`。
- **可用性测试失败**：常见原因包括 CLI 尚未登录、令牌无效，或模型名不被该 CLI 支持。请先在终端里用该 CLI 跑一次最小对话，确认它本身可用。
- **加入应急队失败**：页面会提供“重试加入应急队”，重试即可。

## 步骤 3：创建项目

**目标**：至少登记一个项目，让后续会话有可读的工作目录。向导会先检测是否已经有本地项目：已有时显示当前项目摘要，没有时需要先登记一个。

1. 在“登记一个本地项目”中填写项目名称、文件夹路径，以及可选的项目描述。字段与路径校验和主界面的“新建项目”对话框完全一致。
2. 点击“创建并继续”进入下一步；如果想留在本步骤继续添加，点击“仅创建项目”。
3. 已经有项目时，可以直接点击“继续进入社区”，也可以“再创建一个项目”，或返回基础设置。

:::tip[想先用示例项目体验？]
向导里只提供登记本地项目。“演示项目”位于主界面的“新建项目”对话框的“演示项目”页签：它会自动克隆并注册官方 MonoSpecs Demo 仓库，默认路径为 `data/repos/monospecs-demo`，实际目录以运行时的数据目录（DataDir）配置为准。该方式需要 Git，并且能访问 GitHub。
:::

**常见问题**

- **路径校验失败**：确认文件夹路径正确且真实存在；Docker 部署时，填写的必须是容器内可访问的挂载目录，而不是宿主机上的路径。

## 步骤 4：社区引导

**目标**：把社区入口放在手边。

官网“关于”页汇总了完整的社群入口。点击链接会在新标签页中打开；看完后回到向导，点击“开始使用 HagiCode”即可进入工作区。这一步之后仍可随时重新打开向导。

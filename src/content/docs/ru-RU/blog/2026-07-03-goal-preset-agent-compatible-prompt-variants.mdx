## Заставить всех агентов понимать `/goal`: проектирование совместимого расширения пресета непрерывной работы в HagiCode

## Введение

Идеальная постановка задачи для ИИ-агента на «непрерывную работу» выглядит так: вы пишете цель, выбираете репозитории, которые агент может менять, нажимаете «отправить», и агент движется к цели до конца, не задавая встречных вопросов, не уходя в сторону и не трогая другие репозитории.

В HagiCode для этого есть отдельная точка входа: пресет задачи `goal`, а его командная поверхность — `/goal`. Проблема в том, что **не все агенты понимают `/goal`.** У Claude и Codex есть нативная семантика команд непрерывной работы, поэтому `/goal` они принимают сразу. Остальные CLI (Gemini, Copilot, iFlow, OpenCode и другие) такой слеш-команды не имеют. Если передать им `/goal ...` как есть, в лучшем случае её сочтут недействительной командой, а в худшем выполнят буквально и наступят на грабли.

Самый простой первоначальный вариант был таким: разрешить `goal` только для Claude и Codex, а остальных агентов отклонять. Но это отрезает большую часть матрицы агентов. В этой статье рассказано, как мы решили задачу: **с помощью «осведомлённых об агенте» вариантов промптов (prompt variants). Агенты с нативной поддержкой получают нативную команду, агенты без неё получают резервный промпт, поведение согласовано, а опыт одинаков.**

Материал основан на пакете пресета `goal` в `repos/hagitask` и на реализации разбора на бэкенде в `repos/hagicode-core`.

## Контекст

### Что такое `goal`

`goal` — это встроенный пакет плагина пресета задач, он находится в `repos/hagitask/presets/goal/`. В его `manifest.json` объявлены идентичность плагина, иконка, пакеты локализации и фронтенд- и бэкенд-ресурсы:

```jsonc
{
  "taskPresetId": "goal",
  "version": "1.0.0",
  "icon": "flag",
  "kind": "custom-executor",
  "status": "experimental",
  "entrypoints": { "menuSurface": "session-create", "drawerId": "goal" },
  "ui": { "panel": "./frontend/panel.json", "commands": "./frontend/commands.json" },
  "backend": {
    "taskPreset": "./backend/task-preset.json",
    "prompts": "./backend/prompts.json"
  }
}
```

Его назначение — «режим непрерывной работы»: пользователь вводит описание цели (`goalDescription`), при желании ограничивает область записываемых и доступных только для чтения репозиториев, а бэкенд собирает из этого одиночный неинтерактивный запуск auto-task. Ключевые поля фронтенд-панели `panel.json`:

- `goalCommandIds`: селектор команд, встроенный вариант — только один `/goal`;
- `goalDescription`: обязательное описание цели;
- `targetRepositories`: селектор доступа к репозиториям, с разделением на read и write.

### Откуда берётся `/goal`

Командная поверхность задаётся в `frontend/commands.json`, ключевая часть — строка `preludeTemplate`:

```jsonc
{
  "commands": [
    {
      "id": "goal",
      "label": "goal",
      "preludeTemplate": "/goal {goalDescription}"
    }
  ]
}
```

То есть в итоговый промпт, отправляемый агенту, перед основным текстом добавляется строка `/goal <описание цели>`. Для Claude и Codex эта строка — команда, которую они понимают. Для остальных агентов эта строка — то, что нужно «перевести». Вся сложность адаптации в том, что смысл строки `/goal ...` расходится в зависимости от агента.

## Анализ

### Шаблона на одну локаль уже недостаточно

Ранние пакеты промптов HagiTask **разделялись только по языку**: в `prompts.json` для каждой локали задавался свой набор `systemTemplate` и `userTemplate`. Бэкенд `PresetTaskCatalogProvider` читал их в `PromptPackage.Locales`, а во время выполнения выбирался набор по языку запроса.

Для пресетов, чьи инструкции не зависят от агента, такой модели достаточно. Но `goal` устроен иначе:

- Claude / Codex: можно опираться на нативную командную поверхность `/goal`;
- Остальные агенты: нужен более развёрнутый промпт, который явно объясняет, «как войти в режим непрерывной работы», и предупреждает не выполнять `/goal ...` как команду.

Когда при одной и той же локали нужны две очень разные инструкции, разделения по языку недостаточно. Нужно добавить ещё одно измерение: **семейство агента**.

### Отказ от выполнения — неудачное решение

Изначально в `requirements` пресета `goal` агенты были жёстко ограничены `["claude", "codex"]`, остальные сразу считались несовместимыми. У этого подхода были два недостатка:

1. В панели выбора героя (hero) совместимых героев оставалось очень мало, и легко оказаться без выбора;
2. Многие агенты способны выполнять непрерывную работу, просто у них нет нативного `/goal`. Жёсткий отказ тратит их возможности впустую.

Поэтому решать нужно было не вопрос «кто может запустить», а вопрос «**как для одной и той же цели выдать разные, но эквивалентные инструкции в зависимости от возможностей агента**». Ответ: спускать различия, учитывающие агента, на уровень промптов и решать их вариантами с резервом, а не блокировать на уровне допуска.

## Решение

### Селектор вариантов: агент × язык

Новый контракт пакета промптов вводит в `prompts.json` поле `variants`: в `selectors` объявляются измерения сопоставления, а в `entries` — правила сопоставления и файлы шаблонов для каждого варианта:

```jsonc
{
  "version": "1.1.0",
  "templateEngine": "handlebars",
  "variants": {
    "selectors": ["agent", "language"],
    "entries": [
      {
        "id": "native-zh-cn",
        "match": { "agent": ["claude", "codex"], "language": ["zh-CN"] },
        "systemTemplate": "./templates/zh-CN/native.system.md",
        "userTemplate": "./templates/zh-CN/native.user.hbs"
      },
      {
        "id": "fallback-zh-cn",
        "match": { "language": ["zh-CN"] },
        "systemTemplate": "./templates/zh-CN/fallback.system.md",
        "userTemplate": "./templates/zh-CN/fallback.user.hbs"
      }
      // ... native-en-us / fallback-en-us 同理
    ],
    "fallback": {
      "id": "fallback-default",
      "systemTemplate": "./templates/en-US/fallback.system.md",
      "userTemplate": "./templates/en-US/fallback.user.hbs"
    }
  }
}
```

Резерв устроен в три уровня, каждый следующий слабее:

1. **Нативный вариант (native)**: `match` ограничивает одновременно `agent` (claude/codex) и `language`, поэтому срабатывает только для нативных агентов;
2. **Резервный вариант (fallback)**: `match` ограничивает **только `language`, но не `agent`**, поэтому под него подпадает любой агент. Он предназначен для агентов без нативного `/goal`;
3. **fallback-default**: последний запасной вариант, если не совпал даже язык.

Порядок имеет значение: `entries` обходятся в порядке объявления, native стоит перед fallback. Поэтому claude/codex сначала попадают в native, а остальные агенты доходят до языкового fallback-варианта.

### Два набора шаблонов: нативный и резервный

Для одной и той же цели два системных промпта различаются тем, как они относятся к строке `/goal`.

Нативный шаблон (`templates/zh-CN/native.system.md`):

```text
你是 `goal` task preset plugin 的内置执行提示。

本次运行必须使用 `/goal` 作为持续工作模式的命令表面。把提供的项目路径与仓库范围视为权威工作边界。

这次运行处于非交互环境。不要追问用户；当合理假设可以继续推进时，直接继续并把这些假设明确写在响应里。
```

Резервный шаблон (`templates/zh-CN/fallback.system.md`):

```text
你是 `goal` task preset plugin 的兜底执行提示。

当前 agent 可能不支持原生 `/goal` 命令。如果提示前面出现了 `/goal ...` 这一行，把它视为预设附带的目标元数据，不要把它当成必须逐字执行的斜杠命令。

请以持续工作模式完成任务，并把提供的项目路径与仓库范围视为权威工作边界。

这次运行处于非交互环境。不要追问用户；当合理假设可以继续推进时，直接继续并把这些假设明确写在响应里。
```

Суть стратегии резерва — одна фраза: **«Если перед промптом стоит строка `/goal ...`, считайте её метаданными цели, которые прикрепил пресет, а не слеш-командой, которую нужно выполнить буквально.»** Строка `/goal <цель>`, которую добавляет `preludeTemplate`, для нативного агента — команда, а для резервного агента явно понижается до «метаданных / маркера цели». Так обычное следование промпту воспроизводит то же поведение непрерывной работы.

User-шаблоны (`.hbs`) тоже существуют в двух вариантах. В резервном есть раздел с «пояснением маршрутизации»: он прямо говорит агенту, что запрос направлен в ветку, не зависящую от нативного `/goal`, и требует «не полагаться на нативную поддержку `/goal`; выполнить ту же непрерывную работу обычным следованием промпту».

### Бэкенд: один разбор определяет всё

Сопоставление вариантов выполняется в методе `ResolvePromptSelection` файла `PCode.Application/Services/PresetTaskCatalogProvider.cs`. Сначала он разрешает локаль, затем помещает язык и агента в словарь селекторов и по порядку ищет первый подходящий вариант:

```csharp
public PresetTaskResolvedPromptSelection ResolvePromptSelection(string? locale, string? agentFamily)
{
    var resolvedLocale = ResolvePromptLocale(locale);
    if (!PromptPackage.UsesVariants)
    {
        // 旧的仅按 locale 分文件的预设，走遗留路径，保持向后兼容
        var legacyTemplate = PromptPackage.Locales[resolvedLocale];
        return new PresetTaskResolvedPromptSelection(
            resolvedLocale, NormalizeAgentFamily(agentFamily), null, false,
            "legacy-locales", legacyTemplate);
    }

    var normalizedAgentFamily = NormalizeAgentFamily(agentFamily);
    var selectorInputs = new Dictionary<string, string>(StringComparer.OrdinalIgnoreCase)
    {
        [PresetTaskPromptSelectorNames.Language] = resolvedLocale,
    };
    if (!string.IsNullOrWhiteSpace(normalizedAgentFamily))
    {
        selectorInputs[PresetTaskPromptSelectorNames.Agent] = normalizedAgentFamily!;
    }

    foreach (var variant in PromptPackage.Variants)
    {
        if (!VariantMatches(variant, selectorInputs)) continue;
        return new PresetTaskResolvedPromptSelection(
            resolvedLocale, normalizedAgentFamily, variant.Id, false, "variants", variant.Template);
    }

    // 没有变体命中：落到显式声明的 fallback 变体
    return new PresetTaskResolvedPromptSelection(
        resolvedLocale, normalizedAgentFamily, PromptPackage.FallbackVariant?.Id, true,
        "variants", PromptPackage.FallbackVariant?.Template ?? PromptPackage.Locales[resolvedLocale]);
}
```

Правило сопоставления `VariantMatches` простое: **если вариант объявил какие-то селекторы, во время выполнения все они должны совпасть; необъявленные измерения не ограничивают:**

```csharp
private static bool VariantMatches(
    PresetTaskPromptVariantDefinition variant,
    IReadOnlyDictionary<string, string> selectorInputs)
{
    foreach (var selector in variant.Match)
    {
        if (!selectorInputs.TryGetValue(selector.Key, out var runtimeValue))
            return false;
        if (!selector.Value.Contains(runtimeValue, StringComparer.OrdinalIgnoreCase))
            return false;
    }
    return true;
}
```

Отсюда видно, почему fallback-вариант, который задаёт только `language`, покрывает всех агентов: он не ограничивает измерение `agent`, так что любой агент с совпадающим языком попадает в него. А native-вариант дополнительно ограничивает `agent`, поэтому его проходят только claude/codex.

Откуда берётся семейство агента? Во время выполнения оно сопоставляется с типом исполнителя выбранного героя, см. `PresetTaskRequirementModels.cs`:

```csharp
public static string? Resolve(AIProviderType? executorType) => executorType switch
{
    AIProviderType.ClaudeCodeCli => Claude,
    AIProviderType.CodexCli      => Codex,
    AIProviderType.GitHubCopilot => Copilot,
    AIProviderType.IFlowCli      => Iflow,
    AIProviderType.OpenCodeCli   => Opencode,
    // ... gemini / kimi / qoder / kiro / hermes / codebuddy / pi ...
    _ => null,
};
```

`SessionsController.PresetTasks.cs` при создании сессии сначала получает героя, затем вызывает `PresetTaskAgentFamilies.Resolve(hero.ExecutorType)`, чтобы получить имя семейства, и передаёт его в `ResolvePromptSelection`. После выбора варианта `RenderPrompt` рендерит шаблон через Handlebars и добавляет в начало строку `/goal <цель>`, сгенерированную из `preludeTemplate`:

```csharp
var renderedPrompt = prompt.FillTemplate(normalizedContext);
var commandPrelude = BuildCommandPrelude(normalizedContext); // -> "/goal <goalDescription>"
return string.IsNullOrWhiteSpace(commandPrelude)
    ? renderedPrompt
    : $"{commandPrelude}\n\n{renderedPrompt}";
```

### Смягчение допуска: от allowlist к `any`

Имея резервный промпт, `goal` больше не нужно закрывать для нативных агентов. В `requirements` файла `backend/task-preset.json` значение `["claude","codex"]` заменено на `any`:

```jsonc
{
  "taskKey": "goal",
  "requirements": [ { "type": "agent", "name": "any" } ],
  "inputBindings": [
    { "input": "goalCommandIds",  "promptParameter": "goalCommandIds",  "required": true },
    { "input": "goalDescription", "promptParameter": "goalDescription", "required": true },
    { "input": "targetScopeMarkdown", "promptParameter": "targetScopeMarkdown", "producer": "frontend-computed" }
  ]
}
```

Допуск открыт, а различия перенесены на уровень промптов. Это ключевой компромисс всего решения: **совместимость перестаёт быть переключателем «можно ли запустить», а становится маршрутизацией «каким промптом запускать».**

## Практика

### Как выглядит один сквозной запуск

1. Пользователь в панели `goal` вводит описание цели, выбирает область репозиториев и героя, затем отправляет задачу;
2. Бэкенд по типу исполнителя выбранного героя определяет семейство агента (например, `claude` или `gemini`);
3. `ResolvePromptSelection(locale, agentFamily)` ищет вариант по схеме `агент × язык`:
   - claude/codex + zh-CN → `native-zh-cn`;
   - gemini + zh-CN → native не совпадает, выбирается `fallback-zh-cn`;
4. `RenderPrompt` рендерит выбранный шаблон и добавляет в начало `/goal <описание цели>`;
5. Нативный агент выполняет первую строку как команду; резервный агент по системному промпту воспринимает первую строку как метаданные и обычным следованием промпту воспроизводит непрерывную работу.

### Как добавить учёт агента в собственный пресет

Если вы хотите провести такую же адаптацию для нового пресета, порядок действий такой:

1. В `prompts.json` замените `locales` на `variants` и добавьте `agent` в `selectors`;
2. В native-варианте в `match` укажите и `agent`, и `language`; в резервном варианте укажите только `language`;
3. Объявите верхнеуровневый `variants.fallback` как последнюю страховку (схема требует наличия fallback в режиме variants);
4. Бэкенд менять не нужно: `ResolvePromptSelection` и `VariantMatches` универсальны;
5. Если допуск не должен ограничиваться, установите `agent` в `requirements` равным `any`.

### Частые ошибки

- **Порядок вариантов задаёт приоритет.** native должен стоять перед fallback. Иначе fallback, который ограничивает только язык, заберёт всех агентов, и claude/codex никогда не попадут в нативную ветку.
- **Резервный промпт обязан явно «понижать» строку `/goal`.** Префикс `/goal ...` добавляется безусловно (его задаёт `preludeTemplate`), поэтому фразу в резервном системном промпте о том, что её нужно считать метаданными и не выполнять буквально, опускать нельзя. Иначе агент без нативной поддержки может принять строку за недействительную команду.
- **Ограничение на неинтерактивный режим нужно писать в каждом наборе шаблонов.** `goal` — это auto-task, который ставится в очередь. В шаблонах повторяется, что нельзя использовать AskUserQuestion, нельзя задавать вопросы и нужно продолжать с разумными допущениями, явно их указывая. Это защищает от ситуации, когда агент без присмотра зависает в ожидании ввода.
- **Границы репозиториев держатся на промптах, а не на песочнице.** Шаблоны прямо требуют: «менять только репозитории, явно выбранные как записываемые, а репозитории только для чтения использовать как дополнительный контекст». Это мягкое ограничение на уровне промпта, поэтому при выборе области репозиториев нужно внимательно заполнять настройки.
- **Обратная совместимость достаётся бесплатно.** Если старый пресет не объявляет `variants`, а только `locales`, то `UsesVariants` равно false и выполняется путь `legacy-locales`. Старые пресеты при этом не затрагиваются, их не нужно переделывать под новую модель.

## Итоги

Ответ на вопрос «как расширить систему, если агент нативно не поддерживает `goal`» не в том, чтобы под каждого агента писать отдельную ветку кода. Различия моделируются как варианты промптов по схеме `агент × язык`:

- Нативные агенты (Claude / Codex) используют native-вариант и работают напрямую с командной поверхностью `/goal`;
- Агенты без поддержки используют fallback-вариант, который явно понижает `/goal ...` до метаданных цели и воспроизводит то же поведение непрерывной работы обычным следованием промпту;
- Сопоставление основано на универсальном правиле «если вариант объявил селекторы, все они должны совпасть» плюс поэтапном резерве, а разбор на бэкенде выполняется один раз и определяет результат;
- Допуск расширен от allowlist до `any`, так что совместимость стала вопросом «каким промптом запускать», а не «можно ли запустить вообще».

Ценность этого решения не ограничивается пресетом `goal`. Модель «селектор агент × язык с резервом» универсальна: любой пресет, которому нужны разные инструкции в зависимости от возможностей агента, может её переиспользовать, и при этом старые пресеты она не затрагивает.

Это руководство проведёт вас от чистого Mac до сайта, который работает в интернете. Работать вы будете в двух местах: в терминале, где устанавливаете инструменты, и в Claude Code, который выполняет повторяющиеся команды и редактирует файлы за вас. Каждый шаг заканчивается тем, что можно проверить, так что вы будете знать, что всё получилось, прежде чем идти дальше.

Итоговый путь выглядит так:

1. Установите Node.js.
2. Установите GitHub CLI (`gh`) и войдите в аккаунт.
3. Попросите Claude создать приватный репозиторий и клонировать его.
4. Попросите Claude создать каркас сайта на Astro с шапкой, подвалом и адаптивной версткой, затем сохраните (commit) и отправьте (push) изменения.
5. Установите навык impeccable и используйте его команду `overdrive`, чтобы доработать главную страницу.
6. Опубликуйте сайт на GitHub Pages с помощью workflow GitHub Actions.
7. Подключите домен в Cloudflare и разверните ту же ветку через Workers.
8. Добавьте новую страницу, отправьте её и дождитесь завершения обоих развертываний.

## Для кого это руководство

Это руководство для тех, у кого есть Mac и аккаунт GitHub и кто хочет опубликовать простой статичный сайт без настройки сервера. Знать Astro, GitHub Actions или Cloudflare заранее не нужно. Нужно лишь уметь открыть Terminal и вставить команду.

## Предварительные требования

- Mac с актуальной версией macOS.
- Аккаунт GitHub.
- Аккаунт Cloudflare.
- Доменное имя. Его можно зарегистрировать через Cloudflare или использовать уже имеющийся.
- Установленный и авторизованный Claude Code. Запустите `claude` в Terminal один раз, чтобы убедиться, что он запускается.

## Шаг 1: Установите Node.js

Astro и установщик impeccable работают на Node.js. Используйте текущую версию LTS.

Проще всего воспользоваться официальным установщиком с сайта [nodejs.org](https://nodejs.org). Скачайте пакет для macOS, запустите его и примите настройки по умолчанию.

Если вы уже пользуетесь Homebrew, можно установить Node.js из Terminal:

```bash
brew install node
```

Откройте новое окно Terminal и проверьте оба инструмента:

```bash
node --version
npm --version
```

Обе команды должны вывести номер версии. Если `node` не найден, закройте и заново откройте Terminal, чтобы загрузился новый `PATH`.

## Шаг 2: Установите GitHub CLI и войдите в аккаунт

GitHub CLI, который вызывается командой `gh`, позволяет Claude создавать репозитории и управлять ими без нажатий на сайте GitHub.

```bash
brew install gh
gh --version
```

Затем войдите в аккаунт:

```bash
gh auth login
```

Отвечайте на вопросы так:

- **Где вы используете GitHub?** `GitHub.com`
- **Предпочитаемый протокол?** `HTTPS`
- **Аутентифицировать Git вашими учётными данными GitHub?** `Yes`
- **Как вы хотите пройти аутентификацию?** `Login with a web browser`

Скопируйте одноразовый код, который покажет Terminal, нажмите Enter и завершите вход в браузере. Когда закончите, проверьте результат:

```bash
gh auth status
```

В выводе должно быть написано, что вы вошли в `github.com`.

## Шаг 3: Попросите Claude создать приватный репозиторий

Выберите папку, в которой будут храниться ваши проекты, например `~/Sites`, и создайте её, если её ещё нет:

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

Затем дайте Claude такой запрос:

```text
Используй GitHub CLI, чтобы создать приватный репозиторий с именем my-astro-site в моём аккаунте GitHub.
Инициализируй его с README, чтобы появилась ветка main, и клонируй его в эту папку.
Покажи мне URL репозитория, когда закончишь.
```

Claude должен выполнить что-то равнозначное такой команде:

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

Когда всё закончится, у вас появится папка `~/Sites/my-astro-site` с файлом `README.md`, а репозиторий на GitHub будет приватным. Проверьте основную ветку:

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

Команда должна вывести `main`.

## Шаг 4: Создайте каркас сайта на Astro

Оставайтесь в папке репозитория и запустите Claude там:

```bash
cd ~/Sites/my-astro-site
claude
```

Попросите Claude создать простой сайт:

```text
Создай в этом репозитории базовый сайт на Astro, используя официальный стартовый шаблон basics.
Добавь шапку сайта с названием и ссылками навигации, подвал с текстом об авторских правах
и макет, который работает на телефонах, планшетах и широких настольных экранах.
Оформление сделай простым. Запусти dev-сервер, проверь страницу и покажи, как её открыть.
```

Когда Claude закончит, откройте локальный предпросмотр сами:

```bash
npm install
npm run dev
```

Astro выведет локальный адрес, обычно `http://localhost:4321`. Откройте его в браузере, измените размер окна, чтобы проверить верстку, и остановите сервер сочетанием `Control+C`.

Перед сохранением убедитесь, что сборка для публикации проходит без ошибок:

```bash
npm run build
```

### Сохраните и отправьте первую версию

Попросите Claude сохранить работу:

```text
Сделай commit Astro-сайта с понятным сообщением и отправь его в ветку main на origin.
```

Claude должен выполнить команды примерно такие:

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

Убедитесь на GitHub, что ваш последний commit появился в ветке `main` репозитория.

## Шаг 5: Установите impeccable и доработайте главную страницу через Overdrive

[impeccable](https://impeccable.style) — это дизайн-навык для программных агентов. Он даёт Claude общий словарь для работы над дизайном, например `polish`, `critique` и `overdrive`. Команда `overdrive` добавляет более смелые и выразительные эффекты, такие как шейдеры, пружинная физика и анимация при прокрутке.

Попросите Claude установить навык для этого проекта:

```text
Установи навык impeccable в этом проекте с помощью его официального установщика.
Используй область проекта и провайдер Claude Code. Скажи мне, когда нужно будет перезапустить Claude Code.
```

Claude должен выполнить эту команду из корня проекта:

```bash
npx impeccable install
```

Установщик спросит, устанавливать ли навык для этого проекта или глобально, и предложит дизайн-хук. Примите хук, затем перезапустите Claude Code, чтобы загрузился новый навык.

В перезапущенной сессии инициализируйте дизайн-контекст:

```text
/impeccable init
```

Затем примените проход overdrive к главной странице:

```text
/impeccable overdrive the homepage
```

Просмотрите изменения, которые внёс Claude, прежде чем сохранять их. Overdrive может добавить много движения, поэтому, возможно, стоит оставить только те эффекты, которые помогают читателю понять страницу. Попросите Claude снова запустить сборку и отправить результат:

```text
Запусти npm run build, исправь все ошибки, затем сделай commit изменений overdrive и отправь их в main.
```

## Шаг 6: Опубликуйте сайт на GitHub Pages с помощью GitHub Actions

GitHub Pages может бесплатно размещать собранный сайт. Astro предоставляет официальное действие GitHub Action, которое собирает сайт и публикует его.

### Включите Pages

Откройте свой репозиторий на GitHub и перейдите в **Настройки (Settings) → Pages**. В разделе **Сборка и развертывание (Build and deployment)** выберите в поле **Источник (Source)** значение **GitHub Actions**.

### Попросите Claude добавить workflow

```text
Добавь workflow GitHub Actions в файл .github/workflows/deploy.yml, который использует actions/checkout
и withastro/action для сборки этого Astro-сайта и публикации его на GitHub Pages.
Сохрани блок permissions, который есть в шаблоне Astro.
```

Workflow, который создаст Claude, будет похож на пример из официальной документации Astro:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### Укажите адрес сайта

GitHub Pages публикует сайт проекта по пути, например `https://<your-username>.github.io/my-astro-site`. Astro нужно знать этот путь, иначе ссылки и ресурсы сломаются. Попросите Claude обновить `astro.config.mjs`:

```text
Укажи site как https://<your-username>.github.io и base как /my-astro-site в astro.config.mjs.
Объясни, что делает каждый параметр.
```

Результат должен выглядеть так:

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

Замените `<your-username>` на ваше имя пользователя GitHub. Когда позже вы перейдёте на собственный домен, параметр `base` нужно будет удалить.

Сохраните и отправьте workflow и изменение конфигурации:

```text
Сделай commit workflow для Pages и изменения конфигурации Astro, затем отправь их в main.
```

### Дождитесь первого развертывания

Откройте вкладку **Действия (Actions)** в вашем репозитории. Запуск `Deploy to GitHub Pages` должен стать зелёным через минуту или две. Затем откройте адрес Pages, который показан в разделе **Настройки (Settings) → Pages**.

## Шаг 7: Подключите домен в Cloudflare

Для шага с Cloudflare нужен домен. Есть два распространённых варианта:

- **Зарегистрировать новый домен** через Cloudflare Registrar в панели управления Cloudflare.
- **Использовать уже имеющийся домен.** Добавьте его в Cloudflare как сайт, затем измените серверы имён (nameservers) домена у своего регистратора на два сервера имён, которые выдаст Cloudflare.

Войдите в [панель управления Cloudflare](https://dash.cloudflare.com), затем либо зарегистрируйте домен, либо добавьте существующий. Дождитесь, пока Cloudflare покажет домен как активный. После смены серверов имён это может занять несколько минут.

## Шаг 8: Создайте проект Worker из ветки GitHub

Актуальная инструкция Cloudflare для Astro использует Workers. В панели управления поток Git в стиле Pages по-прежнему доступен в том же разделе **Workers & Pages**, но шаги ниже следуют пути Workers.

Сначала попросите Claude добавить конфигурацию Wrangler для статической сборки Astro. Wrangler — это командный инструмент Cloudflare.

```text
Добавь в корень проекта файл wrangler.jsonc для статического сайта на Astro.
Укажи name как my-astro-site, поставь в compatibility_date сегодняшнюю дату
и отдавай папку ./dist как статические ресурсы. Не добавляй main entry point.
```

Файл должен выглядеть так:

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

Сохраните и отправьте файл. Затем создайте проект в Cloudflare:

1. В панели управления Cloudflare перейдите в **Workers & Pages**.
2. Выберите **Создать приложение (Create application)**, затем вариант импорта репозитория из GitHub.
3. Авторизуйте GitHub-приложение **Cloudflare Workers & Pages**, когда Cloudflare об этом попросит. Выберите либо все репозитории, либо только `my-astro-site`.
4. Выберите `my-astro-site` и ветку `main`.
5. Укажите команду сборки `npm run build` (или `npx astro build`), а команду развертывания — `npx wrangler deploy`.
6. Запустите развертывание.

Cloudflare собирает сайт при каждой отправке в подключённую ветку, поэтому будущие commit будут разворачиваться автоматически.

### Подключите домен

Откройте новый Worker в панели управления, перейдите в **Домены и маршруты (Domains & Routes)** и добавьте свой домен или поддомен, например `www`. Cloudflare создаст DNS-запись за вас, если домен уже находится в той же учётной записи.

## Шаг 9: Проверьте сайт в Cloudflare

Когда завершится первая сборка, посмотрите эти разделы панели управления Cloudflare:

- **Развертывания (Deployments):** последняя сборка должна быть отмечена как успешная. Если она завершилась ошибкой, откройте журнал сборки и прочитайте первую ошибку.
- **Домены и маршруты (Domains & Routes):** ваш домен должен быть активным.
- **Настройки (Settings):** убедитесь, что подключённый репозиторий и ветка именно те, которые вы ожидаете.

Затем откройте домен в браузере. Проверьте шапку, подвал и верстку на телефоне, а также в широком окне на компьютере.

## Шаг 10: Добавьте новую страницу и смотрите, как она выходит в сеть

Теперь у вас есть полный цикл: вы редактируете сайт локально, отправляете изменения на GitHub, а затем платформы собирают и публикуют их.

Запустите Claude в папке проекта и попросите новую страницу:

```text
Создай новую страницу src/pages/about.astro с заголовком, коротким абзацем и ссылкой на главную страницу.
Используй ту же шапку и подвал, что и на других страницах. Запусти npm run build, затем сделай commit и отправь в main.
```

Claude должен создать файл, собрать сайт, сделать commit и push. Затем следите за двумя развертываниями:

- **GitHub:** откройте вкладку **Действия (Actions)**. Workflow Pages запустится снова.
- **Cloudflare:** откройте **Workers & Pages → ваш проект → Развертывания (Deployments)**. Новая сборка начнётся автоматически.

Когда оба покажут успех, откройте в браузере `https://<your-domain>/about`. Если страница не открывается, проверьте, что файл лежит по пути `src/pages/about.astro`, что последнее развертывание завершилось и что браузер не показывает старую кешированную копию.

## Частые проблемы

- **`node: command not found`:** откройте новое окно Terminal после установки Node.js.
- **`gh` не может создать репозиторий:** выполните `gh auth status` и убедитесь, что вход выполнен в ваш аккаунт.
- **GitHub Pages показывает пустую страницу или сайт без стилей:** проверьте `site` и `base` в `astro.config.mjs`. Значение `base` должно совпадать с именем репозитория.
- **Сборка в Cloudflare падает:** прочитайте первую ошибку в журнале сборки. Чаще всего причина в отсутствующем скрипте, неверной команде сборки или конфигурации Wrangler, которая указывает на неправильную папку.
- **Домен не активен:** изменения серверов имён могут распространяться долго. Проверьте статус на странице обзора домена в Cloudflare.

## Следующие шаги

Когда сайт будет опубликован, тот же цикл можно использовать и для настоящего содержимого. Попросите Claude добавлять страницы, запустите `/impeccable critique` для дизайн-обзора или добавьте второе окружение Cloudflare для предпросмотров. Главная привычка проста: вносите небольшое изменение, собирайте его локально, сохраняйте (commit) и пусть платформы опубликуют его.

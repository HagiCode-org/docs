HagiCode 让 AI 改代码时不丢上下文：**先读懂仓库，再划清范围，最后可追踪地执行。** 它是面向项目开发的 AI 工作台，接入你已有的 Agent CLI 和模型，不需要换编辑器。

## 一次开发任务怎么走

以“修改一个涉及多个仓库的功能”为例：

1. **先理解**：在[普通会话](/quick-start/conversation-session)中分析现有代码。普通会话默认只读，需要修改文件时再切换到编辑模式。
2. **再定范围**：对于复杂变更，在[提案会话](/quick-start/proposal-session)中选择项目和仓库，先整理目标、任务与验证方式，再推进执行。

   ![新建提案抽屉，展示仓库选择与提案预览](./img/screenshots/shared/create-proposal-drawser/original.png)

3. **跟踪结果**：在工作台回看会话和执行状态；需要整理提交时，可以使用 [AI Compose Commit](/guides/ai-compose-commit)。

   ![提案工作流执行完成后的会话详情](./img/screenshots/shared/classic-proposal-view/original.png)

4. **留下上下文**：提案与提交记录可供回顾；需要跨仓库协作时，使用 [MonoSpecs](/guides/monospecs) 管理仓库关系与变更范围。

你不必每次都走提案流程：只想了解代码或处理简单问题，可以从普通会话开始。HagiCode 的重点是让任务需要更多上下文时，仍有一条可追踪的推进路径。

## 适合谁

- **适合**：同时维护多个仓库、希望复杂改动先规划再执行的开发者和团队；已经在用 Claude Code、Codex 等 Agent CLI，想把它们放进同一个工作台的人。
- **不是必需品**：如果你只需要在编辑器里补全几行代码，现有工具已经够用。

## 让长期进度看得见

HagiCode 把英雄、成就、日报和 Token 做成反馈，让长期使用中的状态与进度更容易被看见，这也是它和普通 AI 编程工具不同的地方。你可以在[冒险团介绍](/adventure-team-introduction)里看看英雄如何编组、副本如何推进；设计思路见[游戏化设计文章](/blog/2026-03-16-gamifying-ai-coding/)。这部分是工作台体验的一部分，不想用时，也可以只把它当作普通开发工具。

## 获取方式与定价

基础功能免费。Desktop、Container 和 Microsoft Store 是三种不同的获取或部署方式，不是三档付费版本。Microsoft Store 渠道另有一次性购买的 Turbo Engine 增强包，用于解锁更高的提案并发上限，以及文档主题、自定义署名、品牌和头像等能力。具体解锁项目以 [Turbo Engine 增强包](/dlc/turbo-engine-dlc/)为准。

| 你的环境 | 建议入口 |
| --- | --- |
| Windows，且可以使用 Microsoft Store | [Microsoft Store 安装](/installation/windows-store) |
| Windows 手动安装，或 macOS、Linux 本地使用 | [Desktop 安装](/installation/desktop) |
| 服务器、NAS 或团队部署 | [Docker Compose 安装](/installation/docker-compose) |

Steam 主应用已退役，不是当前的安装渠道；详情见 [Steam 分发状态](/faq/steam-distribution-status/)。

## 为什么还要做成工作台

我是 HagiCode 的制作人俞坤。单次问答能解决眼前问题，但真实开发还需要理解项目、划定边界、推进变更、回看结果。我希望把这些原本分散的环节连在一起；游戏化反馈则让长期工作中的进度更容易被看见。你可以只使用其中一部分能力，不需要为了开始编码先学会所有模块。

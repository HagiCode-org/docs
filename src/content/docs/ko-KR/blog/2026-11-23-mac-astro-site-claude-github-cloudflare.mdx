이 안내는 깨끗한 Mac에서 인터넷에 공개된 웹사이트까지 가는 과정을 따라갑니다. 작업은 두 곳에서 합니다. 도구를 설치하는 터미널과, 반복적인 명령을 실행하고 파일을 편집해 주는 Claude Code입니다. 각 단계는 제대로 되었는지 확인할 수 있는 결과로 끝나므로, 다음 단계로 넘어가기 전에 잘 되었는지 바로 알 수 있습니다.

완성까지의 과정은 다음과 같습니다:

1. Node.js를 설치합니다.
2. GitHub CLI(`gh`)를 설치하고 로그인합니다.
3. Claude에게 비공개 저장소를 만들고 복제해 달라고 요청합니다.
4. Claude에게 헤더, 푸터, 반응형 레이아웃을 갖춘 Astro 사이트를 만들고, 커밋한 다음 푸시해 달라고 요청합니다.
5. impeccable 스킬을 설치하고 `overdrive` 명령으로 홈페이지를 다듬습니다.
6. GitHub Actions 워크플로로 사이트를 GitHub Pages에 게시합니다.
7. Cloudflare에서 도메인을 연결하고, 같은 브랜치를 Workers로 배포합니다.
8. 새 페이지를 추가해 푸시하고, 두 배포가 끝나는 것을 지켜봅니다.

## 이 안내의 대상

이 안내는 Mac과 GitHub 계정이 있고, 서버를 설정하지 않고 간단한 정적 웹사이트를 게시하고 싶은 분을 위한 것입니다. Astro, GitHub Actions, Cloudflare를 미리 알 필요는 없습니다. 다만 터미널을 열고 명령을 붙여 넣는 일이 익숙해야 합니다.

## 준비물

- 최신 버전의 macOS가 설치된 Mac.
- GitHub 계정.
- Cloudflare 계정.
- 도메인 이름. Cloudflare에서 등록하거나, 이미 가지고 있는 도메인을 사용할 수 있습니다.
- 설치되어 있고 로그인된 Claude Code. 터미널에서 `claude`를 한 번 실행해 정상적으로 시작되는지 확인하세요.

## 1단계: Node.js 설치하기

Astro와 impeccable 설치 도구는 모두 Node.js에서 실행됩니다. 최신 LTS 버전을 사용하세요.

가장 간단한 방법은 [nodejs.org](https://nodejs.org)의 공식 설치 프로그램을 쓰는 것입니다. macOS 패키지를 내려받아 실행하고, 기본 설정을 그대로 두고 진행하세요.

이미 Homebrew를 사용하고 있다면 터미널에서 다음과 같이 설치할 수도 있습니다:

```bash
brew install node
```

터미널 창을 새로 열고 두 도구를 확인합니다:

```bash
node --version
npm --version
```

두 명령 모두 버전 번호가 출력되어야 합니다. `node`를 찾을 수 없다고 나오면 터미널을 닫았다가 다시 열어서 새 `PATH`가 적용되도록 하세요.

## 2단계: GitHub CLI 설치하고 로그인하기

GitHub CLI, 즉 `gh`를 쓰면 Claude가 웹사이트에서 일일이 클릭하지 않고도 저장소를 만들고 관리할 수 있습니다.

```bash
brew install gh
gh --version
```

그다음 로그인합니다:

```bash
gh auth login
```

질문에는 다음과 같이 답하세요:

- **어디서 GitHub를 사용하시나요? (Where do you use GitHub?)** `GitHub.com`
- **선호하는 프로토콜은 무엇인가요? (Preferred protocol?)** `HTTPS`
- **GitHub 자격 증명으로 Git을 인증하시겠습니까? (Authenticate Git with your GitHub credentials?)** `Yes`
- **인증 방법은 어떻게 하시겠습니까? (How would you like to authenticate?)** `Login with a web browser`

터미널에 표시되는 일회용 코드를 복사하고 Enter를 누른 다음, 브라우저에서 로그인을 마치세요. 완료되면 결과를 확인합니다:

```bash
gh auth status
```

출력에 `github.com`에 로그인되어 있다는 내용이 나와야 합니다.

## 3단계: Claude에게 비공개 저장소 만들어 달라고 요청하기

프로젝트를 둘 폴더를 정하세요. 예를 들어 `~/Sites`로 하고, 없으면 만듭니다:

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

그다음 Claude에게 다음과 같이 요청합니다:

```text
GitHub CLI를 사용해서 내 GitHub 계정에 my-astro-site라는 이름의 비공개 저장소를 만들어 주세요.
main 브랜치가 생기도록 README와 함께 초기화하고, 이 폴더에 복제해 주세요.
끝나면 저장소 URL을 보여 주세요.
```

Claude는 다음과 같은 명령을 실행해야 합니다:

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

완료되면 `README.md`가 들어 있는 `~/Sites/my-astro-site` 폴더가 생기고, GitHub에서 저장소가 비공개로 설정되어 있어야 합니다. 기본 브랜치를 확인하세요:

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

`main`이 출력되어야 합니다.

## 4단계: Astro 사이트 만들기

저장소 폴더에 머물면서 그 자리에서 Claude를 시작하세요:

```bash
cd ~/Sites/my-astro-site
claude
```

Claude에게 기본 웹사이트를 만들어 달라고 요청하세요:

```text
Astro의 공식 basics 스타터를 사용해서 이 저장소에 기본 Astro 웹사이트를 만들어 주세요.
사이트 이름과 내비게이션 링크가 있는 사이트 헤더, 저작권 문구가 있는 푸터,
그리고 휴대폰, 태블릿, 넓은 데스크톱 화면에서 모두 잘 보이는 레이아웃을 추가해 주세요.
디자인은 단순하게 유지하세요. 개발 서버를 실행해 페이지를 확인하고, 보는 방법도 알려 주세요.
```

Claude가 작업을 마치면 직접 로컬 미리보기를 열어 보세요:

```bash
npm install
npm run dev
```

Astro가 로컬 주소를 출력합니다. 보통 `http://localhost:4321`입니다. 브라우저에서 열고, 창 크기를 바꿔 레이아웃을 확인한 다음 `Control+C`로 서버를 중지하세요.

커밋하기 전에 프로덕션 빌드가 성공하는지 확인하세요:

```bash
npm run build
```

### 첫 버전 커밋하고 푸시하기

Claude에게 작업 내용을 저장해 달라고 요청하세요:

```text
Astro 사이트를 명확한 메시지와 함께 커밋하고, origin의 main 브랜치에 푸시해 주세요.
```

Claude는 다음과 같은 명령을 실행해야 합니다:

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

GitHub에서 최신 커밋이 저장소의 `main` 브랜치에 보이는지 확인하세요.

## 5단계: impeccable 설치하고 홈페이지에 Overdrive 적용하기

[impeccable](https://impeccable.style)은 코딩 에이전트를 위한 디자인 스킬입니다. Claude에게 `polish`, `critique`, `overdrive` 같은 디자인 작업용 공통 용어를 제공합니다. `overdrive` 명령은 셰이더, 스프링 물리, 스크롤에 따라 움직이는 모션처럼 더 과감하고 표현력 있는 효과를 추가합니다.

이 프로젝트에 스킬을 설치해 달라고 Claude에게 요청하세요:

```text
impeccable 스킬을 공식 설치 프로그램을 사용해서 이 프로젝트에 설치해 주세요.
프로젝트 범위와 Claude Code 제공자를 사용하고, Claude Code를 다시 시작해야 할 때 알려 주세요.
```

Claude는 프로젝트 루트에서 다음 명령을 실행해야 합니다:

```bash
npx impeccable install
```

설치 프로그램은 이 프로젝트에만 설치할지, 전역으로 설치할지 묻고 디자인 훅을 제안합니다. 훅을 수락한 다음 Claude Code를 다시 시작해서 새 스킬이 로드되게 하세요.

다시 시작한 세션에서 디자인 맥락을 초기화하세요:

```text
/impeccable init
```

그다음 홈페이지에 overdrive 작업을 적용하세요:

```text
/impeccable overdrive 홈페이지
```

커밋하기 전에 Claude가 변경한 내용을 검토하세요. Overdrive는 모션을 많이 추가할 수 있으므로, 독자가 페이지를 이해하는 데 도움이 되는 효과만 남기는 것이 좋습니다. 빌드를 다시 실행하고 결과를 푸시하도록 Claude에게 요청하세요:

```text
npm run build를 실행하고 오류가 있으면 고친 다음, overdrive 변경 사항을 커밋하고 main에 푸시해 주세요.
```

## 6단계: GitHub Actions로 GitHub Pages에 게시하기

GitHub Pages는 빌드된 사이트를 무료로 호스팅할 수 있습니다. Astro는 사이트를 빌드하고 배포하는 공식 GitHub Action을 제공합니다.

### Pages 켜기

GitHub에서 저장소를 열고 **Settings → Pages**(설정 → Pages)로 이동하세요. **Build and deployment**(빌드 및 배포) 아래에서 **Source**(소스)를 **GitHub Actions**로 설정하세요.

### Claude에게 워크플로 추가하게 하기

```text
actions/checkout과 withastro/action을 사용해서 이 Astro 사이트를 빌드하고 GitHub Pages에 배포하는 GitHub Actions 워크플로를 .github/workflows/deploy.yml에 추가해 주세요.
Astro 템플릿에 들어 있는 permissions 블록은 그대로 유지해 주세요.
```

Claude가 만드는 워크플로는 Astro 공식 문서의 예시와 비슷할 것입니다:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### 사이트 주소 설정하기

GitHub Pages는 프로젝트 사이트를 `https://<your-username>.github.io/my-astro-site`처럼 경로 아래에서 제공합니다. Astro는 이 경로를 알아야 링크와 자산이 깨지지 않습니다. Claude에게 `astro.config.mjs`를 수정해 달라고 요청하세요:

```text
astro.config.mjs에서 site를 https://<your-username>.github.io로, base를 /my-astro-site로 설정해 주세요.
각 설정이 무엇을 하는지도 설명해 주세요.
```

결과는 다음과 같아야 합니다:

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

`<your-username>`을 여러분의 GitHub 사용자 이름으로 바꾸세요. 나중에 자신의 도메인으로 옮길 때는 `base`를 삭제하면 됩니다.

워크플로와 설정 변경 사항을 커밋하고 푸시하도록 요청하세요:

```text
Pages 워크플로와 Astro 설정 변경을 커밋한 다음 main에 푸시해 주세요.
```

### 첫 배포 기다리기

저장소의 **Actions** 탭을 여세요. `Deploy to GitHub Pages` 실행이 1~2분 뒤 초록색으로 바뀌어야 합니다. 그다음 **Settings → Pages**에 표시된 Pages URL을 여세요.

## 7단계: Cloudflare에서 도메인 연결하기

Cloudflare 단계에는 도메인이 필요합니다. 흔히 두 가지 방법이 있습니다:

- **새 도메인 등록**: Cloudflare 대시보드에서 Cloudflare Registrar를 통해 등록합니다.
- **이미 가진 도메인 사용**: 도메인을 Cloudflare에 사이트로 추가한 다음, 도메인 등록 업체에서 네임서버를 Cloudflare가 알려 주는 두 개의 네임서버로 변경합니다.

[Cloudflare 대시보드](https://dash.cloudflare.com)에 로그인한 다음 도메인을 등록하거나 기존 도메인을 추가하세요. Cloudflare에서 도메인이 활성 상태로 표시될 때까지 기다리세요. 네임서버를 바꾼 뒤에는 몇 분 걸릴 수 있습니다.

## 8단계: GitHub 브랜치로 Worker 프로젝트 만들기

Cloudflare의 최신 Astro 안내는 Workers를 사용합니다. 대시보드에는 여전히 같은 **Workers & Pages** 섹션 아래에 Pages 방식의 Git 흐름이 보이지만, 아래 단계는 Workers 방식을 따릅니다.

먼저 정적 Astro 빌드용 Wrangler 설정을 추가해 달라고 Claude에게 요청하세요. Wrangler는 Cloudflare의 명령줄 도구입니다.

```text
정적 Astro 사이트를 위해 프로젝트 루트에 wrangler.jsonc 파일을 추가해 주세요.
name은 my-astro-site로, compatibility_date는 오늘 날짜로 설정하고,
./dist 폴더를 정적 자산으로 제공해 주세요. main 진입점은 추가하지 마세요.
```

파일은 다음과 같아야 합니다:

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

파일을 커밋하고 푸시하세요. 그다음 Cloudflare 프로젝트를 만듭니다:

1. Cloudflare 대시보드에서 **Workers & Pages**로 이동합니다.
2. **Create application**(애플리케이션 만들기)을 선택한 다음, GitHub에서 저장소를 가져오는 옵션을 고릅니다.
3. Cloudflare가 요청하면 **Cloudflare Workers & Pages** GitHub 앱을 승인하세요. 모든 저장소 또는 `my-astro-site`만 선택할 수 있습니다.
4. `my-astro-site`와 `main` 브랜치를 선택합니다.
5. 빌드 명령은 `npm run build`(또는 `npx astro build`)로, 배포 명령은 `npx wrangler deploy`로 설정합니다.
6. 배포를 시작합니다.

Cloudflare는 연결된 브랜치에 푸시할 때마다 사이트를 빌드하므로, 앞으로의 커밋은 자동으로 배포됩니다.

### 도메인 연결하기

대시보드에서 새 Worker를 열고 **Domains & Routes**(도메인 및 라우트)로 이동한 다음, 도메인이나 `www` 같은 서브도메인을 추가하세요. 도메인이 같은 계정에 이미 있다면 Cloudflare가 DNS 레코드를 자동으로 만들어 줍니다.

## 9단계: Cloudflare에서 사이트 확인하기

첫 빌드가 끝나면 Cloudflare 대시보드의 다음 위치를 확인하세요:

- **Deployments**(배포): 가장 최근 빌드가 성공으로 표시되어야 합니다. 실패했다면 빌드 로그를 열고 첫 번째 오류를 읽어 보세요.
- **Domains & Routes**(도메인 및 라우트): 사용자 도메인이 활성 상태로 표시되어야 합니다.
- **Settings**(설정): 연결된 저장소와 브랜치가 원하는 것이 맞는지 확인하세요.

그다음 브라우저에서 도메인을 여세요. 휴대폰과 넓은 데스크톱 창에서 헤더, 푸터, 레이아웃을 모두 확인하세요.

## 10단계: 새 페이지를 추가하고 공개되는 과정 지켜보기

이제 전체 순환을 갖추었습니다. 로컬에서 편집하고, GitHub에 푸시하면, 호스팅 서비스가 변경 사항을 빌드하고 배포합니다.

프로젝트 폴더에서 Claude를 시작하고 새 페이지를 요청하세요:

```text
src/pages/about.astro에 제목, 짧은 문단, 홈페이지로 돌아가는 링크가 있는 새 페이지를 만들어 주세요.
다른 페이지와 같은 헤더와 푸터를 사용하세요. npm run build를 실행한 다음 main에 커밋하고 푸시해 주세요.
```

Claude는 파일을 만들고, 사이트를 빌드하고, 커밋과 푸시를 해야 합니다. 그다음 두 배포를 지켜보세요:

- **GitHub**: **Actions** 탭을 엽니다. Pages 워크플로가 다시 실행됩니다.
- **Cloudflare**: **Workers & Pages → 사용자 프로젝트 → Deployments**를 엽니다. 새 빌드가 자동으로 시작됩니다.

둘 다 성공으로 표시되면 브라우저에서 `https://<your-domain>/about`을 여세요. 페이지가 보이지 않으면 파일이 `src/pages/about.astro`에 있는지, 최신 배포가 끝났는지, 브라우저가 오래된 캐시 화면을 보여 주고 있지 않은지 확인하세요.

## 자주 생기는 문제

- **`node: command not found`:** Node.js를 설치한 뒤 터미널 창을 새로 여세요.
- **`gh`로 저장소를 만들 수 없음:** `gh auth status`를 실행하고, 로그인한 계정이 내 계정에 접근할 수 있는지 확인하세요.
- **GitHub Pages에 빈 페이지가 나오거나 스타일이 없음:** `astro.config.mjs`의 `site`와 `base`를 확인하세요. `base` 값은 저장소 이름과 일치해야 합니다.
- **Cloudflare 빌드 실패:** 빌드 로그의 첫 번째 오류를 읽으세요. 대부분은 스크립트가 없거나, 빌드 명령이 잘못되었거나, Wrangler 설정이 잘못된 폴더를 가리키는 데서 생깁니다.
- **도메인이 활성 상태가 아님:** 네임서버 변경은 반영되는 데 시간이 걸릴 수 있습니다. Cloudflare에서 도메인 개요 페이지의 상태를 확인하세요.

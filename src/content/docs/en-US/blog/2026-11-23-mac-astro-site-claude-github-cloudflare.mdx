This guide takes you from a clean Mac to a website that is live on the internet. You will do the work in two places: your terminal, where you install tools, and Claude Code, which runs the repetitive commands and edits the files for you. Each step ends with something you can check, so you know it worked before you move on.

The finished path looks like this:

1. Install Node.js.
2. Install GitHub CLI (`gh`) and log in.
3. Ask Claude to create a private repository and clone it.
4. Ask Claude to scaffold an Astro site with a header, a footer and a responsive layout, then commit and push it.
5. Install the impeccable skill and use its `overdrive` command to polish the homepage.
6. Publish the site to GitHub Pages with a GitHub Actions workflow.
7. Connect a domain in Cloudflare and deploy the same branch with Workers.
8. Add a new page, push it, and watch both deployments finish.

## Who This Guide Is For

This guide is for people who have a Mac and a GitHub account and want to publish a simple static website without setting up a server. You do not need to know Astro, GitHub Actions or Cloudflare beforehand. You do need to be comfortable opening Terminal and pasting commands.

## Prerequisites

- A Mac running a current version of macOS.
- A GitHub account.
- A Cloudflare account.
- A domain name. You can register one through Cloudflare or use one you already own.
- Claude Code installed and signed in. Run `claude` in Terminal once to confirm it starts.

## Step 1: Install Node.js

Astro and the impeccable installer both run on Node.js. Use the current LTS release.

The simplest route is the official installer from [nodejs.org](https://nodejs.org). Download the macOS package, run it and accept the defaults.

If you already use Homebrew, you can install it from Terminal instead:

```bash
brew install node
```

Open a new Terminal window and check both tools:

```bash
node --version
npm --version
```

Both commands should print a version number. If `node` is not found, close and reopen Terminal so the new `PATH` is loaded.

## Step 2: Install GitHub CLI and Log In

GitHub CLI, called `gh`, lets Claude create repositories and manage them without you clicking through the website.

```bash
brew install gh
gh --version
```

Then log in:

```bash
gh auth login
```

Answer the prompts like this:

- **Where do you use GitHub?** `GitHub.com`
- **Preferred protocol?** `HTTPS`
- **Authenticate Git with your GitHub credentials?** `Yes`
- **How would you like to authenticate?** `Login with a web browser`

Copy the one-time code that Terminal shows, press Enter, and finish the sign-in in your browser. When you are done, check the result:

```bash
gh auth status
```

The output should say that you are logged in to `github.com`.

## Step 3: Ask Claude to Create a Private Repository

Pick a folder where you want your projects to live, for example `~/Sites`, and create it if it does not exist:

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

Then give Claude a request like this:

```text
Use the GitHub CLI to create a private repository named my-astro-site on my GitHub account.
Initialize it with a README so the main branch exists, and clone it into this folder.
Show me the repository URL when you are done.
```

Claude should run something equivalent to:

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

When it finishes, you should have a `~/Sites/my-astro-site` folder that contains a `README.md`, and the repository should be private on GitHub. Check the default branch:

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

It should print `main`.

## Step 4: Scaffold the Astro Site

Stay in the repository folder and start Claude there:

```bash
cd ~/Sites/my-astro-site
claude
```

Ask Claude to build a basic site:

```text
Create a basic Astro website in this repository using Astro's official basics starter.
Add a site header with the site name and navigation links, a footer with copyright text,
and a layout that works on phones, tablets and wide desktop screens.
Keep the design simple. Run the dev server, check the page, and show me how to view it.
```

Once Claude has finished, open the local preview yourself:

```bash
npm install
npm run dev
```

Astro prints a local address, usually `http://localhost:4321`. Open it in your browser, resize the window to check the layout, then stop the server with `Control+C`.

Before you commit, make sure the production build passes:

```bash
npm run build
```

### Commit and push the first version

Ask Claude to save the work:

```text
Commit the Astro site with a clear message and push it to the main branch on origin.
```

Claude should run commands such as:

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

Confirm on GitHub that your latest commit appears on the repository's `main` branch.

## Step 5: Install impeccable and Overdrive the Homepage

[impeccable](https://impeccable.style) is a design skill for coding agents. It gives Claude a shared vocabulary for design work, such as `polish`, `critique` and `overdrive`. The `overdrive` command adds bolder, more expressive effects such as shaders, spring physics and scroll-driven motion.

Ask Claude to install the skill for this project:

```text
Install the impeccable skill in this project using its official installer.
Use project scope and the Claude Code provider. Tell me when I need to restart Claude Code.
```

Claude should run this from the project root:

```bash
npx impeccable install
```

The installer asks whether to install for this project or globally, and offers a design hook. Accept the hook, then restart Claude Code so the new skill loads.

In the restarted session, initialize the design context:

```text
/impeccable init
```

Then apply the overdrive pass to the homepage:

```text
/impeccable overdrive the homepage
```

Review what Claude changed before you commit. Overdrive can add a lot of motion, so you may want to keep only the effects that help readers understand the page. Ask Claude to run the build again and push the result:

```text
Run npm run build, fix any errors, then commit the overdrive changes and push them to main.
```

## Step 6: Publish to GitHub Pages with GitHub Actions

GitHub Pages can host the built site for free. Astro provides an official GitHub Action that builds the site and deploys it.

### Turn on Pages

Open your repository on GitHub, then go to **Settings → Pages**. Under **Build and deployment**, set **Source** to **GitHub Actions**.

### Let Claude add the workflow

```text
Add a GitHub Actions workflow at .github/workflows/deploy.yml that uses actions/checkout
and withastro/action to build this Astro site and deploy it to GitHub Pages.
Keep the permissions block that Astro's template includes.
```

The workflow Claude creates will look similar to Astro's documented example:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### Set the site address

GitHub Pages serves a project site under a path, such as `https://<your-username>.github.io/my-astro-site`. Astro needs to know that path, or its links and assets will break. Ask Claude to update `astro.config.mjs`:

```text
Set site to https://<your-username>.github.io and base to /my-astro-site in astro.config.mjs.
Explain what each setting does.
```

The result should look like this:

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

Replace `<your-username>` with your GitHub username. When you later move to your own domain, you will remove `base`.

Commit and push the workflow and the config change:

```text
Commit the Pages workflow and the Astro config change, then push to main.
```

### Wait for the first deployment

Open the **Actions** tab in your repository. The `Deploy to GitHub Pages` run should turn green after a minute or two. Then open the Pages URL shown under **Settings → Pages**.

## Step 7: Connect a Domain in Cloudflare

You need a domain for the Cloudflare step. There are two common options:

- **Register a new domain** through Cloudflare Registrar from the Cloudflare dashboard.
- **Use a domain you already own.** Add it to Cloudflare as a site, then change the domain's nameservers at your registrar to the two nameservers Cloudflare gives you.

Sign in to the [Cloudflare dashboard](https://dash.cloudflare.com), then either register the domain or add your existing domain. Wait until Cloudflare shows the domain as active. This can take a few minutes after a nameserver change.

## Step 8: Create a Worker Project from the GitHub Branch

Cloudflare's current Astro guidance uses Workers. In the dashboard, the Pages-style Git flow still appears under the same **Workers & Pages** section, but the steps below follow the Workers path.

First, ask Claude to add a Wrangler configuration for a static Astro build. Wrangler is Cloudflare's command-line tool.

```text
Add a wrangler.jsonc file at the project root for a static Astro site.
Set the name to my-astro-site, set compatibility_date to today's date,
and serve the ./dist folder as static assets. Do not add a main entry point.
```

It should look like this:

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

Commit and push the file. Then create the Cloudflare project:

1. In the Cloudflare dashboard, go to **Workers & Pages**.
2. Select **Create application**, then choose the option to import a repository from GitHub.
3. Authorize the **Cloudflare Workers & Pages** GitHub app when Cloudflare asks. Choose either all repositories or only `my-astro-site`.
4. Select `my-astro-site` and the `main` branch.
5. Set the build command to `npm run build` (or `npx astro build`) and the deploy command to `npx wrangler deploy`.
6. Start the deployment.

Cloudflare builds the site on each push to the connected branch, so future commits will deploy automatically.

### Attach your domain

Open the new Worker in the dashboard, go to **Domains & Routes**, and add your domain or a subdomain such as `www`. Cloudflare creates the DNS record for you when the domain is already in the same account.

## Step 9: Check the Site in Cloudflare

After the first build finishes, look at these places in the Cloudflare dashboard:

- **Deployments:** the latest build should be marked as successful. If it failed, open the build log and read the first error.
- **Domains & Routes:** your custom domain should show as active.
- **Settings:** confirm that the connected repository and branch are the ones you expect.

Then open your domain in a browser. Check the header, footer and layout on your phone, as well as on a wide desktop window.

## Step 10: Add a New Page and Watch It Go Live

Now you have the full loop: edit locally, push to GitHub, then let the hosts build and deploy the change.

Start Claude in the project folder and ask for a new page:

```text
Create a new page at src/pages/about.astro with a title, a short paragraph and a link back to the homepage.
Use the same header and footer as the other pages. Run npm run build, then commit and push to main.
```

Claude should create the file, build the site, commit and push. Then watch the two deployments:

- **GitHub:** open the **Actions** tab. The Pages workflow runs again.
- **Cloudflare:** open **Workers & Pages → your project → Deployments**. A new build starts automatically.

When both show success, open `https://<your-domain>/about` in your browser. If the page is missing, check that the file is at `src/pages/about.astro`, that the latest deployment finished, and that your browser is not showing an old cached copy.

## Common Problems

- **`node: command not found`:** open a new Terminal window after installing Node.js.
- **`gh` cannot create the repository:** run `gh auth status` and make sure the login has access to your account.
- **GitHub Pages shows a blank page or missing styles:** check `site` and `base` in `astro.config.mjs`. The `base` value must match the repository name.
- **Cloudflare build fails:** read the first error in the build log. Most failures come from a missing script, a wrong build command, or a Wrangler config that points at the wrong folder.
- **The domain is not active:** nameserver changes can take time to propagate. Check the status on the domain's overview page in Cloudflare.

## Next Steps

Once the site is live, you can keep the same loop for real content. Ask Claude to add pages, run `/impeccable critique` for a design review, or add a second Cloudflare environment for previews. The main habit to keep is simple: make a small change, build it locally, commit it, and let the hosts publish it.

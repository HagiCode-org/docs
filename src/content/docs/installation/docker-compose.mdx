本页说明如何用 Docker Compose 部署 Hagicode。它适合服务器、NAS、团队共享或需要环境隔离的场景；个人本地使用请优先考虑 [Microsoft Store](/installation/windows-store) 或 [Desktop](/installation/desktop)。

:::tip[为什么选 Docker Compose]
- 环境隔离，依赖冲突更少
- 可一次启动当前支持的 Hagicode 服务栈
- 配置、升级与维护路径统一
- 宿主机只需要 Docker，**无需另外安装 Node.js 或 Git**
:::

:::note[关于默认数据存储]
当前支持的 Docker Compose 模板按默认本地 SQLite 数据路径组织持久化数据。大多数情况下，您不需要在主机上额外准备独立数据库服务。
:::

## 前置要求

在开始之前，请确保您的系统已安装 Docker 和 Docker Compose。

### 安装 Docker

#### Windows

下载并安装 [Docker Desktop for Windows](https://www.docker.com/products/docker-desktop/)。安装完成后，确保 Docker Desktop 正在运行。

#### macOS

下载并安装 [Docker Desktop for Mac](https://www.docker.com/products/docker-desktop/)。安装完成后，确保 Docker Desktop 正在运行。

#### Linux

请按 Docker 官方文档为您的发行版安装 Docker Engine 与 Docker Compose 插件：[Install Docker Engine](https://docs.docker.com/engine/install/)。不同发行版的软件源与包名不同，请不要直接套用其他发行版的命令。

安装完成后，启动 Docker 服务并设置开机启动：

```bash
sudo systemctl start docker
sudo systemctl enable docker
```

### 验证安装

安装完成后，运行以下命令验证 Docker 和 Docker Compose 是否正确安装：

```bash
docker --version
docker compose version
```

## 快速开始

### 1. 生成 Docker Compose 配置文件

使用 [Docker Compose Builder](https://builder.hagicode.com/) 生成 `docker-compose.yml`。它是独立站点，生成规则与更新以该站点为准。

生成器支持：
- 选择 API 提供商（智谱 AI、Anthropic 官方、自定义 API），并配置 API URL 与 Token
- 自定义端口、容器名称、持久化目录与工作目录
- 选择内置数据库或外部数据库
- 自动处理 Windows / Linux 的平台差异与常见文件权限问题
- 使用受支持的 Docker Hub 镜像

操作步骤：

1. 打开 [Docker Compose Builder](https://builder.hagicode.com/)。
2. 根据您的需求填写配置：选择 API 提供商，配置端口、数据库、工作目录等选项。
3. 点击生成按钮，获取 `docker-compose.yml` 配置。
4. 将生成的配置保存为 `docker-compose.yml` 文件。
5. 如果需要，创建 `.env` 文件配置敏感信息，避免把 Token 直接写进 compose 文件。

#### 镜像来源

生成器使用 Docker Hub 作为受支持的镜像来源：

- **镜像地址**：`newbe36524/hagicode:{tag}`
- **适用场景**：适合支持 Docker Hub 镜像加速的用户
- **注意事项**：部分地区可能需要配置镜像加速器

:::note[获取 API Token]
Docker 部署通过生成器配置的 API 提供商访问模型，您需要先准备一个可用的 API Token：

**智谱 AI**：[获取 API Token →](https://www.bigmodel.cn/glm-coding?ic=14BY54APZA)
- 国内访问稳定，响应更快
- 性价比高，适合日常使用

**Anthropic 官方**：[获取 API Token →](https://console.anthropic.com/)
- 直接使用 Anthropic 的服务

也可以在生成器中选择自定义 API。
:::

### 2. 启动服务

在 `docker-compose.yml` 所在目录执行以下命令：

```bash
docker compose up -d
```

此命令将：
- 下载并启动生成配置中定义的 Hagicode 容器
- 创建并配置网络
- 初始化默认数据目录与运行时依赖

### 3. 验证服务状态

检查容器是否正在运行：

```bash
docker compose ps
```

您应该看到生成配置中定义的服务处于 "running" 状态。

查看服务日志：

```bash
# 查看所有服务日志
docker compose logs

# 查看 Hagicode 服务日志
docker compose logs hagicode

# 实时跟踪日志
docker compose logs -f hagicode
```

## 访问应用

服务启动成功后，通过浏览器访问：

```
http://localhost:45000
```

如果您在生成器中修改了端口，请使用您设置的主机端口。首次打开时会进入初始化向导，请继续阅读 [初始化向导设置](/quick-start/wizard-setup)。

## 配置说明

如需修改配置（如更改端口、切换 API 提供商等），您可以：

1. 重新使用 [Docker Compose Builder](https://builder.hagicode.com/) 生成新配置
2. 手动编辑 `docker-compose.yml` 和 `.env` 文件
3. 重新创建容器使配置生效：

```bash
docker compose up -d
```

:::note
`docker compose restart` 只会重启现有容器，不会应用对 `docker-compose.yml` 或 `.env` 的修改。修改配置后请使用 `docker compose up -d`。
:::

## 数据持久化

当前支持的 Docker Compose 路径默认使用 SQLite 数据文件与持久化卷。若您需要检查数据挂载位置或备份策略，请直接查看生成后的 `docker-compose.yml` 中卷与数据目录映射配置。

## 日常维护

### 停止与启动

```bash
# 停止服务（保留容器与数据）
docker compose stop

# 再次启动
docker compose start

# 停止并移除容器（数据卷仍然保留）
docker compose down
```

:::caution
不要随意给 `docker compose down` 加上 `-v`，它会同时删除 compose 文件中声明的数据卷。
:::

### 升级版本

1. 在升级前先备份数据目录（见下文）。
2. 将 `docker-compose.yml` 中的镜像标签 `newbe36524/hagicode:{tag}` 改为目标版本，或重新用生成器生成配置。
3. 拉取新镜像并重新创建容器：

```bash
docker compose pull
docker compose up -d
```

### 备份数据

先执行 `docker compose stop` 让服务停止写入，再备份 `docker-compose.yml` 中卷与数据目录映射所对应的目录或数据卷，然后执行 `docker compose start` 恢复服务。

**适用对象：** 想了解 HagiTask 生态的使用者、维护者和贡献者。

**前置条件：** 无。若要安装或运行任务，请先准备好 HagiCode 应用及其后端服务。

## HagiTask 是什么

HagiTask 是 HagiCode 的任务包和预设任务模型。一个任务包把任务身份、前端面板、后端提示词、模板、界面文案和商店介绍放在同一个可校验的目录中，应用可以据此发现、安装、管理并运行任务。

任务包不是应用本身，也不会取代应用的运行时配置。应用负责加载任务并执行任务声明的能力；任务包只提供经过约定格式组织的资源。

## 生态中的几个角色

| 角色 | 责任 |
| --- | --- |
| HagiTask | 维护共享 Schema 和随产品发布的内置预设包，是包格式的 source of truth。 |
| 内置预设 | 随应用或运行时提供的可用任务，例如 `normal-session` 和 `research-investigation`。 |
| Community Packages | 维护社区任务的源数据，目录位于 `data/<taskId>/`。 |
| HagiTask Site | 从社区包源生成目录、详情 JSON 和 ZIP 归档，发布到 Community Gallery。 |
| HagiCode 应用 | 展示任务、安装包、保存启用状态，并在运行时执行任务。 |

内置预设与社区任务使用相同的包 Schema，但来源和生命周期不同：内置预设由 HagiTask 仓库维护，社区任务由 Community Packages 仓库维护。站点上的 `/index.json`、详情文档和 ZIP 都是生成产物，不是贡献者直接编辑的源文件。

## 包管理和来源管理不是一回事

从 Gallery 安装一个 ZIP，是把包复制到应用的数据目录并登记版本、来源和启用状态。服务器来源管理则是配置服务器可见的目录，让运行时从该目录发现任务；它不会把浏览器本地文件夹上传为安装包。

有关操作边界和文件夹来源，请阅读[使用 HagiTask](/guides/hagitask/usage)。准备安装时，继续阅读[安装 HagiTask](/guides/hagitask/installation)；要创建或发布任务，请阅读[参与社区贡献](/guides/hagitask/community)。

## Source of truth 责任边界

- docs 维护面向使用者和贡献者的叙事与操作指南。
- HagiTask 维护共享 Schema 和内置预设源。
- Community Packages 维护社区包源数据。
- HagiTask Site 发布由包源生成的目录、详情和归档。

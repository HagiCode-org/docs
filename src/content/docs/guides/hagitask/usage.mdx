---
title: 使用 HagiTask
description: 发现、安装、启用、刷新和运行 HagiTask，并理解来源管理边界。
---

**适用对象：** 已安装 HagiCode 并需要管理或运行任务的用户。

**前置条件：** 已完成[安装 HagiTask](/guides/hagitask/installation)，或应用已经提供内置预设。

## 发现任务

打开应用的 HagiTask/社区任务管理界面。应用会合并显示内置、已安装的社区包、工作区包和受管理来源，并标识每个任务的来源以及是否可移除。社区 Gallery 的目录用于发现和获取社区包；服务器可见目录用于运行时来源发现。

## 安装任务

从 Gallery 选择任务并安装，或对已经取得的受支持 ZIP 使用本地归档安装。安装成功后，应用会记录规范 ID、版本、发布者、来源、归档摘要和安装目录。相同 ID 的已安装任务不会被静默覆盖；需要先处理现有安装。

## 启用和禁用

- **启用：** 将已安装任务放入活动任务目录，使它可以被发现和运行。
- **禁用：** 保留安装记录和包文件，但从活动目录移出，任务不会被运行。
- **卸载：** 只适用于有安装记录的社区任务；内置任务只是信息项，不能卸载。

状态变化完成后，应用会刷新目录。若刷新失败，生命周期操作应保持原有可用状态，而不是留下半完成的目录。

## 刷新和运行

使用刷新操作重新读取当前任务目录。当 Gallery 目录被强制刷新时，应用会重新获取并校验目录；已有有效缓存可能在上游暂时失败时继续提供。刷新不会自动改变任务的启用状态或版本。

运行前确认任务已启用且依赖满足，然后从任务面板或对应的运行入口执行。若任务不显示，先刷新并检查安装状态、任务 ID 和兼容性提示；若 Schema 或包资源无效，请查看[社区贡献指南](/guides/hagitask/community)。

## 包管理与服务器来源管理

这两个操作经常被混淆：

| 能力 | 作用 | 路径含义 |
| --- | --- | --- |
| 包管理 | 安装、启用、禁用和卸载本地 HagiTask 包。 | 应用管理的数据目录。 |
| 服务器来源管理 | 配置运行时用于目录发现的任务源。 | 必须是服务器可见的目录。 |

服务器来源中的路径由后端读取，用于发现目录里的任务包；它不是浏览器路径，也不是上传控件。当前安装流程不把浏览器本地文件夹直接上传为 Community Gallery 包。要安装包，请使用 Gallery 或受支持的本地 ZIP 流程。

## 任务不可用时

1. 确认任务 ID、版本和安装记录仍存在。
2. 确认任务已启用，且所需 agent、skills 和 CLI 已准备。
3. 刷新任务目录并重新打开管理界面。
4. 如果来源是服务器目录，确认后端进程对路径有读取权限。
5. 如果归档校验或包资源失败，回到[安装故障排查](/guides/hagitask/installation)；如果你维护该包，阅读[参与社区贡献](/guides/hagitask/community)。

En la [guía anterior](/es-ES/blog/2026-11-23-mac-astro-site-claude-github-cloudflare/), partiste de un Mac limpio y creaste un sitio Astro desplegado en GitHub Pages y Cloudflare. Publicar el sitio solo completa la mitad del trabajo: todavía necesitas saber si alguien lo visita, qué hacen los visitantes y si Google puede encontrarlo.

Esta guía cubre esa parte. Vas a registrar Google Analytics y Google Search Console, y luego le pedirás a Claude que conecte el seguimiento, el mapa del sitio, las etiquetas sociales y el favicon. Cada paso termina con un resultado que puedes comprobar antes de continuar.

El flujo completo es este:

1. Crea una propiedad de Google Analytics y copia su ID de medición.
2. Pide a Claude que conecte Google Analytics al sitio, lo suba, espere a que termine el despliegue y demuestre que el código existe en producción.
3. Confirma en Google Analytics que tus visitas aparecen en tiempo real.
4. Registra el sitio en Google Search Console.
5. Vincula Search Console con Google Analytics.
6. Pide a Claude que diseñe y añada seguimiento de eventos adaptado a tu sitio, luego publícalo y verifícalo.
7. Pide a Claude que añada la capa básica de SEO: mapa del sitio, `robots.txt`, enlaces canónicos, Open Graph y etiquetas de Twitter.
8. Envía el mapa del sitio en Search Console.
9. Pide a Claude que optimice el título, la descripción y las palabras clave de cada página, y usa herramientas de línea de comandos en tu Mac para generar favicons de varios tamaños.

## Para quién es esta guía

Es para quien completó la guía anterior: tienes un proyecto Astro en un repositorio de GitHub, cada envío a `main` se despliega automáticamente y tienes un dominio público. No necesitas experiencia previa con herramientas de analítica, pero sí debes poder pegar instrucciones breves en Claude Code y hacer clic en algunas páginas de Google.

## Requisitos previos

- Un sitio Astro ya publicado en la guía anterior, con tu dominio personalizado funcionando. En esta guía el repositorio se llama `my-astro-site` y el dominio `example.com`; sustitúyelos por los tuyos.
- Una cuenta de Google.
- Claude Code instalado e iniciado sesión, y `gh` con sesión iniciada (`gh auth status`).
- Acceso para modificar los DNS del dominio. Si el dominio está en Cloudflare, ya lo tienes.

## Paso 1: Crea la propiedad de Google Analytics y obtén el ID de medición

Google Analytics 4 (GA4) se organiza así: una cuenta contiene una o más propiedades, y cada propiedad contiene flujos de datos. Un sitio web corresponde a un flujo de datos web, y ese flujo tiene un ID de medición que empieza por `G-`.

1. Abre [analytics.google.com](https://analytics.google.com) e inicia sesión con tu cuenta de Google.
2. Haz clic en **Empezar a medir** (si ya usas Analytics, ve a **Administración → Crear → Cuenta**). Dale un nombre a la cuenta, por ejemplo `My sites`.
3. Crea la propiedad. Ponle el nombre de tu sitio, elige la zona horaria y la moneda para los informes, y responde las preguntas de negocio que aparecen.
4. Cuando elijas la plataforma, selecciona **Web**.
5. Escribe la dirección del sitio (`https://example.com`) y un nombre para el flujo de datos, y deja activada la **medición mejorada**. Esta registra vistas de página, desplazamientos, clics en enlaces salientes y descargas de archivos sin necesidad de código.
6. Crea el flujo de datos. Google mostrará sus detalles, incluido el **ID de medición**.

Copia el ID de medición, que tiene este formato: `G-ABCD123456`. Más adelante puedes volver a encontrarlo en **Administración → Recopilación y modificación de datos → Flujos de datos → tu flujo**.

El ID de medición no es secreto. Aparece en el código fuente de cada página que lo usa, así que puedes confirmarlo en el repositorio sin problema.

Comprobación: tienes un ID de medición que empieza por `G-`.

## Paso 2: Pide a Claude que conecte Google Analytics

Inicia Claude en la carpeta del proyecto:

```bash
cd ~/Sites/my-astro-site
claude
```

Después describe toda la tarea en una sola solicitud, incluidos el envío y la verificación. Cuanto más precisa sea la descripción del estado final, menos correcciones necesitarás después.

```text
Conecta Google Analytics 4 a este sitio Astro. El ID de medición es G-ABCD123456.

Requisitos:
- Coloca el cargador gtag.js y la llamada config en el <head> del layout compartido, para que cada página tenga exactamente una copia.
- Usa scripts inline normales (is:inline) para que window.gtag sea una función global real. Astro empaqueta los <script> normales como módulos, y eso impide que el código posterior acceda a gtag.
- Renderiza la etiqueta solo en la compilación de producción, no con `npm run dev`.
- Lee el ID de medición desde una constante o una variable de entorno, sin copiarlo en varios sitios.
- Ejecuta `npm run build` y comprueba que dist/index.html contiene la etiqueta.

Cuando la compilación pase, haz commit con un mensaje claro y envía los cambios a main. Después espera a que terminen los dos despliegues: el flujo de GitHub Pages y la compilación de Cloudflare. Por último, usa curl en https://example.com/ y confirma que el HTML publicado contiene el ID de medición. Informa de lo que comprobaste.
```

El fragmento que Claude genera en el layout debería parecerse a este:

```astro
---
const GA_ID = 'G-ABCD123456';
const isProd = import.meta.env.PROD;
---
<head>
  {isProd && (
    <>
      <script is:inline async src={`https://www.googletagmanager.com/gtag/js?id=${GA_ID}`}></script>
      <script is:inline define:vars={{ GA_ID }}>
        window.dataLayer = window.dataLayer || [];
        window.gtag = function () { dataLayer.push(arguments); };
        gtag('js', new Date());
        gtag('config', GA_ID);
      </script>
    </>
  )}
</head>
```

Hay dos detalles que conviene entender, porque son las causas más comunes de "he añadido la etiqueta, pero no pasa nada".

- **`window.gtag` debe ser una función global.** Si el script queda encerrado en un closure, las vistas de página pueden seguir funcionando, pero `window.gtag` estará indefinido. Todos los eventos personalizados que añadirás en el paso 6 fallarán en silencio. Asignar `window.gtag` explícitamente evita ese problema.
- **Actívala solo en producción.** Si la etiqueta también se ejecuta en `localhost`, tus propios clics durante el desarrollo contaminarán los datos.

Mientras esperas el despliegue, Claude usará comandos parecidos a estos:

```bash
gh run watch
curl -s https://example.com/ | grep -o 'googletagmanager.com/gtag/js?id=G-[A-Z0-9]*'
```

`gh run watch` sigue la ejecución de GitHub Actions hasta que termina. La línea con `curl` solo muestra algo cuando la página publicada contiene de verdad la dirección del cargador.

Comprobación: el informe de Claude indica que los dos servicios se desplegaron correctamente y que encontró el ID de medición en el HTML publicado. Si `curl` no muestra nada, el despliegue todavía no ha terminado o la caché está sirviendo una versión anterior. Pide a Claude que vuelva a intentarlo dentro de un minuto y, si la página antigua sigue apareciendo, borra la caché de Cloudflare.

## Paso 3: Confirma en Google Analytics que el sitio está en línea

Ahora comprueba el resultado desde el lado de Google, no solo desde tu navegador.

1. Abre `https://example.com` en el navegador. Si usas un bloqueador de anuncios o un navegador de privacidad, desactívalo para esta prueba, porque puede bloquear Google Analytics.
2. En Google Analytics, abre **Informes → Tiempo real**.
3. En un minuto aproximadamente deberías ver **1 usuario en los últimos 30 minutos** y el evento `page_view` en la lista de eventos.
4. Abre dos o tres páginas más y sus títulos aparecerán en la vista en tiempo real.

También puedes abrir **Administración → Flujos de datos → tu flujo**. Si aparece una marca verde que indica que los datos llegan, el flujo está recibiendo tráfico.

Comprobación: tu propia visita aparece en **Tiempo real**. Los informes estándar, como **Adquisición**, pueden tardar de unas horas a un día en mostrar datos, así que no te preocupes si siguen vacíos.

## Paso 4: Registra el sitio en Google Search Console

Google Analytics te dice qué hacen los visitantes cuando llegan. Google Search Console te dice cómo ve Google tu sitio: qué búsquedas traen visitas, qué páginas están indexadas y qué errores ha encontrado Google.

1. Abre [search.google.com/search-console](https://search.google.com/search-console) e inicia sesión con la misma cuenta de Google que usaste en Analytics. Usar la misma cuenta facilita la vinculación posterior.
2. Haz clic en **Añadir propiedad**. Verás dos tipos.
   - **Dominio** cubre `example.com` y todos sus subdominios y protocolos. Requiere un registro DNS.
   - **Prefijo de URL** cubre una dirección exacta, por ejemplo `https://example.com/`, y ofrece varios métodos de verificación.
3. Si tu DNS está en Cloudflare, elige **Dominio** y escribe `example.com`.
4. Search Console mostrará un registro `TXT`. Copia su valor, que empieza por `google-site-verification=`.
5. En el panel de Cloudflare, abre tu dominio y ve a **DNS → Registros → Añadir registro**. Elige el tipo `TXT`, escribe `@` como nombre, pega el valor en el contenido y guarda.
6. Vuelve a Search Console y haz clic en **Verificar**. Los cambios de DNS suelen tardar unos minutos, aunque a veces pueden tardar más. Si la verificación falla, espera un poco y vuelve a hacer clic en **Verificar**.

Si elegiste el tipo **Prefijo de URL**, la forma más sencilla de verificarlo es con Google Analytics. Mientras uses la misma cuenta de Google, Search Console puede usar la etiqueta que instalaste en el paso 2 como prueba de propiedad.

Comprobación: Search Console muestra "Propiedad verificada" y abre el resumen de la propiedad. Durante un tiempo mostrará "Sin datos", y eso es normal.

## Paso 5: Vincula Search Console con Google Analytics

Después de vincularlos, los términos de búsqueda y el rendimiento de las páginas de destino aparecen en los informes de Analytics. Así puedes comparar el tráfico procedente de búsquedas con lo que hacen esos visitantes.

1. En Google Analytics, abre **Administración**.
2. En **Vinculación de productos**, elige **Vinculación de Search Console**.
3. Haz clic en **Vincular**, luego en **Elegir cuentas** y selecciona tu propiedad de Search Console. Debes ser propietario de esa propiedad de Search Console y editor de la propiedad de Analytics.
4. Haz clic en **Siguiente**, elige el flujo de datos web y haz clic en **Enviar**.

Los datos de Search Console tardan algunos días en empezar a llegar y tienen un retraso de unos dos días. No hay nada que esperar aquí, así que puedes seguir con el siguiente paso.

Cuando se crea la vinculación, los informes correspondientes aparecen en **Informes → Biblioteca**. Los informes de Search Console no se añaden automáticamente al menú lateral. Si quieres que aparezcan allí, publica la colección **Search Console** desde la biblioteca.

Comprobación: en **Administración → Vinculación de productos → Vinculación de Search Console** aparece tu propiedad.

## Paso 6: Añade seguimiento de eventos adaptado a tu sitio

La medición mejorada ya registra vistas de página, desplazamientos, clics en enlaces salientes, búsquedas dentro del sitio y descargas de archivos. No los repliques. Los eventos sirven para lo específico de tu negocio: clics en el botón principal de acción, suscripciones al boletín, formularios de contacto y visitas a la página de precios.

La instrucción más útil no es "añade algunos eventos", sino "revisa mi sitio, propón un plan de eventos y espera mi aprobación". Así siempre decides qué se mide.

```text
Revisa la estructura de este sitio Astro: páginas, layouts, componentes, botones de llamada a la acción, formularios y enlaces salientes.

Paso 1: antes de modificar ningún código, propón un plan de eventos. Muéstrame una tabla con el nombre del evento, el momento en que se dispara, los parámetros y la pregunta de negocio que responde. Usa primero un nombre de evento recomendado de GA4 cuando exista uno adecuado (por ejemplo generate_lead, sign_up o select_content); si no, usa un nombre personalizado en snake_case. No dupliques lo que la medición mejorada ya registra: vistas de página, desplazamientos, clics en enlaces salientes y descargas de archivos. Como máximo, 10 eventos.

Paso 2: cuando apruebe el plan, impleméntalo:
- Marca los elementos con los atributos data-ga-event, data-ga-label y data-ga-location.
- Usa un único listener de clics delegado en document que lea esos atributos y llame a gtag('event', ...). No añadas manejadores onclick en línea.
- En los parámetros, envía solo IDs estables y la ubicación. Nunca envíes el texto de los enlaces, los datos introducidos en formularios, direcciones de correo ni nada que pueda identificar al visitante.
- No retrases ni canceles la navegación de los enlaces.

Paso 3: ejecuta la compilación, haz commit, envía los cambios, espera a que terminen los dos despliegues y usa curl para comprobar que el sitio publicado incluye el script del listener. Después dime en qué elementos debo hacer clic para verificarlo en DebugView de GA4.
```

Claude responderá primero con una tabla. Para un sitio pequeño, un plan razonable se parece a esto:

| Evento | Momento de disparo | Parámetros | Pregunta que responde |
| --- | --- | --- | --- |
| `cta_click` | El visitante hace clic en el botón principal de llamada a la acción | `label`, `location` | ¿Qué botones y zonas de la página generan acción? |
| `generate_lead` | El formulario de contacto se envía correctamente | `form_id` | ¿Cuántos visitantes se convierten en contactos? |
| `nav_click` | Se hace clic en un enlace del encabezado o del pie de página | `label`, `location` | ¿Qué elementos de navegación se usan? |
| `theme_toggle` | Se usa el cambio de tema | `value` | ¿Merece la pena mantener el interruptor de modo oscuro? |

Revisa la tabla con espíritu crítico. Elimina los eventos que nadie consultará y renombra los que describen una función en lugar de una decisión. Después responde algo como "aprobado, pero quita `theme_toggle`" para que Claude lo implemente.

El listener que Claude escriba será más o menos así:

```js
document.addEventListener(
  'click',
  (event) => {
    const el = event.target.closest('[data-ga-event]');
    if (!el || typeof window.gtag !== 'function') return;
    window.gtag('event', el.dataset.gaEvent, {
      label: el.dataset.gaLabel,
      location: el.dataset.gaLocation,
      transport_type: 'beacon',
    });
  },
  true,
);
```

Un botón marcado tendrá este aspecto:

```astro
<a href="/contact" data-ga-event="cta_click" data-ga-label="hero_contact" data-ga-location="home_hero">
  Contáctanos
</a>
```

### Verifica los eventos

1. En Google Analytics, abre **Administración → Visualización de datos → DebugView**. DebugView muestra los eventos que llegan en unos segundos.
2. Para poner el navegador en modo de depuración, instala la extensión de Chrome **Google Analytics Debugger** o pide a Claude que añada temporalmente `debug_mode: true` a la llamada `config`.
3. Visita el sitio publicado y haz los clics que indicó Claude.
4. Cada clic debe aparecer como un evento en la línea de tiempo de DebugView, con los parámetros esperados.

Una vez que un evento ha llegado, también aparece en **Administración → Visualización de datos → Eventos**. Si quieres usar `label` o `location` en los informes estándar, regístralos en **Administración → Visualización de datos → Definiciones personalizadas → Crear dimensión personalizada** con el ámbito **Evento**. Solo los parámetros registrados de esta forma aparecen en los informes estándar.

Quita todos los ajustes temporales de `debug_mode` y pide a Claude que envíe una versión limpia.

Comprobación: cada clic rastreado aparece en DebugView con el nombre y los parámetros correctos, y el código final ya está en `main`.

## Paso 7: Añade la capa básica de SEO

Los motores de búsqueda necesitan un mapa de páginas, instrucciones sobre qué pueden rastrear y la descripción que se muestra cuando alguien comparte una página. Astro tiene una integración oficial para el primer punto, y el resto son unas cuantas líneas en el layout. Claude puede añadir los componentes e integraciones de Astro necesarios y hacerlo rápido.

```text
Añade SEO básico a este sitio Astro.

1. Mapa del sitio: instala la integración oficial @astrojs/sitemap con `npx astro add sitemap`. Asegúrate de que `site` en astro.config.mjs sea el dominio de producción https://example.com y elimina la opción `base` que quedó del alojamiento de proyecto de GitHub Pages.
2. robots.txt: crea src/pages/robots.txt.ts para devolver "User-agent: *", "Allow: /" y una línea Sitemap que apunte a https://example.com/sitemap-index.xml. Esa dirección debe generarse a partir de la configuración `site`, no escribirse a mano.
3. Un componente SEO reutilizable para el layout compartido que genere: <title>; meta description; un enlace canónico generado a partir de la URL actual y de `site`; etiquetas Open Graph (og:type, og:title, og:description, og:url, og:image, og:site_name, og:locale); etiquetas de tarjeta de Twitter (twitter:card summary_large_image, twitter:title, twitter:description, twitter:image); y la meta etiqueta theme-color. Cada página debe pasar su propio título y descripción mediante props.
4. Proporciona una imagen social predeterminada de 1200x630 en public/og-default.png para las páginas que no tengan una propia.
5. Añade datos estructurados JSON-LD de tipo WebSite al sitio. Si el sitio tiene blog, añade también el tipo Article a los artículos.
6. Ejecuta `npm run build`, muestra el contenido de dist/sitemap-index.xml, muestra dist/robots.txt y confirma que el HTML generado de la página principal incluye todas las etiquetas anteriores.

Cuando todo esté correcto, haz commit, envía los cambios, espera a que terminen los dos despliegues y usa curl para confirmar que https://example.com/sitemap-index.xml y https://example.com/robots.txt devuelven 200 con el contenido correcto.
```

Qué hace cada parte:

- **Mapa del sitio.** `@astrojs/sitemap` genera `sitemap-index.xml` y uno o más archivos `sitemap-0.xml` durante la compilación. Necesita la configuración `site` para crear URL absolutas.
- **`robots.txt`.** Indica a los rastreadores qué pueden rastrear y dónde está el mapa del sitio. Si quieres que una página no aparezca en los resultados, usa `noindex`; no basta con bloquearla en `robots.txt`.
- **Enlace canónico.** Cuando una misma página puede abrirse con varias direcciones, indica a Google cuál es la oficial.
- **Etiquetas Open Graph y Twitter.** Determinan el título, la descripción y la imagen que aparecen cuando se comparte un enlace en redes sociales o aplicaciones de mensajería.
- **JSON-LD.** Los datos estructurados ayudan a los buscadores a entender de qué trata una página. No garantizan resultados enriquecidos, pero cuestan poco de añadir.

Comprobación: el `sitemap-index.xml` publicado enumera tus páginas, `robots.txt` contiene la línea `Sitemap:` y el código fuente de la página muestra las etiquetas canónica, Open Graph y de Twitter. También puedes pegar la URL en una herramienta de validación de tarjetas sociales o compartirla en una aplicación de mensajería para ver la vista previa.

## Paso 8: Envía el mapa del sitio en Search Console

Search Console no sabe que existe tu mapa del sitio hasta que se lo indiques.

1. En Search Console, abre tu propiedad y elige **Sitemaps** en el menú lateral.
2. En **Añadir un nuevo sitemap**, escribe `sitemap-index.xml`.
3. Haz clic en **Enviar**.
4. El estado debería cambiar a **Correcto** y mostrar el número de páginas detectadas. Si aparece **No se pudo obtener**, abre primero la dirección del sitemap en el navegador. Si carga, espera unos minutos y actualiza, porque la primera lectura puede tardar.

Después pide a Google que revise hoy mismo tus páginas más importantes:

1. Pega la URL de la página principal en la barra de búsqueda de la parte superior de Search Console.
2. Si la página todavía no está indexada, haz clic en **Solicitar indexación**.

La indexación todavía puede tardar unos días, y los informes de Search Console tienen retraso. Vuelve dentro de una semana.

Comprobación: en **Sitemaps** aparece `sitemap-index.xml` con el estado **Correcto**.

## Paso 9: Optimiza los metadatos de cada página y añade favicons de varios tamaños

La capa básica da a cada página metadatos genéricos. El título y la descripción son el texto que la gente lee en los resultados de búsqueda, así que merece la pena revisarlos página por página. Los favicons necesitan varios tamaños, porque los navegadores, los teléfonos y los marcadores piden archivos distintos.

### Títulos, descripciones y palabras clave

```text
Revisa cada página de este sitio y optimiza sus metadatos de búsqueda.

Para cada página, muéstrame una tabla de antes y después con el título, la meta description y las palabras clave, y después aplica los cambios. Reglas:
- Título: único en cada página, de unos 60 caracteres como máximo, con el tema principal al principio y el nombre del sitio al final.
- Descripción: única en cada página, de 120 a 160 caracteres, en una frase natural que explique qué obtendrá el visitante e invite a hacer clic. No llenes el texto de palabras clave ni copies frases entre páginas.
- Palabras clave: de 5 a 8 términos extraídos del contenido real de la página. Conserva la meta etiqueta keywords solo si el layout ya la admite, y no inventes temas que la página no trata.
- Comprueba que cada página tenga exactamente un <h1> coherente con su título y que cada imagen tenga un atributo alt.

Después ejecuta la compilación y escribe un informe breve con las páginas que todavía comparten título o descripción.
```

Conviene ajustar las expectativas: los buscadores ignoran en gran medida la meta etiqueta keywords. Escribir las palabras clave te ayuda a aclarar de qué trata cada página. Lo que aparece de verdad en los resultados de búsqueda son el título y la descripción.

### Favicons de varios tamaños

Un `favicon.svg` es un buen punto de partida, pero algunos lugares necesitan archivos concretos: los navegadores antiguos y los marcadores usan `favicon.ico`, la pantalla de inicio de iOS usa `apple-touch-icon`, y Android y los manifiestos de aplicaciones web usan PNG de 192 y 512 píxeles.

macOS incluye `sips` para escalar PNG. Para generar `.ico` necesitas ImageMagick, que puedes instalar con Homebrew. Deja que Claude use estas herramientas directamente en tu Mac:

```text
Genera un conjunto completo de favicons a partir de mi imagen fuente public/logo-source.png (un PNG cuadrado de al menos 512x512).

1. Usa el comando `sips` de macOS para crear public/icon-192.png, public/icon-512.png y public/apple-touch-icon.png (180x180).
2. Si ImageMagick no está instalado, instálalo con `brew install imagemagick`. Usa `magick` para crear public/favicon.ico con imágenes de 16x16, 32x32 y 48x48.
3. Si ya tengo public/favicon.svg, conservarlo; si no existe, crea una versión sencilla que coincida con el logotipo.
4. Añade public/site.webmanifest con referencias a icon-192.png e icon-512.png.
5. Actualiza el <head> del layout con las etiquetas <link> correspondientes: icono SVG, respaldo .ico, apple-touch-icon y manifiesto.
6. Ejecuta `file` sobre cada imagen generada para confirmar su tamaño real, ejecuta la compilación y comprueba que estos archivos aparecen en dist/.
```

Claude ejecutará comandos parecidos a estos:

```bash
sips -z 192 192 public/logo-source.png --out public/icon-192.png
sips -z 512 512 public/logo-source.png --out public/icon-512.png
sips -z 180 180 public/logo-source.png --out public/apple-touch-icon.png
brew install imagemagick
magick public/logo-source.png -define icon:auto-resize=48,32,16 public/favicon.ico
file public/*.png public/favicon.ico
```

Los enlaces del `<head>` serán así:

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="icon" href="/favicon.ico" sizes="48x48" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<link rel="manifest" href="/site.webmanifest" />
```

Por último, cierra el ciclo como en los pasos anteriores:


## Preguntas frecuentes

- **El informe en tiempo real está vacío.** Un bloqueador de anuncios o un navegador de privacidad está bloqueando la etiqueta. Prueba en una ventana privada con las extensiones desactivadas y confirma el ID de medición en el HTML publicado.
- **Las vistas de página funcionan, pero los eventos personalizados no.** En el sitio publicado, abre la consola del navegador y ejecuta `typeof window.gtag`. Debe devolver `function`. Si devuelve `undefined`, el script de la etiqueta se empaquetó como módulo; pide a Claude que use `is:inline` y asigne `window.gtag` explícitamente.
- **Los eventos aparecen en DebugView, pero no en los informes.** Los informes estándar pueden tardar hasta un día, y los parámetros personalizados solo aparecen cuando están registrados como dimensiones personalizadas.
- **Search Console no puede verificar el dominio.** Comprueba que el registro `TXT` esté en el dominio raíz (`@`), que el valor esté copiado completo y que no esté activado el proxy de Cloudflare, porque los registros TXT no pasan por el proxy. Después espera un poco y vuelve a intentarlo.
- **El sitemap aparece como "No se pudo obtener".** Abre `https://example.com/sitemap-index.xml` en el navegador. Si devuelve 404, revisa que `site` en `astro.config.mjs` sea el dominio de producción y que la integración del sitemap aparezca en `integrations`.
- **La vista previa en redes sociales está desactualizada.** Las plataformas guardan vistas previas en caché. Después de cambiar las etiquetas, usa sus herramientas de depuración para actualizar la caché.

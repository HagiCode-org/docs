Esta guía te lleva desde un Mac sin configurar hasta un sitio web publicado en internet. Trabajarás en dos lugares: en la Terminal, donde instalas las herramientas, y en Claude Code, que ejecuta los comandos repetitivos y edita los archivos por ti. Cada paso termina con algo que puedes comprobar, así sabes que todo ha funcionado antes de seguir.

El camino completo tiene este aspecto:

1. Instalar Node.js.
2. Instalar GitHub CLI (`gh`) e iniciar sesión.
3. Pedirle a Claude que cree un repositorio privado y lo clone.
4. Pedirle a Claude que prepare un sitio Astro con cabecera, pie de página y diseño adaptable, y después guardar los cambios y subirlos.
5. Instalar la skill impeccable y usar su comando `overdrive` para pulir la página de inicio.
6. Publicar el sitio en GitHub Pages con un flujo de trabajo de GitHub Actions.
7. Conectar un dominio en Cloudflare y desplegar la misma rama con Workers.
8. Añadir una página nueva, subirla y ver cómo terminan los dos despliegues.

## Para quién es esta guía

Esta guía es para personas que tienen un Mac y una cuenta de GitHub y quieren publicar un sitio web estático sencillo sin configurar un servidor. No necesitas saber antes nada de Astro, GitHub Actions ni Cloudflare. Sí necesitas sentirte cómodo abriendo la Terminal y pegando comandos.

## Requisitos previos

- Un Mac con una versión actual de macOS.
- Una cuenta de GitHub.
- Una cuenta de Cloudflare.
- Un nombre de dominio. Puedes registrarlo a través de Cloudflare o usar uno que ya tengas.
- Claude Code instalado e iniciado sesión. Ejecuta `claude` en la Terminal una vez para confirmar que arranca.

## Paso 1: Instalar Node.js

Astro y el instalador de impeccable funcionan con Node.js. Usa la versión LTS actual.

La forma más sencilla es el instalador oficial de [nodejs.org](https://nodejs.org). Descarga el paquete para macOS, ejecútalo y acepta las opciones por defecto.

Si ya usas Homebrew, puedes instalarlo desde la Terminal:

```bash
brew install node
```

Abre una ventana nueva de la Terminal y comprueba las dos herramientas:

```bash
node --version
npm --version
```

Ambos comandos deberían mostrar un número de versión. Si no se encuentra `node`, cierra y vuelve a abrir la Terminal para que se cargue el nuevo `PATH`.

## Paso 2: Instalar GitHub CLI e iniciar sesión

GitHub CLI, llamado `gh`, permite a Claude crear repositorios y gestionarlos sin que tengas que hacer clic por la web.

```bash
brew install gh
gh --version
```

Después inicia sesión:

```bash
gh auth login
```

Responde a las preguntas así:

- **Where do you use GitHub?** (¿Dónde usas GitHub?) `GitHub.com`
- **Preferred protocol?** (¿Protocolo preferido?) `HTTPS`
- **Authenticate Git with your GitHub credentials?** (¿Autenticar Git con tus credenciales de GitHub?) `Yes`
- **How would you like to authenticate?** (¿Cómo quieres autenticarte?) `Login with a web browser`

Copia el código de un solo uso que muestra la Terminal, pulsa Intro y termina el inicio de sesión en tu navegador. Cuando acabes, comprueba el resultado:

```bash
gh auth status
```

La salida debería indicar que has iniciado sesión en `github.com`.

## Paso 3: Pedirle a Claude que cree un repositorio privado

Elige una carpeta donde quieras guardar tus proyectos, por ejemplo `~/Sites`, y créala si no existe:

```bash
mkdir -p ~/Sites
cd ~/Sites
claude
```

Después pídele a Claude algo como esto:

```text
Usa GitHub CLI para crear un repositorio privado llamado my-astro-site en mi cuenta de GitHub.
Inicialízalo con un README para que exista la rama main, y clónalo en esta carpeta.
Muéstrame la URL del repositorio cuando termines.
```

Claude debería ejecutar algo equivalente a:

```bash
gh repo create my-astro-site --private --add-readme --clone --description "My Astro site"
```

Cuando termine, deberías tener una carpeta `~/Sites/my-astro-site` que contenga un `README.md`, y el repositorio debería ser privado en GitHub. Comprueba la rama por defecto:

```bash
cd ~/Sites/my-astro-site
git branch --show-current
```

Debería mostrar `main`.

## Paso 4: Preparar el sitio Astro

Quédate en la carpeta del repositorio e inicia Claude allí:

```bash
cd ~/Sites/my-astro-site
claude
```

Pídele a Claude que cree un sitio básico:

```text
Crea un sitio web básico de Astro en este repositorio usando la plantilla oficial basics de Astro.
Añade una cabecera del sitio con el nombre del sitio y enlaces de navegación, un pie de página con texto de copyright,
y un diseño que funcione en teléfonos, tabletas y pantallas de escritorio anchas.
Mantén el diseño sencillo. Ejecuta el servidor de desarrollo, revisa la página y muéstrame cómo verla.
```

Cuando Claude termine, abre tú mismo la vista previa local:

```bash
npm install
npm run dev
```

Astro muestra una dirección local, normalmente `http://localhost:4321`. Ábrela en tu navegador, cambia el tamaño de la ventana para comprobar el diseño y después detén el servidor con `Control+C`.

Antes de guardar los cambios, asegúrate de que la compilación de producción funciona:

```bash
npm run build
```

### Guardar y subir la primera versión

Pídele a Claude que guarde el trabajo:

```text
Guarda el sitio Astro con un mensaje claro y súbelo a la rama main en origin.
```

Claude debería ejecutar comandos como:

```bash
git add .
git commit -m "Scaffold Astro site with header, footer and responsive layout"
git push origin main
```

Confirma en GitHub que tu último cambio aparece en la rama `main` del repositorio.

## Paso 5: Instalar impeccable y aplicar overdrive a la página de inicio

[impeccable](https://impeccable.style) es una skill de diseño para agentes de programación. Le da a Claude un vocabulario común para el trabajo de diseño, como `polish`, `critique` y `overdrive`. El comando `overdrive` añade efectos más atrevidos y expresivos, como shaders, física de muelles y animaciones dirigidas por el desplazamiento.

Pídele a Claude que instale la skill para este proyecto:

```text
Instala la skill impeccable en este proyecto usando su instalador oficial.
Usa el ámbito del proyecto y el proveedor Claude Code. Dime cuándo tengo que reiniciar Claude Code.
```

Claude debería ejecutar esto desde la raíz del proyecto:

```bash
npx impeccable install
```

El instalador pregunta si quieres instalarlo para este proyecto o de forma global, y ofrece un hook de diseño. Acepta el hook y después reinicia Claude Code para que cargue la nueva skill.

En la sesión reiniciada, inicializa el contexto de diseño:

```text
/impeccable init
```

Después aplica el paso de overdrive a la página de inicio:

```text
/impeccable overdrive the homepage
```

Revisa lo que ha cambiado Claude antes de guardar. Overdrive puede añadir mucho movimiento, así que quizá quieras conservar solo los efectos que ayuden al lector a entender la página. Pídele a Claude que vuelva a ejecutar la compilación y que suba el resultado:

```text
Ejecuta npm run build, corrige cualquier error, después guarda los cambios de overdrive y súbelos a main.
```

## Paso 6: Publicar en GitHub Pages con GitHub Actions

GitHub Pages puede alojar el sitio compilado de forma gratuita. Astro ofrece una GitHub Action oficial que compila el sitio y lo despliega.

### Activar Pages

Abre tu repositorio en GitHub y ve a **Configuración (Settings) → Pages**. En **Compilación y despliegue (Build and deployment)**, cambia **Origen (Source)** a **GitHub Actions**.

### Deja que Claude añada el flujo de trabajo

```text
Añade un flujo de trabajo de GitHub Actions en .github/workflows/deploy.yml que use actions/checkout
y withastro/action para compilar este sitio Astro y desplegarlo en GitHub Pages.
Mantén el bloque de permisos que incluye la plantilla de Astro.
```

El flujo de trabajo que cree Claude se parecerá al ejemplo documentado por Astro:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7
      - name: Install, build, and upload your site
        uses: withastro/action@v6
```

### Configurar la dirección del sitio

GitHub Pages sirve un sitio de proyecto bajo una ruta, como `https://<your-username>.github.io/my-astro-site`. Astro necesita conocer esa ruta, o sus enlaces y recursos se romperán. Pídele a Claude que actualice `astro.config.mjs`:

```text
Define site como https://<your-username>.github.io y base como /my-astro-site en astro.config.mjs.
Explica para qué sirve cada ajuste.
```

El resultado debería tener este aspecto:

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://<your-username>.github.io',
  base: '/my-astro-site',
});
```

Sustituye `<your-username>` por tu nombre de usuario de GitHub. Cuando más adelante pases a tu propio dominio, eliminarás `base`.

Guarda y sube el flujo de trabajo y el cambio de configuración:

```text
Guarda el flujo de trabajo de Pages y el cambio de configuración de Astro, y después sube los cambios a main.
```

### Esperar al primer despliegue

Abre la pestaña **Actions** de tu repositorio. La ejecución `Deploy to GitHub Pages` debería ponerse en verde en uno o dos minutos. Después abre la URL de Pages que aparece en **Configuración (Settings) → Pages**.

## Paso 7: Conectar un dominio en Cloudflare

Para este paso de Cloudflare necesitas un dominio. Hay dos opciones habituales:

- **Registrar un dominio nuevo** a través de Cloudflare Registrar desde el panel de Cloudflare.
- **Usar un dominio que ya tengas.** Añádelo a Cloudflare como sitio y después cambia los servidores de nombres del dominio en tu registrador por los dos servidores de nombres que te dé Cloudflare.

Inicia sesión en el [panel de Cloudflare](https://dash.cloudflare.com) y después registra el dominio o añade el que ya tienes. Espera hasta que Cloudflare muestre el dominio como activo. Puede tardar unos minutos después de cambiar los servidores de nombres.

## Paso 8: Crear un proyecto Worker desde la rama de GitHub

La guía actual de Cloudflare para Astro usa Workers. En el panel, el flujo Git de estilo Pages sigue apareciendo en la misma sección **Workers y Pages (Workers & Pages)**, pero los pasos siguientes siguen la ruta de Workers.

Primero, pídele a Claude que añada una configuración de Wrangler para una compilación estática de Astro. Wrangler es la herramienta de línea de comandos de Cloudflare.

```text
Añade un archivo wrangler.jsonc en la raíz del proyecto para un sitio Astro estático.
Define el nombre como my-astro-site, define compatibility_date con la fecha de hoy,
y sirve la carpeta ./dist como recursos estáticos. No añadas un punto de entrada main.
```

Debería tener este aspecto:

```jsonc
{
  "name": "my-astro-site",
  "compatibility_date": "2026-11-23",
  "assets": {
    "directory": "./dist"
  }
}
```

Guarda y sube el archivo. Después crea el proyecto en Cloudflare:

1. En el panel de Cloudflare, ve a **Workers y Pages (Workers & Pages)**.
2. Selecciona **Crear aplicación (Create application)** y elige la opción de importar un repositorio desde GitHub.
3. Autoriza la aplicación de GitHub **Cloudflare Workers & Pages** cuando Cloudflare lo pida. Elige todos los repositorios o solo `my-astro-site`.
4. Selecciona `my-astro-site` y la rama `main`.
5. Define el comando de compilación como `npm run build` (o `npx astro build`) y el comando de despliegue como `npx wrangler deploy`.
6. Inicia el despliegue.

Cloudflare compila el sitio con cada subida a la rama conectada, así que los cambios futuros se desplegarán automáticamente.

### Asociar tu dominio

Abre el nuevo Worker en el panel, ve a **Dominios y rutas (Domains & Routes)** y añade tu dominio o un subdominio como `www`. Cloudflare crea el registro DNS por ti cuando el dominio ya está en la misma cuenta.

## Paso 9: Revisar el sitio en Cloudflare

Cuando termine la primera compilación, mira estos lugares en el panel de Cloudflare:

- **Deployments (Despliegues):** la última compilación debería aparecer como correcta. Si falló, abre el registro de la compilación y lee el primer error.
- **Dominios y rutas (Domains & Routes):** tu dominio personalizado debería aparecer como activo.
- **Settings (Configuración):** confirma que el repositorio y la rama conectados son los que esperas.

Después abre tu dominio en el navegador. Revisa la cabecera, el pie de página y el diseño en el teléfono y también en una ventana de escritorio ancha.

## Paso 10: Añadir una página nueva y verla publicarse

Ahora tienes el ciclo completo: editar en tu equipo, subir a GitHub y dejar que las plataformas compilen y desplieguen el cambio.

Inicia Claude en la carpeta del proyecto y pídele una página nueva:

```text
Crea una página nueva en src/pages/about.astro con un título, un párrafo corto y un enlace de vuelta a la página de inicio.
Usa la misma cabecera y el mismo pie de página que las otras páginas. Ejecuta npm run build, después guarda los cambios y súbelos a main.
```

Claude debería crear el archivo, compilar el sitio, guardar los cambios y subirlos. Después observa los dos despliegues:

- **GitHub:** abre la pestaña **Actions**. El flujo de trabajo de Pages vuelve a ejecutarse.
- **Cloudflare:** abre **Workers y Pages → tu proyecto → Deployments**. Una nueva compilación empieza automáticamente.

Cuando los dos muestren que han terminado correctamente, abre `https://<your-domain>/about` en el navegador. Si la página no aparece, comprueba que el archivo está en `src/pages/about.astro`, que el último despliegue ha terminado y que tu navegador no está mostrando una copia antigua en caché.

## Problemas habituales

- **`node: command not found`:** abre una ventana nueva de la Terminal después de instalar Node.js.
- **`gh` no puede crear el repositorio:** ejecuta `gh auth status` y asegúrate de que el inicio de sesión tiene acceso a tu cuenta.
- **GitHub Pages muestra una página en blanco o sin estilos:** revisa `site` y `base` en `astro.config.mjs`. El valor de `base` debe coincidir con el nombre del repositorio.
- **La compilación de Cloudflare falla:** lee el primer error del registro de la compilación. La mayoría de los fallos se deben a un script que falta, un comando de compilación incorrecto o una configuración de Wrangler que apunta a la carpeta equivocada.
- **El dominio no está activo:** los cambios de servidores de nombres pueden tardar en propagarse. Revisa el estado en la página de resumen del dominio en Cloudflare.

## Próximos pasos

Una vez que el sitio esté en línea, puedes mantener el mismo ciclo para contenido real. Pídele a Claude que añada páginas, ejecuta `/impeccable critique` para una revisión de diseño o añade un segundo entorno de Cloudflare para las vistas previas. El hábito principal es sencillo: haz un cambio pequeño, compílalo en tu equipo, guárdalo y deja que las plataformas lo publiquen.
